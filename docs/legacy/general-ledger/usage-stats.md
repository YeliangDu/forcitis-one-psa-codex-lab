# U8C 使用面统计（只读盘点，近 12 个月）

> 离线整理产物。不连接任何服务器；原始数据来自此前只读查询导出（r_stats.tsv、r10.tsv、r1.tsv）。本文只含计数、编码与名称，不含金额；用户只以计数出现，不含任何人名。

## 0. 数据来源与口径

- **数据来源**：QZ = 权责账套（库 `u8cloud_QZ`），SF = 收付账套（库 `u8cloud`）。查询脚本见 `u8c_readonly_queries.sql` 与说明 README_queries.md（stats.sql 32 个 key、q10 的 Q3/Q4/Q6/Q7、r1 的非空表行数）。
- **统计窗口「近 12 个月」**：2025-10 至 2026-09。凭证按 `year+period BETWEEN '202510' AND '202609'`（注意：该字符串区间包含 SF 的 2026 年 `00` 期，即期初期间凭证）；日志按日期 2025-10-01 至 2026-09-30；ky_apilog 的「近 12 月」同此；xx_xlog 的「近约 90 天」为 doc_time ≥ 2026-07-15。数据导出时间约 2026-10-14，故部分「总计 / 末次」含 2026-10 的数据。
- **账簿范围**：科目使用面、辅助核算、职责分离只统计 5 个重点账簿 1001-0001 / 1002-0001 / 1003-0001 / 1006-0001 / 1007-0001（SF 另有 28 个账簿有用户授权记录，多为休眠 / 历史公司账簿，未纳入）。公司（sm_createcorp）与角色范围覆盖两套账全部：QZ 5 家公司，SF 52 家公司。
- **凭证口径**：`gl_voucher.dr=0` 且 `discardflag<>'Y'`（§6.3 的 g4 例外，含作废）。「已审核 / 已记账 / 出纳」= `pk_checked` / `pk_manager` / `pk_casher` 非空且不为 'N/A'。「有发生」= 近 12 个月 gl_detail 存在分录行（不看金额是否为 0，含未审核未记账凭证）。
- **来源 pk_system**：GL 总账手工制单；FA 固定资产；TR 与 XX 的含义材料中未注明（XX 凭证量最大，疑为外部/接口导入，TR 疑为转账类），本文只按代码呈现。
- **科目分类**：数字科目按首位 1 资产 / 2 负债 / 4 权益 / 5 成本 / 6 损益（无 3 共同类）。QZ 另有一套以 A–E 开头的「Q 科目」，其级次结构与数字科目逐级相同（A=资产、B=负债、C=权益、D=成本、E=损益，按总数对应推断），单独列表。
- **日志口径**：sm_operatelog 记录的是进入功能节点的次数（enterfunctioncode），不是业务单据数；操作人数为 distinct operatorid。
- **未取到的数据**：e8_users（用户状态分布）、g3_cash_tagged（现金科目分录与已标注现金流量对照）两段在两套账均查询报错，无数据；Q1_match_2026_by_prefix 同样报错（与本文无关）。因此总有效用户数无法跨角色去重，只给各角色的有效人数。
- 角色名称、功能名称、科目名称为系统档案中的岗位/功能/科目名，不是个人姓名；用户一律只给计数。

**对新系统的含义**

- 末级科目整体使用率偏低：1001-0001 在 QZ 为 42.7%（数字科目 40.7%、Q 科目 44.7%），SF 为 52.6%；其他四个账簿更低（QZ 2.6% / 16.7% / 9.3% / 6.6%，SF 7.4% / 21.9% / 11.1% / 8.9%）。新系统不应整库平移 950 个科目（QZ）/ 470 个科目（SF）给每个账簿，宜用「标准科目模板 + 按主体启用」，零发生科目以停用状态保留或不迁入（迁入前须另核期初余额，零发生不等于零余额）。
- 使用集中在损益类（1001-0001 末级使用率 QZ 61%~64%、SF 见上表）和二级的资产/负债类；权益类（QZ 8.3%）、一级科目、成本类的使用率低，可优先作为裁剪或隐藏候选。
- QZ 的数字科目与 Q 科目是两套并行的科目树且都在用（有发生末级 167 与 184），属于同一业务口径下的双轨编码。新系统只需一棵科目树，加「科目映射表」承载对旧编码的追溯；需业务确认两棵树的发生是否重复或对应。
- 异常科目为 0（无非末级有分录、无封存科目），科目树结构本身干净，迁移无需做非末级清洗。

**对新系统的含义**

- 必须在系统层强制：制单人 ≠ 审核人（现状已是硬规则，保持）；记账人 ≠ 制单人应作为默认强制项（SF 存在 619 张违反），确需例外（期初、接口导入）必须由独立的「导入/期初」流程承接并留痕，而不是复用人工记账。
- 「审核=记账」是现状常态（QZ 59%），新系统可保留「审核后由同一人记账」的选项，但须作为可配置策略而不是默认放行，并加审计事件。
- 把「未审核即记账」做成不可能：记账前置条件是已审核（GL003），新系统不再允许写入无审核人的已记账凭证；迁移时要对存量的这类凭证做标记，不宜当作正常数据。
- 出纳人字段当前恒为空，新系统若引入出纳签字控制，历史凭证不应回填。
