### SCH-06 离职归还提醒的起算点

- 起算点 = 离职版本的生效日，即事件信封的 `businessDate`（最后工作日次日，业务时区零点），不是事件发布时刻、也不是作业运行时刻。依据 ADR-0068 决定 1.5、1.9；归还提醒周期「满七个日历日」按业务日期（Asia/Shanghai）数，提醒日 = 生效日 + 7 个日历日。
- 晚到、重复的离职事件不改变起算点（设计 §5.2 已写，与此一致）；手工归还不套期限（契约 §3 第 11 项）。

### Q-B31-1 INV-138 数什么：只数实际用印，还是也占用

- 依据与差异：INV-138 原文是「累计用印份数不超过批准份数」；设计 §3.2、§9 第 2 条与规则稿 YY-06 写成「占用、释放」（放弃或关闭即释放占用），含义不同。用户 B31R-Q7 的话是「同一老系统单号累计用印份数在系统内计数，超上限即拒」，说的是累计用印，没有说占用。
- 选项与代价：
  - A 只数实际用印（按原文）：登记用印时在锁内核对，累计超批准份数即拒；没有占用和释放，规则简单。代价是两张同源申请可以先后都通过申请，后一张到登记时才被拒。
  - B 提交即占用、放弃或关闭即释放（设计现写法）：提前拦住超份数申请。代价是多一套占用、释放、更正规则，且占用不是 INV 原文说的「用印」，须修订 INV 文字。
- 推荐 A：与用户原话和 INV 原文一致，先上线最简；若实际出现提前占坑的纠纷，再按 B 加（那时是改规则，不改历史）。
- 若选 A，设计 §9 第 2 条「放弃或关闭即释放占用」应改为「放弃或关闭不改变累计用印」。INV 的分类（聚合稿标 A，实际跨申请）与文字归 one-architecture，锁键与约束归 one-data。

### Q-B31-2 老系统单号路径的份数上限怎么定

- 已定（B31R-Q7）：同一老系统单号累计用印份数在系统内计数，超上限即拒；批准页必留，行政核对留痕。
- 未覆盖的细节：上限由行政登记时录入批准页所载份数（设计 §9 第 3 条）。同一单号再次登记时批准页所载份数与第一次不一致，怎么办。
- 推荐：同一老系统单号的批准份数以首次登记为准；之后登记的份数与首次不同即拒并提醒行政核对，更正走冲正并留痕。
- 键用「老系统单号」只在过渡通道成立，合同、报价、投标模块上线即废止（B31R-Q7）；废止后键换成新系统的来源审批实例。老系统单号作为键的命名与「老系统」字样的使用范围归 one-glossary（GLO-10）。

### Q-B31-3 冲正是否计入累计

- 若选 Q-B31-1 的 A：累计用印 = 全部用印记录份数之和，冲正记录按反向份数计入，因此冲正一条后，对应份数在累计里腾出来。
- 要用户定的点：一条错记的用印被冲正后，那几份是否可以再用。推荐：可以再用（错记本来没发生）；但冲正只能由行政负责人做，且须留原因（防止借冲正绕上限）。
- 这一条只在 INV-138 与冲正的交界上，若 Q-B31-1 选 B，则另按占用口径重写。

### Q-B31-4 一个用途要不要对应多个印章类型

- 背景：Q2 里「合同章、法定代表人名章、合同专用章」同属合同类用途；用途 → 印章类型表（RUL-05）一个用途可能要盖不止一种章。
- 推荐：允许一个用途对应多个印章类型，用印申请逐印章类型填份数，台账按（法人、印章类型）逐条引用；对应表初版由行政随印章清单提供。
- 此问可由行政回答，不必占用户时间；也可以在印章清单到位后由 one-1a-admin 直接核对，我只在表里有「一对多」时需要改规则卡。

## 四、周年贺卡三问（one-1a-admin 7.8 G-3，2026-10-22）

依据：用户原话「满周年就有，全体正式员工，不补发」及闰日、重新入职、漏发不补（intent `2026-10-20-232338`，B31P 定稿；HD-02 登记资格为在职员工）。

1. **满 0 年（入职当年）发不发：不发。** 「满周年」是满 N 个整年，N≥1；入职当日不是周年。蓝图卡 D 写的 N≥1 与此一致。不需要用户。
2. **试用期是否排除：不依赖 `employment_phase`。** 周年 N≥1 即入职满一整年，已过法定试用期上限，试用期与周年不会重叠，所以不需要 W2 的 `employment_phase`。「正式员工」原话更可能指雇佣类型（与实习、派遣等非正式雇佣相对）而不是试用期；哪些雇佣类型算「正式」用户没说，列入待用户清单（Q-B31-5，推荐：在职且为正式雇佣类型，类型清单由人事字段给出，作业不写死）。人事侧没有雇佣类型字段前，作业按「在职」选人并在卡里标注此限制，不当作定论。
3. **手工提交「周年贺卡」类型：一律拒绝。** 周年贺卡只由系统作业生成（「满周年自动生成」）；用户已定「漏发不补」，手工补登等于补发，与之冲突；去重键（员工、本次入职日期、周年日期、活动类型，含已取消记录）也要求只有一条来源。这是由已定原话推出的规则，不是新口径，不需要用户；错发的撤销走取消（原因必填、保留原记录，HD-05）。

3. **改派加事后知会**：知会对象为被兜底的第一审批人及其上级，知会内容含改派原因（离职、休假、停用）与单据号；不并行双批，同一审批节点同一时刻只有一个待办人。「不兜到总经理」写成约束：兜底角色解析结果不得为总经理岗位，命中即视为缺人。
