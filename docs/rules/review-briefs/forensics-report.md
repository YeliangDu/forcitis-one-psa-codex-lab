# 评审模板 6：取证报告（读老系统 / A8 生产数据的结果）

通用做法、输出格式、七条通用盲区 B1–B7 见 [README.md](README.md)。取证规则的出处是 ADR-0037 和 METHODS.md「生产取证不逐次请示」一条；CLAUDE.md 第 4 条：设计以行业通行做法为主要依据，老系统生产数据只作参考与核对；确需复刻的老行为（迁入对账、过账口径、在途单据）仍以生产数据为证据，不凭推测。本类评审**不连生产库**，只读报告、查询原文与登记。

## 出题人填（只填这一栏）

- 产出：取证报告路径（或所在文档与章节）、对应的登记片段（`phase1a/infra/legacy-read/` 里的文件）、查询脚本或 SQL 原文路径、落盘文件路径（若有）、基线提交。
- 不填：「口径已核对」「无个人信息」之类结论。

## 必读材料（自己读）

1. ADR-0037 原文（尤其第 5 项取证账号、第 7 项登记、第 8 项读取口径）与 METHODS.md 的「生产取证不逐次请示」全部分条。
2. 报告本身，以及报告引用的**每一条**查询的 SQL 原文（不是描述）。
3. `phase1a/infra/legacy-read/` 中对应片段；`LEGACY_READ_REGISTER.md` 的开头说明。
4. 被读的表与列：`docs/data/legacy-views/seeyon-views.sql`、`external-read-registry.yaml`、老系统结构说明（报告引用的）；凭据列清单 `credential_columns.csv`。
5. 报告结论所服务的规则卡、ADR 或设计文档（看结论被拿去做什么）。

## 必查项

| # | 查什么 | 判过 | 判不过 |
|---|---|---|---|
| F1 | **账号** | 用的是取证专用只读账号（`one_evidence_ro` 一类）；若用了别的账号，有用户对这一次的批准原文 | 用了运行时账号、高权限账号或老系统应用的数据源 |
| F2 | **读取口径**（ADR-0037 第 8 项） | SQL 里没有 `NOLOCK` / `READ UNCOMMITTED`；设了语句与锁等待超时；大表按主键分批；写明低峰执行 | 任一缺失 |
| F3 | **输出不含明细、个人信息、凭据值** | 报告和消息里只有计数或聚合；凭据列只做 `COUNT`；明细若落盘，只在 ECS 专用目录（0700，最长 7 天），不带回本机 | 出现具体人名、工号、手机号、金额明细、凭据值 |
| F4 | **小计数不构成个人识别** | 出题人在出题时写明最小组阈值；未写明时本模板默认：小于 5 的组须由作者说明为何不构成识别（说明成立则过，未说明则标「需作者说明」，不单独判不过） | 小组可推出个人且无说明 |
| F5 | **登记完整**（B7） | 报告里的每一个查询都对应一条登记（`legacy-read/` 片段，#298 合入前是 `LEGACY_READ_REGISTER.md` 表里的一行），账号、库与表、用途、输出形式与去向、落盘目录与删除时点与实际一致 | 有查询未登记；登记与实际不一致 |
| F6 | **结论回指证据** | 报告每个结论都能指到一条查询和它的结果；写明范围、时间、过滤条件、样本量 | 结论没有对应查询；把推测写成事实 |
| F7 | **「没查到」不等于「不存在」**（B5） | 空结果 / 0 行时，报告区分：对象不存在、无权限、被过滤、时间窗内没有；评审员读 SQL 判断这几种能否被区分 | 用 0 行断言「老系统没有这个」而未排除权限或过滤 |
| F8 | **对象真实存在、口径真实**（B6） | 报告用到的表、列、状态值、枚举映射，评审员在引用的结构说明中核对一致 | 列名或状态值是猜的 |
| F9 | **可复现** | 评审员读 SQL 能推出报告里的数字类型与量级（不要求连库）；SQL 与报告引用的版本一致 | 报告里的数字无法由 SQL 得出 |
| F10 | **落盘与删除** | 若有落盘文件，删除时点已到则已删并补写删除时刻（评审员读登记）；未到的写明时点 | 过期未删；未写时点 |
| F11 | **证据状态标注** | 报告对转述给用户的数字注明已核实 / 已抽查 / 未核实（） | 未标注 |

## 本类特有的盲区（主动找）

- **B5 最易中**：子代理或前一份报告说「老系统没有 X」「X 表为空」。评审员核对 SQL 的库、schema、过滤，看这个断言是否站得住。
- **B3 / B4**：取证执行器在哪里运行、用什么架构与驱动；报告对 ADR-0037 的复述与原文字面一致。
- **B2**：SQL Server 版本差异（函数、分页、排序规则）；2016 版本不支持的语法。
- **B6**：状态值的含义是否来自老系统的实际取值（以生产数据为证据），而不是来自新系统的命名。
- **B1**：报告里给新系统取的名字是否符合 `terms.yaml`；老系统的叫法（方言）只在引用原文时出现，并有标注。
- **B7**：取证引出的新发现（新增读取列、新例外）是否登记到读取列登记。

## 输出

按 README 的「通用输出格式」；报告里涉及的具体数据值不要在评审报告里重复，只引用位置。字数不超过 400。
