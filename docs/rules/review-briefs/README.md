## 怎么用（出题人 = 要评审的会话或调度，评审员 = 独立代理）

1. 出题人从对应模板复制「评审员提示词」，**只填「产出」一栏**：产出的路径、PR 或提交号、基线提交号。其余一律不填。
2. **作者只交产出，不交结论，也不写提问。** 不写「已自测通过」「应该没问题」，不写「请重点看 X 是否…」。结论和提问会把评审员引到作者想让他看的地方，盲区恰恰在作者没想到的地方。要补充上下文，只给指向原始材料的路径，不给摘要。
3. 评审员**自己读**模板列出的原始材料（规范条款、ADR、代码、数据），不读作者对它们的转述。读不到的材料写进报告「未读到」，不得当作通过。模板「必读」里列出的作者写的材料（PR 描述的说明栏、one-data 的审查记录、intent 的「原话」栏若是调度转述）里含有结论：**评审员先独立判完必查项，再读这些材料对照**，不一致的单列。

4. 评审员的模型按 METHODS.md 的模型策略与调度最新指示选（代码或守护 PR 首轮 opus；一般改后由作者交 Codex 复核并贴 PR，调度对照必改清单核准、不另派；安全与生产改动首轮及修后终审均 opus，ADR 起草与首轮评审 opus；纯文档作者自检；Codex 先行与待命分级按 TEAM-32、33、67）；出题人在提示词里显式写明模型。只读：不改文件、不推送、不起容器。
5. 一份报告对应一份产出；一份产出可以被多个类型的模板各审一遍（例如一张涉 DDL 的代码卡审代码卡和表结构两份）。

## 评审员提示词（通用骨架，各模板有自己的「必读」「必查项」）

```
请用中文回复。你是独立评审员，只读，不改文件、不推送、不起容器。
评审类型：<类型>。产出：<路径 / PR / 提交号>；基线：<提交号>。
先读 CLAUDE.md，再读 <模板文件> 的「必读材料」所列原始材料——自己去读，不要依赖产出作者的任何转述。
按模板「必查项」逐项判「过 / 不过 / 未核实」；再把本 README 的通用盲区 B1–B7 和模板里的「本类特有的盲区」逐条主动找一遍。
模型：<按 TEAM-67 填写本轮模型；代码首轮 opus，一般改后 Codex，安全门 opus>。
输出格式见模板文件末尾，不超过 <字数> 字，不贴大段代码。
```

## 通用输出格式

每份报告三段，顺序固定：

1. **结论**：「通过 / 有非阻断建议 / 有阻断问题」三档之一，一句话理由。
2. **问题分级**：Blocker / High / Medium / Low（口径见 RULES ⑤）。每条给：编号、文件:行号（或条款号、命令）、失败场景（什么输入 / 状态 → 什么错误结果）、建议。Blocker 与 High 尽量附可复现的失败测试或命令（METHODS M1 第 2 条）。
3. **证据**：每条结论的依据。证据状态只能是三种：**已核实**（评审员自己读了原文、跑了命令）、**已抽查**（核对了一部分，写明抽了哪些）、**未核实**（没读到或没跑，写明原因）。没有证据的结论不写；「未核实」不得写成「通过」（本模板的规定，标注方式与的「已核实 / 已抽查 / 未核实」一致）。末尾单列「**未读到 / 无法判定**」：必读材料中读不到的、必查项里按模板口径判不了的，各写一行原因。
