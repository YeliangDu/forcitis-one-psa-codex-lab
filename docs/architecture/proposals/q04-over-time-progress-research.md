## 0. 先说结论

1. **「每期估进度」是否进入对外财报，决定一切**，因此建模须分甲乙两种情形（第 4 节）：
   - 甲：只是管理口径的产值（项目经理按月估完成百分比，用于经营分析与分成），不过账或只进管理账，与法定收入确认分离。此时主研究的倾向（C）不受影响，产值估计是另一类对象，放在项目管理侧，不进 AGG-44。
   - 乙：进财报收入（时段履约）。主研究否决条件 1 成立，须有「按期存的、可审批的、可冲销重建的」估计记录；三个选项都要另加计量记录。
2. **成熟产品一致做法**：估计按（项目或合同行）×期间存成一条独立记录；多数带状态与过账关系（D365：Created→Posted→Eliminated，可冲销；SAP 结果分析按期间算、结算过账）；本期收入一律用累计差额法（累计进度×合同额−已确认累计）。Deltek 例外：只存「当前」百分比与累计已赚金额，历史靠审计日志或另设，帮助页未描述历史（一手）。
3. **准则对比（对 one-rules 初判的核对，详见第 1.4 节）**：基本同意「设计合同整体按时段确认站不住」，但理由要收窄：第十一条第（三）项不成立的依据是「有权就累计至今已完成部分收款」须有合同或法律的明确权利，不是「须协商」本身；《民法典》承揽合同关于定作人解除合同时承揽人可获赔偿的规定可能被审计师引作法律依据，**须律师与审计师判断**。检查服务、按月收费咨询适用第（一）项的判断同意，且应按履约义务（服务类别）分开。
4. **审计所需最小输入集**（第 2.3 节）：估计依据与口径、预计总成本或预计总工作量、累计实际投入、估计时点（所属期间与估计日）、估计人与审批人、版本（修订序号）、与上期差异说明。
5. **需先问财务与审计师**的问题见第 5 节；其中最关键一个：「每期估进度」用于什么（管理产值还是财报），哪些合同按时段。

## 1. 准则要点（CAS 14，财会〔2017〕22 号；全部二手，须核对原文）

出处标注：搜索摘要来自 Deloitte 中国《企业会计准则第 14 号——收入》PDF（`deloitte.com` 的 cas14_2017-zh PDF，2026-10-16 通过搜索摘要取得，未取到原文页）及教材 / 培训课件摘录。

### 1.1 时段履约的三个条件（第十一条，满足任一）

- （一）客户在企业履约的同时即取得并消耗企业履约所带来的经济利益（二手；摘要给出的判断思路是「假设由别的企业接手，是否需要重新执行已完成的部分」）。
- （二）客户能够控制企业履约过程中的在建商品。
- （三）履约过程中所产出的商品具有不可替代用途，且企业在整个合同期间内有权就累计至今已完成的履约部分收取款项。
- 均不满足的，属于某一时点履行，判断控制权转移时点。

### 1.2 履约进度（第十二条）

- 按履约进度在该段时间内确认收入，履约进度不能合理确定的除外。
- 考虑商品性质，采用产出法或投入法：
  - 产出法：已转移给客户的价值，如实测完工进度、已达到的里程碑、已完成或交付的产品；
  - 投入法：投入的人工工时、机器工时、发生的成本等；成本法是累计实际成本占预计总成本的比例。
- 履约进度不能合理确定，但已发生成本预计能得到补偿的，按已发生成本金额确认收入，直至进度能合理确定。（二手；条号以原文为准）
- 每个资产负债表日重新评估履约进度；变化作为会计估计变更（二手；搜索摘要称「重新估计属于会计估计变更」，对应的具体条款与《企业会计准则第 28 号》适用关系须核对）。
- 投入法下通常要剔除不反映履约进度的已发生成本（如非正常损耗、尚未转移控制权的材料）：搜索工具标注为一般知识，**未核实**。

### 1.3 合同资产与应收款项（二手）

- 已向客户转让商品而有权收取对价，但该权利取决于时间流逝之外的其他因素（如还要履行其他履约义务）：合同资产。
- 仅取决于时间流逝的无条件收款权：应收款项。
- 同一合同的合同资产与合同负债以净额列示，不同合同之间不抵销。
- 对本系统的含义：时段履约下，「已确认收入但尚未开票」的部分先形成合同资产，开票并达到无条件收款权时转应收；与开票额度（AGG-44）要对应，见第 4 节。

### 1.4 对 one-rules 初判的核对

初判：设计合同解约时按已完成工作量收款须协商，第十一条（三）不成立，全部按时段站不住；检查服务、按月收费咨询可能满足（一），多半按服务类别分开。

**同意的部分**：
- 第十一条各项是「满足任一」，（三）须同时具备「不可替代用途」与「整个合同期间内有权就累计至今已完成部分收款」。后者按条文字面须在每个时点都成立；解约时收款靠协商，则这条不成立。
- 设计成果多为按客户项目定制，不可替代用途一项通常可成立，所以卡点在收款权，不在成果性质。
- 检查服务、按月咨询、驻场服务：客户随履约取得并消耗利益，（一）成立的可能性大，履约进度多用时间进度或工时（产出法的时间进度 / 投入法）。

**须补充或不同意的部分**：
1. 「须协商」不等于「无权收款」。准则要求的是**合同条款或法律上**的可执行权利（应用指南的判断思路，二手，须核对）。若合同写明「解约时按已完成工作量付款」，则（三）可能成立；若合同没写，须看《民法典》承揽合同章关于定作人随时解除、承揽人可获损失赔偿的规定能否构成该权利，这属法律与审计判断，本稿不裁定。须让财务按合同范本逐类核对（第 5 节 Q3）。
2. 不能只看「设计合同」整体，应按**履约义务**判断：同一份合同里方案设计、施工图设计、驻场配合服务可能是不同履约义务，进度方法与按时段与否可以不同。
3. 第（二）项（客户控制在建商品）也要排除：若合同约定设计成果的知识产权或阶段成果在交付前即归客户，则（二）可能成立。须核对合同范本的权属条款。
4. 全部按时段站不住，不意味着全部按时点：若部分合同满足（一）、（二）或（三），则**同一系统内两类并存**，这对建模是关键：履约义务须带「履行方式：时点 / 时段」属性。

**结论**：同意「整体按时段」不成立与「检查服务类可能按时段」；不同意把理由简化为「须协商」；条号与措辞核对前不对外引用。

## 2. 设计、咨询类实务：进度计量与估计须留什么

### 2.1 常用方法（实务常识，未逐条取一手来源；Deltek 与 D365 页面支持其存在）

| 方法 | 类型 | 做法 | 风险 |
|---|---|---|---|
| 阶段里程碑 | 产出法 | 方案 / 初设 / 施工图等阶段各占合同额一定比例，完成阶段（常以提交或获批为标志）计入；阶段内可再按完成度折算 | 阶段内进度靠判断；里程碑权重须在合同或预算中固化 |
| 工时 | 投入法 | 累计实际工时 ÷ 预计总工时 | 返工、低效工时会虚增进度；须剔除不反映进度的工时 |
| 成本（成本法） | 投入法 | 累计实际成本 ÷ 预计总成本 | 预计总成本须持续更新；同上剔除不反映进度的成本 |
| 时间进度 | 产出法 | 已服务月数 ÷ 合同期，用于按月服务 | 仅适用于服务量均匀的服务 |
| 项目经理手工 % | 判断 | 项目经理直接录入完成百分比（Deltek 的 percent complete 即此类，一手） | 最易被审计质疑，须留依据与复核 |

### 2.2 与产品的对应

- Deltek 方法 P（percent complete × 合同额，二手）要求项目经理保持百分比更新；方法 M（工时×乘数）作为不依赖手工估计的备用，也属二手。
- D365 完成度方法分自动 / 手工 / 来自成本模板（一手，见第 3.4 节），与上表同构。

### 2.3 估计记录应保留的输入（面向审计与复核；本节为建议，非来源条文）

- 所属**会计期间**与**估计日**（估计时点）；
- 对象坐标：履约义务（及合同、付款条件项）；
- **方法**：里程碑 / 工时 / 成本 / 时间 / 手工；
- **计算口径与输入快照**：累计实际投入（工时或成本，来自哪个期间的哪个数据快照）、预计总投入、已完成里程碑清单与权重、剔除项及原因；
- **结果**：累计履约进度 %、累计应确认收入、上期已确认累计、本期应确认额（累计差额）；
- **估计依据说明**与相对上期的变化理由；
- **估计人、复核人、审批人**及时间；
- **版本**：修订序号、是否取代某一版；
- 合同变更与可变对价的状态（对交易价格的影响）；
- 状态与关联过账凭证引用。

## 3. 成熟产品如何存每期进度估计

### 3.1 Deltek Vantagepoint（一手：Deltek 帮助页；方法公式二手）

- 来源：`help.deltek.com/Product/Vantagepoint/4.5/st_bill_contents_billing_terms_fees_tab_db.html`，2026-10-16。
- 粒度：项目（或计费阶段）；若按类别分摊则每类别一个 percent complete。
- 存的是**当前值**：Pct Compl 与 Fee to Date 始终同步（输入一个，算另一个）；页面未描述 percent complete 的历史或变更日志。每期估计的历史是否保留，帮助页**不能回答**。
- 与开票的关系：发票费用 = Fee to Date − 前期已开票费用，累计差额法（一手）。
- 收入方法 P / M / R / N（二手，来自 Deltek PS / Vision 帮助摘要）：P = percent complete × 补偿额 + 累计可报销费用；M = 累计直接人工 × 乘数 + 可报销费用；N = 不自动生成，靠日记账。
- 审批、不可改、冲销：帮助页未涉及。**取证需求**：Vantagepoint 的审计跟踪与收入重新生成（revenue regeneration）是否保留每期 percent complete。

### 3.2 SAP S/4HANA（二手：SAP Learning / SAP 博客 / 搜索摘要）

- 结果分析（results analysis）：对控制对象（项目或销售订单行）按期间计算，选实际与计划成本收入，算「估值收入、在制品、销售成本」，成本法 POC = 实际成本 ÷ 计划成本，应用于计划收入（博客例：实际 20、计划 100、计划收入 200，得 40）。
- 通过结算过账到 FI、CO-PA 等；用于结算的结果分析版本通常是版本 0（二手）。
- 方法：成本法、完工合同法等；POC 可转入收入核算与报告（RAR），并可在其中手工改。
- 事件驱动收入确认（EBRR，SAP S/4HANA Cloud 专业服务）：成本与收入随业务事务发生即匹配过账；固定价项目默认成本法键 SPFC；期末结账对已确认收入按实际 POC 重估（二手）。
- 状态、审批、冲销的细节：本次**未取到**。**取证需求**：结果分析数据是否可按版本与期间重新计算覆盖、重算时是否冲回上期。
- 对比：SAP 把估计的**计算**与**过账**分开；计算可模拟，结算才过账；估计值按期间保存在结果分析数据，不靠重放事实。

### 3.3 Oracle Fusion Project Financials（二手：Oracle 文档搜索摘要，页面全文未取到）

- percent complete 收入方法：生成收入进程先算 percent complete 金额再生成收入事件；前提：合同行或项目的 percent complete 大于 0、金额大于 0、`To Date` 不早于当前会计期末（二手）。
- percent complete 可由项目进度更新、手工录入或在进度更新后覆盖（二手）。
- 粒度：收入计划上的计算层级可为合同行或关联项目 / 任务（两页文档对两种层级产生几个事件的描述互相矛盾，二手摘要已指出）。
- 变更收入方法：由 as-incurred 改为 percent complete 会冲回已确认的收入分配；手工事件不再适用时可改金额为 0 或永久收入冻结（二手）。
- 更早的 Oracle Projects（EBS）：每条 percent complete 录入带 As Of Date，用于保持历史（二手，旧版文档）。
- 累计差额法的明文：没有取到 Fusion 页面；JD Edwards 页面写明用百分比×价值表再减前期收入（另一产品）。**取证需求**：Fusion 页面原文。

### 3.4 Microsoft Dynamics 365 Project Operations（一手：Microsoft Learn）

- 来源：`learn.microsoft.com/en-us/dynamics365/project-operations/revenue-recognition/rev-rec-completed-contract-method`（页面日期 2026-09-03，访问 2026-10-16）；`.../prod-pma/eliminate-project-estimate`（2026-01-30，访问 2026-10-16）。适用于 Project Operations Integrated with ERP；估计已改名为 revenue recognition。
- **粒度**：估计项目（estimate project）× 期间代码（period code）× 估计日；固定价与投资类项目才可附着到估计项目。
- 创建参数：期间代码、估计日、「连续」（只在上期已过账时创建）、完工成本方法、**完成方法**（自动 / 手工 / 来自成本模板）、预测模型。
- 手工方法：完成百分比取上期估计，创建后可在估计页修改（一手）。
- 校验警告：完成度大于 100%、小于 0、待完成金额为负、无对应合同金额、无关联成本估计。
- **状态**：Created → Posted → Eliminated（页面）。过账后「估计期间状态从 Created 变 Posted」；完工合同法过账在制品，完成百分比法过账应计。
- **更正**：Reverse 贷记已过账的在制品或应计，再为该期重新创建估计；页面要求「不得跳过期间」，反冲中间期间后须重新过账，因后续期间依赖上期估计。
- 完成：完成度达 100% 后 Eliminate，状态变 Eliminated，在制品转入损益；可 Reverse elimination 回到 Posted。
- 审批：这几页未写审批流。
- 对本系统：D365 是「按期间存估计、过账与冲销有顺序约束」的典型，且估计行本身有状态。

## 4. 对 FORCITIS one 的建模含义（只给可选方案与代价，不裁定）

先固定三个共同点（两种情形都适用）：
- 本期金额按累计差额：**本期收入 = 累计进度 × 合同额（交易价格） − 已确认累计**（负数即冲回）；这是 Deltek、SAP、Oracle、D365 的共同做法（Deltek 为一手，其余二手，见第 3 节）。
- 估计是判断，**不能从事实重算**（主研究第 4.1 节），所以必须按期保存输入快照。
- 估计变更按「重新估计」处理：新估计取代旧估计，差额计入当期，不改前期。

### 4.1 情形甲：只是管理产值（不过账，或只进管理账）

特征：用于经营分析、人员绩效、项目进展，不是法定收入。
- **对象**：「产值估计」属项目管理侧，不在收入确认上。字段见第 2.3 节子集（口径、依据、估计人），审批可轻（项目经理填、部门负责人复核）。
- **与 AGG-44**：无关系，不占额度、不触发审批；与法定收入并行存在，**必须在名称与界面上区别**（词表要登记「产值」与「收入」的使用范围，避免混用；按 CLAUDE.md 第 2 条先查 `terms.yaml`）。
- **与 AGG-77**：不过账；若进管理账，则是单独的管理账凭证，不进法人账。
- **主研究结论**：C 仍可成立，否决条件 1 不触发；否决条件改写为「管理产值被拿去对外披露或作法定凭据」。
- **代价**：两套口径并存，月度对账（产值 vs 法定收入）需要说明，财务会问「为什么两个数不同」；产值估计本身要有审计线（若用于分成，仍须有留痕）。
- **选项**：
  - 甲-1：只追加不可改的估计事实（每期一行，修订产生新行，带修订序号），不设状态机，审批用 `platform.approval`。代价：「当前有效值」要查最大修订；
  - 甲-2：简单状态（草稿 / 已确认），行上可改。代价：历史靠审计日志。

### 4.2 情形乙：进财报收入（时段履约）

特征：主研究否决条件 1 成立。须加「履约进度估计」。

**对象形态（二选一，代价如下）**

| 形态 | 做法 | 好处 | 代价 |
|---|---|---|---|
| 乙-1 有状态独立对象 | 「履约进度估计」：草稿→审批中→已确认→已过账 / 已冲销；粒度为履约义务×期间；新版本取代旧版本（修订序号） | 与 D365 一致；状态与审批清楚；期末关账可检查「本期所有时段履约义务都有已确认估计」 | 新聚合与新状态机，要走 ADR（主研究 B2 同类）；与 ADR-0016 决定 4 的关系要重议 |
| 乙-2 只追加不可改事实加审批 | 估计事实只追加（含输入快照）；修订是新事实指向前一版；审批用 `platform.approval`，通过后才生成对应的收入确认事实（沿用主研究 C 的占用行与转实） | 与 C 一致；状态仍只在占用行；改动较小 | 「当前有效估计」需推导；审批履历在审批平台，审计师须接受（主研究 W-6） |

**与 AGG-44（开票与收入额度）**：
- 时段履约下，每期确认额不再来自「客户认可证据」，而来自估计；确认额仍须占额度（RULE-222 二次校验），不得超过付款条件项累计额度，但**确认额可以先于开票**，差额形成合同资产（第 1.3 节）。这与时点履行下「证据触发才确认」的额度语义不同，**RULE-184 / 213 的口径须重审**（待 one-rules）。
- 额度占用的对象仍是金额，但「触发条件」由证据改为估计，AGG-44 须区分触发类型：证据触发（时点）、估计触发（时段）。
- 若估计让累计确认额低于已确认额（进度回退），产生负额确认事实（冲减），而冲减在 AGG-44 内释放额度。

**与 AGG-77（过账）**：
- D365 做法：估计行有状态，过账后改状态，冲销须按期间顺序；SAP：计算与过账分离；本系统可选：
  - 过账事实携带估计 ID 与修订序号（AGG-77 现仅有「来源单据引用」，主研究 :516，须加字段，或把估计 ID 作为来源引用）；
  - 过账只在估计「已确认」之后，冲销指向原过账。
- 代价：估计修订已过账的期间，是冲销重做（D365 方式，需顺序约束）还是当期累计差额调整（会计估计变更的通行处理，不改前期）。准则按估计变更处理（二手，第 1.2 节），倾向后者；但已关账期间内发现的是**差错**而非估计变更，处理不同，须问审计师。

**期末关账与估计变更**：
- 每期关账前要求所有时段履约义务有「已确认」的本期估计（D365 的「连续」选项与警告清单是同类控制）；缺失时按「缺失或无效输入失败并告警」（CLAUDE.md 第 6 条）阻断关账，而不是静默沿用上期。
- 已关账期间不得改估计；新估计只影响当期及以后。
- 估计校验：进度 >100% 或 <0、合同额为零、预计总成本小于累计实际成本，均须拒绝或升级审批（D365 同类警告）。
- 合同变更（金额、范围）改变交易价格，估计须引用变更版本（与主研究 S9「配置与规则版本固定」同类）。

**历史迁入**：
- 老系统有没有每期进度或产值数据：**未知**，须取证（第 6 节）。若没有，迁入时只能迁已确认收入与累计，进度估计无历史；若有，是迁入为估计事实（标「历史迁入」，不伪造审批）还是只作对账参照，由用户与财务定。
- 在途合同切换时点的「累计已确认」就是新系统的期初累计，累计差额法从此起算。

### 4.3 甲乙并存的可能

同一系统可能两者同时：管理产值每月估，财报只对少数按时段履约义务估。此时：
- 估计对象要带「用途」（管理 / 法定），或分两类对象；
- 管理产值与法定估计之间的差异，是常见审计问询点，宜保留对账视图。
