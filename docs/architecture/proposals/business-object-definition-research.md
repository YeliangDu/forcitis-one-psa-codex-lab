**一致**：都以「名词所指、业务关心的一类事物」为起点；都区分概念与实现（BIZBOK 信息概念 / TOGAF 业务信息 / ArchiMate 业务对象都在实现层之上）；单据不是对象（BIZBOK 与 ArchiMate 一致）。

**冲突**：
1. **是否必须进数据库**：BIZBOK 明说不一定；TOGAF 元模型写业务信息由数据实体实现（关系，非强制基数）；ArchiMate 写「可以」。用户「每个对象至少一张或一组表」比三者都严。
2. **身份**：DDD 以身份为实体的定义，BIZBOK 不单列身份。两者不矛盾，但「有身份」只能从 DDD 引入。
3. **「业务对象」一词**：BIZBOK 用作信息概念的同义；G190 附录与 ArchiMate 用作「有形的数据侧对象」，与信息概念分开。FRAMEWORKS 已定按 BIZBOK。
4. **状态**：BIZBOK 要求有限状态；DDD 实体只要求身份与连续性，只追加的记录（如考勤记录）在 DDD 是实体，在 BIZBOK 状态难写。

## ③ 结论

### 3.1 采用哪一层

采用 **BIZBOK 的概念层定义**（FRAMEWORKS B2 已锁定，且 G178 / G190 冲突时按 BIZBOK）：业务对象 = 业务关心的一类持久事物，有定义、类型、状态、关系，分一级、次级、汇聚。理由：本项目的价值流、阶段门、能力命名都以 BIZBOK 对象为锚；DDD 与 TOGAF 数据层是实现层，用来检验对象「落得下去」，不用来定义对象。

三层关系（对应而非等同）：

| 层 | 本项目产物 | 关系 |
|---|---|---|
| 业务对象（BIZBOK；≈ TOGAF Business Information） | `ENTERPRISE_INFO_MAP_DRAFT.md` OBJ-nn | 定义「是什么」 |
| 聚合（DDD） | `ENTERPRISE_AGGREGATES_DRAFT.md` AGG-nn | 一对象经 METHOD 第 ④ 步五种方式对应聚合：一对一、次级在内、一拆多、无聚合、技术聚合 |
| 表（≈ TOGAF Data Entity → 物理；ArchiMate Data Object → Artifact） | 数据访问注册表、one-data 表清单 | 表归聚合，不直接归对象；汇聚对象与外部记录系统的对象可以无表 |

### 3.4 主要争议例

1. **OBJ-70 考勤记录**：DDD 看是实体（有身份、只追加），BIZBOK 要求有限状态却写不出——是对象还是 OBJ-111 月度考勤确认的明细（次级、无独立状态）？
2. **OBJ-22 报价估算分解**：无独立状态、随父冻结，又无表——更像 OBJ-21 报价的属性组，按 BIZBOK 次级勉强成立；信息图已定为从属对象、由父对象流程承载（intent 2026-10-17-201810）。
3. **OBJ-55 组织单元**：已有表、有状态，但信息图不把它计入一级也未判次级；依附判断缺位。
4. **OBJ-78 分摊规则**：依附「待定」已久，聚合稿按配置型版本暂列；是对象的类型（参照数据）还是一级对象未定。
5. **OBJ-81 收入确认**：有状态，但聚合稿 AGG-47 写「无聚合（规则层）」，T7 命中只因不变量 INV-86 引用了它；信息图写「形态待定（Q20）」，两份表清单都没对上表，类型缺；随 Q20 定。
6. **OBJ-103 财务**：按 BIZBOK 汇聚对象应整体豁免 T4、T5、T7、T8；若保留在对象清单，标准里须写明豁免。
7. **OBJ-41 延期申请、OBJ-113 用印申请等「申请」类**：BIZBOK 把单据排除在外，它们有状态但无类型、无表，须人工判是对象还是另一对象（协议变更、用印）的单据。

### 3.5 结论要点

1. 框架里「业务对象」的定义以 BIZBOK 为准；DDD 补「身份」，TOGAF / ArchiMate 补「由数据实现」，Kimball 只作度量标注。
2. 能直接机器核对的是 T1–T8 八条；「身份」「持久」两条是框架核心但现有产物没有字段，先补字段再纳入。
3. 「对象必须有表」框架不支持为普遍规则（BIZBOK 明说不一定），只适合本系统为记录系统、非汇聚的对象。
4. 现有 103 个对象没有一个同时违反多条核心条件而像假对象；问题集中在词表（76）与表清单（22）两个产物缺口，以及上列 7 个争议例。

### 3.6 DAMA 与 Kimball 取得后的补充

结论不变，补三点：
1. **实体定义无附加条件**：DAMA 的实体只要求「组织收集其信息」，不要求持久、状态、入库；与 BIZBOK 的「持久、有状态」相比更宽，说明 T5（状态）是 BIZBOK 的收紧，不是通行要求。
2. **参照数据、主数据按用途划分**：参照数据（分类、代码与说明）是其他数据的取值集合；主数据是关键实体的权威数据。OBJ-78 分摊规则若只是供其他对象引用的规则取值，更像参照数据（类型），与 3.4 第 4 项的疑问一致；是否列为对象仍由 BIZBOK 判，DAMA 不替代。
3. **事实、维度是分析层概念**：维度行（含 Type 2 新增行）不是新实体，事实行是度量事件；不能用「有事实 / 有维度」判对象真伪，与「度量角色只作标注」一致。身份方面，Kimball 的持久键与 DAMA 的「唯一性范围」支持先给信息图补 `identity` 列，并写明作用域。
