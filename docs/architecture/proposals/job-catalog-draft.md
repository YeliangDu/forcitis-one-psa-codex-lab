## 1. 设计原则：哪些进职位目录

| 概念 | 是什么 | 归属 | 依据与把握 |
|---|---|---|---|
| 职位（job） | 一类职责相同、任职要求相同的工作，如「幕墙设计师」 | **进职位目录**（OBJ-58） | 职位目录口径（BIZBOK p589 Job，只作旁证）；通行职位体系「族 → 子族 → 职位 → 职级」〔中〕 |
| 岗位实例（position） | 某组织单元里一个编制位 | **不建**（不管编制，Q-08） | 用户已定 |
| 职级（grade） | 同一通道内的能力与责任档位 | 参考数据；任职属性；费率表键 | 信息图 §2.6；Q17 |
| 职称（专业技术资格） | 人社系统评定的初级（员级、助理级）、中级、副高级、正高级 | **人员属性**（取得日期、评审机构、证书号），不进目录 | 人社部发〔2019〕16 号工程系列职称改革意见〔中，层级划分〔高〕〕 |
| 注册执业资格 | 注册建筑师、勘察设计注册工程师、监理工程师、建造师等 | **注册执业证书（OBJ-64）**，人员下的次级对象 | 已核规章（OBJ-64 行）〔高〕 |
| 项目角色 | 项目经理、专业负责人、校对、审核、审定、交付经理、驻场代表等 | **项目团队成员（OBJ-34）的角色类型**（Q13 待研究），不进目录 | 设计企业按项目设签署与责任角色〔中〕 |
| 管理职务 | 组织单元负责人（部门、事业部、区域） | 待用户题 J-4：职位 或 任职上的「负责人」标记 | ADR-0029 取证：A8 `ORG_LEVEL` 是管理职务、不是职级 |
| 驻场、兼职、外派 | 工作安排方式 | 任职或项目团队成员属性 | 信息图 OBJ-57（主 / 兼） |

- P-0 两个独立维度（one-coordinator 补充约束 ①）：职位 = 职位族 × 职位（族 → 子族 → 职位），职级单独一维；任职记（职位，职级）一对值，职位只配可适用的职级区间（P-3）。
- P-1 职位名不含级别：不写「T2 幕墙设计师」「高级幕墙设计师」；对外头衔由「职位 + 职级」派生（如「幕墙设计师 · 职级 5」可显示为「高级幕墙设计师」，派生规则随 J-2 定）。这样晋升只改职级，不换职位，ADR-0029 的「调岗」建议不会因晋级被触发。
- P-2 职位按「工作内容 + 任职要求」划分，不按部门、业务线、法人划分；同一职位可在多个组织单元出现（任职记组织单元）。
- P-3 职位可配职级区间（OBJ-58「可配职级区间」），区间只作校验预警，不拒绝（任职职级超出区间时警）。
- P-4 职称、注册资格与职级只作参照（§3.3），不强绑：不因取得职称自动晋级，也不以无注册资格拒绝任职；签章与投标人员要求另由 OBJ-64 的规则校验。
- P-5 目录规模宜小：职位数以「权限对照、招聘需求、资源需求匹配能用」为限，细分能力用人员「技能标签」（OBJ-56）承载。
- P-6 主数据版本化（DATA_DESIGN_CHECKLIST §14.1 D17，维度型，补充约束 ②）：职位目录条目、职位族与子族、职级定义按 D6 写法带生效区间（左闭右开、防重叠、只追加、只许关闭不许改写，`DECLARED` 业务声明日）；改名、改族、改职级区间、停用均产生新版本，不改旧版本；`job_code` 与 UUIDv7 根 ID 跨版本不变；任职按工作日取当时有效版本，费率与报表按发生日取值；查询日期早于最早版本时失败告警（D17 第 5 条）。

## 3. 职级体系

### 3.1 方案（待用户题 J-1、J-2）

| 方案 | 结构 | 好处 | 代价 |
|---|---|---|---|
| A 单序列 | 全员一条序列，如 1–12 级；职位只给区间 | 费率表键最少，跨族比较简单 | 技术骨干只能走「升管理」才上得去，与设计企业通行双通道不符〔中〕 |
| B 双通道 + 支持序列（推荐） | 专业通道 P（技术、项目管理、市场商务、职能专业人员）、管理通道 M（管理层族）、支持序列 S（出纳、助理类）；通道间设对等关系（如 P6 ≈ M2） | 国内设计与咨询企业通行（技术与管理双通道）〔中〕；技术专家不必转管理 | 对等关系与跨通道转换规则要另定；费率表行数增加 |
| C 按族各自分级 | 每族自定级数 | 贴合各族 | 费率与比较口径不统一，费率表不可控；不推荐 |

### 3.2 级数（J-2）

- 专业通道 8 级（P1–P8，推荐）或 7 级、10 级；管理通道 5 级（M1–M5）；支持序列 3 级（S1–S3）。
- 代价：级数多则晋升节奏细，但标准成本费率表（键含职级，Q17）行数与维护量上升；级数少则同级内差异大，靠薪档区分。级数与编码字母须避开老系统 T / M / S / A 的取值，免得迁入时同名异义（M 与 S 字母若沿用，须由 one-glossary 判定是否同名异义）。

### 3.3 与职称、注册资格的参照（方案 B、8 级；只作参照，不强绑，P-4）

| 职级 | 职称参照 | 注册执业资格参照 | 典型职责 |
|---|---|---|---|
| P1–P2 | 员级、助理级 | — | 在指导下完成任务 |
| P3–P4 | 中级（工程师） | 可取得二级注册或一级考试通过 | 独立完成专业任务 |
| P5–P6 | 副高级（高级工程师） | 一级注册建筑师、一级注册结构工程师、监理工程师、一级建造师等 | 专业负责、校审 |
| P7–P8 | 正高级 | 同上 | 技术带头、审定、标准编制 |

职称层级依人社部工程系列职称改革意见〔高〕；职级与职称对应为行业常见做法〔中〕，具体对应由用户与人力定。

### 3.4 与现行 T1–T7 的关系（补充约束 ③；对照、不强绑）

- 现行：A8 岗位 136 个（在用 110），名称为「职级代码 + 职能」，职级只能从名称前缀解析；前缀除 T1–T7 外还有 M3–M9、S1–S4、A1–A4（ADR-0029 取证；`DELIVERY_RESOURCES_EVIDENCE.md` §11）。新目录把前缀拆走：职能名 → 候选职位（§7），前缀 → 新职级的对照输入。
- 对照只作迁入初值与人工核对依据，不强绑：每人新职级由人力按新职级标准确认；T 与 P 不按数字等号（T1 不必然 = P1），M、S、A 前缀与新管理、支持序列的对应同样待核。
- 对照表（老前缀、人数、建议新职级、把握、核对人）待 J-1、J-2 答复后由 one-data 出；答复前，新职级字段填「待定」并保留老前缀原值作来源对照列（D16，只在防腐层使用）。

## 7. 给 one-data 的映射说明（工作包 ③）

- 映射粒度：**按人**（在职人员的当前主任职）为主，辅以「A8 岗位 → 候选职位」的规则表供批量建议；A8 岗位本身不是目标对象，不建 1:1 对照。
- 每人目标字段：`job_code`（§2 编码）、`job_grade`（方案未定前填「待定」并保留原职级编码原值）、`career_track`（随 J-1）、是否组织单元负责人（随 J-4）、映射依据（岗位名规则 / 人工）、把握（高 / 中 / 低）。
- 不在本次映射内、另行取数：职称（人员属性）、注册执业证书（OBJ-64）、项目角色（OBJ-34，Q13）。
- 规则表字段：A8 岗位 id、岗位名、去掉职级前缀后的职能名、候选 `job_code`、职级前缀原值、人数、疑点。职能名剥离只用于生成候选，最终以人工核对为准（ADR-0029 第 3 项第 1 条对解析老命名的保留意见仍适用）。
- 需标出的情形：一个 A8 职能名对应多个新职位（如幕墙类按设计 / 结构 / 检查拆分）；无法归入任何职位（报目录缺口，不硬塞）；职级前缀不在 T、M、S、A 内或缺失；管理职务（`ORG_LEVEL`）与岗位不一致。
- 职级映射（老 T1–T7、M3–M9、S1–S4、A1–A4 → 新职级）按 §3.4，待 J-1、J-2 答复后另出对照；本次只统计各前缀人数与对应职位分布。
- 目标为版本化主数据（P-6）：迁入时每个职位只建首个版本，生效日取新目录启用日；任职的历史区间引用老前缀原值，不回溯改写。
- 明细与个人信息不进会话与仓库（CLAUDE.md 第 4 条、ADR-0037）：仓库内只放规则表与按职位、职级的计数。
