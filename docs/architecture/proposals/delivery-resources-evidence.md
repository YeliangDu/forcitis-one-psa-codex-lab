## 0. 先说六个结构性事实

1. **项目是 A8 的只读镜像，老系统自己不立项。** A8 项目档案底表 `formmain_0051` 5,432 个，老系统 `psa_pm_project` 5,404 个，由生产 SQL Agent 作业「同步项目档案到 PSA」写入（`docs/legacy/seeyon-oa/access-register.md` #38）；立项流程 `formmain_0299` 经创建项目日志 `T_FST_CRE_PROJECT_LOG` 生成档案（1,450 行，2022-04 至 2026-02，成功 1,448、失败 2）。
2. **老系统自建的是四级 WBS（项目、合同条款、交付包、任务包）、WBS 预算基线、计划与工时，且 WBS 才上线一个多月。** 条款、交付包、任务包的创建时间全部落在 2026-09-07 之后（条款 9,403 条在 2026-09、51 条在 2026-10），是预算编制或回填一次性建出；`[mig]/V20260701100100__create_project_wbs_tables.sql:1-60` 建表，`V20260810150000` 建预算基线表。
3. **交付闭环的表都建了，数据是 0。** 成果单 `psa_deliverable_submission`、成果附件 `psa_deliverable_attachment` 0 行；交付包的成果状态 `dlv_status`、生命周期、收入场景全空；任务包 `LOCKED`、`REWORK` 状态与返工交付包、返工原因 0 行。验收、返工在老系统里是设计，不是存量事实。
4. **A8 没有 WBS、工作包、交付物、里程碑、质量问题、返工、成果验收这几个对象本身**（表单与模板名全量检索，见 §局限）。A8 只有项目档案，加一组围绕项目的节点流程：启动会、阶段评审、成果内审、预算编制与变更、结项、结算、满意度调查、客诉。
5. **工时是老系统自建的主渠道。** A8「项目工时填报单」「商机工时填报单」2026-04-28 / 04-30 停用，老系统有 530,453 张日工时单、700,861 行明细（含已删）；A8 的工时档案表 676,868 行、原始打卡 794,524 行留在 A8。
6. **考勤与休假在 A8，老系统只读视图；工作日历两边各有一份同形副本。** 请假、年假、特殊假、销假、外勤、补卡、月度考勤确认都是 A8 流程（OA #48–#53、#70，随 6e HRM 迁入）；老系统 `psa_leave_records` 是视图。`psa_calendar` 与 A8 自建表 `T_FST_CALENDAR` 都是 4,018 行（2016-01-01 至 2026-12-31）。

另有一条对上一份取证的**补充**：`PRESALES_OBJECTS_EVIDENCE.md` §8 说「风险交付」在现状里只有手工录入的运营报表。本次发现工时归档表 `psa_time_sheet_works_end.sub_type` 把工时行分成六类，其中「风险客户交付」「待签合约交付」由生产作业按 BI 视图 `T_FST_INVALID_DELIVERY` 回写（`docs/legacy/seeyon-oa/access-register.md` #31），近 24 个月分别有 8,604、1,881 行（见 §14）。风险交付在系统里没有授权记录，但有项目级红绿分类和工时分类。

## 18. 局限

- **镜像不是来源**：老系统的项目、预算、计划条目一部分是 A8 的同步副本（作业 #38、#39）；本次只核对了行数（项目 A8 5,432 vs 老系统 5,404），没有逐行核对。老系统旧预算明细 `psa_pm_budget_works`（212,295 行）、`_works_cost`（27,199 行）本次只查了行数，未逐列取证。
- **快照无历史**：状态是当前值，没有迁移时间，算不出阶段停留与转化周期；A8 变更历史表 `CAP_FORM_DATA_HISTORY`、`FORM_FIELD_CHANGE_LOG` 为空（见上一份取证），预算与项目档案被直接改写。
- **「近 24 个月」口径不一**：项目用立项日期；工时用工时日期；流程表单用创建时间（档案类表单创建时间可能是导入或归档时间，A8 项目 2020 年有批量建档）；`psa_leave_records_month` 只含 2026-04 起，请假统计改用 `psa_leave_records` 与 A8 档案。
