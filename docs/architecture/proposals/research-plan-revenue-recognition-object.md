# 研究计划：收入确认是无状态规则层，还是有状态对象

状态：历史记录｜2026-10-16｜负责：one-architecture

状态：计划稿（只定怎么研究，不含研究结论）。起因：ADR 待决题 Q-04 用户选「暂不定」，附注「这个研究下再决议」（intent `intent/2026-10-16-134134-*.md`）。
出处：盘点 `ADR_PENDING_INVENTORY.md` P-041；ADR-0016 决定 4；ADR-0047 第 5 条；ADR-0049 第 4 条；`ENTERPRISE_AGGREGATES_DRAFT.md` Q20、AGG-44/47/57/43、INV-22/40；信息图 OBJ-81；`CONSTRUCTION_PLAN_DRAFT.md`（一次投产、全量历史进交易库）；`decision-page/PENDING.json` Q-04。

三个选项（沿用确认页）：A 无状态规则层（现行）；B 有状态对象（须另开 ADR 修订 ADR-0016 决定 4）；C 规则层加事实记录（规则仍无状态，另存确认事实）。

## 1 要回答的问题

总问题：收入确认要不要有自己的生命周期和持久状态。拆成可判定的子问题，每题答「A / B / C 下是否需要状态、状态记在哪」：

| 编号 | 子问题 | 判定标准 |
|---|---|---|
| S1 | 累计履约进度与累计已确认额：由什么算出，能否每次从事实重算 | 重算结果与审计留痕是否一致 |
| S2 | 期满待办（ADR-0049 第 4 条）：谁持有「送达后开始、退回作废、重报重算」的计时与待办 | 载体能否不依赖收入确认对象 |
| S3 | 视为同意认定：认定动作与结果是否需要保存，保存在哪 | 认定可复核、可撤销、可追溯 |
| S4 | 审计师认可闸门（ADR-0047：第 6 类证据须审计师书面认可再经财务批准）：闸门状态挂在谁身上 | 认可前后行为切换不丢证据 |
| S5 | 冲销与更正：已确认收入被退回、改期、改额时如何留痕 | 是否需要「被冲销的那一笔」可引用 |
| S6 | 收入期间归属与跨期调整（期满日所在月） | 期间关闭后更正的路径 |
| S7 | 履约义务额度（INV-22、AGG-44 额度行）与确认行的关系 | 额度占用是否已足够表达状态 |
| S8 | 对账与审计追溯：总账、合同资产、应收与确认之间如何互相解释 | 审计师能否从一笔分录追到证据与规则版本 |
| S9 | 规则版本：确认时用的规则版本如何固定（规则变更不改历史） | 是否必须存「当时的口径」 |
| S10 | 全量历史迁入：老系统已确认的收入怎样表达（施工方案：一次投产、历史进交易库） | 迁入事实能否不伪造「确认过程」 |
| S11 | 与现有 ADR 的相容：ADR-0016 决定 4、ADR-0047 第 5 条、ADR-0049 第 4–6 条、INV-40 收入覆盖检查 | 逐条列冲击与是否需修订 |

## 2 证据来源

1. 一手准则：CAS 14（收入）及应用指南；IFRS 15 及应用指南、实施示例（履约进度、合同资产与应收、合同变更、累计追补）；审计准则中收入证据与截止的相关要求（只取与「证据与留痕」有关部分）。
2. 成熟产品（官方文档，只取对象与规则设计，不取界面）：Deltek Vantagepoint / Costpoint（收入确认方法与结果持久化）；Oracle Project Revenue（收入行、冲销与重新计算）；SAP PS 结果分析（结果分析版本、数据与过账分离）；Microsoft Dynamics Project Operations（收入确认计划、实际行）。每个产品回答三问：有无收入确认对象、状态机有哪些、更正怎样表达。
3. 仓库内：已采纳 ADR（0016、0021、0036、0037、0046、0047、0049）、规则卡 ACC-R01 与规则清单 C7、聚合稿 Q20/Q21、信息图 OBJ-81 与 OBJ-35。
4. 生产取证（老系统收入确认相关表）：表结构与状态值、量级、有无冲销与更正痕迹、在途单据数。按 ADR-0037 每次登记一行；明细与个人信息不进会话与仓库，只取计数与分布。
5. 用户既有决定：Q22 五项证据全选、R4、D-8（期满判定归收入侧）、`2026-10-14-100`（历史权责事实一律进交易库）。

## 3 方法

1. 先固化事实表：从 S1–S11 各取 2–3 个具体场景（含老系统生产中出现过的一种），统一写成「输入事实、期望结果、应留痕内容」。
2. 对每个场景在 A / B / C 下各走一遍，记录：需要持久化什么、谁持有、乐观锁与额度占用是否够用、重算是否可复现。
3. 评估表（每个子问题一张行，每个选项一列）：

| 子问题 | 选项 | 是否需要状态 | 代价（表、事件、迁移） | 收益（可追溯、可更正） | 对已采纳 ADR 的冲击（无 / 细化 / 修订） | 证据出处 |
|---|---|---|---|---|---|---|

4. 冲击面单列两处：ADR-0016 决定 4（B 须修订，C 是否算「仍为无状态规则层」须判）；ADR-0049 第 4 条期满待办载体（三选项各给载体候选）。另查 INV-40、AGG-44/47/57/43 的变动。
5. 反证环节：对最终倾向的选项，专门找一个让它失败的场景（如审计师要求逐笔回放、跨期更正、迁入历史）。
6. 结论形式：不预选；给出「倾向、前提、否决条件」，并标明哪些结论依赖财务或审计师意见。
