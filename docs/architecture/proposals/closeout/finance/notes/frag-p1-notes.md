## 接缝问题

1. **PRC-133 与 PRC-147（B-09，revenue 组）的分工**：报销被借款全额冲抵、净额为零时不产生应付，PRC-133 不会触发。由 PRC-147 经 api 调 B-12「标记费用报销已付」置已付（S-19、S-24）。两处接缝：①B-09 → B-12 在 §4.1 目前没有边，需按 S-16、S-19 新增（api 方式）；②AGG-59「标记费用报销已付」要带结清方式（付款 / 借款冲抵），命令参数在聚合稿里没写。PRC-133 的 notes 与 step desc 已写明，不改 PRC-147。
2. **PRC-74 的内部调用**：确认应付内含「占用进项发票入账」，实际是 B-10 调 B-23（边存在）。流程 owner 是 B-11，故 `cross_bc` 只记 B-11 → B-10，没有记 B-10 → B-23（B-11 到 B-23 没有边）。沿用 v1 的 `inner` 写法，请 one-architecture 确认记法。
3. **PRC-75 的 B-10 → platform.identity 校验不相容职务**：边存在。INV-81 的校验在「审批付款」与「登记银行结果」两处触发，yaml 只在审批步写了 `platform.identity` 的 `cross_bc`，登记银行结果也走同一校验（决策里写了），聚合稿 AGG-53 引用列已含 platform.identity，不新增边。
4. **PRC-77 缴款的资金支出**：税款缴纳的银行支出是走 PRC-75（需有税款应付）还是只登记缴款回单、由流水匹配过账，聚合稿没有写（AGG-90 只引用 AGG-77）。当前按「登记完税凭证、经 AGG-77 税费过账」写，不经 PRC-75。需 one-architecture 判断。
5. **PRC-112 / PRC-114 的支付承载**：利润分配应付经 AGG-52「提交应付利润」，退回出资的应付类型 AGG-52 没有（G-11 末段仍开，待用户定）。PRC-112 步 5「登记利润分配支付」仍无触发事件（G-10 仍开），建议改由「应付已结清」触发的同 BC 事件策略；需 one-architecture 定号。
6. **PRC-64 触发事件「银行文件已到达」**由 platform.integration 发布，不在聚合稿事件目录里（平台事件）。写作 `triggers` 的 event，publisher 为 platform.integration；是否进事件目录请 one-architecture 定。
7. **PRC-76 的 B-29 读**：`direction: in`（B-29 → B-11 api，边存在）。

## 结构问题

1. **资金账户没有解冻命令**（PRC-65）：聚合稿 AGG-87 只有开立、冻结、销户，冻结后只能销户。〔缺〕「解冻资金账户」，是否需要请定。
2. **暂估应付的命令形态**（PRC-74）：PRC-73 写「无票先确认应付（暂估）」，但 AGG-52「确认应付」的合约是「来源为供方履约确认时先在进项发票上占用再写应付」。无票时占用能否跳过、取得发票后「重入占用」是哪个命令，聚合稿没有。PRC-74 步 1 写了「无票暂估」分支并标 pending P1-Q2。
3. **利润分配过账时点**（PRC-112）：v1 的「提交过账候选」在支付登记之后。会计上决议时点就确认应付股利，更早；AGG-109 的命令列没有决议后过账。请 one-architecture 与总账确认（本稿保持 v1 顺序）。
4. **分包变更对预算占用的调整**（PRC-71）：变更价款变化后，AGG-80 只有「预算占用 / 释放预算占用 / 调整预算」，没有按增减额重占用的命令（INV-10 只对框架协议写了重占）。本稿 PRC-71 未写预算调整，需要的话请补命令。
5. **出资 AGG-54 的分期实缴**：信息图状态为「认缴 → 实缴 → 部分退回 / 已退回」，没有「部分实缴」。若有分期实缴，状态机要加。
6. **PRC-75 的 SH-E6 同角色多职务**：发起、出纳都是 SH-E6（职能人员），靠 `segregation` 按人员判定；是否需要把出纳拆成独立角色请 one-architecture 在角色清单层面定。

## 格式问题

1. `decision` 项增加 `outcome`（结局词）：goto end 的出口各自可以有不同结局，只靠步骤级 `outcome` 表达不了。步骤级 `outcome` 仍保留，用于无 decision 的最后一步。建议写进 CONVENTIONS。
2. `decision` 项增加 `alert: true`：标记「拒收并告警」类分支（CLAUDE.md 第 6 条）。期间闸门分支另在 `when` 里原文写「期间已关账 → 拒收并告警」，两者重复，请定保留哪个。
3. `timeout` 增加 `relative_to`：法定截止日这类相对期限无法用 ISO 时长从触发起算（PRC-77）；并允许 `pending` 引用 T-01。
4. offline 步的操作人与登记人不同时（PRC-112 步 3 股东会决议由 SH-O1 形成、SH-E6 登记）：增加 `recorded_by`，`actor` 写决议人。
5. 事件策略与单聚合维护的字段按任务单自拟：事件策略 `triggers`（event 名与发布 BC）、`steps`、`outcomes`、`scenarios`、`migration`；单聚合维护 `states`（name、transitions、note）、`commands`（actor、command、emits、where、evidence、from、to、decision）、`permission`、`page`、`migration`。CONVENTIONS 没规定，请定。
6. 单聚合的 `commands` 里加 `where`、`evidence`、`from`、`to`：为保证外部、线下证据与状态转换可核对。
7. 起草、占用等 `decision.when` 里有少量带规则引用的业务条件长句，若要求短句请定拆法。
8. `segregation.roles` 写了 `[system]`（PRC-75 最后一条，说明记账由系统完成）与同一角色（`[SH-E6]`，按人员判定）：CONVENTIONS 的「同一人不得同时担任所列角色」对同一角色两个人的情形没写。
