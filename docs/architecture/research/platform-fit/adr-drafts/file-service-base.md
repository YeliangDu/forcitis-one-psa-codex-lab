## 背景

触发：用户同意派 opus 起草平台服务 ADR（intent `2026-10-20-211104`），任务号 ARC-1020-COO-04；复审（`R-ADR草案复审.md` §三）判原稿拆分，本稿为第一份，《文件保存期》（Q04）、《在线预览》（Q05）两稿依赖本稿。

为什么现在定：
1. 仓库无文件服务；OSS 写入只服务归档（`OssObjectStore`）；ADR-0019「文件 → 阿里云 OSS，平台文件服务」未建。
2. 最早使用方是通用审批先行上线（ADR-0054 唯一例外，TRN-03）：用印申请 AGG-113 含「用印事由与文件」，ADR-0054 要求先行期附件与历史版本保全；时点 W0（`R-opus复核.md` §2 ③）。
3. 不可变文件与哈希是真接缝：报价发出核验拟发文件（ADR-0057）、签章服务、执业签章文件指纹（Q03 (b)）都引用它，事后无法回补（`R2-签章服务复核.md` §3）。
4. INV-46、58、85 要求底层文件不被覆盖；CC-I03 入口要求「保留期、病毒扫描、权限随单据」。

通行做法：《电子档案管理办法》（国家档案局令第 22 号）第三、十六条要求来源可靠、带元数据；Deltek 附件可修改、可清除（`AEC_OBJECTS_INSPECTION_EVIDENCE.md` §6.4），不照搬。

关系：ADR-0039、0043、0042、0036；ADR-0026 决定 3（参与人只读由业务模块维护，与「所属模块签发链接」一致）。预签名签名是对象存储凭据，与 ADR-0009 决定 2 无关。

**取代 ADR-0051 的范围**：决定 2 第 1 条「另有平台命名空间 `platform`（10 个模块不变）」改为「另有平台命名空间 `platform`，模块按已采纳 ADR 与 `contexts.yaml` 登记」；决定 3 说明句「另有 `reporting` 与 10 个平台模块沿用」改为「另有 `reporting` 与平台模块（按已采纳 ADR 登记）沿用」，表 platform 行追加 `file`。不写死模块数，同批签章、外部访问稿只写「相容」。

## 决定

### 1. 模块落点

1. 新建平台模块，暂名 `platform.file`（「文件服务」），schema `platform_file`，接口 `/api/v1/platform/files`。名称待 one-glossary，定名前代码不落地。
2. 依赖：`platform.file → platform.integration, platform.audit, platform.identity, platform.scheduling`。业务模块与其他平台模块按需 `→ platform.file`（api）。本模块不依赖业务模块、不订阅业务事件。
3. 对象存储、恶意文件检测（及预览服务）适配器在 `platform.integration`，以本系统用语的端口供本模块调用。所有落盘只经本模块「写入内容」。

### 2. 职责与边界

| 职责 | 做法 |
|---|---|
| 写入内容 | 前端上传与平台模块调用同一用例：后端流式写入临时区，边写边算 SHA-256；大小、媒体类型白名单为配置项（缺失启动失败）；可带「上一版本」或「派生自」。不提供浏览器直传 |
| 上传主体 | （主体类型，主体 ID）；类型取值「用户」「一次性链接」（外部访问稿）「平台模块」（签章服务回收签后件、集成层落盘企业微信媒体） |
| 内容哈希 | SHA-256，小写十六进制 64 位，本系统唯一的内容哈希；`Content-MD5` 只作传输校验；写后读回核对大小与哈希，不符整笔失败 |
| 恶意文件检测 | 每个文件检测；未通过的隔离、不可关联；检测服务不可用时不放行并告警（CLAUDE.md 规则 6） |
| 关联与分级 | 文件经关联挂到 `kernel.DocumentReference`；关联时由所属模块给出访问级别、个人信息标记与保存类别，缺一则失败。**关联前任何人不可下载** |
| 按单据授权 | 下载、读取由单据所属模块校验自身权限与数据范围后经 api 申请；本模块核对文件已关联到所给单据、可用、未处置 |
| 版本与派生 | 见第 4 条 |
| 封存登记 | 业务聚合封存时登记，只追加、不可撤销；保存期内拒绝处置（处置规则在保存期稿） |
| 下载链接 | 预签名 GET，默认 5 分钟、上限 15 分钟（超上限启动失败）；强制 `Content-Disposition: attachment` 与登记的媒体类型 |
| 读取内容 | 平台模块（签章送签、外部持有人下载）经 api 取字节流，边读边核对哈希；业务模块不可用 |
| 审计 | 写入、关联、封存、签发链接、读取内容写 `platform.audit`；detail 不写原文件名与链接 |

不做：档案移交、四性检测、长期保存格式转换；全文检索；文件夹与共享；在线编辑；CAD / BIM 预览；出件模板（另立）；签章与验签；外部主体与公开入口。

### 3. 数据形状

工作名，按 NAMING_STANDARD 与词表定稿；主键 UUIDv7（D16）；跨 schema 不建外键。

| 表（工作名） | 角色 | 要点 | 可变性 |
|---|---|---|---|
| `stored_files` | 根：存储文件 | 对象键、`content_hash`（`CHECK` 64 位小写十六进制）、字节数、媒体类型、上传主体类型与 ID、检测状态、`previous_file_id`（为空表示首版，`uk` 保证至多一个后继）、`derived_from_file_id` 与派生方式（为空表示非派生）、`version` | 对象键、哈希、字节数、媒体类型、上传主体、两个引用列由触发器拒绝 UPDATE；禁 DELETE；状态只经领域方法 |
| `stored_file_names` | 子表：原文件名 | 原文件名（`INTERNAL` + `PI`，「用途：下载时还原文件名」）、是否已去标识 | 只允许一次 UPDATE：经处置流程置为去标识值并置标记，触发器拒绝其他改动 |
| `file_bindings` | 子表：关联 | 文件 ID、单据类型与单据 ID、访问级别、个人信息标记、关联主体、时间；一个文件可关联多张单据 | 只追加 |
| `file_holds` | 子表：封存登记 | 文件 ID、发起封存的单据、封存人、时间、理由 | 只追加 |

- 原文件名单列，使内容不可改与到期去标识不冲突。
- 对象键：`<环境前缀>/files/<yyyy>/<mm>/<文件 ID>`；临时区 `<环境前缀>/staging/<来源>/<文件 ID>`（第 5 条）。键中不含文件名、单据号、人名。
- 保存类别由保存期稿的类别配置校验。
- `SPI` 文件按 ADR-0043 第 5 项先评估后处理，U-14 定前不接收新的 `SPI` 文件。
- 引用约定：签章、报价发出核验、证据封存、银行流水原始文件一律引用「文件 ID + `content_hash`」，比对以哈希为准。

### 4. 版本与派生（签署件的关系模型）

1. **上一版本**（`previous_file_id`）：同一逻辑文件的修订，线性、不分叉，一个文件至多一个后继。业务上的「被取代、签发、认可」仍属所在聚合（AGG-27 文件版本清单等）。
2. **派生自**（`derived_from_file_id` + 派生方式）：由另一文件经处理得到的新文件，不占版本链；一个文件可有多个派生件。本期派生方式取值：「签署」（签后件派生自签前件）、「格式转换」（如出件生成的 PDF）。
3. **签署件**：签后件是签前件的**派生件**，不是其新版本。签前件可以另有 v2；重签或失败重试各产生新的派生件。签章服务登记签前、签后两个文件的 ID 与哈希。签前件出新版本后，要签新版本的，从新版本另行派生。
4. 两种引用在写入时声明、此后不可改，被引用文件须「可用」；关联时核对「上一版本」已关联到同一单据，否则关联失败。

### 5. 上传、检测与不可变

1. 流程：写入临时区并算哈希 → 检测 → 「可用」（仍在临时区）→ 关联时复制到正式键（禁止覆盖）并读回核对。临时区到期未关联的由生命周期规则过期，应用不删；行状态「未关联已过期」。
2. **临时区时效由来源决定**（按前缀配生命周期）：「用户」「平台模块」默认 2 天；「一次性链接」不短于链接有效期上限加 2 天（外部稿上限 14 天，即至少 16 天），配置小于此值启动失败。
3. **外部回传的关联与审核**：所属模块签发链接时给出访问级别、个人信息标记与保存类别，随链接保存；持有人提交时，外部访问模块即以这些值把文件关联到所属单据（关联主体为该链接），未提交的随临时区过期。我方审核人员经所属模块的下载命令打开，按该模块权限与数据范围授权；退回不删除，文件仍按类别保存。
4. 检测「未通过」：状态「已隔离」，记 `ALERT` 并通知上传主体，不进正式区。
5. 不可变以应用层为准：触发器禁改、写入禁止覆盖、应用身份无删除权、新版本只能新建。对象级 WORM（邀测、不可关闭）只作日后加固（`R-opus复核.md` §2 ③）。

### 6. 存储桶（须 one-ops 复核，复核前不建桶）

| 桶 | 内容 | 存储类型 | 保护 |
|---|---|---|---|
| 业务文件桶（新建，每环境一个，国内同地域） | 业务文件与临时区 | 标准 | 禁止覆盖；应用 RAM 显式 Deny `oss:DeleteObject*`；临时区按来源前缀过期（第 5 条）；正式前缀不过期 |
| 归档桶（现有，INFRA_RUNBOOK §5.3） | 流程与审计归档 | Archive，Bucket 级 WORM 2557 天 | 不变，不放业务文件 |

不复用归档桶：须解冻才能读；统一锁定天数与按类别处置冲突。须 one-ops 复核：版本控制及其与禁止覆盖的组合（结果要求：应用身份既不能覆盖也不能删除）；冗余与恢复演练；处置删除身份。

### 7. 接口（契约先行，CS-1.10）

1. 前端：`POST /api/v1/platform/files`（上传，带 `Idempotency-Key`）；`GET /api/v1/platform/files/{id}` 只给本人上传、未关联文件的检测状态。下载在各业务模块资源下用命令 `POST …/{单据 ID}/files/{文件 ID}:download`（有副作用，不用 GET）。
2. api 7 项（名称待 one-glossary）：**写入内容**（带主体类型、可选上一版本或派生自）、关联、封存登记、申请下载链接、**读取内容**（仅平台模块）、按单据列出、迁入入口（仅 `platform.migration`）。加保存期稿 3 项、预览稿 1 项共 11 项，不超 CS-1.12 的 12 项。
3. 错误码在本模块定义、中文名全局唯一（文件未通过检测、文件未关联到该单据、文件已处置、哈希不符等）。
4. 指标：写入失败数、检测待处理最久时长、检测未通过数、哈希不符数；失败按 O-2 记一次。

### 8. 建造时点

W0 内、通用审批先行上线（TRN-03）前建成并验收：第 1–7 条全部。恶意文件检测是 CC-I03 已登记的入口要求，其选型与对外调用须用户同意（CLAUDE.md 规则 9），在批准页让用户知情（复审 X-9）。

## 影响面

- 新增 `platform.file`、`platform_file`；集成层对象存储与检测端口；业务文件桶（用户建，名字与凭据不进仓库）。
- 使用方随各自批次加边：`organization.administration`（W0）、`delivery.acceptance`、`presales.opportunity`、`accounting.cashbank`、`accounting.ledger`；签章、外部访问、出件模块。外部访问稿按第 5 条第 3 点在签发链接时保存分级与保存类别。
- `platform.approval` 不依赖本模块：审批参与人经单据所属模块读附件（ADR-0026 决定 3）。
- ADR-0051 按「取代」两项改写；`contexts.yaml` 登记本模块。
- 文档：CC-I03 回填；INFRA_RUNBOOK 增业务文件桶一节（one-ops）。

## 迁移方案

1. 量级（只计数，`docs/legacy/runtime-usage/prod-usage.tsv` 只读采集）：老系统 `infra_file` 231 行、`infra_file_content` 105 行（内容存库）、`infra_file_config` 7 行；`psa_deliverable_attachment` 0 行；近 180 天上传 POST 132 次（`R-opus复核.md` B-6）。A8 附件（历史用印约 4,176 件等）行数与字节数未取证，须按 ADR-0037 登记一行后只取计数。
2. 迁哪些由各目标模块迁入规格定（§14.2 M1）；TRN-04 已定不回 A8 补录。
3. 方式（ADR-0036）：集成层只读抽取、分批低峰；经迁入入口写入，同样算哈希、检测、写正式键；新主键 UUIDv7，老 ID 只进来源对照；不发事件；分级与保存类别由目标模块给出，缺则拒收带原因代码（M6）。
4. **检测服务是硬依赖**：先行上线与迁入演练都须检测可用；检测选型与对外调用须用户同意（CLAUDE.md 规则 9），未就绪则不开放上传、不开始迁入，不跳过检测。
5. 核对：来源行数 = 写入 + 拒收，字节合计一致，逐文件哈希入核对清单（M9）；演练按 ADR-0054 决定 8，会话只收计数。

## 回滚方案

1. 先行上线前：整体回退（迁移脚本、依赖边、测试桶）。
2. 先行上线后：已产生的文件与元数据不回滚、不删除（ADR-0054 保全、TRN-04），一律前进修复；接口变更按 ADR-0035。
3. 检测服务更换：端口不变换适配器；切换期新上传不放行并告警。
4. 桶的版本控制只能暂停不能关闭、对象级 WORM 开启不可关闭，one-ops 结论前不开。
5. ADR-0051 的改写为措辞放宽，回退即恢复原句并删除表中 `file`。

6. 新增测试（语义与权限类不外包）：内容列 UPDATE、DELETE 被拒；原文件名只能经处置改一次；写入禁止覆盖并读回核对；链接时效超上限、链接来源临时区时效短于链接上限加 2 天均启动失败；日志与审计 detail 无预签名地址；未关联到所给单据即拒绝；关联前不可下载；「上一版本」未关联到同一单据即拒绝；读取内容只限平台模块（ArchUnit）；迁入入口只被 `platform.migration` 调用。

8. 测试镜像：不新增；对象存储用端口的内存实现。若需 OSS 兼容容器，先登记 `test-images.txt`。

## 后果

- 先行期附件从第一天起有不可变文件与哈希；签章、核验、证据封存直接引用「文件 ID + 哈希」。
- 授权留在单据所属模块，每个使用方自建下载命令；文件模块不依赖业务、无成环。
- 签署件按派生建模，签前件的修订与重签互不冲突；签章服务稿按此改写。
- 检测失败即不放行，检测故障会阻断上传，靠告警处理。
- 不可变依赖应用层与运维不越权，桶策略须复核。
- 未定：检测选型；版本控制组合；单文件大小上限。

### 须交其他会话的问题

- **one-glossary**：模块名；存储文件、内容哈希（统一指纹 / 校验和叫法）、上一版本、派生自与派生方式、文件关联、封存登记（暂名 hold，避开 seal）、检测状态、写入内容、读取内容、上传主体类型、临时下载链接、业务文件桶、临时上传区；「签发」同名异义；`object_key` 类别词；错误码中文名。
- **one-ops**：业务文件桶（版本控制组合、Deny 删除、按来源前缀的临时区生命周期、冗余与恢复演练）；大小上限与 nginx `client_max_body_size`；对象级 WORM 是否申请。
- **one-security**：上传威胁；检测选型、不放行策略与重扫；预签名时效；按 ID 枚举越权；文件与文件名的个人信息标记。
- **one-architecture**：ADR-0051 改写措辞与合入次序；`stored_file_names` 单次更新豁免写法。
