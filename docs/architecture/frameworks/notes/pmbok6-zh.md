# 《项目管理知识体系指南》第六版中文本要点笔记

本文自行概括项目管理与系统架构的关联，不复制过程输入输出清单。短引：0 处。章节位置已抽查。

## 核心思想

- **论断：WBS 将全部项目范围细化为可管理的工作包，活动安排还须处理时序和资源需求。** 依据：PMB6#工作分解、PMB6#资源需求。含义：分别保存范围、交付物、工作包与活动安排的管理依据，不因树形相似就合并记录。
- **论断：项目管理过程可以重复、交叠和相互作用，方法须按项目情况裁剪。** 依据：PMB6#生命周期与裁剪。含义：不把五个过程组固定为阶段状态机，也不按全部过程清单造菜单和表，仍从实际对象、规则和职责形成契约。
- **论断：整体变更控制须综合处理范围、成本和进度影响，估算、批准基准、预测与实际分别提供判断依据。** 依据：PMB6#整体变更控制、PMB6#成本估算与预算。含义：分别记录原估算、批准基准、后续预测、实际及变更处理决定，修订时保留历史，避免覆盖原承诺。
- **论断：控制质量产生的内部核实结果不能替代客户或发起人的正式验收。** 依据：PMB6#质量核实与验收。含义：内部质量核实与正式验收分别留存，不用内部检查通过推定客户验收或付款条件已满足。
- **论断：挣值是已完成工作的批准预算价值，PV、EV、AC 的范围和成本构成须可比。** 依据：PMB6#挣值。含义：经营分析先核验比较口径，不将 EV 等同收入确认、开票或回款，也不把未经核验的完成百分比用于全部度量。
- **论断：项目知识既含可编纂内容，也依赖情境和人际交流，知识积累应贯穿项目过程。** 依据：PMB6#项目知识。含义：持续记录可复用内容及其情境，不从知识文件清单直接推定主记录匹配、来源优先级或版本表实现。

## 对本系统的启示

- **业务对象（对照：原笔记未列本系统编号）：** 项目、范围、交付物、资源需求、基准和变更请求不能混为一种记录。工作分解把全部范围细化为可管理部分，工作包是范围管理及估算的单元，活动安排则还要处理时序和资源；树形结构相似不能证明对象相同。（PMB6#工作分解、PMB6#整体变更控制、PMB6#资源需求）

- **价值流（对照：原笔记未列本系统编号）：** 本书不涉及 BIZBOK 价值流图。项目的商业论证、效益管理和交付内容有联系，但项目阶段、五个过程组与价值流阶段不能直接等同；过程会重复、交叠和相互作用。（PMB6#生命周期与裁剪）

- **能力（对照：原笔记未列本系统编号）：** 本书不涉及企业业务能力图。团队技能和资源特性属于资源需求与人员安排的输入，不能自动成为企业能力目录。（PMB6#资源需求）

- **流程（对照：原笔记未列本系统编号）：** 指南要求按项目情况裁剪，不是所有项目逐项执行的单一方法论。整体变更控制关注对范围、成本、进度等影响的综合处理；质量核实与客户/发起人的正式验收是不同结果，不能用内部检查通过代替验收。（PMB6#生命周期与裁剪、PMB6#质量核实与验收、PMB6#整体变更控制）

- **数据建模（对照：原笔记未列本系统编号）：** 估算是特定时点基于已知信息的判断；批准的成本基准、后续预测和实际成本应分开记录。变更有提出、审查和处理决定，不能覆盖基准后失去历史。书中的文件清单提供信息需求线索，不直接规定实体、聚合或物理表。（PMB6#整体变更控制、PMB6#成本估算与预算）

- **度量与 BI（对照：原笔记未列本系统编号）：** 挣值把已完成工作的价值表达为对应批准预算，而不是合同收入或现金收款。PV、EV、AC 的范围和成本构成必须可比；基准偏差与完工预测回答不同问题。不能把项目经理填报的完成百分比未经口径核验就用于全部度量。（PMB6#挣值）

- **主数据（对照：原笔记未列本系统编号）：** 知识复用既有可编纂内容，也依赖情境和人际交流，应在项目过程中持续积累。人员技能、资源类型和组织资料可跨项目复用，但本书不涉及本系统的主记录匹配、来源优先级及版本表实现。（PMB6#资源需求、PMB6#项目知识）

## 我们的取舍

**已审定（one-architecture 2026-10-18，已抽查）。**

- **采纳：范围、计划基准、预测、实际和批准变更分别追溯。** 理由：适合项目制专业服务的预算、完工估算和范围变更核对。
- **采纳：质量核实、正式验收及采购履行证据分别保存。** 理由：内部工作完成不自动满足客户验收或付款条件。
- **不采纳：把过程组当成固定阶段状态机，或按全部过程清单造菜单和表。** 理由：指南要求裁剪，系统要从实际业务对象、规则和职责形成契约。
- **不采纳：将 EV 等同收入确认、开票或回款。** 理由：批准预算计量与合同及会计计量目的不同；收入确认仍按本项目已定口径。
