# 数据安全法、网络安全法与第三级通用安全要求要点笔记

本笔记保存与 FORCITIS one 相关的阅读要点，不构成架构决定。正文为自行概括，短引0处；目录编号只表示设计对照，不证明功能已实现、已定级或已通过测评。

国标信息栏取自扫描版封面：2019年5月10日发布、12月1日实施，代替2008版；版权页载中国标准出版社2019年4月第一版。法律资料为HTML，无封面或版权页，信息栏相应项记未核。数据安全法正文题注载2021年6月10日通过；网络安全法正文题注载2025年10月28日修正，本笔记保留该快照条号，修正决定及其施行日期未核，不将网页转载日期当作施行日期。

## 核心思想

- **论断：内部敏感标签不能代替法定重要数据认定，分类结果必须能说明风险和保护措施。** 依据：DSEC#数据分类分级、DSEC#全流程安全、DSEC#三级个人信息保护。含义：OBJ-56 人员、OBJ-73 月度薪酬结算及 OBJ-98 会计分录逐类登记字段分级、处理目的、责任人和保护方式；是否属于重要数据另列依据与待核状态。

- **论断：单点登录成功只能证明一个登录环节成功，不能证明已满足第三级身份鉴别要求。** 依据：DSEC#三级身份鉴别、DSEC#三级访问控制。含义：PRC-187、PRC-188 要连同上游身份源核对唯一身份、失败控制、会话退出、远程传输保护，以及至少两种组合鉴别且其中一种使用密码技术的证据；本笔记不直接改身份方案。

- **论断：访问控制必须落实到用户或进程与数据客体的关系，只有菜单权限不足以保护数据。** 依据：DSEC#三级访问控制、DSEC#三级个人信息保护、DSEC#网络信息最小收集。含义：OBJ-123 人员薪酬档案和 OBJ-73 的读取、修改、下载分别检查主体、数据范围与字段；离岗和外部服务结束时收回权限，敏感授权继续遵守 ADR-0032。

- **论断：未覆盖用户、未保护审计进程或不能还原事件结果的日志，不足以证明审计要求已落实。** 依据：DSEC#三级审计、DSEC#网络等保与日志。含义：对 PRC-193 迁入及平台管理操作核对审计主体、时间、类型、结果、集中分析和备份；相关网络日志按所供法律条文至少留存六个月，业务账证和个人信息分别确定期限。

- **论断：存在备份文件不能证明具备恢复能力，更不能证明已满足异地实时备份和热冗余要求。** 依据：DSEC#三级备份恢复、DSEC#三级数据完整性、DSEC#三级数据保密性。含义：OBJ-53 证据、OBJ-98 会计分录及其关联配置分别登记备份范围、频度、介质、保存期和恢复程序，并以恢复核对、异地传送及切换记录验证各项要求。

- **论断：清理业务记录与清除存储空间中的敏感残留是两项不同的控制，归档不能自动满足二者。** 依据：DSEC#网络信息更正删除、DSEC#三级剩余信息保护、DSEC#三级备份恢复。含义：OBJ-56 的个人信息删除、备份轮换、介质报废和恢复后的访问限制各有处理条件；依法仍需保存的账证限制用途，平台归档作业另核，不借业务结项流程证明已安全销毁。

## 对本系统的启示

- **数据分级必须能落到保护措施。** 对照 OBJ-56 人员、OBJ-73 月度薪酬结算、OBJ-123 人员薪酬档案及 PRC-125：建议按 NAMING_STANDARD §2.5 登记个人信息、薪酬和鉴别凭据的列级分级，并分别列出传输、存储、展示、日志、备份和销毁的控制。业务重要、内部敏感与法定重要数据分别记录判断依据；目录或行业认定依据未取得时写待核，不由内部标签直接推定。（DSEC#数据分类分级、DSEC#全流程安全、DSEC#三级数据保密性）

- **身份鉴别应核对整个信任链。** 对照 PRC-187 校验致远单点登录票据、PRC-188 识别企业微信登录身份：建议逐环节核对身份唯一、票据校验、失败限制、超时退出、远程管理防窃听及组合鉴别证据；不能因同时接入两个身份源就声称满足两种组合鉴别。PRC-129 已退役为平台作业登记，不再作为业务流程。身份鉴别平台机制的业务对象编号，本系统暂无对应；具体方案和适用等级交 one-security，遵守 ADR-0041 投产前定级的决定。（DSEC#三级身份鉴别、DSEC#三级访问控制）

- **权限应随用途和人员状态收敛。** 对照 OBJ-123、OBJ-73、PRC-123 及 PRC-197 同步差旅员工与组织：查看、修改、下载分别授权，接口、查询与存储账号都限制到必要客体，默认及过期账号及时处理，外部服务终止即收回访问。敏感权限授予保持 ADR-0032 的逐人要求；业务处理仅传必要字段，不能向服务商发送完整薪酬或人员档案。（DSEC#三级访问控制、DSEC#三级个人信息保护、DSEC#网络信息最小收集）

- **审计日志需要覆盖行为、保护记录并可供分析。** 对照 PRC-193 编排历史数据迁入与 OBJ-98 会计分录：建议核对操作主体、对象、时间、事件类型、结果、批次及必要批准依据；管理员改配置、启用远程通道、使用工具同样审计。记录不得被普通业务用户修改删除，审计进程防未授权中断，记录按计划备份并集中分析。采用 terms.yaml 的「审计日志」；其平台记录的业务对象编号，本系统暂无对应，不能用 OBJ-53 证据冒充审计模型。（DSEC#三级审计、DSEC#网络等保与日志）

- **备份验收须检查恢复后的业务关系。** 对照 OBJ-53 证据、OBJ-98 会计分录及 PRC-193：备份清单应含重要业务数据、关联证据、审计、配置及恢复所需软件，逐类登记方式、频度、介质、保存期和责任。建议恢复后核对行数、金额、证据摘要、关联和配置版本，并记录耗时及缺口；本地恢复、异地实时备份、热冗余分别提供证据。PRC-190 重投领域事件、PRC-191 归档数据到对象存储均已退役为平台作业登记，归档成功不能当作恢复测试；专门的备份恢复业务流程，本系统暂无对应。（DSEC#三级备份恢复、DSEC#三级数据完整性、DSEC#三级数据保密性）

- **保存期限与介质清除应分别制定规则。** 对照 OBJ-53、OBJ-56 及 VS-10 获得期间报告：所供网络安全法第二十三条的相关网络日志至少六个月，不能套成全部业务账证的保存期，也不能变成个人资料的统一最短期限。建议逐类确定保存依据、到期动作与备份轮换；归档存储、临时导出、缓存和退役介质释放前分别核对残留清除。涉及法定留存未满或技术难删的个人信息，结合 PIPL#个人信息删除 限制处理；恢复备份时继续落实已生效的删除和访问限制。（DSEC#网络等保与日志、DSEC#网络信息更正删除、DSEC#三级剩余信息保护）

- **接口和分析入口同样受数据安全控制。** 对照 PRC-197、PRC-90 出具经营月报，以及 terms.yaml 中 `kind: metric` 的「直接人工」「项目成本」：人机与同步接口均校验输入，开发测试用受控数据；按 BI_SCOPE §3 的来源、粒度与口径记录度量，查询先按范围授权再聚合，个人薪酬和凭据明细不复制进分析层。新增接收方、出境或境外执法请求分别核对法律条件，不由存在接口推定发生跨境。（DSEC#三级应用输入检查、DSEC#三级个人信息保护、DSEC#合法收集数据、DSEC#重要数据出境、DSEC#境外执法提供）

## 我们的取舍

- **建议采纳：以第三级通用要求逐项核对身份、权限、审计、数据保护及备份恢复，并保留适用条件和验证证据。** 理由：补读表明技术控制依赖制度、人员、建设及运维管理共同生效；沿用 ADR-0041，等级仍在投产前确定，本笔记只提供差距核对输入。（DSEC#全流程安全、DSEC#三级身份鉴别、DSEC#三级审计、DSEC#三级备份恢复）

- **建议不采纳：因阅读第三级要求就宣布定为三级，或用单点登录、数据库授权和归档文件分别代替组合鉴别、完整访问控制及灾备能力的证据。** 理由：条款对主体客体、记录保护、异地实时备份及热冗余有不同要求，目录和静态配置不能证明运行效果；不在本笔记中改变既有安全决定。（DSEC#三级身份鉴别、DSEC#三级访问控制、DSEC#三级备份恢复）
