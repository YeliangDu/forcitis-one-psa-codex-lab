# Prove It! 要点笔记

本笔记保存与 FORCITIS one 相关的阅读要点，不构成架构决定。正文自行概括，短引 0 处。题名、作者、年份与版本据 EPUB 题名及版权页，出版者为 John Wiley & Sons Australia, Ltd；版权页明确首次出版于 2017 年，不采用 EPUB 元数据中较早的制作日期。资料清单仅有 EPUB，正文有 Page_数字 的印刷页标，表中印刷页据内嵌页标实际读取；没有 PDF，PDF 页写「—」，不是漏填或自造转换页码。阅读聚焦第 5–10 章所列页，未逐页通读全书；作者方法名仅用于原书定位。

## 核心思想

- **论断：一项行动完成，只能证明工作做过，不能证明希望产生的经营结果已出现。** 依据：BARR#结果先于行动、BARR#结果与项目、BARR#计划顺序。含义：OBJ-100 经营计划和 PRC-88 须区分目标结果、度量、目标值与行动；PRC-181 复盘不能用行动完成率替代返工率或回款率等业务结果。
- **论断：在说明目标实现时会观察到什么之前就选指标，容易只选到已有且好算的数据。** 依据：BARR#证据先于指标、BARR#模糊目标具体化、BARR#直接证据。含义：度量清单先写可观察证据，再检查 OBJ-35、OBJ-66、OBJ-106 是否提供原料；缺少证据时列采集缺口，不能把访问量或填表量冒充业务效果。
- **论断：指标名称不足以确定口径，统计量、属性数据、范围数据和时间数据必须共同声明。** 依据：BARR#统计量、BARR#属性数据、BARR#范围数据、BARR#时间数据。含义：利用率须能定位分子、分母及纳入范围，目标达成率须带目标类型；这些字段补充 BI_SCOPE.md §3.3，而不是由各页面自行解释。
- **论断：单点较上月变差并不充分证明过程恶化，先识别自然波动才能决定是否干预。** 依据：BARR#波动与信号、BARR#能力基线。含义：PRC-90 展示连续观测和数据截至时点，PRC-181 区分需要调查的信号与一般波动；现行预警仍按批准规则执行，不能用本书直接改阈值。
- **论断：把指标责任定义为监测、解释和发起改进，比只追究是否命中目标更能暴露真实问题。** 依据：BARR#学习而非评判、BARR#指标责任。含义：OBJ-66 工时单和 PRC-91 认定的原始记录应可追查；团队对异常解释与改进行动负责，不将跨流程结果简单归为某个人未达标。
- **论断：战略与改进措施之间的因果关系需要验证，画出关系图本身不构成成效证据。** 依据：BARR#结果关系图、BARR#根因而非症状、BARR#业务实验。含义：PRC-181 记录改进前基线、实施时点、观察窗口及其他变化，并将结果反馈到 OBJ-100 下一版计划，不能把同期相关直接写成因果。

## 对本系统的启示

- **计划目标与行动完成分开记录。** OBJ-100、PRC-88 和 PRC-181 可采用结果、度量、计划目标值、行动的顺序；目标达成率还须引用确定的目标类型及版本。不能因系统功能交付或某项催收动作完成，就认定业务结果达成。（BARR#结果与项目、BARR#计划顺序）
- **客户调查是采集手段，不是一个完整指标。** OBJ-106 和 PRC-37 对应 VS-02.7 完成收尾；建议明确调查问题、量表、受邀总体、实际回应者与观察期间，再判断得分能支持何种结论。不能以投诉少推断客户满意，也不能以回收份数代替满意程度；统一客户满意度计算口径，本系统暂无对应已核定的 metric 词条。（BARR#直接证据、BARR#属性数据、BARR#范围数据）
- **利用率的可复算性依赖基础记录和排除条件。** OBJ-66、PRC-23、PRC-91 与 OBJ-28 工作日历应能提供可计费工时、有效性认定及可用工时的来源条件；建议检查更正、休假与日历版本能否回放。书中四要素指导如何写清问题，具体公式仍以 terms.yaml 的利用率定义为准。（BARR#统计量、BARR#属性数据、BARR#范围数据）
- **交付时效同时观察程度和发生率。** OBJ-35、PRC-28 的约定、签发、送达、认可时间可以支持不同的观察问题；建议先区分哪种结果与客户需求一致，再选迟交时长或迟交比例，不能把两者视为同一个指标。具体新指标名称、起止事件和缺失日期处理均待提议，本系统暂无对应已核定口径。（BARR#变化敏感性、BARR#证据先于指标）
- **月报与复盘保留连续证据。** PRC-90 的结果展示应注明口径版本、连续观测值和更新时点，PRC-181 解释异常与措施效果；XmR方法可以作为待评估的分析手段，但样本量、分布适用性与变更处理尚未在本卡验证。（BARR#波动与信号、BARR#业务实验）

### 供度量设计

- **度量选择**：依次写目标、结果、可观察证据、候选指标，再按证据相关性和采集可行性筛选，度量清单不能只有名称与公式。（BARR#证据先于指标）
- **指标口径·统计量**：写明计数、合计、平均或比率及单位，不能只填一个抽象名称。（BARR#统计量）
- **指标口径·属性数据**：逐项列出被计算的原始量，比率明确分子和分母，作为业务库可度量原料的字段检查项。（BARR#属性数据）
- **指标口径·范围数据**：把纳入与排除条件落实到可追查的对象、状态或分类条件，按同一范围读取分子分母。（BARR#范围数据）
- **指标口径·时间数据**：写明观察期间和计算频率，按需要发现信号的速度选择频率，而不是按月报版面决定。（BARR#时间数据、BARR#持续观测）
- **目标值**：先固定度量及基线，再制定有量纲的计划目标值，不能先写提高百分之十再寻找公式。（BARR#计划顺序）
- **KPI分级**：本书所核章节区分目标结果、证据与量化方式，未定义本系统 KPI／派生指标／基础指标三层；四要素应用于每层定义，依赖层级另行登记。（BARR#证据先于指标、BARR#统计量）
- **总线矩阵**：结果关系图表达目标影响关系，不是业务过程乘维度的矩阵；后续按 BI_SCOPE.md §3.2 将所需证据落到过程事实，再检查矩阵覆盖。（BARR#结果关系图）
- **粒度**：属性与范围数据明确计算对象，但未规定事实表一行的粒度；本系统另声明一行代表什么，并检查时效起止事件能否成对取得。（BARR#属性数据、BARR#范围数据、BARR#变化敏感性）
- **事实表类型**：持续时间序列不等于期间快照设计，所核章节未提供交易事实／累积快照／期间快照的选型规则；按 BI_SCOPE.md §3.1–3.2 另行选择。（BARR#持续观测、BARR#波动与信号）
- **维度一致性**：范围条件和计算要一致，才能进行同口径比较；维度键与历史归属不是该四要素的直接结论，按 BI_SCOPE.md §3.1 检查共享维度及生效期。（BARR#范围数据、BARR#时间数据）
- **效果验证**：记录措施前后同口径序列、实施时点与其他变化，区分过程信号和自然波动，不能只挑两个有利数字证明效果。（BARR#波动与信号、BARR#业务实验）

## 我们的取舍

- **建议采纳：四要素作为指标描述和业务库原料检查的补充。** 理由：能把抽象指标名还原为明确数据条件，并与 BI_SCOPE.md §3.3 的单位、期间类型、加总规则和版本并用。（BARR#统计量、BARR#属性数据、BARR#范围数据、BARR#时间数据）
- **建议采纳：复盘先核对结果证据，再讨论措施是否有效。** 理由：项目完成和经营改善是不同结论，各需证据。（BARR#结果与项目、BARR#业务实验）
- **建议不采纳：把过程指标直接用于个人奖惩或以每月未达标自动归责。** 理由：结果受流程和系统约束，作者主张对监测、解释和行动负责。（BARR#学习而非评判、BARR#指标责任）
- **建议不采纳：未经适用性验证，用XmR界限替换现有业务预警阈值。** 理由：统计信号与已批准的业务处置条件需要分开，书中案例不是本系统运行证据。（BARR#波动与信号）
- **建议不采纳：将结果关系图当作总线矩阵或把四要素当作物理数据模型。** 理由：它们说明为何度量及如何量化，没有直接给出事实表与一致性维度设计。（BARR#结果关系图、BARR#属性数据）
