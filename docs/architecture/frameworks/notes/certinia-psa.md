## 核心思想

- **论断：该产品数据表宣称可把商机交接为项目，并在交接前软预订及安排资源。** 依据：CERT#商机到项目。含义：可用 OBJ-01、OBJ-18、OBJ-29 及 PRC-05、PRC-17 检查客户、报价、资源需求的来源追溯；宣传本身不能证明本系统商机与项目应为一对一。
- **论断：体验指南将对象访问权与具体记录共享分开，可见对象页面仍可能看不到记录。** 依据：CERT#外部记录共享、CERT#对象权与记录权。含义：PRC-28 的 OBJ-35、OBJ-53 如需外部协作，应分别核对项目记录范围及字段可写权，现行授权继续按已采纳 ADR 执行。
- **论断：计费事件的生成、发票日期编号录入、重算和释放在指南中是分别操作的动作。** 依据：CERT#计费事件处理。含义：VS-04 的收入确认、开票与回款分别追溯，不把 Billing Event 直接等同 OBJ-83 或 OBJ-81，也不以重算证明完整变更链。
- **论断：指南允许向项目下的安排、里程碑和任务提交工时，而非只向项目提交。** 依据：CERT#工时挂接粒度。含义：可用 OBJ-44、OBJ-45、OBJ-66 及 PRC-20、PRC-23 分别核对需求、安排与实际；计费费率、成本费率及可计费状态仍由本系统定义。

## 对本系统的启示

- 往来单位 OBJ-01、商机 OBJ-18、项目 OBJ-29 对照 PRC-05、PRC-17 及 VS-01、VS-02 时，可用服务交接是否保留客户、报价、资源需求来源来出关卡；不能依据宣传中的一键转换推定我方商机与项目为一对一。（CERT#商机到项目）
- 资源需求 OBJ-44、资源分配 OBJ-45、工时单 OBJ-66 在 PRC-20、PRC-23 中分别核对需求、安排和实际；计费费率与成本费率及可计费状态须由我方定义，数据表没有给足计算证据。（CERT#资源能力日历、CERT#工时挂接粒度）
- PRC-28 的交付物 OBJ-35、证据 OBJ-53 如需外部协作，要核对项目记录范围及字段可写权；现行授权模型继续按已采纳 ADR 执行，不能照抄该版本站点设置。（CERT#外部记录共享、CERT#审批与共享配置）
- VS-04 的收入确认、开票与回款需各自追溯，产品 Billing Event 是商业计费事件，不能直接等同增值税发票 OBJ-83 或收入确认 OBJ-81。（CERT#计费事件处理、CERT#计费收入自动化宣称）

### 供成熟产品关卡

- 协议：现有资料仅提商机交接和客户对象，未展示签署协议、组成文件及基线模型，关卡证据不足。（CERT#商机到项目）
- 履约义务：里程碑与计费事件有独立动作；未说明会计义务识别及价格分摊，不能用功能清单替代证明。（CERT#工时挂接粒度、CERT#计费事件处理、CERT#计费收入自动化宣称）
- 变更：计费事件支持重算不等于保存双方批准的范围价款工期变更，资料未覆盖完整变更链。（CERT#计费事件处理）
- 全过程咨询服务范围：PS 云有估算资源交付能力清单，但未给中国建设项目全过程咨询的范围、统筹费及资质责任模型，需另行实证。（CERT#跨云能力组合、CERT#估算资源前置）

## 我们的取舍

- **建议采纳：** 用独立的资源需求、安排、工时、计费动作和记录范围检查产品关卡。理由：指南给出了具体动作与权限边界。（CERT#工时挂接粒度、CERT#外部记录共享）

- **建议不采纳：** 把统一平台宣传、客户增长数字和自动化口号当成本系统功能或效果证明。理由：没有运行及统计口径证据，也不能据此覆盖 ADR-0016、ADR-0047 的收入与事实约束；相关改变须待提议。（CERT#计费收入自动化宣称）
