## 决定

1. **迁入通道**：
   - 抽取只在集成层的迁入适配器中进行；装载只经目标 BC `api` 中的迁入用例（与业务用例同样经领域校验，不直接写目标表）。
   - 迁入以离线命令运行，不挂在 HTTP 接口或定时作业上。离线命令进程只加载迁入适配器与迁入用例，**不加载定时作业、事件监听与出站投递 worker**。
   - **迁入数据库角色**：专用角色，授权不超过应用运行角色（只有目标表的 DML，没有 DDL，不能读写目标之外的 schema）；连接上限计入实例连接数预算（INFRA_RUNBOOK，ADR-0025 第 2 条）；只在批准的时间窗内 `LOGIN`，时间窗外 `NOLOGIN`，开关由 one-ops 执行并记运维记录。
   - 读取授权按 SESSION_PLAYBOOK §5「迁入读取授权」。
2. **来源标识**：来源系统沿用 ADR-0033 第 2 项第 8 条的三个代码（组织源、老系统、核算系统），只出现在集成层的来源对照与迁入登记中；领域模块与 kernel 不出现来源系统名。老 ID 一律登记为来源对照，迁入行的主键是新生成的 UUIDv7。某个迁入阶段遇到文本形态的来源标识时，另立条款修订 ADR-0033 第 2 项第 1 条，本 ADR 不定。
3. **迁入批次**：
   - 每次运行是一个迁入批次（MigrationBatch），登记在 `platform_integration.migration_batches`：来源系统、对象类型、范围（期间 × 法人）、状态、开始与结束时刻、行数、来源 ID 集合摘要、来源快照标识、操作人。
   - 状态：进行中 `RUNNING` → 待核对 `AWAITING_TIE_OUT` → 已生效 `EFFECTIVE`；失败时整批冲销为已冲销 `REVERSED`，修正后可回到进行中，或放弃为已放弃 `ABANDONED`（终态）。取值与术语在首个迁入阶段登记（ADR-0018）。
   - **业务表不加 `migration_batch_id`**（用户已定）。批次挂在来源对照上：`source_references` 新增 `migration_batch_id uuid`（为空表示由来源同步或人工登记分配，非迁入）与 `source_row_digest bytea`（来源行规范化后的 SHA-256，用于重跑比对），两列成对 CHECK 同空同非空。逐行追溯经「自有 ID → 来源对照 → 批次」。
   - `platform_numbering.legacy_numbers` 的「导入批次」`import_batch` 在 R-1b 改为 `migration_batch_id uuid NOT NULL`。
   - 「迁入批次」是唯一写法，其他写法在 R-1b 中改为本写法（G-MG6）。
4. **迁入单据的编号**（用户已定：编号列存原编号作展示号）：
   - 迁入单据的编号列存原编号，作展示号；不向编号服务取号、不耗计数器。原编号对照 `legacy_numbers`（带来源系统，ADR-0033）仍是权威对照。
   - 迁入标记只在事实行（第 6 条）；单据表不加迁入标记列，是否迁入经来源对照判断。
   - 单据表的编号 CHECK 写作「编号非空，或状态为草稿」（ADR-0031：草稿未取号前可以丢弃）。迁入单据的编号恒非空，这条 CHECK 对迁入只是兜底。编号列不加新格式的格式 CHECK，格式由编号服务保证。
   - 原编号与已有编号在（单据类型, 编号）唯一约束上冲突时拒收（原因代码「编号冲突」），不改写原编号。
   - **适用的对象类型**：有业务编号列的单据，即 `platform.numbering` 的单据类型——工时单（Phase 2）；合同与收入确认单（6a）；开票与回款（6b）；费用、付款与预提（6c）；分包与采购（6d）。不适用：主数据（员工、组织、客户等没有业务编号，老 ID 进来源对照）；权责事实行（没有编号，带迁入标记）；条款、修订等「父号-序号」的子级（随父单据）。
5. **迁入不产生副作用**：
   - 迁入用例**不发布领域事件**。理由：L1 的财务事实直接读 `operations.facts` 过账明细（ADR-0025 第 3 条），不依赖事件；累积快照可随时从 OLTP 重建（ADR-0025 回滚方案）。批次生效后，由运维命令对受影响的累积快照从 OLTP 全量覆盖。
   - 不发通知、不向外部系统推送、不耗编号计数器、不启动流程实例；需要的流程结论（如已审批）作为单据状态迁入。
   - `accounting.ledger` 不为迁入标记的事实生成分录：历史凭证不迁（ADR-0025 第 6 条、GL-083 迁期初余额），在途凭证由 A8 插件推完（ADR-0022 迁移方案「在途单据」）。
6. **历史期间与迁入过账通道**（用户已定：新增终态「历史期间」）：
   - `accounting.period` 新增期间状态取值「历史期间」：终态，**永不接受业务过账，只接受迁入过账通道**。每个法人在 FORCITIS one 首个业务期间之前的 (期间, 法人) 由迁入离线命令建为历史期间，写审计；历史期间不能转为其他状态，其他状态也不能转为历史期间。
   - 「历史期间」是会计类用语，按 ADR-0018 登记为提议术语，**待财务确认**；确认前代码与界面用该提议写法。
   - **核对闸门在批次上**：批次核对通过或差异经签字（第 8 条）才转为已生效；不逐期关账，不发关账事件，不触发 ADR-0025 的 L2 冻结。历史期间不生成 L2 快照；历史期间的经营存量分析来自只进 OLAP 的历史（ADR-0025 第 6 条）。
   - 迁入过账通道在 `operations.facts`：与业务过账同样校验借贷平衡、幂等键、法人一致；期间校验改为「历史期间或开放期间」；事实行带迁入标记（取值原生 / 迁入，列名与术语在实现 PR 中按 NAMING_STANDARD 定）；不发布事件（第 5 条）。
   - **迁入事实所属期间在新系统中已是业务期间时**：开放期间经迁入过账通道直接写入，同受批次闸门约束；已按业务关账的期间，按 ADR-0016 第 2 条落在当前开放期间并标注原期间——见待用户决定 U-1。
7. **装载顺序、重跑与拒收**：
   - **冻结来源快照**：批次开始时，迁入适配器把本批次范围的来源行一次读出，写入目标库中只有迁入角色可读的快照表（按批次，表名在首个迁入阶段规格中按 NAMING_STANDARD 定；表由属主在批次开始前建立）。批次只从快照读取，不再读来源。快照在批次生效且该阶段切换窗口结束后由 one-ops 删除，与 SESSION_PLAYBOOK §5「迁入读取授权」的删除时点一致。
   - 按来源键集分块提交（默认每块 1,000 行），批次记录已完成的位置。**重跑即续跑**：同一批次再次运行从断点继续，已装载的行按 `source_row_digest` 比对，相同则跳过。
   - **先迁原行，后迁冲销行**：冲销行在其原行之后装载，冲销关系在装载时建立；原行不在本批次也不在已生效批次中的冲销行拒收。
   - **引用**：批次只能引用本批次或已生效批次的行。
   - **已生效批次的行不覆盖**：同一来源行再次出现且摘要不同时拒收，按冲销重做或单据修正（ADR-0031）处理；未生效批次内的非事实行（单据、主数据）可由本批次重跑按来源键更新；事实行只追加。
   - **拒收**：不合格的行写入 `platform_integration.migration_rejects`（批次、来源对象与来源 ID、原因代码），不静默跳过。原因代码至少包括取值无法映射、必填缺失、编号冲突、原行缺失、法人不在范围（ADR-0022 的五家法人之外）。处置取值：修正后重跑 `RERUN_AFTER_FIX`、确认不迁 `EXCLUDED`（权责事实须财务签字，其他由业务管理员确认，均写说明）；批次转为已生效前每条拒收都要有处置。超范围法人一律拒收，不自动建法人。
8. **核对（迁入核对 MigrationTieOut）**：
   - 每个批次按（期间 × 法人 × 对象类型）比对来源快照与目标，**至少**比对：行数；金额合计（收入确认类同时比对含税额、不含税额、税额，ADR-0024）；来源 ID 集合摘要；按 (期间, 法人, 来源单号) 的行数与金额（ADR-0021 第 4 条第 5 款）。冲销行按冲销关系抵消后比对。
   - 结果写入 `platform_integration.migration_tie_outs`；摘要不一致时自动输出差异清单（来源有目标无、目标有来源无、金额不等的来源 ID），写入核对结果，不靠人工查找。
   - 零差异，或差异经财务签字（签字人、时间、说明），批次才转为已生效。
   - 应核对的（期间 × 法人 × 对象类型）集合以该阶段迁入规格的对象清单为准（SESSION_PLAYBOOK §14.2 M1），缺一项即不能生效（G-MG7）。
9. **可见性与失败处理**（用户已定：批次未生效不可见，失败整批冲销）：
   - 批次转为已生效之前，其迁入行对业务不可见：`operations.facts` 的读取视图（含 L1 视图）与各 BC 的查询仓储统一排除「经来源对照属于未生效批次」的行，过滤只实现在一处（每层一个共享谓词，G-MG8）；迁入角色与核对不受此过滤。
   - 批次失败：事实行经迁入过账通道整批冲销（ADR-0016 第 2 条允许的更正方式），原行保留并双向关联；批次转为已冲销，非事实行保持不可见。修正后重跑（回到进行中）或放弃（已放弃，行永久不可见）。**不按数据库时间点恢复**：生产库与 it_portal、dev 同一 RDS 实例（ADR-0025 第 2 条），时间点恢复会把共用实例上的其他库一起退回。
   - 批次生效后发现的错误：另开更正批次，在同一历史期间经迁入过账通道冲销并重过账，同样经核对生效；业务期间中的事实按 ADR-0016 第 2 条；单据按 ADR-0031。
10. **演练**：
    - 演练在 dev 进行，至少一次完整演练（含重跑续跑与失败冲销）。除 6e 外可用真实数据：演练库或 schema 只有运维角色可访问；会话只拿计数与核对结果，不看明细；该阶段核对通过后删除演练数据。
    - 6e 的敏感数据（薪酬、个税社保、银行卡）只在生产迁入，dev 演练用合成数据。员工银行卡按 ADR-0021 第 1 条属员工档案主数据，随 6e（自建 HRM）迁入，按 6e 敏感数据处理。
11. **审计与老角色迁入**：
    - 每个批次在审计中记开始、结束、生效、冲销、放弃与核对签字（操作人、批次、行数、摘要），不逐行写审计；逐行追溯靠来源对照与批次。
    - 老角色迁入（ADR-0026 第 8 项，ADR-0034 第 2 项第 6 条）同样登记一个迁入批次（对象类型为角色授予）：`account_role_grants.migration_batch_id`（ADR-0034 已定，`MIGRATION` 渠道必填）指向它。这是授予行的渠道列，不是单据或事实表，不受第 3 条「业务表不加批次列」限制；核对与可见性闸门不适用，按 ADR-0026 第 8 项的差异逐项确认与 ADR-0034 的批次回退执行。

## 影响面

- **模块**：
  - `platform.integration`：迁入适配器（含收入确认等表单的迁入适配器，只在迁入离线命令中加载）、来源对照新增两列、迁入批次、拒收与核对三张登记表、来源快照表；
  - 各目标 BC：在 `api` 中提供迁入用例（不发事件）；单据表编号 CHECK 按第 4 条；查询仓储接入可见性谓词；
  - `operations.facts`：迁入过账通道、事实行迁入标记、读取视图的可见性谓词；
  - `accounting.period`：期间状态新增「历史期间」（终态）；
  - `accounting.ledger`：不为迁入标记的事实生成分录；
  - `platform.numbering`：`legacy_numbers` 形状（ADR-0033）与批次列改名；
  - `reporting`：批次生效后的累积快照全量覆盖命令。
- **文档**：SESSION_PLAYBOOK §5「迁入读取授权」、§14.2 M3–M10（随本 ADR 采纳生效）；`NAMING_STANDARD.md` §4 登记 G-MG1–G-MG8；术语提议见 `backend/glossary/proposed/data-migration.yaml`；`proposals/EVENT_ANALYTICS_FIELDS.md` 中 `source.documentRef`「`MIGRATION` 时必填」对迁入不适用（迁入不发事件），采纳时在该文件加注。
- **运维**：迁入角色与时间窗、连接数预算、来源快照表的建立与删除、dev 演练库的访问控制（one-ops）。
- **阶段**：影响 Phase 2 起每个有迁入的阶段（含 6a–6f 的 OA 迁入）；1a 只有 `legacy_numbers` 形状与批次术语；R-1b 依赖 ADR-0033 已合入。

## 迁移方案

1. **R-1b**（ADR-0033 合入之后；首次部署前）：`legacy_numbers` 按 ADR-0033 改形状，`import_batch text` 改为 `migration_batch_id uuid NOT NULL`；`source_references` 建表时带 `migration_batch_id uuid`（可空）与 `source_row_digest`。`migration_batches` 建成之前，这两列不建外键（`legacy_numbers` 与批次表跨 schema，永不建外键；`source_references` 与批次表同 schema，批次表建成时补外键），列注释写明「迁入批次，见 ADR-0036」。批次术语统一；实现 G-MG1、G-MG6。
2. **首个迁入权责事实的阶段之前**：建迁入批次、拒收、核对三张登记表与迁入过账通道，期间状态加「历史期间」，可见性谓词；实现 G-MG2、G-MG4、G-MG5、G-MG7、G-MG8；该阶段的迁入规格按 SESSION_PLAYBOOK §14.2 评审。推迟到此时更有价值的理由：此前没有任何迁入代码与目标表，守护无对象可测；登记表的列要由首个阶段的迁入规格验证。
3. **每个迁入阶段**：按 §5 取得读取授权 → dev 演练（含重跑续跑与失败冲销）→ 冻结来源快照 → 生产迁入 → 核对、签字、生效 → 删除快照。
4. **6e 入口**：敏感数据的迁入方案（只在生产执行、可见角色）单独评审。

## 回滚方案

1. 本 ADR 未被采纳：迁入规则回到 ADR-0025 第 6 条与 GUIDING_PRINCIPLES §9a 的原文；R-1b 已做的列改名保留（只是命名）。采纳后要改变决定：另立新 ADR 取代对应条款。
2. 单个批次失败：整批冲销（第 9 条），修正后重跑或放弃；不按数据库时间点恢复（共用实例，见第 9 条）。
3. 批次生效后发现错误：更正批次冲销重做（第 9 条），不回滚数据库。
4. 「历史期间」的实现有问题：历史期间只有迁入写入，问题批次整批冲销后修正；状态取值本身不撤销（终态，已有行引用）。

## 后果

- 迁入有统一的通道、批次、拒收与核对，每个阶段只需写迁入规格，不再各自发明做法。
- 历史期间是只接受迁入的终态，不需要重开已关账期间，也不需要为历史期间逐期关账；代价是期间状态多一个取值，期间校验要区分历史期间与业务期间。
- 迁入单据保留原编号作展示号、不耗计数器，编号序列不因迁入而跳号；代价是编号列里新旧格式并存，展示与检索不能假设新格式。
- 业务表不带批次列，表结构保持干净；代价是可见性与逐行追溯要经来源对照关联，读取侧多一个谓词。
- 迁入不发事件、离线进程不加载作业与投递，副作用在进程层面隔离；代价是批次生效后要手工触发一次累积快照重建。
- 失败整批冲销而不做时间点恢复，共用实例上的其他库不受影响；代价是冲销行留在事实表中。
- 来源系统名只在集成层，领域保持中立；新增来源系统只需登记新代码。

## 备选方案（未采用）

- **历史事实只进 OLAP，不进 OLTP**：与 ADR-0025 第 6 条、GUIDING_PRINCIPLES §9a 冲突，同一项目的数据会拆在两处。
- **历史期间建为可关账的「迁入中」状态，对账后逐期关账**：每个历史期间都要走关账前置检查、发关账事件、触发 L2 冻结，而这些检查（两账同时关账、U8C 对账等）对没有总账分录的历史期间不成立；用户已定终态「历史期间」。
- **迁入时以「例外重开」写入已关账期间**：ADR-0022 第 10 条的例外须财务负责人逐次审批，批量迁入会把例外变成常规，且重开窗口内业务过账无法区分。
- **把历史事实都落到当前开放期间并标注原期间**：期间口径失真，历史期间报表无法与老系统对账（只用于 U-1 的少量情形）。
- **迁入单据按新格式发号，或编号列留空**：发号占用计数器、编号与业务时间错位；留空要求查询与展示处处经对照表，用户已定存原编号作展示号。
- **业务表加 `migration_batch_id` 或 `legacy_id` 列**：用户已定业务表不加批次列；`legacy_id` 已被 ADR-0033 否决。
- **切换窗口按数据库时间点恢复**：生产库与 it_portal、dev 共用 RDS 实例，时间点恢复会退回其他库；用户已定失败整批冲销。
- **逐行写审计**：数百万行迁入会使审计表膨胀，且逐行追溯已由批次与来源对照满足。
