## 背景

- **触发**：用户 2026-10-16/17 决定先定命名体系 ADR，覆盖全部命名面（领域、流程、bc 与包、DDL、接口与错误码、权限、配置、指标日志审计、界面与消息键、外部系统 ACL、多语言）；ADR 只放稳定原则与结构，细则（动词表、模板、各面格式、缩写）进 NAMING_STANDARD 等可演进文档，ADR 不反复改。用户原话「现在刚开始，代价是最低的时候」：长期正确的结构完整采用，迁移量只作排期（one-coordinator 转达，intent 已记）。
- **现状**（`proposals/NAMING_SYSTEM_RESEARCH.md`）：`terms.yaml` 664 条，一行同时是概念和 zh / en / snake 三个名字，改名即改概念、加语言即改结构；英文既是代码名又被当作译文；命令 46、事件 95、状态 46 条形式不一；消息键、多语言、角色码、审计动作名、触发器 / 函数 / 序列、读模型视图、测试名没有规范或守护。PostgreSQL 标识符超过 63 字节会被静默截断，`DdlNamingTest` 无长度检查（2026-10-17 核实）。
- **适配研究**（ADR-0041 决定 6）：调研第 2 节逐项列了要求、代价与收益；标准版本与链接已联网核对，结果与核不到的项见 `proposals/NAMING_ADR_0053_NOTES.md` 第 1 节，核不到的不作硬依据。
- **与已采纳 ADR 的关系**：
  - 取代 ADR-0005 决定 1「`docs/domain/00_战略设计/03-通用语言.md` 是唯一词源」：改为决定 1 第 3 条，唯一来源是 `glossary/` 下的概念与指称源；该句已因 ADR-0018 决定 1 失效但未登记取代，本 ADR 补登。「GLOSSARY.md 不另立术语」保留，GLOSSARY.md 改为投影。ADR-0005 决定 2、3 不变（决定 6 第 3 条重申 ASCII）。
  - 取代 ADR-0018 决定 1 第二句「每条术语包括：中文、英文代码名、snake_case、类别……别名（含老名，标注废弃）、禁用写法、状态（已批准 / 提议中）」：改为决定 2 的三层结构，中文、英文代码名是指称，snake_case 由代码名投影，别名与禁用写法并入指称使用状态，概念状态按决定 5。决定 1 其余句（单一来源、生成 GLOSSARY.md 等、03 冻结）不变。
  - 取代 ADR-0018 决定 2「方言」第 1 点「登记为别名类型 `dialect` 并列入禁用写法」与第 2 点「标为 `undetermined`」的登记形式：方言改为该概念下使用状态「禁用」、来源类型「方言」的指称；待定改为审批状态「提议」、来源类型「待定」的指称。方言的定义、不进代码与界面、业务 Admin 确认、已有裁定一概不变。
  - ADR-0018 决定 3「列注释的中文必须与词表中文一致」按「与 zh-CN 标准角色首选指称一致」读，属补充；决定 4、5 与后果不变。
  - 相容、不取代：ADR-0039 决定 1（外部概念只在集成层）是决定 1 第 4 条在 ACL 面的落点；ADR-0003 决定 1–2、ADR-0050 决定 13、ADR-0051 决定 2（命名空间 = 包 = schema 前缀）是 bc 与包、DDL 面的现行规则；ADR-0035（契约演进）、ADR-0038（迁移基线）约束改名在已发布接口与已应用迁移上的做法；ADR-0033 的 UUIDv7 是数据行标识，与概念 id 无关。

## 决定

1. **原则**：
   1. 概念 id 永久不变：改名、加语言、换 bc 名都不改；退役后不复用。
   2. 指称可增可改，只经决定 5 的生命周期。
   3. 词表是命名的唯一来源：各命名面上的业务名由指称投影或按决定 3 由已登记原子组合，不在别处另立名字。GLOSSARY.md、数据字典、OpenAPI 术语说明、消息目录中的业务名词都是投影。
   4. 领域名不含老系统与外部系统名：外部系统概念只在 ACL 范围（ADR-0039）的命名面出现；老名只作禁用指称供检索。
   5. 缺失即失败：命名面上出现未登记的词、禁用指称，或必需的指称缺失，守护失败并给出可粘贴的登记草稿；只有决定 6 第 5 条的运行时回退例外，且须告警。
2. **三层模型**：
   1. **概念层**：id、种类、所属 bc（`bcs.yaml`）、使用范围（领域 / 共享内核 / ACL）、定义、标准依据、与其他概念的关系（同义对照、上下位、同名异义互列；语义参照 W3C SKOS 的映射与层级关系）、概念状态。
   2. **指称层**（概念与指称分离，参照 ISO 704:2022、ISO 1087:2019）：一个概念有多条指称，每条带语言标签、角色、使用状态（首选 / 可用 / 禁用，对应 SKOS 的 prefLabel / altLabel / hiddenLabel）、审批状态与来源类型（标准用语、方言、老名、待定等）。角色参照 XBRL 标签角色，区分标准名、简称、全称、说明、代码名等；（概念, 语言, 角色）至多一条首选指称。
   3. **命名面层**：每个命名面的名字是指称的投影，规则为「取哪个语言与角色的首选指称、按什么格式变换」（如 snake_case 由代码名机械变换，不手写）。投影规则写在细则，不进词表。
3. **组合**：命令、事件、状态取值等由结构化槽位（对象、动词及细则定义的其他槽位）加受控词表按语言渲染，不做字符串翻译，渲染结果作为指称写出、可反解回槽位；不能由槽位生成的名字作为例外逐条登记并说明理由。受控动词表、状态词表、槽位与模板属细则。
4. **命名面归属**：`NAMING_STANDARD.md` 是全部命名面细则的唯一入口（CODING_STANDARD 同例），逐面写明格式、细则所在文件与守护；某面的细则另有专门文件时（如 `bcs.yaml`、`ddd/contexts.yaml`、ACL 归类），NAMING_STANDARD 只指向它。命名面至少包括下表各行；新增命名面只在 NAMING_STANDARD 加一行并挂守护，不改本 ADR。

   | 命名面 | 守护类别 |
   |---|---|
   | 概念、聚合、实体、值对象、命令、事件、状态、读模型 | 词表构建校验 + 后端词表测试 |
   | 流程、能力、价值流、阶段、业务对象、文档与卡编号 | 架构生成器校验 |
   | 命名空间、bc、Java 包 | 架构测试 + 架构生成器 |
   | schema、表、列、约束、索引、触发器、函数、序列、Flyway 文件、报表视图与 BI 列 | DDL 测试 |
   | HTTP 路径与查询参数、JSON 字段、OpenAPI schema、事件载荷键 | 契约测试 |
   | 错误码、权限码、角色码、业务编号规则代码 | 后端命名测试 |
   | 配置键、作业、锁、指标、日志字段、审计动作名 | 后端命名测试（运行时拼出者靠复审，登记盲区） |
   | BPMN 流程、决策、用户任务键 | 后端命名测试 |
   | 界面文字与消息键（PC、H5、服务端发出的文字） | 前端检查 + 服务端外发文字测试 |
   | 前端目录、文件、组件、设计令牌 | 前端 lint 与结构检查 |
   | 外部系统与 ACL 名 | 词表 ACL 归类 + 集成层隔离测试 |
   | 测试名、分支、提交 | 复审与 CI 检查 |

   无守护的面在 NAMING_STANDARD 标「待建」并写阶段，期间由复审检查。
5. **生命周期与改名**：
   1. 概念：提议 → 已批准 → 已弃用 → 已退役。提议可以先用、构建列出提醒（ADR-0018 决定 4）；弃用后新增使用由守护告警，退役后拦截，id 留档。
   2. 指称：新增或改动先登记为「提议」，批准后生效。
   3. 改名只改指称：新名登记为首选，旧名降为禁用并指向新名，概念 id 不变。各命名面的迁移列入同一变更单（SESSION_PLAYBOOK §12）；已发布接口与事件按 ADR-0035，已应用迁移按 ADR-0038。
   4. 机器可读的引用（守护数据、生成器、文档中的词条引用）用概念 id，不用名字或行号。
6. **多语言结构**：
   1. 语言标签用 BCP 47（RFC 5646、RFC 4647）。
   2. 业务源语言为 `zh-CN`：定义以中文为准，其他语言的指称是对同一概念的指称，不是对中文名的逐字翻译。
   3. 代码标识符恒为英文 ASCII：代码名是英文的「代码名」角色指称，与英文界面用的标准名分开登记，可以同词，但不互相推导。
   4. 界面与服务端发给人的文字一律经消息键取用，不在页面或代码里写死文字；消息用 Unicode CLDR 与 ICU 消息格式（复数、选择），业务名词以占位符取指称，不在消息里另写。消息语法版本与库属细则。
   5. 回退：缺某语言的指称或消息时回退到 `zh-CN` 并告警（日志或指标），不显示键名；构建时对已承诺交付的语言做完整性检查，缺失即失败。启用哪些语言由用户定，登记在细则。
7. **治理**：
   1. one-glossary 起草与初裁用语：新概念与指称、同名异义、方言判定、ACL 归类；业务用语由业务 Admin 确认，会计用语由财务确认（ADR-0018 决定 4）；文档中的用语问题按 `glossary/new_term_issue.py` 登记。
   2. one-architecture 维护 NAMING_STANDARD 的命名面清单、投影规则与守护清单；新增语言、改源语言须用户决定。
   3. 守护不通过不得合并；改断言须写理由（CLAUDE.md 第 5 条）。
8. **本 ADR 的边界**：新增词、指称、语言、命名面、动词、模板、格式、缩写规则都只改细则与词表；只有改变决定 1 的原则、决定 2 的分层、决定 6 第 2、3 条才另开 ADR。

- 词表：`glossary/terms.yaml` 结构改为概念 + 指称（`term-fields.yaml` 的 `homonyms`、`upstream_term` 并入关系，`aliases`、`forbidden` 并入指称）；`build_terms.py`、`term_rules.py`、`build_glossary.py`、`build_issues.py`、`new_term_issue.py`、`glossary/gate/` 数据。
- 规范：NAMING_STANDARD §2.1（词源仍写 `03-通用语言.md`，已过时）、§7 命名面清单改为决定 4 的归属表并补空白面；CODING_STANDARD CS-1.5、CS-2.12、CS-3.1 与 C-8 的指向；`CROSS_CUTTING_MATRIX.md:173`「多语言没有任何需求证据」按批准页第 1 题改写。
- 后端：`Glossary.java` 与 G37–G43、G48 读取层；`OutwardTextGuardTest` 与 `*Texts` 改为消息键；`DdlNamingTest` 加长度与新对象类别。
- 前端：`scripts/check-copy-glossary.mjs`、`copy-allow-list.yaml` 改为消息目录校验；页面写死的中文改为消息键。
- 已采纳 ADR 中按行号引用 `terms.yaml` 的（如 ADR-0031）在结构变更后失效，走勘误登记为概念 id。

## 迁移方案

排期由 one-coordinator 定；顺序与负责如下，细目见 NOTES 第 2 节。

1. 本 ADR 采纳后：NAMING_STANDARD 重组为命名面归属表并补各面细则（one-architecture）。
2. 词表一次切换（one-glossary，按批准页第 2 题）：脚本把现有条目拆成概念 + 指称，id 沿用；同批输出旧投影（zh、en、snake、aliases、forbidden）与新投影的逐项比对，不等即失败；读取方同批切换，旧字段只留一个兼容视图，读取方全部迁完后删除。
3. 受控动词表与状态词表登记，名词补登（门禁报告未登记对象 60、聚合 78），再按批准页第 4 题处理存量命令 46、事件 95、状态 46 与未登记名 1,143 条。
4. 消息键：前端消息目录与服务端消息键先立结构、只放 `zh-CN`，新页面起即用；存量页面随下一次改动迁。
5. 补守护：63 字节、触发器 / 函数 / 序列、角色码、审计动作名、读模型视图、测试名、ACL 名称约定、日志键。

## 回滚方案

本 ADR 只改文档、词表结构、生成器与守护，不改业务数据。词表切换前保留旧结构文件；切换后新旧投影逐项相等，回滚即由新结构重新生成旧字段（兼容视图）并把读取方切回。已执行的改名按决定 5 是指称变更，回滚只需把首选与禁用对调，概念 id 与引用不受影响。

## 需同步修改的守护规则

- `glossary/term_rules.py`、`build_terms.py`：校验概念 id 唯一且不复用；（概念, 语言, 角色）至多一条首选指称；同 bc 内首选名不重复；禁用指称不与任何首选冲突；组合名可反解回槽位，例外须登记。
- 后端 `Glossary.java` 与 GlossaryTest（G37–G42）、`NamingSurfaceTest`（G43–G48）：改读指称投影。
- `DdlNamingTest`：标识符不超过 63 字节；覆盖触发器、函数、序列、视图。
- `OutwardTextGuardTest` 与前端 `check-copy-glossary.mjs`：改为消息目录校验（键已登记、占位符取指称、无写死文字）。
- 新增：角色码、审计动作名、测试名、ACL 名称约定的守护；每面待建守护在 NAMING_STANDARD 登记阶段。

## 后果

- 改名不再动概念与引用；加语言只加指称与消息，不改结构；英文代码名与英文界面名不再混用。
- 一次性代价：词表与约 10 个读取方同批切换、前端文字检查重写、存量命令与事件改名（影响已有代码与事件载荷，按 ADR-0035 处理）；越晚越贵。
- 词表源文件变长、评审 diff 变多；靠生成器投影与比对兜底。
- 未定事项随批准页：多语言范围、词表切换方式、源语言与代码名关系、存量迁移方式（NOTES 第 3 节）；决定 2 第 2 条与决定 6 第 3 条按推荐写成，用户选其他项时批准前改稿。

## 备选方案（未采用）

- 维持一行即概念加三个名字（加语言或改名都要改结构，英文代码名与译文混用）。
- 分阶段迁移词表、新旧结构长期并存（两套读取逻辑，用户要求按长期正确一次采用）。
- 以 TBX 文件作日常编辑源（评审 diff 不可读；TBX 只作交换格式，见 NOTES）。
- 命令、事件名逐条人工登记、不立组合规则（存量已形式不一）。
