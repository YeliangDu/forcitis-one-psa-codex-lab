# ADR-0023：经营分析纳入现代化：经营子域、reporting 与语义层、BI 重构

- **状态**：已采纳（用户 2026-10-14：「批准 ADR-0023」；待决项 Q1–Q12 已决定，见 BI_SCOPE.md §6.1。方向为用户决定，经 psa-coordinator 转达：「BI 要重构，不满足经营管理需要。经营分析纳入现代化：经营子域 4 个 BC、reporting 与语义层纳入，BI 重构同步规划。暂停 BI 迁移会话在老数据源上的新建模，现有报表照常运行。」；覆盖先前「BI 工具和看板由 BI 项目负责」的边界；L2 对总账的适用已被 ADR-0022 取代；第 2 条 L1 采集限制对一次性历史装载的适用已被 ADR-0025 取代）（决定 1 中经营子域 4 个 BC 的个数与 `operations.budgeting` 单列及「占用额度并拦截单据的预算归 budgeting（划分待用户确认）」一句的落点、决定 3 中 `operations.budgeting` 作为术语登记对象的模块名已被 ADR-0051 取代）（决定 5、6（部分）已被 ADR-0054 取代）
- **日期**：2026-10-14

## 背景

- 先前边界（用户原话）：「现代化负责 reporting 数据层、KPI 语义层（按 OAT）和 BI 过渡不中断；BI 工具和看板由 BI 项目负责。」本次改为经营分析整体纳入现代化。
- 现状（BI_SCOPE.md §1，只读盘点）：
  - 老 BI（Express + Vue，约 133 页，近 90 天 171 名用户、22.3 万次调用、1.02 万次导出）经 BI 库 118 个 `T_FST_*` 视图跨库读 A8 与老 PSA，并直接写 A8 表 8 处；
  - 新经营分析（BI-olap `analytics/`，PG + 语义层 + React，11 个事实、64 个指标）于 2026-10-10 至 10-11 建成，未上线；
  - 两者都不读 U8C。
- 经营管理需要满足不了的证据（BI_SCOPE.md §1.5）：
  - 应收四套算法、两种逾期定义（FORCITIS/BI#59）；收入三处来源无统一定义；利用率三套算法且硬编码；
  - 没有期间快照，没有毛利与权责口径成本，经营结果无法与财务勾稽，计划与实际脱节；
  - BI 自己在写合同条款、开票、商机等业务数据；
  - 指标用方言且不满足 OAT 的声明要求。
- 经营子域 4 个 BC（`GLOSSARY.md` §1）中，`operations.facts`、`operations.policy` 已在主干（ADR-0016），`operations.planning`、`operations.budgeting` 原为「蓝图未覆盖」、OA 盘点中归「6f 视情况」；`terms.yaml` 中这两个 BC 与 `reporting` 均为 0 条。
- OAT 正本：仓库中的 `08-FORCITIS Operating Accounting Taxonomy.md` 只是槽位文件，245 条原语的机器主数据在 `ddd-theory` 研究仓库。
- 总账三大报表由 psa-gl-scope 起草（ADR-0022，新增 `accounting.reporting`）。

## 决定

1. **范围**：经营子域 4 个 BC（`operations.facts`、`operations.policy`、`operations.planning`、`operations.budgeting`）与 `reporting`（蓝图 BC-15，只读分析模块）全部纳入现代化。`operations.planning`、`operations.budgeting` 由「6f 视情况」改为建设范围：目标值（承诺目标、预算目标、销售承诺、滚动预测）归 planning；占用额度、拦截单据的预算归 budgeting（划分待用户确认）。
2. **分层**：
   - L0 记录系统：各 BC 与 `operations.facts` 过账管道，唯一事实来源，分析侧不回写。
   - L1 `reporting` 集成层：一致性维度 + 一业务过程一事实表；由领域事件增量构建，不再从 A8、老 PSA 库采集；维度按生效期保留历史。
   - L2 期间快照：由 `accounting.period` 关账事件按 (期间, 法人) 生成并冻结，更正走重述新版本。
   - L3 语义层：**指标定义在 `operations.policy`**（口径版本、指标定义，按版本生效、审批留痕），**执行在 `reporting`**（先授权、后聚合）。
   - L4 消费：页面、导出、BI 工具、AI 只经语义层或 L1 / L2 只读视图取数，不自带指标算法。
3. **口径按 OAT 声明**：每个指标必须声明 OAT 原语（或登记的经营扩展原语）、`terms.yaml` 词条、单位、期间类型（存量 / 流量）、加总规则、事实归属 BC、核算基础（权责 / 收付 / 经营）、含税口径、口径版本。构建时守护（扩展 ADR-0018 的 G37–G39）：缺声明、用未登记词或方言即失败。`reporting`、`operations.planning`、`operations.budgeting` 的术语与 OAT 有而词表无的指标按 ADR-0018 起草登记（清单见 BI_SCOPE.md §3.3）。
4. **与总账三大报表不重复建设**（与 ADR-0022 的 `accounting.reporting` 分工）：
   - 报表行项目只在 `accounting.reporting` 计算，语义层以引用方式使用其已关账期间结果，不重算；
   - 经营指标（净服务收入、贡献毛利、利用率、DSO、剩余履约义务、商机管道等）只在 `reporting` 与 `operations.policy`；
   - 期间、法人、项目坐标、客户、供应商、人员维度两边共用同一份主数据；
   - 经营口径与法定口径的差异由 `operations.policy` 的口径差异清单逐期勾稽，作为关账前置检查之一。
5. **BI 过渡不中断**（GUIDING_PRINCIPLES §8）：每个迁移阶段切换前，受影响的每个 `T_FST_*` 对象都要有形状一致的过渡来源并通过对账，老 BI 代码在过渡期不改。
   - 老 PSA 自有表：靠反向同步保持，视图不动。
   - A8 表单来源（6a–6f 一次切换、不设双源期）：由 `reporting` 生成同形状的过渡视图，回填 BI 库的镜像表（用户决定 Q7：「过渡镜像回填 BI 库」）。
   - 不得写回 A8。
   - BI 自身对业务数据的写入，随对应阶段迁入相应 BC 的界面后停用。
   - 各对象组的切换时点见 BI_SCOPE.md §4.3。
6. **BI 重构同步规划**：
   - 工具四个选项（用户决定 Q1：「先不定，由 R0 出对比后再定」）：保留老 BI 只换数据源、以新经营分析为基础、并入 FORCITIS one、引入 BI 工具，或组合（BI_SCOPE.md §5.1）。
   - 阶段草案 R0–R6（编号为占位，由 psa-coordinator 统一）：R0 口径与语言基线（可与 Phase 1a 并行）→ R1 reporting 骨架与语义层（Phase 1a 出口后）→ R2 PSA 自有事实（随 1b、2、3）→ R3 合同、收入、开票、回款、费用、付款（过渡镜像就绪是 6a–6c 切换的入口）→ R4 经营计划与预算 → R5 财务勾稽（G1 后）→ R6 全面替换、老 BI 下线（Phase 5 的 BI 部分）。

## 后果

- 新经营分析在老数据源上的新建模暂停；其 20 份口径 ADR、11 份对账证据、权限模型与规模测试作为 R0、R1、R3 的输入。代码冻结、只作设计输入，未合并 PR #50–#58 不合入（用户决定 Q3）。
- 6a、6b、6c 的入口各增加一条：受影响的 `T_FST_*` 过渡来源已就绪并对账（Proposed revision，由 psa-coordinator 并入 brief）。
- brief Phase 5 中的 BI 部分改由 R6 承接；Phase 5 出口「BI 查询清单在 `reporting` 上结果一致」保留。
- 应收等指标改为单一口径后，老页面读到的数会变，须在切换前由财务确认（BI_SCOPE.md §3.3 的六项口径裁决）。
- BI 仓库调研文档记载的「BI 整体替换：2026-12-31」与本路线不相容，已被本决定取代（用户决定 Q2），日期在统一编排时重估。
- Q1–Q12 的用户决定、待财务 F1–F5 与待业务 B1–B5 见 BI_SCOPE.md §6.1。

## 备选方案（未采用）

现代化只做数据层、BI 工具和看板留给 BI 项目（用户已改变边界；且看板自带算法会继续造成口径分裂）；新经营分析继续从 A8、老 PSA 采集并先上线（在老数据源上新建模已由用户暂停，6a–6f 切换后源头不再增长）；在 `reporting` 中重算三大报表（与 `accounting.reporting` 重复建设、口径不一）；过渡期写回 A8 让老视图继续可用（违反 ADR-0021）
