# ADR-0021：OA 业务流程迁入新系统的边界与顺序：权责事实全部在新系统

- **状态**：已采纳（用户 2026-10-14：「采纳；6a–6c 并入 Phase 4 前 (Recommended)」；起因：「现代化后，我想完善其他子域和 BC，想把 OA 上的业务过程迁到新系统，应该怎么做？」；约束：「确保权责业务事实全部在新系统」）（决定 3 中「客商主档随 6b / 6c 先行」的先后表述、后果「新建 BC」一条中 `organization.incentive` 单列的表述与新增人事及假勤 BC 的落点已被 ADR-0051 取代，先后按 ADR-0051 决定 9 的依赖次序读）（决定 2 至 4、后果（部分）已被 ADR-0054 取代）（决定 1、后果（部分）已被 ADR-0055 取代）
- **日期**：2026-10-14

## 背景

- 致远 A8 是 PSA 之外第二个、也是更大的权责事实来源（生产只读盘点，OA_PROCESS_INVENTORY.md）：近 180 天 29,056 个模板实例；39 个在用模板产生、变更或审批权责事实（合同、收入确认、开票、回款、费用、付款、分包、薪酬）。
- A8 绕过 PSA 直接给 U8C 生成凭证：凭证插件按 16 种表单累计 402,285 行、对应 32,339 张单据，近 180 天 99,179 行；A8 销项开票插件累计开具 5,956 张发票，近 180 天 1,143 张。
- 合同与付款条款的唯一来源在 A8，PSA 经 14 个跨库视图和 8 处 Java 直查读取，并经 9 个作业 / 脚本写回 A8；其中 26 处承载权责事实。
- U8C 自身也产生凭证：总账手工、固定资产、出纳（2026 年两套账手工凭证 171 + 244 张）。
- 用户 2026-10-14：「确保权责业务事实全部在新系统」（GUIDING_PRINCIPLES §9a）。

## 决定

1. **边界（分类规则）**：
   - **迁入**：凡产生、变更或审批权责发生制业务事实的 OA 流程——合同签订与变更、交付与收入确认、工时与成本、费用、开票与应收、回款、分包与应付、付款——一律迁入，不得归「视情况」。用户 2026-10-14 明确纳入：非项目采购、员工借还款、合伙人注资退回（「都算，都进新系统」）；薪酬与整个人力资源管理（「新系统要自建整个hrm，算薪要迁入」）。PSA 已有同名能力的 A8 流程（项目预算、报价）也迁入，消除双入口。
   - **主数据全部进新系统**（用户 2026-10-14：「主数据全部进新系统」）：客户、集团、联系人、供应商（客商）主档，OA→U8C 部门映射等口径对照，员工档案与银行卡。员工银行卡是敏感个人信息：加密存储、最小授权、访问留痕。
   - **视情况**：只引用上述事实、不产生事实的流程（商机、线索、拜访、经营目标、交付质量），按 BC 建设节奏决定。
   - **留在 OA**：纯行政（用印、合同借阅、IT 需求与 IT 资产领用 / 调拨 / 报修 / 报废 / 内购、员工活动）。
   - **已停用**：只迁历史（只读），在途实例排空或逐单判定。
2. **记录系统**：上述权责事实与主数据的记录系统一律是 FORCITIS one，权责事实经 `operations.facts` 单一过账管道（ADR-0016）。A8 不得作为这些事实的产生地或存放地；跨库读取 A8 得到的此类数据改为新系统自有事实；U8C 只接收新系统推送的结果，不反向产生权责事实（U8C 手工、出纳类凭证由财务逐类判定，含业务事实的类别改为在新系统发起）。A8 交互只在 `platform.integration` 防腐层，单向所有权；PSA 写入 A8 的权责数据通道在对应阶段删除。**不设双源期**（用户 2026-10-14 H-1：「迁入新系统，不设双源期」）：每类事实在会计期间边界一次切换，切换日起只在新系统发起，A8 同类数据不再作为新系统的输入。
3. **顺序**（阶段草案见 OA_PROCESS_INVENTORY.md §6，编号保留 6x）：6a 合同与收入（行级强耦合，同一阶段切换）→ 6b 开票与收款（含替代 A8 销项开票插件）→ 6c 费用、付款与预提（含新建「应付与付款」BC）→ 6d 分包与采购（含非项目采购）→ 6e 自建 HRM 与薪酬（组织、人事、假勤、算薪、奖金；组织主数据的源头从 A8 转到新系统）→ 6f 客户经营与经营计划（视情况；客商主档随 6b / 6c 先行）。**6a、6b、6c 是 Phase 4 出口的前置条件**（用户：「6a–6c 并入 Phase 4 前」）。每个流程走同一条流水线：盘点 → 归属 BC → 用语登记（A8 叫法先登记为待确认，ADR-0018）→ 规则抽取与评审（审批路由写成 DMN）→ BC 设计（触账走过账管道；缺界面先补设计正本，ADR-0013）→ 历史只读迁入、在途排空 → 期间边界切换 → A8 模板与凭证插件对应表单停用 → 无遗留检查。
4. **每个阶段出口须证明本阶段权责事实无遗留**，检查方法（只读查询模板 `oa_residual_check.sql`）：
   1. 事实目录：本阶段涉及的事实类型取自「权责事实完整性矩阵」（OA_PROCESS_INVENTORY.md §4），逐行写明目标 BC 与过账类型；矩阵中本阶段各行的「产生地」「存放地」都已是 FORCITIS one；
   2. 源头关停：本阶段 A8 模板已停用；切换日后新实例为 0；在途实例为 0 或逐单有关闭结论；
   3. 旁路关停：A8 凭证插件（`LEXMISCIF_VOUCHER`）对本阶段表单在切换日后无新凭证；涉及开票的阶段，A8 销项开票插件无新发票；
   4. 跨库清零：老库中引用 `a8_db` 的视图、作业、脚本只剩组织主数据类（6e 后为零）；新系统中除 `platform.integration` 外没有任何模块持有 A8 连接或引用 A8 表名（ArchUnit + 词表禁用写法）；
   5. 存量对账：历史事实迁入后带来源标记，按 (期间, 法人, 来源单号) 与 A8 档案比对行数与金额，差异为 0 或经财务签字；
   6. U8C 对账：切换日后 U8C 外部接口凭证逐张可追溯到新系统过账序号或仍在迁移中的 A8 表单；手工、出纳类凭证按财务判定的类别复核，业务类权责事实为 0。
   任一项不满足，阶段出口不成立。

## 后果

- brief Phase 4 出口增加「6a、6b、6c 出口满足」（Proposed revision）；ADR-0016 后果中「A8 产值只读接入」改为迁入（修订提议）。
- 新建 BC：「应付与付款」（用户 2026-10-14：「新建「应付与付款」BC」；模块路径与蓝图编号由总账范围评估 psa-gl-scope 统一）；`organization.payroll`、`organization.incentive` 由「蓝图未覆盖」转为 6e 建设范围，并新增人事、假勤 BC（自建 HRM，范围草案见 OA_PROCESS_INVENTORY.md §6.3）。过账类型补「员工往来、应付、付款、预提、减值、分包成本、职工薪酬、权益（注资退回）」。
- 组织主数据：Phase 1a 至 6e 之前仍以 A8 为源（phase1a/COLUMN_OWNERSHIP.md 不变）；6e 切换后由新系统 HRM 为源，A8 改为接收方（同步方向反转，经 `platform.integration`）。
- 每个迁入阶段都要补抽 A8 表单规则（含 A8 表单触发器的隐式回写），并新增逐列所有权矩阵覆盖 A8 档案表。
- 税务数电平台对接从 A8 插件迁到 `platform.integration`；科目映射 DMN 须与 A8 的科目、部门、银行对照表逐行对齐，对照表本身迁入新系统。
- 留在 OA 的只剩行政流程；致远 SSO 保留。

## 备选方案（未采用）

按流程逐个评估「视情况」（会让产生权责事实的流程留在 OA，违反 §9a）；先迁收入确认单、合同留在 A8（条款与收入行级耦合，形成两个写入方）；保留 A8 凭证插件、只让新系统接管 PSA 自己的推送（U8C 仍有旁路，期间闸门与冲销规则管不到）；设 A8 只读接入的双源期（用户决定不设）；薪酬留在 A8 或外接薪酬系统（用户决定自建 HRM）
