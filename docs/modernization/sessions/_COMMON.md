## §11 总调度会话

职责第1条：开场：读 STATUS.md、SESSION_LOG.md 最后几条、brief 待决项；ListAgents 查看各工作会话的状态
职责第2条：派发：按会话画像（§2.1 第 16 条）为下一个工作单元写好「派工单」（见下），发给对应会话；工作会话尚不存在时，先起草其画像，再请用户按会话名…
职责第3条：接收与核对：工作会话结束前（完成、部分完成或阻塞）都向 one-coordinator 报告（§4 第 7 步）；调度会话核对产出（读分支上的文件…
职责第4条：衔接：一个单元的改动影响其他单元时（例如 platform.identity 的 api 变化），通知受影响的会话
职责第5条：汇总给用户：把所有需要用户决定的事（审批、口径、推送 / PR、部署、生产变更）汇总成一张清单，一次问清；用户的回答以原话转达
职责第6条：收尾：每次调度会话结束前按 §4 收尾协议记日志
消息约定·少叫醒、少重复第1条：只在对方需要做事或做决定时发消息；入队、合并、关闭等状态以 GitHub 上的 PR 状态为准，不发通知
消息约定·少叫醒、少重复第2条：不回纯确认：收到指令直接做，做完报结果；同意不回
消息约定·少叫醒、少重复第3条：一次说完：同一会话的多件事合成一条；回复一到三行，不复述来信；长内容写进文件，消息只给路径
消息约定·少叫醒、少重复第4条：待用户答复的事项只由调度会话汇总，有新增或变化时列一次；各会话回复里不附待办提醒
消息约定·少叫醒、少重复第5条：子会话默认不开完成通知（wake_when_done 不设），确需等其结果时才开
消息约定·少叫醒、少重复第6条：给用户的回复先写结论；转述其他会话的报告只取用户需要知道或决定的部分
消息约定·少叫醒、少重复第7条：外发被限流时不停等：app 在用户久未发言时会暂停会话的外发消息
