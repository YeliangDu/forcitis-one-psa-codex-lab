方法一句话

TOGAF 管走的顺序，DDD 管切的边界，事件风暴、BPMN、DMN 管动的方式，DAMA、OLTP、OLAP 管数据与度量。接缝消不掉，但每条接缝定一条衔接规则、一个能校验的交接物，串成闭环：

目标 → 能力 → 价值流阶段 → 子域 / BC → 聚合 · 命令 · 事件 → 流程 / 决策 → 数据对象 → 表 → 事实 → 指标 → KPI → 回到目标

八步（从愿景到代码）

  1. 愿景与原则：目标、可度量的 KPI。你定。
  2. 能力与价值流：企业「做什么」；价值流的阶段由哪些能力支撑。你确认。
  3. 战略设计：按战略差异化分核心、支撑、通用子域，划 BC 与上下文关系。你定。
  4. 行为建模：每个价值流阶段做事件风暴，得出命令、事件、聚合；规则分类落位。我提议、评审把关。
  5. 数据设计：由聚合导出数据对象、类别、负责 BC；一个 BC 一个 schema。评审把关。
  6. 分析设计：事实取领域事件，维度取主数据，指标挂回 KPI。你定口径。
  7. 迁移规划：差距分析，排过渡架构（阶段）。你批准。
  8. 实施与治理：先登记再写代码，CI 校验代码与施工图一致，结构变化写 ADR。

六条接缝（点开看规则）

1 能力 ↔ 子域 / BC

子域分类看能力的战略差异化，不看老系统模块；每个叶子能力只归一个 BC。

2 价值流 ↔ 事件风暴 ↔ BPMN

价值流阶段的边界就是关键事件；只有人工步骤（任务、超时、退回）画成 BPMN，自动反应写成事件策略。

3 业务规则 ↔ DMN ↔ 聚合

规则分四类：不变式放聚合，判定（路由、资格、级别）放 DMN，流转放 BPMN，计算放值对象或领域服务。

4 聚合 ↔ 数据对象 ↔ 表

数据对象 = 聚合的状态 + 它发出的事件；主数据由拥有聚合的 BC 负责，跨 BC 只按 ID 引用。

5 交易库 ↔ 分析库

事实来自领域事件或过账明细，不在交易表上算分析；一致维度就是各 BC 的主数据；指标挂回 KPI 与目标。

6 架构 ↔ 代码

BC = 模块 = schema；上下文映射 = 模块依赖图；结构变化先改施工图再改代码，CI 校验。
