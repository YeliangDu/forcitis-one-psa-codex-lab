## 题面

**Q-04 收入确认要不要有自己的状态？**

背景（给用户看的说明，约 200 字）：
现行 ADR-0016 决定 4 写收入确认是「无状态规则层」。但后来已批准的 ADR-0047 又要求收入确认记下证据类型、认可日，历史行迁入时记「历史迁入」，并照常走审批——这些都要有一条存下来的收入确认记录。所以纯粹「什么都不存」已经和已批准的决定对不上。
真正要选的是：这条记录是**放在「开票与收入额度」里的一行**（规则不变，只追加记录，额度、审批中占用、冲销都在同一处），还是**单独成为一张有审批状态的单据**（像开票申请那样）。
调研的四个成熟产品（Deltek、Oracle、SAP、Microsoft）都保存确认结果，但都没有给它配重型审批状态机。

## 选项

| 选项 | 一句话 | 代价 | 依赖前提 |
|---|---|---|---|
| A 维持纯规则层，只留过账记录 | 收入确认不另存记录，结果只在过账事实里 | 与已批准的 ADR-0047 三处（证据类型列、历史迁入、审批）冲突，要回头改 ADR-0047；冲销、成本配对、结项收入覆盖检查都只能从会计分录反查 | 无 |
| B 有状态对象（独立单据） | 收入确认像开票申请一样是单独的单据：草稿 → 审批中 → 已确认 / 驳回，冲销 | 须另立 ADR 修订 ADR-0016 决定 4；额度要跨单据先占后写，需要定时清理孤儿占用；历史迁入要给状态机开一个「迁入即已确认」的口子 | 无 |
| C 规则层加确认记录（放在额度里的一行） | 规则不变；每次确认、冲销、迁入都追加一行记录，放在「开票与收入额度」里，审批状态交审批平台 | 须由 one-architecture 判定「行上有占用中 / 已确认 / 已释放」是否仍算「无状态规则层」，判为不算就要走 B 的 ADR；ADR-0047「证据关联到收入确认」一句要细化为「关联到交付物」 | 设计服务按时点确认（A1）成立；审计师接受审批履历留在审批平台；单份合同的确认行不会多到拖慢（待取证） |
| 暂不定 | 不预设 | 6a 中 AGG-44 确认行字段、成本配对、结项收入覆盖检查排在最后做 | — |

## 推荐与理由（写在说明里，不预选）

推荐 **C**，理由：
1. A 与已批准的 ADR-0047 有三处字面冲突，选 A 反而要再改一份已批准的 ADR。
2. B 带来的好处（可追溯、可冲销引用、迁入不伪造过程、规则版本固定）C 都有，靠的是「有一条带编号、只追加的记录」，不靠独立单据；B 多出跨单据占额度和修订 ADR-0016 的成本。
3. 四个成熟产品都存确认结果、都用冲销或差额更正，没有一个给确认结果配审批状态机；审批在别处。
4. 期满待办（ADR-0049 第 4 条）研究结论是不依赖这一题：按提交轮次在收入侧建投影、提醒交平台待办，A、C 通用，可以先做。

**会让推荐翻转的情况**（任一出现改选 B）：
- 财务认定有服务按时段确认、须每月估计进度（研究报告 W-1）；
- 审计师要求每笔收入确认自带完整审批履历（W-6）；
- one-architecture 判定 C 的行状态已构成生命周期，与 ADR-0016 决定 4 不符；
- 取证显示单份合同的确认行很多、开票与收入频繁同时写同一合同（E1、E9）。
