# Q-04 确认页草稿：收入确认是规则层，还是有状态对象

依据：同目录 `Q04_REVENUE_OBJECT_RESEARCH.md`（已按 `Q04_REVIEW.md` 修订，待 sonnet 复核）。格式对齐 `architecture/decision-page/PENDING.json`。**不预选**：所有选项 `rec`、`sug` 均为 false，页面不设默认选中；推荐只写在说明文字里。
题目只问用户能判断的部分；会计口径（时段履约、差错与估计变更、审计留痕要求等）在研究报告第 7 节「问财务」W-1 至 W-8，不在本页问。

## 题面

**Q-04 收入确认要不要有自己的状态？**

背景（给用户看的说明，约 200 字）：
现行 ADR-0016 决定 4 写收入确认是「无状态规则层」。但后来已批准的 ADR-0047 又要求收入确认记下证据类型、认可日，历史行迁入时记「历史迁入」，并照常走审批——这些都要有一条存下来的收入确认记录。所以纯粹「什么都不存」已经和已批准的决定对不上。
真正要选的是：这条记录放在哪、自己带不带可改的状态。四项：A 只留过账；C 在「开票与收入额度」里存不可改的确认事实，审批中的占用单独记；轻量 B 在额度里放一行有状态的确认行；独立聚合 B 单独成一张有审批状态的单据（像开票申请那样）。
调研的成熟产品（Deltek、Oracle、SAP、Microsoft）都保存确认结果，但都没有给它配重型审批状态机；SAP S/4HANA EBRR（事件驱动收入确认）最接近 A。可比性有限：这些产品的场景（主要是按履约进度分期确认）与本系统不同；产品文档为官方页摘要，由子代理检索、未复读，Oracle EBS 为二手。

## 选项

| 选项 | 一句话 | 代价 | 依赖前提 |
|---|---|---|---|
| A 纯规则层，只留过账记录 | 收入确认不另存记录，结果只在过账事实里 | 与已批准 ADR-0047 三处（证据类型列、历史迁入、审批）冲突，要回头改 ADR-0047；过账事实须携带业务坐标（履约义务、付款条件项、证据引用），聚合稿 AGG-77 现只带来源单据引用，要加字段；冲销、成本配对、结项收入覆盖检查都只能从会计分录反查 | 过账事实能携带业务坐标 |
| C 不可变事实版 | AGG-44 内存只追加、不可改的确认事实（证据引用、证据类型、认可日、规则与配置版本、金额）；审批中另有占用行，沿用额度占用模式，只记金额、审批实例 ID、占用状态（占用中 / 已转实 / 已释放）；审批通过时一个事务内二次校验额度、追加确认事实、占用转实 | 是对 ADR-0016 决定 4 的**细化**（规则无状态，状态只在占用行、与额度占用同生共死），选 C 须在 ADR-0016 状态行写明「细化」；确认事实与过账事实是两个聚合，不能同事务，须 outbox＋对账；确认事实表要加数据库禁止 UPDATE / DELETE 的触发器与 ArchUnit 守护；ADR-0047 U-1 (a) 要细化字面（见下） | 设计服务按时点确认（A1）成立；审计师接受审批履历留在审批平台；单份合同的确认事实与占用行不会多到拖慢（待取证） |
| 轻量 B：AGG-44 内有状态的确认行 | 额度里放一行确认行，行自己带状态（占用中 / 已确认 / 已释放 / 已冲销），可改状态；不另立聚合 | 确认行自带可改状态，与 ADR-0016 决定 4 的张力最大，倾向要修订该决定（须 one-architecture 判定）；确认记录可改，须另靠状态转换只追加实现来保证可追溯；ADR-0047 U-1 (a) 同样要细化，或加「待开放」态 | 同 C |
| 独立聚合 B | 收入确认像开票申请一样是单独的单据：草稿 → 审批中 → 已确认 / 驳回，冲销 | 须另立 ADR 修订 ADR-0016 决定 4；额度要跨聚合先占后写，需要定时清理孤儿占用；历史迁入要给状态机开一个「迁入即已确认」的口子；审计师长期不认可时大量待开放对象挂起 | 无 |
| 暂不定 | 不预设 | 阻断施工方案 W3 中 B-08 开票与收入的迁入设计（`CONSTRUCTION_PLAN_DRAFT.md:178`；B-08 迁入含 19,869 行收入确认与 434 行退回，`:229`）；6a 中 AGG-44 确认行字段、成本配对、结项收入覆盖检查排在最后做 | — |

## 对比开票（为什么 C 把申请寄在占用行上）

开票是「开票申请（AGG-45）→ 发票（AGG-46）」；收入确认是「收入确认申请（占用＋审批）→ 确认事实」。两者对称：都是先申请、审批，通过后才产生不可改的事实。唯一不对称是收入确认的申请寄在 AGG-44 的占用行上，而不是独立聚合。理由：审批通过时要在一个事务内校验额度、追加确认事实、占用转实，放在同一聚合内就没有跨聚合的先占后写，也没有孤儿占用。

## 须让你知情（选哪项都会碰到）

1. **ADR-0047 U-1 (a) 要细化字面。** U-1 (a) 写认可前各类证据「可登记、关联到收入确认、封存」，那时收入确认（确认事实）还不存在。拟细化为：证据先关联交付物提交轮次 / AGG-110，确认事实形成时再引用该证据。**U-1 (a) 是你 2026-10-16 未改动、按预选提交的条目（defaulted，视为同意）**，改字面须让你知情；选 B 的独立聚合可以不细化，但要接受待开放对象长期挂起。
2. **聚合稿 AGG-44 要改。** 现稿把「视为同意」的判定放在收入确认行上，这与 ADR-0049 的前提不符（认定要先于收入确认成立）。拟改为：期满记录证据（AGG-38），或 AGG-44 内单独的认定事实。
3. **ADR-0049 第 4 条要改述。** 第 4 条（期满待办载体）现写「随 Q20 交用户」。研究结论是它不依赖本题：按提交轮次在收入侧建投影、提醒交平台待办，A、B、C 通用。拟改述为「可先行，须用户确认」，即你确认后即可先做。
4. **冲击清单补一项。** ADR-0047 U-2 (a) 写「收入确认审批中由财务复核」，审批对象是什么也随本题定（C：占用行上的审批实例；独立聚合 B：该单据）。

## 推荐与理由（写在说明里，不预选）

倾向 **C 不可变事实版**，理由：
1. A 与已批准的 ADR-0047 有三处字面冲突，选 A 反而要再改一份已批准的 ADR，还要给过账事实加业务坐标。
2. 独立聚合 B 带来的好处（可追溯、可冲销引用、迁入不伪造过程、规则版本固定）C 都有，靠的是「有一条带编号、不可改的确认事实」，不靠独立单据；独立聚合 B 多出跨聚合占额度和修订 ADR-0016 的成本。
3. 轻量 B 的确认行自己可改状态，既要修订决定 4，又失去「事实不可改」的保证；C 把可改的部分限制在占用行，状态与额度同生共死。
4. 成熟产品都存确认结果、都用冲销或差额更正，没有一个给确认结果配审批状态机；审批在别处。
5. 选轻量 B 再日后提升为聚合根，提升时要重构表与仓储并修订决定 4，已落库的确认数据要迁移；W3（2027-01-28 至 2027-07-22）含 B-08 与全部历史收入确认的迁入，提升窗口是 W3 迁入演练之前，之后代价陡增（研究报告第 9 节）。C 的确认事实表可原样保留，日后提升代价更低。

**会让推荐翻转的情况**（任一出现改选轻量 B 或独立聚合 B）：
- 财务认定有服务按时段确认、须每月估计进度（研究报告 W-1）；
- 审计师要求每笔收入确认自带完整审批履历（W-6）；
- 取证显示单份合同的确认行很多、开票与收入频繁同时写同一合同（E1、E9）；
- one-architecture 日后认定占用行状态已构成收入确认的生命周期（目前已判定为细化）。
