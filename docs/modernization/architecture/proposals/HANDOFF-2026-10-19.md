## 4. 本轮已定的判定（下一位不要再讨论）

1. **对象 ≠ 表 ≠ 聚合**。检查口径是「每个聚合 ≥1 张表」，**不是**「每个对象一张表」；允许一对象多表，禁止一表跨两聚合的对象。
2. **业务对象是锚**：阶段门、流程编排、事实认定、约束作用点全部指向 09；状态是对象的字段，不是独立节点。
3. **一级对象 = 依附图源点**（BIZBOK p.194–198）；数量可证但不可"客观"，必须先定判据与候选集。
4. **流程只登记 L2/L3（约 60–80 条）**；200 条里其余是 L4/L5 活动，画进流程图，不进登记表。

## 7. 踩过的坑（省下一位的时间）

1. **不要用 `qlmanage` 预览 SVG**——会补成正方形并裁切，看着像"节点被裁"，其实是工具问题。用 Chrome headless。
2. **SVG 绘制顺序**：方框 → 连线 → **标签最后**。反过来标签会被方框盖住（已踩）。
3. **列间隙 <60px 放不下中文标签**，必然压框；本图列间隙 A-B 40 / B-C 110 / C-D 110。
4. **OCR 双引擎**：RapidOCR 中文表格更准，Vision 英文行切分更稳；两引擎逐行比对，`agreement<0.75` 记争议。
5. **并发 OCR 临时文件名必须带书标识**——曾因共用 `p00001.png` 导致跨书串页，全量重跑才修好。
6. **`企业资料` 里 `Domain-Driven Design-Eric Evans-2003.pdf` 是错标**：正文是 Silverston《Data Model Resource Book Vol 2》，已改名并归到 Vol 2（sha256 未变）。
7. **GB 50500-2013 已于 2025-09-01 废止**，现行为 **GB/T 50500-2024**（推荐性标准）；写口径时别引旧版。
8. **`is_fk` 字段在 Deltek DDL 导出里全为空**，关系只能靠主键包含推断；通用键（PKey/RowID）会造成假 hub。
