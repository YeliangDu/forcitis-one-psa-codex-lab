# 流程负担与理论跑完时间分析：计划与取证清单

依据：用户要求全部流程完成后做流程负担分析，并批准把「理论跑完时间」并入、要求想全面（one-coordinator 2026-10-16 转，intent 已记）。全部铺开、质量检查通过后做；产出按 M-7 每价值流一页加一页总览。

## 1. 模型

- **输入**：骨架（步骤、角色、`where`、判断概率、审批与加审规则、超时）＋每步耗时参数＋流程频次（生产取证）＋工作日历（`organization.attendance` 已建）＋角色→职位→部门→人映射（权责对照表，与泳道、负担分析同一口径；人级只在私下页）。
- **计算**：每流程按路径枚举加判断概率做离散事件仿真（标准库实现，固定随机种子，可复现）；输出最快、典型、P90、最慢（超时路径），办理与等待分开，流程效率（办理/总时长），关键路径，SLA 达成概率；按工作日历折算工作日。
- **权责发生制重点**：月末最后 N 个工作日发起的单据在关账前走完的概率（跨期风险），按单据类型列出。

## 2. 分析项（对应用户八点）

| # | 项 | 输出 |
|---|---|---|
| 1 | 时间 | 每流程四个时长、办理与等待、效率、关键路径、SLA 概率、跨期风险 |
| 2 | 负担与容量 | 职位×频次×耗时（月均、月末、年末、里程碑峰值）；利用率（>80% 标红，排队用 M/M/c 近似）；单点角色（只有一人持有）与代理 |
| 3 | 审批与交接 | 每单人工审批次数与占时、规则自动放行比例、跨角色交接次数、返工环与返工率、重复录入、外部等待（客户签认、银行、分贝通、企业微信） |
| 4 | 内控 | 同一人持有角色组合的职责冲突（对照 `segregation`）、审批权与责任人匹配 |
| 5 | 端到端价值流 | 跨流程串联时长（签约→开票→回款等）、事项发生到入账的及时性 |
| 6 | 假设分析 | 去掉某节点、加人、改阈值的影响；对各参数做一次单因素敏感性，列最敏感的五个 |
| 7 | 校准 | 上线后以事件日志做流程挖掘校准（实现约束见第 4 节） |
| 8 | 隐私 | 个人级结果不进仓库与会话，只给用户私下页；仓库只放职位级 |

## 3. 取证清单（按 ADR-0037 请 one-ops 只读、只取汇总、每次登记一行；明细与个人信息不进会话与仓库）

| # | 内容 | 来源 | 口径 |
|---|---|---|---|
| E-B1 | 各类单据近 24 个月月度件数（报销、付款、采购、开票、收款、合同、交付物提交、工时单、请假加班、用印、IT 工单等），含月末最后 5 个工作日占比 | 老系统、A8 | 按单据类型×月计数 |
| E-B2 | 各类单据从发起到办结的时长分布（P50、P90、最大），审批节点数分布 | A8 流程实例、老系统 | 按单据类型汇总 |
| E-B3 | 退回、驳回、撤回比例（返工率） | A8 | 按单据类型 |
| E-B4 | 各审批人岗位的月均待办与处理时长（职位级汇总，不出人名） | A8 | 按岗位汇总 |
| E-B5 | 客户签认等待时长（交付物送达到签认）分布 | 老系统交付与证据记录 | P50、P90 |
| E-B6 | 报销与付款的金额分布（供阈值建议，审批阈值页 T-1） | 老系统、A8 | 按单据类型分位数 |
| E-B7 | 角色持有情况：每个审批或经办角色有几人持有（单点识别） | 老系统权限、A8 | 计数 |
| E-B8 | 分贝通、银行、企业微信的外部回执时长 | 对接日志 | P50、P90 |

## 4. 实现约束（写进过渡 ADR 与 CODING_STANDARD 建议）

各流程实现须产生可做流程挖掘的事件日志：case ID（单据或流程实例 ID）、活动（命令或任务名）、时间（服务端时刻）、处理人（人员 ID）、所在 BC；由审计或事件发布登记统一提供，不另建日志表。

## 5. 骨架补充字段（CONVENTIONS 第 5 节追加）

- 步骤 `effort: {typical_min, p90_min}`（办理耗时估计，取证后校准）；`wait: {typical_h, p90_h}`（外部或人工等待，可空）；判断出口 `p`（出口概率估计，取证后校准）。
- 流程级 `frequency_ref`：引用取证编号（E-B1）。

## 6. 排期

- 取证：铺开期间并行，one-ops 约 1–2 天（取决于 A8 只读库访问）。
- 工具：仿真与汇总脚本 1.5 天（铺开期间可并行写，用样板流程验证）。
- 分析与页面：全部铺开且质量检查通过后 1.5–2 天（四个时长、负担、容量、端到端、敏感性），每价值流一页＋总览一页；个人级私下页另出。
