# PRC-35「项目或协议终止、结项后清算成本」归段核对

依据：用户归段判据（2026-10-16，经 one-coordinator，intent 已记，#421；原文见 STAGE_ALIGN_REPORT.md 末尾）。只给建议，不改目录。目录现状：type event_policy，stages [VS-02.7, VS-04.5]，owner_bc B-07，无 stages_note。

## 1 触发与触发状态所在段

骨架（finance 组）的事件触发共 5 个。「协议已结算」不在其中，骨架只写了「协议已终止」。

| 触发事件（来源 BC） | 对应对象状态 | 该状态是哪段的退出条件 | 结论 |
|---|---|---|---|
| 项目已结项（B-04） | OBJ-29 项目「已结项 → 已归档」 | VS-02.7 收尾 | 精确，归 VS-02.7 |
| 项目已终止（B-04） | OBJ-29 项目「已终止 / 已取消」 | 无。只出现在 VS-02 的 ends_in（停止），不是任何段的退出条件 | 不归段 |
| 项目已取消（B-04） | 同上 | 同上 | 不归段 |
| 协议已终止（B-05） | OBJ-05 协议「已终止」 | 无销售合同一侧的段。VS-04 的 ends_in 有此状态，但 VS-04.5 退出条件是「已结算（结算书经双方确认）」。同名状态只出现在 VS-05.6 供方结算（供方协议）与 VS-13.6 离职结清（劳动合同），这两处是别的协议类型，与本策略清算的合同履约成本、售前投入无关 | 销售合同一侧不归段；按用语字面比对出来的 VS-05.6、VS-13.6 不采用 |
| BusinessFactAttributed（B-16，entry 3） | 无。是过账结果回执，不是对象状态 | 无 | 不参与归段 |

用户说的「协议已结算」（OBJ-05「已结算（结算书经双方确认）」）是 VS-04.5 的退出条件，若作为触发，则 VS-04.5 精确成立。但现骨架没有这个触发，脚本因此判 VS-04.5 目录所标「判据不支持」。这是需要定的一点：是给骨架补触发「协议已结算」，还是把 VS-04.5 从 stages 去掉（见第 3 节）。

参与者：PRC-35 骨架没有 roles，步骤 actor 全是 system，只在拒收时通知 SH-E6。VS-04.5 参与者含 SH-E6；VS-02.7 参与者（SH-E2、E4、M1、C6b、C6c、X4）不含 SH-E6，通知对象不在此段，但它是告警接收人，不是流程参与者，不构成偏差。

## 2 与 VS-10 获得期间报告的关系

- 成本清算结果进入期间报表。PRC-35 第 1 步在成本结转批次（AGG-43）里记「终止清算」结转行，第 2 步提交过账候选，经 PRC-92 走单一过账管道到 B-16，落成本结转类型的会计分录 OBJ-98；第 3 步订阅 BusinessFactAttributed 置已过账。报表读 OBJ-98「已记账（不可逆）」，所以清算成本经这条过账进入期间。
- 过账口径：所属期间在关账中则返回「期间关账中、可重试」；落账期间已关账而法人有开放期间，则落当前开放期间并标原期间（ADR-0045 决定 1、2；INV-92）。因此晚到的清算不会改已关账期间。
- VS-10 的哪段进入条件引用它：没有一段的进入条件点名 PRC-35，门只引用对象状态，不引用流程。相关的是：
  - 贯穿活动「成本结转」（人工成本分配、间接成本分摊、合同履约成本结转）：输出 OBJ-98「已记账」成本结转类型分录。终止清算的分录属此类，但该活动的输入只列 OBJ-73「已过账」与 OBJ-97「开放」，没有列项目「已结项」或协议「已终止」，所以活动描述没覆盖到 PRC-35 的触发。
  - VS-10.1 期间关账的进入条件：OBJ-97「开放」且 OBJ-98「已记账」，且限定「期末结转类型」分录。清算分录是成本结转类型，不被这一条覆盖。
  - VS-10.2 报表发布的退出条件：OBJ-98「已记账」，note「期间内分录均已记账」，泛指期间内全部分录，清算分录在内。
- 结论：关系成立，经 OBJ-98 与 VS-10.2 退出条件衔接，不需要给 VS-10 加门。可以注意的是 VS-10 成本结转活动的输入没有写出清算的触发状态，属价值流文字补充，不影响归段。

## 3 建议

建议保持 stages [VS-02.7, VS-04.5]，补 stages_note，并给骨架补触发「协议已结算」（若用户不补，则 stages 改为 [VS-02.7]）：

```yaml
stages: [VS-02.7, VS-04.5]
stages_note: >-
  事件策略按触发状态归段（用户判据 #421）：项目已结项=VS-02.7 退出条件 OBJ-29「已结项 → 已归档」；
  协议已结算=VS-04.5 退出条件 OBJ-05「已结算（结算书经双方确认）」（骨架 triggers 待补）。
  项目已终止、项目已取消、协议已终止是 VS-02、VS-04 的 ends_in 终点，不是任何段的退出条件，
  不另归段；这两段不相邻，是按触发状态跨价值流归两段，不是跳段。
```

需用户或 one-glossary 对口径的两点：
1. 终止、取消、协议终止三种触发没有归段，算不算 PRC-35 的主场景。目录名字叫「项目或协议终止、结项后清算成本」，主场景恰是终止，但按判据这几个状态不是任何段的退出条件。若要为它们找归属，要么 VS-02、VS-04 增加「终止」段（改价值流），要么认定终止清算属价值流终点后的处置，不归段，二者都不是本次能定的。
2. 骨架 triggers 增补「协议已结算」是 finance 组改骨架，不是本次范围。
