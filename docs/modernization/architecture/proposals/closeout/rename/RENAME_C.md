## 取舍

- 状态：进行时（××中）、等待或否定态（待××、未××）、被动式（被××）、名词与动词（生效、有效、逾期、暂停）一律改「已××」，改成「进入该状态的动作已发生」。例：审批中→已提交审批；整改中→已开始整改；待认领→已登记。草案、草拟、编制中、起草中并入「草稿」，「草稿」保留（会计与单据通用词，改「已草拟」反而不通）。
- 带前缀的状态机写法（`人员:候选人`、`use_request:草稿`）前缀只作机器标识，名称取后半。
- 事件：已建模块的英文类名不改，只改中文名；中文名无词表登记的，以事件目录标题（描述句）为旧名，补短名。
- 命令：宾动倒置、缺宾语、名词短语、「〔缺〕」占位前缀、以条件开头的，改动宾；「生效××」（使动用法，约 20 条）全表一致沿用，不改。
- 术语表：1378 条 proposed（词表无此名，交 one-glossary 登记，使用范围领域，bc 随聚合）、100 条 registered、1 条 conflict（认领收款 与词表命令「到账认领」）。旧名已登记而改名的（如「审批中」「待认领」「待处理」「合同签署事实」），在 glossary_note 注明须由 one-glossary 同步改 zh。

## 拿不准的项（yaml 里 `uncertain: true`，共 28 条）

1. 状态「试用期」「正式」：人事通用词，保留；是否改「已入职试用」「已转正」。
2. 状态「未中标」→「已落标」、事件「投标未中标」→「投标已落标」：「落标」是否为行业与词表接受的用语。
3. 状态「待查」→「已创建」、「待主张」→「已认定可主张」、「待入职」「待离职」「死信」「未开放」「未结」：无自然的「已××」时的退而求其次的取名。
4. 命令「登记合同—项目关联与范围挂 WBS」→「登记合同项目关联」、「记分配行与流水行」→「登记收款分配」、「驳回释放」「退回开放」「终止清算成本」、「补休到期转计薪」：原名语义不清，新名按参数与上下文推定，需聚合负责会话核对。
5. 命令「追加收入确认事实并占用转实」「开具销项发票并改写 WIP」：同事务两个动作，保留；是否应拆两条命令。
6. 事件「验收通过」（MilestoneAccepted）→「里程碑已验收」：是否与「交付物已认可」同一事件。
7. 事件「在职」「离职」（Employed、Separated）：原是 platform.integration 的值对象，被当事件名用，改名同时存疑是否应是事件。
8. 事件「达成」「回款」「独立性检查要求」「开票准入」：词表名为单词或名词，补主语后的新名需 one-glossary 复核。

对象改名后，命令宾语（如「创建独立性检查」）与状态/事件的主语须随 RENAME_A 同步，本表未预判。
