证据来源：`processes.revenue.yaml`（含 single_aggregate 的 commands、states、transitions）、`commands.yaml`、`state-machines.yaml`、聚合稿 `agg_new.md` §2.2、`NOTES.md`、`C_DEFAULTS.md`。本组 BC：B-01–B-06、B-08、B-09、B-26、B-28、B-29。本表只分拣，不改任何骨架或目录；「真缺口」一律待对象划分裁定后补。

判定三类：真缺口、误报、设计如此；另有「他组」（对象不属本组 BC，写归属组与 BC，不分拣）。

## 两类共性原因

1. **脚本按命令名动词判 C/U/D，且只认单元级聚合**。命令名不含「创建、修改、结束、撤销」等词表词（认定、停用、退还、没收、关闭、放弃、标记不再受托、解除）时判不出；命令在单聚合维护（PRC-10、PRC-12、PRC-14、PRC-27、PRC-33、PRC-42）的 commands 里、或条目级 aggregate 与单元级不同（PRC-14 挂 REF-01 而命令属 AGG-33、PRC-33 挂 AGG-38 而命令属 AGG-110），被漏识别；拟命令（`proposed: true`）在状态机里有转换，但流程步骤未绑定 command（人工步骤只写 gap），也判成无人创建。这一类多为误报。
2. **版本化配置、只追加事实、外部引用登记，天然没有「修改」或「结束」**：版本只追加新版本不改旧版（改 = 发布新版本，旧版被取代或停用），事实只追加（更正靠撤销后另起新记录或追加新结论），外部引用登记后不删除、不设终态（`PRC-14` scope）。脚本把它们当缺口，属设计如此。真缺口集中在状态机只有「创建 + 一个终态」的小聚合（AGG-26 资源分配、AGG-08 市场活动、AGG-105 满意度调查、AGG-37 外部检测）与拟命令未入流程（AGG-36 停用、AGG-05/06 编制）。
