# 收入线 C 类撤题：设计方按原则自定清单（告知用户）

日期：2026-10-16。来源：one-coordinator 派 opus 独立审题（`REV_PAGES_REVIEW_2026-10-16.md`，「C 类撤题」25 题），这些题不再问用户，由 one-arch-revenue 按用户已定原则自定。依据的用户原则：「能通过规则和不变量守卫的就不要人来守」「正常单人、异常加一、特殊加二」「看谁对费用负责，谁负责谁批」（intent 163556、164324）；收入与证据口径（intent 141725、144613、144943）；全部历史迁入（U-4，intent 133348）。不同意的任一条，告诉 one-architecture 即改。

| 题 | 定为 | 依据 |
|---|---|---|
| VS01-06 协议价目版本要否单独审批 | 不单独审批，由报价评审与合同评审覆盖 | 同一价格已在报价与合同两处有人负责，再批是重复守卫（「能规则化的不要人来守」） |
| VS01-11 截止后撤销投标是否必然放弃商机 | 不必然放弃，由客户经理判断去向（议标、重新招标或丢单） | 撤销不等于丢单；商机负责人对后续机会负责（谁负责谁定） |
| VS01-12 投标保证金退还提醒时限 | 未中标：书面合同签订后 5 日；截止前撤回：收到撤回通知后 5 日；废标：无对应条文，按招标人宣布废标后 5 日作内部提醒参数（可配置，非法定期限）；均到点提醒 | 招标投标法实施条例第 57 条（合同签订后 5 日内退还，已核原文）、第 35 条（撤回通知后 5 日内退还，原文未取到，交法务核一次）；废标情形条文未规定，只作内部提醒 |
| VS01-15 往来单位档案合并后的引用 | 自动改指向保留的档案并留痕，由往来单位档案维护人执行（原题写「由财务执行」，改） | 改执行人的理由：合并是主数据操作，不是财务动作；往来单位档案由档案维护人核实与维护（P-3「正式往来单位＝档案已核实」，intent 120544），权责片段 AGG-01「合并往来单位」R 为档案维护职能；改指向是机械动作，系统可做 |
| VS01-18 资质核查结果要否审批 | 不设审批，登记核查结果即可 | 核查结果是外部事实，登记人与延续批准人已分离；到期由系统判定（intent 163915） |
| VS01-19 独立性检查结论如何更正 | 追加新结论、保留历史，不覆盖 | 结论是投标与签约的前置拦截依据（INV-33）；业务事实只追加、更正靠新版本（SESSION_PLAYBOOK §14.1 D8）。不援引诉讼证据要求（intent 141725 未覆盖此对象） |
| VS02-06 资源分配由谁确认 | 被分配人所属部门负责人单级确认，不走审批平台；产能冲突由系统预警 | 人员归部门管理，部门负责人对产能负责（谁负责谁批）；可算的产能交系统 |
| VS02-09 改派签发人要否审批 | 不审批，系统核对证书有效、专业与等级相符即可，改派留操作审计 | 证书条件已由不变量守卫（INV-47），再加审批无增量 |
| VS02-11 设计变更、延期通知可否撤销 | 允许撤销，并留痕（补「撤销设计变更」「撤回延期通知」命令） | 线下常发生，不补则系统无法追溯；撤销只追加记录、不删原记录 |
| VS02-14 审核人能否是提出或编制人本人 | 不能：设计变更内审人 ≠ 提出人；不符合项关闭人 ≠ 登记人；复盘评审人 ≠ 编制人，系统拒绝同一人 | 不相容职务分离，系统可守（规则守卫，不靠自觉） |
| VS02-21 老系统已删除的工时单 | 不进工时表，进迁入暂存区保留可查 | 仍属「全部历史迁入」（U-4），只是已删不是业务事实，进工时表会与重填单冲突（一人一日一单） |
| VS02-22 迁入证据的诉讼证明力 | 登记迁入批次、迁入时重算内容哈希，原始时间由来源声明并标「迁入」，不冒充服务端采集时间 | 不伪造采集时间；证明力靠原件保全（intent 141725） |
| VS02-25 发包人提供的资料 | 登记后不可改，只可追加说明 | 资料是延期申请（AGG-31）与免责判断的依据，属业务事实，按只追加、更正靠追加说明（SESSION_PLAYBOOK §14.1 D8）。不援引诉讼证据要求（intent 141725 未覆盖此对象）；若要作诉讼证据，经证据关联登记（P-1，intent 120544） |
| VS03-02 检查项缺证据能否提交 | 不齐则拒绝提交：判定项须引用本次检查证据，未检项须选原因并说明 | 「有没有证据」交系统，审核人只判断「够不够」 |
| VS03-03 不符合项等级 | 默认取检查表模板的等级映射，改动须写理由并在复核页标出偏离 | 可算的交系统，人只看偏离是否有理 |
| VS03-04 复查未通过的去向 | 系统自动退回整改，轮次加 1，带出新整改期限 | 去向唯一，不必人选 |
| VS03-05 关闭不符合项的证据时序 | 所引复查证据采集时间不得早于整改申报日，否则拒绝并告警 | 时序错乱的证据不能证明整改完成；规则可守 |
| VS03-06 检查提交人与审核人、登记人与复核人 | 必须不同人，系统拒绝同一人 | 检查结论是对外责任文件，自查自审无独立性 |
| VS03-09 检查锁定后证据 | 锁定即自动封存本次检查引用的证据 | 锁定即定稿，证据随之不可改（intent 141725） |
| VS03-10 证据与检查的关联 | 检查与复查的证据采集后自动关联；不符合项由检查人员选择支撑证据 | 能自动的自动，需判断的由人选 |
| VS03-13 业主能否在客户端登记整改申报 | 暂不开放，检查负责人收函后登记 | 客户不是本系统用户（客户门户未定） |
| VS03-14 外部检测报告采信由谁决定 | 检查负责人单级决定，不另设审批 | 技术判断、不涉资金；检查负责人对检查结论负责 |
| VS03-17 非保险委托周期检查要否建计划 | 暂不建，直接「安排检查」，到期只作提醒 | 聚合稿 AGG-34 定义为「检查计划（OBJ-48，仅 IDI）」；到期提醒作派生、不记状态，是用户已定口径（U-3，intent 090004，第 ③ 步回溯 R-04）。非保险委托的周期检查直接安排检查，到期同样走派生提醒 |
| VS03-18 标记不再受托要否必填原因 | 必填原因 | 与协议终止原因必填一致，便于客户流失分析 |
| VS04-19 登记付款条件达成要否审批 | 不设审批；登记须附与条件类型对应的外部证据，缺失或不符即拒绝 | 用户原则「能通过规则和不变量守卫的就不要人来守」（intent 163556）；证据与类型对照是拟规则 PAY-R1，规则卡未出（已交 one-rules），本结论以该规则卡生效为前提；金额加审阈值未定（intent 171147 T-1），定前不加审 |

骨架与规则落点：上述定法已体现在 `processes.revenue.yaml` 对应流程（VS02-11 的两条撤销命令列入 NOTES 新用语，待聚合稿回补）；涉及规则的（VS03-02、03、04、05，VS02-14，VS04-19）已在 NOTES「规则化」小节列为拟规则，交 one-rules 出规则卡。
