# Q-04 收入确认的存储方式（收窄稿，供 VS-04 用户页）

日期：2026-10-16。one-arch-revenue 起草，one-architecture 合成到 VS-04 页。依据：`Q04_REVENUE_OBJECT_RESEARCH.md`（倾向 C 与四条否决条件）、`Q04_REVIEW.md`（J1–J4）、`Q04_OVER_TIME_PROGRESS_RESEARCH.md` §4.1（情形甲）、`Q04_AEC_CONTRACT_MODELS.md` 及其评审；用户收入事实（intent 144613、144943 R-9）。会计口径由财务定，本稿不裁定。

## 1. 前提：用户已定的三个口径

| 口径 | 用户原意 | 在系统里是什么 |
|---|---|---|
| 经营产值 | 业务团队每期估进度，只作内部经营管理，管产值与客户确认之间的差额和时滞 | 项目侧的「产值估计」，不是收入，不过账 |
| 权责收入 | 以客户确认为准（企业会计准则 CAS 14，某一时点履行） | 收入确认记录，客户认可证据触发 |
| 对外财报收入 | 按开票确认，增值税也按开票 | 销项发票与其过账事实，推 U8C（U-8） |

由此，研究里会推翻倾向的条件「某类服务按时段、每期估进度入账」**不成立**：进度不进收入。三个口径各存各的，不互相触发。

## 2. 只剩一个问题要用户定

**权责收入的确认记录怎么存？**

| 选项 | 一句话 | 代价 |
|---|---|---|
| **C 不可改记录（推荐）** | 收入确认写下后不可改，更正只能冲销；审批中的金额先占着额度，财务复核通过才写下确认记录 | 是现行决定（收入确认是规则、不建单据）的细化，不需改 ADR；确认记录与会计过账靠事件传递和每日对账衔接 |
| 轻量版 | 在额度里放一行可改状态的确认行 | 确认行可改，要修订现行决定；日后要升级成单据得重构，窗口在历史迁入演练之前 |
| 单独单据版 | 收入确认像开票申请一样成一张有审批状态的单据 | 要另立决定；额度要跨单据先占后写，还要清理没人认领的占用；历史迁入要开「迁入即已确认」的口子 |
| 暂不定 | 先不选 | 卡住开票与收入模块的历史迁入设计 |

推荐 C 的理由：

1. 已批准的收入证据决定（ADR-0047）要求每笔确认记证据类型、认可日、历史迁入并照常审批，必须有一条存下来的记录；C 正好给出这条记录，又不新建单据。
2. 诉讼要求证据不可改、有时间戳（intent 141725）：C 的确认记录只追加、带内容摘要，更正留冲销痕迹。
3. 成熟产品都保存确认结果、用冲销更正，没有一个给确认结果配重型审批状态机；审批在审批平台。

## 3. 选 C 后怎么落（给评审看，用户页只放一句）

- 表都在开票与收入模块（AGG-44，每份协议一个）：额度（付款条件项、履约义务）、开票占用、**收入确认占用**（只记金额、审批实例、占用中 / 已转实 / 已释放）、**视为同意认定**（只追加）、**收入确认事实**（只追加：金额含税与不含税和税额、认可日与期间、证据类型、来源「正常 / 历史迁入」、规则与配置版本、冲销引用、审批实例、内容摘要）、确认事实与证据的引用（只追加）。表级见 `data-model.revenue.yaml` AGG-44。
- 流程：客户认可或视为同意成立 → 占用收入额度并发起收入确认审批（财务复核，ADR-0047 U-2 (a)）→ 通过：一个事务内二次校验额度、追加确认事实、占用转实，再经事件提交过账候选；驳回：释放占用。历史确认直接写确认事实（来源「历史迁入」），不经占用与审批。
- 经营产值：项目侧只追加的产值估计（每期一行、修订带序号；暂作完工估算 AGG-23 内子表，归属由 one-architecture 判），不占额度、不触发审批、不过账。
- 开票：开票申请 → 销项发票（税务平台）→ 过账，与权责收入互不触发。
- 三口径对照：分析库读模型「收入三口径对照」（协议 × 期间：经营产值、权责收入、开票收入及差额、时滞），不在业务表上算。

## 4. 用户须知情（随本题一并告知）

- 已批准的 ADR-0047 U-1 (a)「客户认可前证据可登记、关联到收入确认、封存」：那时还没有确认记录，字面细化为「证据先关联交付物的提交轮次，确认时再引用」。这是用户按预选提交的条目，改字面须让用户知道。
- 没有法定审计：「审批履历留在审批平台、确认记录引用审批实例」是否可接受，问内部审计与财务负责人（并入 A1-02）。
