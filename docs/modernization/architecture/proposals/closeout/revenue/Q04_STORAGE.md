# Q-04 收入确认的存储方式（one-arch-revenue 提案，交 one-architecture 判定与合成确认页）

日期：2026-10-16。依据：`Q04_REVENUE_OBJECT_RESEARCH.md`（倾向 C 与四条否决条件）、`Q04_REVIEW.md`（J1–J4）、`Q04_OVER_TIME_PROGRESS_RESEARCH.md` §4.1（情形甲）、`Q04_AEC_CONTRACT_MODELS.md` 与其评审、用户收入事实答复（intent 144613、144943 R-9）。本稿只定存储形态；会计口径由财务定，不在此裁定。

## 1. 用户事实对四条否决条件的影响

| 否决条件（主研究 §0） | 用户事实 | 结论 |
|---|---|---|
| 1 某类履约义务按时段、须每期估进度入账 | 每期估进度只作内部「管理产值」，权责收入以客户确认为准；适用 CAS 14（R-1、R-3、R-9） | **不触发**（情形甲）。进度估计不进收入确认 |
| 2 审计师要求确认记录自带完整审批履历 | 没有法定审计，只有内部审计（R-4、R-9） | 不触发；改问内部审计与财务负责人是否接受「审批履历在 `platform.approval`、确认事实引用审批实例」（并入 A1-02） |
| 3 单协议确认行多、并发写同一协议频繁 | 无事实 | 仍待取证 E1、E9（one-ops 只出计数） |
| 4 占用行状态构成确认生命周期 | — | 维持「细化」判定，作复核点 |

**提案：Q-04 选 C（不可改确认事实 + 审批中占用行），作为 ADR-0016 决定 4 的细化。** 推荐理由同主研究 §0；本稿新增的是落表方式与三个口径的分开存放。

## 2. 落表（详见 `data-model.revenue.yaml` AGG-44）

AGG-44 每协议一个聚合，表全在 B-08：

| 表 | 作用 | 可变性 |
|---|---|---|
| `billing_revenue_capacities` | 根：协议、承担法人、币种 | 乐观锁 |
| `payment_term_capacities` / `performance_obligation_capacities` | 付款条件项可开票额度、履约义务分摊价格与累计确认（INV-21、22） | 随占用转实更新 |
| `billing_reservations` | 开票占用（INV-73 同事务） | 占用中 → 已转实 / 已释放 |
| `revenue_recognition_reservations` | 收入确认审批中的占用：金额、审批实例、状态 | 占用中 → 已转实 / 已释放；不存证据 |
| `deemed_acceptance_determinations` | 视为同意认定事实（先认定、后确认，ADR-0049；订正聚合稿 J4） | 只追加，带摘要 |
| `revenue_recognitions` | 不可改确认事实：金额（含税、不含税、税额）、认可日与期间、证据类型、来源（正常 / 历史迁入）、规则与配置版本、冲销引用、审批实例、摘要 | 只追加，库层禁 UPDATE / DELETE |
| `revenue_recognition_evidences` | 确认事实 → 证据（AGG-38）与提交轮次（AGG-27）的引用及证据摘要快照 | 只追加 |

审批通过回调时，AGG-44 一个事务内：二次校验额度（RULE-222）→ 追加确认事实 → 占用转实。确认事实与过账事实（AGG-77）不同事务：经事件发布登记表投递过账候选，加日对账兜底（Q04_REVIEW 第 8 条）。迁入的历史确认直接写确认事实（来源「历史迁入」），不经占用与审批（ADR-0036 M7）。

## 3. 三个收入口径分开存，不混用

用户事实给出三个口径，存放各自独立：

| 口径 | 含义 | 存在哪 | 状态 |
|---|---|---|---|
| 管理产值 | 业务团队每期估的进度产值，只作内部管理 | **新对象「产值估计」**，项目管理侧（暂作 AGG-23 完工估算内只追加子表 `progress_estimates`，归属待 one-architecture 判），每期一行、修订带序号，项目经理填、部门负责人复核（进度研究 §4.1 甲-1） | 聚合稿没有，**结构问题**交 one-architecture |
| 权责收入 | 客户确认时点的收入（A1） | AGG-44 `revenue_recognitions` | 本稿 |
| 开票收入 | 对外财报与增值税按开票 | AGG-46 销项发票 + 过账事实；推 U8C 的凭证口径按 U-8 | 已有 |

产值与客户确认之间的差额和时滞（用户 R-9 说的管理指标）、开票与权责的差额，做 `reporting` 读模型「收入三口径对照」，按协议 × 期间；不在交易表上算（D9）。

## 4. 需要他人处理

- **one-architecture（结构问题）**：① 「产值估计」的承载（暂作 AGG-23 内子表；是否独立聚合由你判；不进 AGG-44）；② 聚合稿 AGG-44 订正：视为同意判定改为单独认定事实、「确认视为同意期满」命令随之改写；AGG-47 注释与 N-12、Q20 行「选有状态对象须新开 ADR」字样改写为「选 C 为细化」；③ 读模型「收入三口径对照」登记到 `reporting`。
- **one-glossary**：`progress_assessment`（履约进度认定，已批准为 `receivables.wip` 的聚合，定义「计量认定单」）与用户事实不符：法定收入不按进度计量，进度只用于管理产值。须重审其 bc 与定义；新增「产值估计」（拟 `OutputValueEstimate`）与「收入三口径对照」；词表另有 `tm_period_bill`、`final_account`、`interim_payment_certificate` 定为 `receivables.wip` 的聚合，聚合稿 B-08 没有对应聚合，须对齐。
- **one-rules / 财务**：内部审计与财务负责人是否接受「审批履历在审批平台」（替代原 W-6）；E1、E9 取证。
- **用户须知情（合成确认页）**：ADR-0047 U-1 (a)「认可前登记证据」字面细化为先关联交付物提交轮次、确认时再引用（用户按预选提交的条目）。

## 5. 不做

不预建时段履约的计量结构（CS-1.8）；`performance_obligation_capacities` 只保留「履约方式」一列族以便识别，取值现只有时点。若日后财务认定某类服务按时段入账，按主研究乙-2 加估计事实，届时走 ADR。
