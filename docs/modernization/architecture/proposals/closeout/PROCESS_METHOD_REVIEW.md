# 流程设计方法提议稿：opus 首轮对抗评审

对象：`PROCESS_METHOD_DRAFT.md`（下称「稿」，行号指该文件）；连带 `BPMN_STYLE.md`（下称「画法」）。对照：同目录 RESEARCH、CONVENTIONS、process-catalog.yaml、STRUCTURAL_ITEMS、COVERAGE_REPORT、bpmn_check.py；METHOD.md、FRAMEWORKS.md；ADR-0050、ADR-0007、ADR-0016、ADR-0036；CODING_STANDARD CS-1.8、1.10、5.x；GUIDING_PRINCIPLES §4、测试一节。2026-10-16。

## 结论：改后再交

方向对（目录唯一、流程挂聚合命令、`where` 四类、下游交付成表），能回答用户「对应过吗」「哪些节点在本系统」。但有五类问题须改后再交：① 把未经用户认可的聚合稿、依赖边、⑥a 清单标成【已定】；② 冲突清单漏了 BIZBOK 锁定版本、新框架引入、「一个事实只手写一处」、守护 10、ADR-0007 等至少 7 处；③ 同一流程的步骤要在骨架 yaml、描述级 BPMN、可执行 BPMN 三处手写，自相违反「一个事实只手写一处」；④ 可执行版现在就画，违反 CS-1.8 与 ADR-0050 决定 3「⑥b、⑦ 按阶段」；⑤ 交付表一半的「检查」没有承载字段或脚本，判定不了。另外画法规则还没在任何一张真实图上跑过（目录 `bpmn` 字段全空，三组 `bpmn/` 目录为空），用户 intent 153009 明确要先看样板。

## 批准页须让用户知情的事项

1. 流程总数口径：目录 145 条，其中业务流程 91 条（82 + 新增 9），另有事件策略、单聚合维护、读模型、合并 54 条不画图；18 条业务流程字段待补。
2. 流程所依的聚合稿、依赖边、流程清单仍是提议稿；批准方法后，铺开中对聚合稿的回补会一并请用户认可。
3. 要改的已采纳决定（过渡 ADR 承载）：流程登记改由目录 yaml 手写；全部业务流程画描述级图；引入 Silver 画法、实例化需求等新参照（改 FRAMEWORKS）；范围按 U-2、U-5 改全企业。
4. 两层图的代价：描述级 91 张；可执行版建议推迟到各流程实现时出（如用户要求现在出，增加 30 张及一致性维护）。
5. 验收场景口径：分支覆盖加关键路径，不是全路径；与现行测试口径的关系。
6. 用户审看方式：逐图看还是每价值流一页；铺开前先看按新方法重画的三组样板。
7. 工期估算与对投产准入、地基批的影响。
8. 尚未核实的出处：Silver 规则（二手）、BIZBOK 新版（未读全文，方法锁定 v11）、Flowable 未列元素（未部署验证）、bpmn-js 只读页（未实跑）。
