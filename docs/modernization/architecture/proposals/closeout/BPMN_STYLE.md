# BPMN 画法约定（三组共用，one-architecture 定，2026-10-16；第 2 版按方法稿评审修订）

依据：用户「流程的画法也不符合 BPMN 最新版本的要求」（intent `2026-10-16-155312`）；调研 `PROCESS_METHOD_RESEARCH.md`（OMG 官网核实：当前正式版仍是 BPMN 2.0.2，formal/13-12-09，2014-01 发布；ISO/IEC 19510:2013 对应的是 2.0.1）。风格借 Bruce Silver《BPMN Method and Style》的描述级规则（规则文字为本项目归纳）。本约定是提议稿，随流程设计方法稿交用户批。

## 1. 两层文件

| 层 | 文件 | 用于 | 元素范围 |
|---|---|---|---|
| 描述级 | `closeout/<组>/bpmn/PRC-NN.bpmn` | 全部业务流程；给用户看 | BPMN 2.0.2 协作图（Collaboration），含 BPMNDI；**由骨架 yaml 生成（`bpmn_gen.py`），不手写**；本次三组样板为手画，只用于给用户看 |
| 可执行 | `PRC-NN.bpmn20.xml` | 只限人工编排流程，**随实现 PR 出**，放 `platform.approval`（ADR-0007） | Flowable 支持元素白名单（调研第 7 节）；不用信号承载领域事件；不用脚本任务、业务规则任务 |

命名空间用标准 `http://www.omg.org/spec/BPMN/20100524/MODEL`、`.../DI`；描述级文件不出现 `flowable:` 扩展。

## 2. 结构

- 一个文件一个流程；`process` 的 `id` 写 `PRC-NN`，`name` 与目录 `process-catalog.yaml` 一致（CI 核对）。
- **泳池**：FORCITIS one 一个泳池（白盒）。客户、供应商、外部系统（企业微信、U8C、银行、税务、人社与公积金经办平台）各画一个**黑盒泳池**，只用消息流连接。内部角色的线下动作一律画在本泳道的手工任务，不单开泳池。
- **泳道**：FORCITIS one 泳池内按角色分泳道，泳道名「角色（SH-编号）」；系统自动步骤放泳道「系统」。不按 BC 分泳道；BC 写在任务的文档属性（`documentation`）里。

## 3. 元素与 `where` 的对应

| `where` | 元素 | 放在 | 说明 |
|---|---|---|---|
| in_system | 用户任务 `userTask` | 执行角色的泳道 | 名称「动词＋名词」；`documentation` 写 `AGG-NN 命令名；B-NN` |
| automatic | 服务任务 `serviceTask` | 「系统」泳道 | 同上 |
| external:<系统> | 发送任务 `sendTask` 或服务任务，与该外部系统黑盒泳池间画消息流；回执用中间消息捕获事件 | 发起角色或「系统」泳道 | 消息流命名为报文内容 |
| offline | 手工任务 `manualTask` | 执行角色的泳道 | 紧跟一个用户任务「登记…」录入结果与证据（证据画数据对象）；同一执行人且无等待、无计时时，可合并为一个「登记…」用户任务 |
| 客户等外部方的动作 | 不画在本泳池内 | 外部方黑盒泳池 | 以消息流进出（如「送达交付物」「书面认可」） |

- **判断点**：排他网关紧跟产生结局的任务；网关名写问句，出口标签写结局词（「通过 / 不通过」「已认可 / 已退回」）。并行用并行网关成对出现。
- **超时与升级**：任务上的边界计时事件（中断或非中断写清）。中断：出口接升级任务后汇回主线或结束；**非中断：出口接提醒或升级任务，再接独立结束事件「已提醒」，不汇回主线**（汇回会产生双令牌，R14）。
- **跨 BC**：本流程发给其他 BC 的领域事件画中间抛出信号事件，名称为事件名；由他 BC 事件触发的流程用**信号开始事件**；跨 BC 的 api 调用画服务任务，名称后注明「→ B-NN」；对方 BC 的反应是另一个流程，用文本注释写对方流程号。
- **读写**：读写的聚合画数据存储引用 `dataStoreReference`，名称「AGG-NN 名称」，用数据关联连到任务；证据画数据对象。
- **开始与结束**：一个触发一个开始事件，按触发类型（消息、信号、计时、空）；同一流程有两种触发时可有两个开始事件，各自命名；结束事件按结局命名（形容词短语，如「已认可」「已终止」），与价值流阶段的出口用语对齐。
- **审批**：`approval.engine` 为 `platform.approval` 的，画成用户任务并在 `documentation` 写「审批平台：单据类型」；`aggregate` 的画成用户任务；`external` 的画成外部方泳池发来的消息。
- **子流程**：调用活动 `callActivity` 只用于同一编排 BC 内的子流程，`calledElement` 写 `PRC-NN`；跨 BC 一律信号或服务任务。

## 4. 不用

复杂网关、升级事件、条件事件、链接事件、编排图、会话图；通用任务 `task`（必须标类型）；跨泳池顺序流。

## 5. 检查

- 脚本（`bpmn_check.py`，只用 Python，不引入 npm）：至少一个开始事件且都已命名、至少一个结束事件且已命名、排他网关出口有标签、无通用任务、消息流只连不同泳池、不出现第 4 节元素、`process` id 与名称和目录一致。
- 评审：命名是否「动词＋名词」、结局词是否与阶段出口一致、分层与粒度。
- 图形：必须含 BPMNDI；页面用 bpmn-js 18.30.1 只读查看器渲染，保留 bpmn.io 水印，任务上叠加显示「AGG-NN 命令 / B-NN / 在哪」。
