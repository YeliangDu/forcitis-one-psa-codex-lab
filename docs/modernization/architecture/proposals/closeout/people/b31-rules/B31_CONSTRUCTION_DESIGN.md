## 1. 范围与分段

### 1.1 先行上线的最小集合

B-31 的“四类表单”是以下四类行政记录，**其中只有用印及受控 IT 类别存在人工审批路径**：

1. **用印申请与实际用印登记**
   - 聚合：AGG-113。
   - 流程：PRC-139。
   - 人工审批 `doc_type`：`用印审批`。
   - 来源审批已通过且 INV-138 满足时直达已批准，不再审批。
   - 无来源单据时按有效制度配置走人工审批。
   - 实体章线下办理，本系统保存实际登记、文件证据及印章台账引用。
   - 依据：`A §2.2 AGG-113`；`P/b31.processes.yaml：PRC-139`；签章稿决定 3、9及迁移方案第 2 项。

2. **IT 需求工单**
   - 聚合：AGG-114。
   - 流程：PRC-142。
   - 人工审批 `doc_type`：`IT需求审批`。
   - 类别配置要求人审的进入审批；常规类别提交后直接待受理。
   - 须交付受理、处理、退回、解决、提出人确认关闭及重开。
   - 不设置受理超时提醒或系统代关。
   - 依据：`A §2.2 AGG-114`；`C/ARCH_VS14.md：B31-2、B31-3`。

3. **IT 资产使用**
   - 聚合：AGG-115；维修另属 AGG-121。
   - 流程：PRC-143 领用、PRC-155 调拨、PRC-156 归还；PRC-157 报修与维修登记。
   - 新领用、调拨、归还、维修均不新增人工审批，`doc_type` 不适用。
   - 领用规则通过后登记交付；同法人调拨记录双方交接；离职归还提醒纳入本期。
   - AGG-121 是资产类表单的独立维修生命周期，不是第五类通用审批表单。
   - 依据：`A §2.2 AGG-115、AGG-121`；`C/ARCH_VS14.md：B31-5、6、7及A5`。

4. **员工活动登记**

   - 流程：PRC-144。
   - 全部活动由规则校验后登记，不设人工批准或活动金额加审，`doc_type` 不适用。

   - “已批准”仅表达规则通过，界面须说明其含义。
   - 依据：`A §2.2 AGG-116`；`P/b31.notes.md：规则候选R-B31-10、OBJ-116生命周期`。

## 2. 模块结构

### 2.1 包结构

```text
com.forcitis.one.organization.administration
├── package-info.java
├── api/
├── events/
├── application/
├── domain/
├── infrastructure/
│   └── persistence/
└── web/

backend/src/main/resources/db/migration/organization_administration/
```

- `api`：类型化查询端口、ID、只读结果；公开方法总数不超过 12。
- `events`：聚合产生的事实事件，英文名待登记。
- `application`：一类一个用例、唯一公开入口 `execute`；事务边界；审批及人员事件处理；本 BC 定时入口。
- `domain`：五个聚合、状态机、规则与仓储端口，不引用 Spring、JDBC 或流程引擎。
- `infrastructure.persistence`：参数绑定 SQL、乐观锁、约束及只追加历史落库。
- `web`：HTTP 请求响应及鉴权，调用 application；不直接返回领域对象。

依据：`M/NAMING_STANDARD.md §§0、2.2、3`；`CODING_STANDARD.md：CS-2.1—2.9`。

### 2.2 对外 API

按已知消费需求开放下列职责，暂不创造英文接口名：

1. 查询实际用印登记：按登记 ID 核对报价版本、法人、拟发文件与实际凭据；已关闭申请仍可核验。
2. 查询资产当前使用人及使用期间。
3. 按人员查询未归还资产，供离职交接读取。
4. 必要的活动登记只读查询，具体消费者及字段在实施契约中确认。

业务操作由本模块 HTTP→application 进入；不为每个内部命令增加跨模块公开方法。通用审批不能反向调用 B-31 内部实现。

依据：`ADR-0057：决定1、2`；`P/b31.notes.md：接缝问题`；`NAMING_STANDARD §0`。

### 2.3 事件

沿现行目录保留：

- AGG-113：用印申请已批准、用印已办理。
- AGG-114：IT 需求已解决。
- AGG-115：资产已领用、资产已调拨、资产已归还。
- AGG-116：员工活动申请已批准，表示规则通过。

依据：`P/b31.events.yaml`；`backend/src/main/java/com/forcitis/one/platform/approval/events/ApprovalCompleted.java`。

## 3. 聚合与数据

### 3.1 通用数据规则

schema 草案为 `organization_administration`。以下 13 张业务表沿用现有表级设计，**当前均未建成**：

- 自有主键 `id uuid`，由 `kernel.IdGenerator` 生成 UUIDv7。
- 可变行具备 `version bigint`；写入同时匹配版本及前置状态。
- 审计列为 `created_at`、`created_by`、`updated_at`、`updated_by`；时刻为 `timestamptz`，操作人引用 `UserId`。
- 单据具备业务日期、法人、编号及所用配置版本引用；具体法人含义逐表登记。
- 状态、类型为 `text + CHECK`；英文枚举待用语确认。
- 默认 `NOT NULL`；确需可空时写明业务含义；业务值、时间无数据库默认值。
- 同 schema 引用建立具名外键；跨 schema 仅类型化 ID，不建外键。
- 金额如获确认需要承载，使用金额＋币种及 `Money`，不先建假定金额字段。
- 字段均为结构化列，不用通用 `jsonb` 表单替代领域模型。

依据：`M/SESSION_PLAYBOOK.md §§14、14.1`；`NAMING_STANDARD §§2.3—2.5`；`P/b31.data-model.yaml`。

### 3.2 AGG-113 用印申请

**状态机**

- 草稿／已驳回／已撤回，经提交进入审批中；来源审批通过且 INV-138 满足时进入已批准。
- 审批中，经本轮结果进入已批准／已驳回／已撤回。
- 已批准经实际登记进入已用印；分次登记保持已用印。
- 已用印在份数到齐或明确放弃剩余份数后关闭。
- 原单重提保留编号、旧轮次、意见与凭据，新轮重新核验。

**命令**

提交用印申请、批准用印申请、驳回用印申请、撤回用印申请、登记用印、关闭用印申请。

**不变量**

- INV-118：实际用印须基于已批准申请。
- INV-119：本申请累计登记份数不超过批准份数。
- INV-138：同一来源审批实例累计用印份数不超过批准份数。

依据：`A §1.2、§2.2 AGG-113`；`P/b31.state-machines.yaml：seal_application`。

**表与列草案**

- `seal_applications`：`id`、`document_number`、`business_date`、`legal_entity_id`、`applicant_id`、`reason_text`、`requested_count`、`approved_count`、`status`、`approval_instance_id`、`round_number`、制度配置版本引用、印章台账条目引用、通用审计与版本列。
- `seal_application_documents`：`id`、`seal_application_id`、文件名称、份数、不可变文件版本 ID、内容哈希、报价版本追溯引用。
- `seal_application_source_documents`：`id`、`seal_application_id`、来源 `DocumentReference` 的类型和 ID、`source_approval_instance_id`、来源批准份数快照、所对应申请轮次。
- `seal_usage_records`：`id`、`seal_application_id`、`registration_key`、`used_at`、`used_count`、`handler_id`、用印法人、台账条目及版本引用、拟发文件与实际盖章凭据的文件 ID／内容哈希、报价版本引用、核验配置版本引用；只追加。

申请编号按已确认编号规则唯一；实际登记以申请＋登记请求键去重。关闭不删除实际登记。

**并发设计待复核**：INV-138 不能仅靠申请行乐观锁。建议对来源审批实例建立事务级串行化锁，在锁内读取有效占用、校验并只写当前申请；涉及多个来源时按固定顺序加锁。有效占用、释放及更正口径尚须规则定稿，未定前不实现自动释放，不新增未经批准的聚合编号。

### 3.3 AGG-114 IT 需求工单

**状态机**

- 草稿／已退回／已撤回，按类别规则提交至审批中或已提交。
- 审批中通过→已提交；驳回→已退回；提出人撤回→已撤回。
- 已提交→处理中→已解决→已关闭。
- 处理中可因需求不成立或无法实现直接退回，不发布解决事件。
- 已解决可因提出人反馈未解决而重开至处理中。
- 只有提出人人工确认且已有处理结论才关闭。

**命令**

提交、批准、驳回、撤回、受理、解决、关闭、退回 IT 需求。

**不变量**

INV-120：关闭须有处理结论；解决命令须先取得结论。

**表与列草案**

- `it_requests`：`id`、`document_number`、`business_date`、`legal_entity_id`、`requester_id`、`category_code`、`description_text`、`priority_code`、`handler_id`、`conclusion_text`、`status`、`approval_instance_id`、`round_number`、类别／责任／金额适用配置版本引用、审计与版本列。
- `it_request_handlings`：`id`、`it_request_id`、`handling_key`、`handled_at`、`handler_id`、`description_text`、处理结论及受理序号；只追加。

依据：`A §2.2 AGG-114`；`P/b31.commands.yaml`；`C/ARCH_VS14.md：B31-2、3`。

### 3.4 AGG-115 IT 资产使用记录

采用“每资产卡片一根”的施工候选，表结构冻结前由负责会话复核。

**三台状态机**

- 领用：草稿→已通过→已领用。
- 调拨：草稿→已申请→已调拨／已撤销；无当前使用人时→已转领用。
- 使用期间：在用→已结束。结束原因区分归还与调拨，只有归还命令产生“已归还”业务结局。

**命令**

申请领用资产、登记领用、申请调拨资产、撤销调拨申请、调拨资产、归还资产。

**不变量**

INV-121：同一资产使用期间不重叠；申请时提前检查，交付和调拨时兜底。

**表与列草案**

- `it_asset_use_ledgers`：`id`、`fixed_asset_card_id`、当前使用人／期间投影、审计与版本列；卡片 ID 唯一。
- `it_asset_use_requests`：`id`、`it_asset_use_ledger_id`、`document_number`、`business_date`、`request_type`、`user_id`、`receiving_user_id`、`status`、领用规则版本引用、双方交接证据；历史审批引用仅供迁入保留。
- `it_asset_use_periods`：`id`、`it_asset_use_ledger_id`、`user_id`、`source_request_id`、`started_at`、`ended_at`、`status`、`end_reason_code`、归还验收及设备状态、`separated_at`、原组织单元引用、`return_reminder_due_at`、`return_reminded_at`、提醒配置版本引用、审计与版本列。

使用区间采用左闭右开；对根 ID＋时间区间建立排他约束，并限制每根最多一个未结束期间。调拨在同一事务结束旧期间、开启新期间并改变申请状态，全部属于同一聚合。

跨法人转让、卡片、折旧、报废和账务归 B-24。

依据：`A §2.2 AGG-115`；`P/b31.data-model.yaml`；`C/ARCH_VS14.md：B31-5—7、A6`。

### 3.6 AGG-116 员工活动申请

**状态机与命令**

- 提交员工活动申请：草稿→已批准，表示规则通过。
- 完成员工活动：已批准→已完成。
- 取消员工活动登记：已批准／已完成→已取消，原因必填。
- 已取消不可修改、恢复或完成；重登创建新记录并引用被取消记录。

本聚合无已登记 INV 编号；采用 B31-8、B31-10 已定约束，不新增 INV。

**表与列草案**

- `employee_activity_requests`：`id`、`document_number`、`business_date`、`legal_entity_id`、`activity_type_code`、`applicant_id`、`description_text`、费用预估引用、`status`、规则版本引用、周年员工引用、所依据入职日期、周年日期、`cancel_reason`、`cancelled_by`、`cancelled_at`、取消前状态、被取消登记引用、审计与版本列。
- `employee_activity_participants`：`id`、`employee_activity_request_id`、`participant_id`；申请＋参与人唯一，登记后不可改。
- `employee_activity_types`：`id`、`activity_type_code`、名称、启停状态、生效区间、配置版本、生效依据、作者、确认人及确认时间、`decision_ref`；按 D15 只追加版本。

周年初次生成以员工＋入职日期＋周年日期＋活动类型去重，重复调度返回原记录，包括已取消记录。显式重登按被取消登记引用唯一返回后继记录，重新校验当前规则；不得因取消使自动任务重新生成。

取消不自动冲销报销、费用或采购单据。

依据：`A §2.2 AGG-116`；`P/b31.state-machines.yaml：employee_activity`；`P/b31.scenarios.yaml：PRC-144-S09—S13`。

### 3.7 印章台账归属与第一段接口

**台账由签章服务拥有；B-31 不自建第二份印章主数据。**

签章服务第一段须提供：

- 台账根：每法人×印章类型一条稳定身份，UUIDv7。
- 维度版本：载体、启停状态、保管部门、生效日／失效日。
- 同一法人、同一类型任一时点最多一个启用条目的排他约束。
- 印章类型清单按 D15 配置型版本化。
- 按条目 ID＋用印时点查询有效版本；早于最早版本失败告警。

B-31 在申请中引用台账条目，在实际登记中保存所用版本。法人／类型不能自由填写替代引用。初始约 35 组是取证规模，不是固定上限，也不是必须预置的笛卡尔积。

台账英文名、schema、表名、接口名及权限前缀待 NAM-1020-COO-01。是否逐枚建档须行政确认同类多枚事实；不在第一段预建自然人执业章、数字证书全量台账或签章记录骨架。

依据：签章稿决定 1—3、迁移方案第 2 项；`PF/R2-签章服务复核.md §2`。

### 3.8 状态历史、配置及索引

- 本 BC 增加 `state_transitions`，按 ADR-0058 统一模板生成，同业务状态变更事务落库、只追加。
- 不能仅依赖安全审计或事件发布登记还原长期状态。
- 两类人审需持久保留每轮业务内容、配置版本、审批实例及结果；补充轮次表的名称与结构待 one-data 冻结，不覆盖旧轮。
- D15 配置保存有效版本、生效日、确认人、确认时间与决定依据；单据保存具体版本 ID。
- 列表索引覆盖权限范围列、业务时间及 ID；到期扫描使用状态＋到期列部分索引；同聚合子表外键建立前导索引。
- 长度、代码格式、枚举 CHECK、数据分级、保留期和查询路径一并登记。

**结构待定**：AGG-115 一个命令可能同时改变申请及两个使用期间；ADR-0058 的 `(aggregate_id, sequence_no)` 与根版本映射如何完整表达这些转换，须统一裁定。不能擅自把子实体 ID 解释为聚合 ID，也不能漏记转换。用印登记后自动关闭亦须明确版本推进和转换记录边界。

依据：`ADR-0058：决定1—8`；`SESSION_PLAYBOOK §14.1 D7、D12—D19`。

### 4.3 驳回、撤回与回调

依据：`P/b31.state-machines.yaml`；`platform/approval/api/ApprovalProcesses.java`；`ApprovalOutcome.java`；`events/ApprovalCompleted.java`。

## 6. 权限与数据范围

### 6.1 权限码草案

资源英文名尚未确认，以下中文占位符不作为可执行权限串：

```text
organization.administration:<用印申请资源>:read/create/update/submit
organization.administration:<用印撤回资源>:execute
organization.administration:<实际用印登记资源>:read/create

organization.administration:<IT需求资源>:read/create/update/submit
organization.administration:<IT受理资源>:execute
organization.administration:<IT解决资源>:execute
organization.administration:<IT退回资源>:execute
organization.administration:<IT关闭资源>:execute
organization.administration:<IT撤回资源>:execute

organization.administration:<资产领用资源>:read/create/execute
organization.administration:<资产调拨资源>:read/create/execute
organization.administration:<调拨撤销资源>:execute
organization.administration:<资产归还资源>:execute
organization.administration:<资产维修资源>:read/create/execute

organization.administration:<员工活动资源>:read/create
organization.administration:<活动完成资源>:execute
organization.administration:<活动取消资源>:execute
```

斜杠表示分别登记权限。动作限定于现有标准动作；不自造 `withdraw/transfer/complete/cancel` 权限动作。资源分别命名以避免一个宽泛 `execute` 授予全部办理权。

审批任务操作复用审批平台权限和处理人校验，不给领用或活动增加批准权限。印章台账维护权限归签章服务。

依据：`NAMING_STANDARD §2.3、G43`；`backend/glossary/terms.yaml：standard_actions`；`platform/identity/api/Permission.java`。

### 6.2 数据范围

- 按权限分别计算范围，显式传入查询与写前加载。
- 本人：申请人／提出人／使用人等，逐表登记含义。
- 行政、IT 经办人按正式授予的法人及组织范围办理，不能把骨架“看全部”直接变成全局权限。
- 事实部门保存发生时归属；本人及直接下属范围按 ADR-0026 展开。
- 审批参与关系仅授该单据、附件和审批历史的只读访问，不扩大到相关单据或写权限。
- 子表继承根范围；列表、详情、计数、附件及导出同口径。
- 无功能权限为 403；有功能权限但资源越范围为 404；空范围返回零行；解析异常拒绝。
- 请求不携带执行者身份；执行身份来自会话，系统作业使用已登记系统身份。

依据：`ADR-0026：决定1—3`；`NAMING_STANDARD §2.6 A-10`；`ADR-0043`。

当前代码中的 `AccessScope` 仍位于 identity API，未读到 ADR-0026 所述共享 `CurrentAccess` 落地。该基础必须由安全／身份负责会话补齐或明确批准接入方式，不能在 B-31 内复制一套范围计算。

### 6.3 职责分离与敏感信息

- 用印申请人不能审批本人申请；办理人与申请人的分离按现有流程提议交安全方定稿。
- 资产使用人不能登记自己的领用、调拨或验收自己的归还。
- 管理模式不办理业务审批，平台管理员身份不自动获得行政业务权限。
- 员工引用登记 PI；描述、附件及维修凭据按实际内容分级，日志不记录正文。
- 审批字段不能直接暴露受限内容；文件授权随业务单据。

依据：`P/b31.processes.yaml：segregation`；`P/b31.commands.yaml`；`ADR-0026：决定4—7`；`ADR-0043`。
