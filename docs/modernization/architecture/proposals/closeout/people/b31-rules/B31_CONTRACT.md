### 3.1 等用户页的口径（one-rules，B31_RULING_REPLY.md）

实现卡**不得**按「占用/释放」或「放弃即释放」写，也不得自编 INV 号，直到用户答复：

- Q-B31-1：INV-138 只数实际用印（推荐）还是也占用。
- Q-B31-2：同一既有审批单号的批准份数以首次登记为准，之后不一致即拒并提醒行政（推荐）。
- Q-B31-3：冲正是否腾出份数（推荐腾出，仅行政负责人可冲正并留原因）。
- Q-B31-4：一个用途可否对应多个印章类型（推荐可以，行政可答）。

规则稿 `B31_RULES.yaml` 与 B31R 答复的差异（附录 RUL-01–08）待 one-rules 逐条回复后才作规则卡。

## 4. 审批接入契约

1. 业务模块不碰流程引擎，只依赖审批 api 与 `ApprovalCompleted`（ADR-0007）。
2. 三类人审：用印审批、信息技术服务审批、合同原件借阅审批（裁定第 5 项：施工设计的「两类人审」改为三类）。单据类型走编号模块注册表，审计主体以类型码记录，**不新增** `DocumentType`、`AuditSubjectKind` 常量；流程键、权限码、投递用途三类枚举新增见 `B31_PLATFORM_CONSTANTS.md`，由 one-architecture 合成一次冻结通道申请（裁定第 10 项）。
3. 回调须同时匹配单据引用、流程类型、实例 ID、轮次与当前状态；重复事件幂等；旧轮事件不改新轮；未知对应或不支持结果拒绝并告警。
4. `ApprovalCompleted` 结果映射（裁定第 8 项，用印与 IT；借阅沿用，待借阅状态机）：

| 审批结果 | 业务状态 |
|---|---|
| APPROVED | 用印：已批准；IT：已提交（借阅沿用，待借阅状态机） |
| REJECTED | 已驳回（本轮终止，发起人可重提新一轮）；IT 的「驳回→已退回」改为「已驳回」 |
| RETURNED＋审批人 | 已退回（退回发起人修改后重提） |
| RETURNED＋发起人 | 已撤回 |
| RETURNED＋系统（启动被拒） | 不进业务状态：单据留在提交前状态，记拒绝原因并告警 |
| CANCELLED | 已取消（终态） |

「已退回」「已驳回」等状态词与审批、人事词条同名异义，状态词中文名交 one-glossary（M11）。
5. 审批人解析在本模块完成，以 `FormFieldUsers` 传入；取不到人时的处理（平台默认转流程管理员，与高风险用途缺人即挂起相反）待审批模块 owner 与 one-security（APR-05）。
6. 来源审批载荷读取接口不纳入先行期（裁定第 9 项）。

## 5. 权限、定时与数据范围

- 权限码 `organization.administration:{资源}:{动作}`，清单见 `B31_PLATFORM_CONSTANTS.md` §2。数据范围沿 ADR-0026；共享 `CurrentAccess` 未落地，B-31 不自建范围计算；审批参与关系 `document_participants` 尚无实现（DATA-11）。
- 定时：本 BC 自声明 `@Scheduled`＋`@SchedulerLock`，不依赖 `platform.scheduling`；入口放 `infrastructure/scheduling` 薄类再调 application 用例（裁定补充）。季度复核、月度抽检、借阅逾期都做成本 BC 的到期列表（聚合上的到期时点列＋查询），提醒走企业微信投递，不建通用待办。
- 物理承载（one-data）：法人列落在请求与期间（先行期取领用人当日法人归属）；不建当前使用人投影，靠「ended_at IS NULL」部分唯一索引；根不惰性建，业务键 `asset_card_number`；迁入历史状态用 CHECK 并集加 `origin_kind`；预估金额、有效期、预盖登记、冲正行见裁定 §7。7.4–7.8 开表前须 one-data 逐卡签发。
