# QC-OBJECTS：人员组对象增删改查检查分拣

来源：one-architecture 的 `object_check.py`（`closeout/object_check.py --local --states people/state-machines.yaml`，基线 `origin/claude/one-architecture-closeout-plan` a2daae39）对人员组所报问题，清单 `crud_people_issues.md`、矩阵 `crud_people_matrix.md`。本文逐条分拣：每行一个「对象 × 检查项」；2 项「无人结束或归档」与 6 项「缺结束或归档」判据相同，合并为一行。

判定：启发式误报（命令实为结束 / 逆向 / 创建，但名字不含词表词，或带〔缺〕前缀被判「?」，或检查读不到 withdraw / on_reject 边）；设计如此（有意的结构，或他组聚合、长期配置、一拆多）；真缺口（已补）（本次在分片里补了〔缺〕命令并入流程）；真缺口（交 one-architecture）（需聚合稿或他组流程补，已写入对应分片 notes「结构问题」）。

两类共性原因，先说清：
1. 检查对步骤命令名带〔缺〕前缀一律判「?」（`cc.MISSING in cmd` 先于关键词分类），本组 29 处〔缺〕步骤全部落成「?」，是误报的最大来源；
2. 判据是命令名子串匹配，不读状态机。其实 `--states` 已经传了人员组状态机，转换里有 `from: null`（创建）、指向终态（结束）、`kind: reverse`（逆向）、`kind: non_state`，也有 withdraw / on_reject 边触发的目录命令，都没用上。

## 2. 建议 one-architecture 扩充 object_check（词表与口径）

按本组 86 行中占多数的启发式误报归纳，由多到少：

1. **读状态机而不是猜名字**（一次解决约六成误报）：创建 = 转换 `from: null`；结束 = 转换指向终态；逆向 = `kind: reverse`；`kind: non_state` 算修改。`--states` 已经在读，只是没用于分类。目录里 `unused_ok` 为「由骨架 withdraw / on_reject 边触发」的命令（撤回 / 驳回类）计入逆向。
2. **〔缺〕前缀先剥掉再分类**：现在带〔缺〕一律判「?」，本组 29 处〔缺〕步骤全受影响。
3. **按动词（命令名开头）判，不按子串**：`批准用印申请`、`批准员工活动申请` 因含「申请」先中 CREATE，`驳回经营计划审批` 因含「计划」判 C；UPDATE 词应先于 CREATE 判，或只看开头两字。
4. **词表增补**（命令实为结束 / 逆向 / 创建 / 修改，但名字不在词表）：
   - END：废止（`废止知识条目`）、减员（`参保减员`）、锁定（`锁定`）、归还（`归还资产`）、离职（`办理离职`、`离职生效`）、已减员；
   - REVERSE：驳回（`驳回调岗申请`、`驳回奖金核定`、`驳回用印申请`）、退回（`退回知识条目`、`退回薪酬重算`、`退回 IT 需求`）、废止、减员、重新生成（`重新生成月度考勤`）、恢复、启用（对停用的逆向）；
   - CREATE：增员（`参保增员`）、草拟（`草拟奖金核定`）、指定（`指定法人归属`）、计算（`计算`）；
   - UPDATE：更名（`更名法人主体`）、启用、补卡、指定。
5. **机器初态为草稿时，其出向命令按创建计**：`提交招聘需求`、`提交请假`、`提交 IT 需求`、`提交劳动合同` 是首个领域命令（草稿不是领域命令）。
6. **3 项「合不成一张状态机」改为：同名命令相连、或有 `kind: entry` 入口的子机视为同一聚合的子生命周期，不报**（第 3 节逐个判断是否应拆聚合）。「状态名冲突」只在两状态之间无转换时才报（`待申报` / `已申报` 有 `提交申报` 相连）。
7. **「并列」判断对出现在聚合稿命令列的命令名跳过**（`并入扣缴申报`）；**「多个 BC 写同一对象」对聚合稿标「一拆多」的对象跳过**，或只比较写入方是否都在该对象的聚合 BC 集合内。
