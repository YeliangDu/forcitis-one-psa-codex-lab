## 2. 提议新增流程（正式编号 PRC-136–138，owner_bc B-13）

### 2.1 PRC-136 调岗（任职变更）

触发：人力按人事业务生效日登记（发起人是用人经理还是人力：待用户）。依据：U-12；老系统与 A8 的「人事异动」只作证据（`OA_PROCESS_INVENTORY.md` 组织与人事）；词表「待调整权限」。

1. 读新职位（职位目录）与新组织单元，已停用或撤销则拒绝告警（INV-63、INV-60）。
2. SH-E6 终止任职（AGG-63）→ 任职已变更，旧区间止于业务生效日。
3. SH-E6 建立任职（AGG-63）→ 任职已变更，主任职不重叠（INV-62）。判断：调岗同时调整薪酬或改变用人单位法人 → 步 5。出：事件 → platform.identity。
4. platform.identity 订阅任职已变更，标记数据范围待复核并通知区域负责人（沿用 PRC-80 步 4 的命令，生成待调整权限，只提醒不收回）。
5. （分支）B-15 调整薪酬档案（AGG-93）。

批准：聚合稿没有调岗批准命令，待用户。晋升只改职级不换职位（`JOB_CATALOG_DRAFT.md` §1 P-1），同走本流程。缺口：PG-02、05、06、07。

### 2.2 PRC-137 入职开通企业微信并绑定外部身份

触发：Employed（见 PG-01：Q-03 无首日兜底，应早于入职生效日开通）。依据：intent 2026-10-16-134134 Q-03；`IDENTITY_LIFECYCLE.md`（招聘入职是人力过程，企业微信是信息过程，有前后顺序）。

1. SH-E6（信息）在企业微信开通成员账号（外部动作，无命令）。
2. platform.integration 接收「企业微信成员已创建」，匹配到人员；匹配不到唯一人员 → 告警，去步 4；匹配键待用户。
3. platform.identity 建立登录身份并绑定外部身份（人员 ID 为键）；绑定后方可登录，不设口令兜底。
4. 入职业务生效日前仍未绑定 → 告警信息与人力，不静默。

缺口：PG-01–04、13。

### 2.3 PRC-138 离职停用企业微信并解绑

触发：Separated。依据：Q-03；RULE-363；ADR-0027 第 1 项；`IDENTITY_LIFECYCLE.md`（在职判断以人事离职为准，不以企业微信账号存在与否为准；近 24 个月离职者 15% 离职后仍成功登录）。

1. platform.identity 吊销会话（调用 PRC-129），并按 ADR-0027 删除全部角色授予、停用应急账号。
2. platform.identity 停用登录身份：即使企业微信账号仍存在也拒绝登录。
3. SH-E6（信息）在企业微信停用账号（外部动作）。
4. platform.integration 接收「企业微信成员已停用」。
5. platform.identity 解绑外部身份。
6. 规定时限内企业微信账号仍未停用 → 告警，时限待用户。

缺口：PG-03、04、12、13。
