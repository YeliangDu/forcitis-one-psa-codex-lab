## 接缝问题

1. **reporting 订阅关账事件**：PRC-101、102 按 R-30 写了 `event out → reporting`，但聚合稿 §4.1 的依赖骨架没有 reporting 这个节点（分析库按 ADR-0023 决定 2 订阅全部事件，「仅分析」约定见 F-4）。边没改，请 one-architecture 确认是否把 reporting 记入骨架。
2. **关账事件的发布方是 B-19，编排方是 B-17**：PRC-101、102 属 B-17，命令在 AGG-81（B-19），事件由 B-19 发布。`cross_bc` 的 event out 写在触发它的步骤上；B-20 → B-19、B-21 → B-19 的事件边 §4.1 已有，方向一致。
3. **B-17 订阅 BusinessFactAttributed / BusinessFactRestated 无反应命令**（G-19 ②）：PRC-92 仍沿 v1 保留向 B-17 的 event out；B-17 实际只在月结检查时读取，建议聚合稿订阅方列改为「不订阅，api 读取」，不改边。
4. **B-03 → B-16 无边**（他组 PRC-08 调过账）：PRC-92 的 api in 沿 v1 未列 B-03，归 revenue 组与 one-architecture 裁。
5. **发起关账 ≠ 确认关账没有不变量编号**：只写在 AGG-81 内含列与 ADR-0045 决定 1，聚合稿 §1.2 没有 INV 条目，流程的判断点只能引 ADR；建议补一条（ADR-0046 §8.5 要求发起人、确认人入审计记录）。
6. **v1 角色错配**：PRC-104 把 SH-X7（资金监管主办银行）列为外部方，实际对方是 U8C（外部系统）。已去掉，U8C 写在 `where: external:U8C`；见格式问题 9。
7. 方向核对无异常：PRC-93、135 → platform.integration；PRC-104 → platform.integration、B-21 → B-20（读对账状态，in）；PRC-103、106 订阅 B-19 事件；PRC-106 → B-20、B-19 读；PRC-101、102 → B-16、B-19、B-20。

## 结构问题

1. **PRC-101 的 `human_orchestration` 应为 false**：R-15 裁定确认关账是聚合命令（`approval.engine: aggregate`），本流程没有 platform.approval 的人工任务，不需要 Flowable 编排；目录与 v1 仍写 true，请改目录。PRC-94 保持 true（手工凭证审批走 platform.approval）。
2. **配置版本缺「起草」命令**：ADR-0022 决定 2 要求起草人不得担任批准人，AGG-82、85、94 只有「发布…版本」。PRC-100 暂写〔缺〕起草科目表版本、〔缺〕起草映射表版本、〔缺〕起草授权表版本；草稿另存、版本行确认时才写（评审 R-31），请回聚合稿补命令或草稿状态。
3. **〔缺〕登记外部记账确认**：AGG-84 推送状态「已推送 → 已确认记账」没有对应命令（PRC-135 状态机）；建议并入「推送与重投」或补命令，由对账读取 U8C 记账结果后回写。
4. **月结检查无聚合，关账中是否接受过账未定（AGG§7-15，评审 R-18 判属架构问题）**：B-17 零聚合，检查结果不落状态；PRC-101 在发起前与确认时各检查一次，若「关账中」仍接受过账，两次之间检查结论会失效。请 one-architecture 定「关账中」口径，并定检查结论是否需要落一个技术记录。
5. **待处理队列清空路径与「配置新版本只在期间首日生效」冲突**：事实因授权表或映射表缺项进队列，补配置后新版本按 ADR-0022 决定 2 只在期间首日生效，本期队列清不空、关不了账。备选：(a) 版本生效日可定为当前开放期间首日（只限开放期间）；(b) 缺项事实改经受控手工凭证处理；(c) 冲销该事实后下期重提。财务取舍见待用户定 P2-02。
6. **第 13 期的期末凭证**：INV-108 只允许年度审计调整类受控手工凭证显式指定第 13 期，AGG-99 期末结转运行没有显式落账期间；ADR-0046 移交 P-3 推荐第 13 期允许模板期末凭证，若采纳须扩展 AGG-99 与 INV-92。随 ADR46-P3 定。
7. **新旧科目对照缺聚合与表**：PRC-104 对账要经新旧科目对照把 U8C 余额对到新科目（ADR-0022 决定 8，评审 R-26）；归属 B-20 还是 platform.integration 防腐层，请定。
8. **「推送与重投」命令在两处使用**：首次推送在 PRC-93 自动完成，死信重投在 PRC-135；命令粒度（逐凭证还是批次）聚合稿未写，请随 AGG-84 细化。
9. **年度审计调整类凭证**：AGG-98 内含列写有凭证类别「年度审计调整类」，用户已定无法定审计、只有内部审计（S-06），该类别与 INV-108 中第 13 期显式落账期间规则是否保留，随待用户定 S-06 后回写。

## 格式问题

1. `decision` 项增加 `outcome`：goto 为 end 时写结局词；一步有多个结局时必须在 decision 上写（步骤级 `outcome` 只够一个结局）。
2. `segregation` 同一角色重复：`roles: [SH-E6, SH-E6]` 加 `as: [performer, reviewer]` 对位，表示同一角色下不同人；rule 一句。
3. 独立入口：步骤加 `entry`（入口名），`triggers` 每条加 `entry`（入口步序号）。PRC-92（入口 1、3）、PRC-100（入口 1、3、5）用到。
4. 新增 `checks`：列月结前置检查清单（ADR-0022 决定 10），PRC-101 步 1、PRC-102 步 4 用。
5. `timeout.after` 取值「配置：财务设定的关账提醒日」，不是 ISO 时长（ADR-0046 第 5 项第 5 条只定提醒、不设强制期限）。
6. 事件策略：`triggers`（event、publisher_bc）、`steps`（v1 的 `trigger`、`step` 改名）、`outcomes`；单聚合维护：`states`（可多个状态机，每个有 `values` 与 `transitions`，转换带 `by`、`guard`）、`commands`（带 actor、where、permission、page）；读模型：`reads`、`subscribes`、`query`、`permission`、`page`、`scope`。
7. `goto` 指向另一流程（PRC-93 → PRC-135，PRC-102 → PRC-101）时，不写结局词，也不进本流程 `outcomes`。
8. `pending` 新增编号 P2-01 至 P2-03，合并确认页时统一编号；原 ADR22-G1G2 一律换成 S-05。
9. 外部系统作角色：roles 的 `as: external` 只能写 SH- 编号，U8C、银行等外部系统没有位置；本批只用 `where: external:U8C` 表达。请裁定是否允许 `{id: external:U8C, as: external}`。
10. 无人工角色的流程（PRC-92）`roles` 写 SH-E6 informed（接收拒收告警），沿 v1。
11. `月结检查` 步骤有 `command` 无 `aggregate`（B-17 没有聚合）；〔缺〕命令前缀写在 `command` 里，`aggregate` 照填所属聚合。
12. v1 `actor` 变动：PRC-104 步 1 由 SH-E6 改 system（读取 U8C 由集成自动完成）；PRC-101 步 3、PRC-102 步 6、PRC-104 步 3、PRC-105 步 2 的确认人 / 评审人改为 SH-M1 占位（评审 R-01 ②，待 F-01）。
