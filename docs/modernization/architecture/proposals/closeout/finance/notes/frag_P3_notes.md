## 格式问题

1. 决策分支加 `outcome` 与 `rule`：`goto: end` 的分支需要各自的结局词，CONVENTIONS 只有步骤级 `outcome`；本稿在 `decision` 条目上加 `outcome`（与 `when`、`goto`、`rule` 同级）。
2. 审批步骤加 `approval.on_reject_outcome`：驳回直接结束时的结局词（PRC-97）。
3. 触发加 `entry`：PRC-99 有四个入口，`triggers` 条目写 `entry: 步骤序号`，对应 BPMN 多个开始事件；也可拆成多个流程，由 one-architecture 定。
4. `segregation` 在同一角色内两人不同时，写 `roles: [SH-E6]` 加规则文字（PRC-99）；是否需要「同角色异人」的写法请定。
5. 事件策略与读模型的字段按交付说明写：事件策略 `triggers` 条目为 `{type, name, bc}`，步骤沿用业务流程步骤字段（含 v1 的 `post`、`calls`），`scenarios` 只列编号；读模型加 `subscribes`、`notes`。
6. v1 的 `trigger`、`gate`、`pending`、`notes`、`calls`、`platform_task` 等字段原样保留；新增 `type`（business / event_policy / read_model）便于合并。
