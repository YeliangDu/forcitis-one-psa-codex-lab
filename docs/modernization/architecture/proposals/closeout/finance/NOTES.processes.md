## 6. 格式问题

- v1 中文 actor 被 SH- 覆盖（可从 processes.v1.yaml 回查）；platform_task 步骤 actor 写 platform，审批人在 `approval.approver`。
- 干系人映射：财务 / 出纳 / 财务主管 = SH-E6（职能人员）；项目经理 / 验收人 = SH-E2；员工 = SH-E3（SH-E3 是设计师和顾问，借用，没有「全体员工」类别，请裁）；部门负责人 = SH-M1；股东 = SH-O1。同一编号靠 `as` 区分职务，但出纳 / 财务主管 / 税务会计的细分只能丢掉，不相容职务（INV-81、关账发起与确认不同人）在 yaml 里只剩 performer / reviewer / approver，要用 `platform.identity` 校验；如需细分请 one-architecture 在 SH- 下加子类。
- `pending` 不在约定里，保留，取值为 §4 的编号；请裁定是否保留此字段。
- 空角色：PRC-92 的 roles 只写 SH-E6 informed（接收待处理队列告警）；全系统流程无人工角色时是否允许 `roles: []` 请裁。
- `decision.goto` 数字为本流程 v1 步骤序号（1 起），含系统补偿步；事件策略与单聚合维护段只给 cross_bc，不含步骤。
