# 报销各类情形与分贝通差旅：功能覆盖对照

用户：「还要考虑从分贝通的报销流程。报销分多种情况，现在是不是都考虑到了，这个要查一下原 A8 系统。」（流程方法页 F-0）。one-architecture：分贝通保留为外部服务；A8 报销模板只按功能对照，不参考 A8 的流程设计，结果并入 A8 覆盖对照（⑦）。

证据：老系统代码与设计文档、仓库已有盘点（`OA_PROCESS_INVENTORY.md`、`runtime/a8_templates.tsv`、`runtime/a8_u8c_vouchers.tsv`），只读，2026-10-16。没有新做生产取证；需要取证的列在第 4 节。

## 1. 结论（白话）

- **报销其实有三种「谁先出钱」**：
  - 员工先垫付、公司再报销：A8 日常、差旅、业务招待报销单，以及员工在分贝通 APP 上传的垫资发票；
  - 公司直接付给分贝通：机票、酒店、火车、打车在分贝通下单，月底按账单结算，员工不经手钱；
  - 系统按出差天数生成的出差补贴，不靠发票。
- **PRC-87 已覆盖第一种**，补上报销类型与来源后，第三种也能纳入。
- **第二种目前没有流程**：老系统只做到「拉取月账单、整月核对」，没有生成应付、付款和凭证；新系统要补「分贝通月账单对账 → 应付 → 付款」。
- **还缺三个事前环节**：出差申请（分贝通订票前要有申请）、业务招待事前申请（决定可报销额度），以及分贝通超标订单审批。

## 3. 结构问题（交 one-architecture；需要新流程号、可能需要新聚合）

| # | 问题 | 建议 |
|---|---|---|
| G-F1 | 业务招待事前申请（额度）没有聚合与流程；AGG-59 已写「超事前预批额度 P-37 预警」，但额度从哪来没有落点 | 新增聚合「费用事前申请」（B-12），覆盖业务招待额度；新流程「事前申请费用额度」（B-12，走审批平台）。是否扩到所有费用类别，交用户定 |
| G-F2 | 分贝通公司直付订单的月账单对账、应付、付款、成本归属都没有 | 新流程「核对分贝通月账单并确认应付」：分贝通（external:分贝通）推送订单 → 按出差申请归属到项目或部门 → 月账单核对（差异处理）→ 确认供方应付（AGG-52，往来方为分贝通）→ PRC-75 付款 → 费用事实过账。编排 BC 待定：B-12（费用归属在报销侧）或 B-10；订单与账单是否成聚合（建议 B-12 新聚合「差旅订单账单」）交 one-architecture |
| G-F3 | 出差申请与分贝通超标审批没有落点 | 新聚合「出差申请」（B-12）与新流程「申请出差并同步分贝通」，超标审批作为该流程的审批节点（engine platform.approval，结论回写分贝通，external:分贝通）；补贴按出差申请的类型与天数生成 |
| G-F4 | 直接付款申请（无来源单据）、预付核销、外部代发：现 PRC-75 由「应付已确认」触发，没有「先申请付款、后形成应付」的入口 | 确认 AGG-52 是否提供「登记其他应付 / 预付」命令与对应流程；缺则补命令与流程（E7、E8、E10、E11） |
| G-F5 | 信息服务费备案 | 判断是否属于供方协议的一种（AGG-55 协议类型），属则并入 PRC-70；否则新增 |
| G-F7 | 出差补贴标准（按差旅类型与天数）由谁定、按版本生效 | 配置型版本（D15），财务编制、财务负责人批；标准取值交用户 |
| G-F6 | 分贝通作为外部系统的集成登记（订单、发票、账单、审批回写、组织员工同步） | 按 §14.3 登记集成册；员工与部门向分贝通单向同步归 B-13 或 platform.integration |

## 4. 需要生产取证或问财务的（不做明细，只出计数）

问财务（事实题，建议 one-coordinator 一并问用户）：
1. 现在怎么付分贝通的账单：预充值、月结，还是两者都有；付款走 A8 哪个表单。
2. 员工还会不会把分贝通订单再报进 A8 差旅报销单（防重复报销）；2026-09 以后的规定。
3. 「待打款」之后的线下付款，记账走 A8 付款申请单、U8C 手工凭证，还是出纳直接做。

取证清单（按 ADR-0037 经 one-ops 只读通道，只出计数或聚合）：
- A8 付款申请单按收款单位为分贝通的月度单数与金额合计（近 24 个月）；
- A8 差旅报销单含分贝通订单引用的占比；
- A8 报销、借款、还款、预付核销表单的字段清单（只取字段名与类型，不取值）；
- A8 各报销模板在途单据按当前节点的分布与超过 90 天的数量；
- 老系统差旅单按状态的分布、分贝通 webhook 按消息类型的计数；
- 员工银行卡视图（老系统迁移脚本注明用于「分贝通报销打款」，代码里没有引用）的实际消费者数。

## 5. 对 PRC-87 的直接改动（本组做，不等结构裁定）

- 报销类型：日常、差旅、业务招待；第 2 步发票来源可为「员工录入（external:税务 查验）」或「分贝通垫资发票（external:分贝通，验真结果随发票）」。
- 明细支持补贴行（不需要发票），补贴标准为配置（待定 G-F7）。
- 业务招待引用事前申请，超额度预警（待 G-F1 落聚合后接上）。
