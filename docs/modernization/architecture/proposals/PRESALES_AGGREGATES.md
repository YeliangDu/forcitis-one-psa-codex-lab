# 售前到签约：不变量 → 聚合 → BC（第 2 稿，待用户定）

依据：METHOD 第 2、3 步（ADR-0041，#222 合入后生效）；信息图 `PRESALES_INFO_MAP.md` 与用户确认（intent `2026-10-15-205406`）；行业研究 `AEC_BUSINESS_OBJECTS.md`；取证 `PRESALES_OBJECTS_EVIDENCE.md`。约束：已采纳 ADR 优先（ADR-0016 决定 1、8、9；ADR-0021）；一个事务只改一个聚合（§14 第 1 项）；跨 BC 只经 api 或事件；模块依赖不成环（ModularityTest）。

第 1 稿经 opus 对抗评审（2026-10-15），主要修改：依赖骨架改为无环；补「合同与投标承诺一致」；限额占用前移到提交审批；5 条「不变量」改归为策略或预警；补联合体、多标段、合同—项目对应；保证金下沉到应收；拆分「战略协议」；补阶段与迁移；事件改用词表已有名称。

## 1. 依赖骨架（先定方向，再划 BC）

```
往来单位（含协议价目）  ←  售前  ←  合同  ←  应收（保证金、质保金）
                                  ↖        成本（售前投入转入）
reporting（风险交付度量、承诺量达成、售前投入）读所有
```
箭头指向被依赖方。下游依赖上游的 api，上游的变化经事件通知下游；上游从不引用下游。

## 2. 不变量（违反即拒绝）

| # | 不变量 | 来源 | 所在聚合 |
|---|---|---|---|
| I-1 | 线索关闭须有原因；已确认的线索不能再关闭；挂起可恢复为跟进 | 用户 | 线索 |
| I-2 | 一个线索至多建一个商机（商机带唯一的来源线索；先建商机，线索响应事件转为已确认） | 取证（261 条不一致）；评审 | 商机 |
| I-3 | 商机必须有正式往来单位（线索可以没有）；只有一个负责人 | 用户（不强制建客户） | 商机 |
| I-4 | 赢单须有证据：某次投标中标，或直接委托的委托证据 | 招标投标法第 45 条 | 商机 |
| I-5 | 同一（商机，标段）任一时刻只有一个生效报价版本；已通过的版本不可改 | 用户（只有版本链） | 报价版本（每版本一个聚合，部分唯一索引） |
| I-6 | 同一招标同一标段，我方只能以一种身份参加一次（单独、牵头或成员） | 招标投标法第 31 条；条例第 37 条 | 投标（部分唯一索引） |
| I-7 | 依法招标的合同，基线化前须完成与中标投标承诺的比对；实质性条款（价格、范围、工期、质量）不得背离，差异只能拒绝或澄清；非招标的差异须有处理结论 | 招标投标法第 46 条；词表 `proposal_commitment_snapshot`、`commitment_deviation` | 合同 |
| I-8 | 合同须有来源：赢单商机，或经审批的直建例外 | 词表 `contract_source_ref` | 合同 |
| I-9 | 回签即生效；生效后只能经变更产生新基线 | 用户 | 合同 |
| I-10 | 框架协议限额：合同提交审批时占用，驳回、作废、终止时释放，变更按增减额重占或释放；回签后超额只预警 | 用户（有限额型）；词表 `framework_capacity_reservation` | 框架协议 |
| I-11 | 保证金的退还与没收互斥、各只发生一次；履约保证金可部分扣减 | 条例第 35、57、58 条 | 保证金 |
| I-12 | 风险交付授权：同一对象同类型同时段唯一；转正与叫停互斥 | 词表 | 风险交付授权 |

改归为策略、判定或预警（不拦操作）：商机终态后新建报价或投标（写入前检查）；保证金比例上限（判定、预警）；风险交付超额度、超期（度量与预警，`reporting`）；承诺量达成（度量）；售前投入转入（流程编排，见 §5）。

## 3. 聚合

| 聚合 | 内部 | 要点 |
|---|---|---|
| 线索 | 来源（类型）、认领人、挂起 / 关闭原因 | 公海池认领用聚合版本号（乐观锁）即可 |
| 商机 | 参与团队与角色、委托方式（分类第二套）、丢单信息（原因、竞争对手、中标单位、中标价） | 来源（分类第一套）在线索上 |
| 报价版本 | 成本估算、工时估算、协议价目版本引用 | 每版本一个聚合（与词表 `quote` 一致）；「新版生效、旧版被取代」在同一事务里改同类型两个实例，先例 `ConfirmSourceReference` |
| 投标 | 招标标识 + 标段、参与方式与联合体成员、采购方式、资格预审结果、投标报价（报价版本 ID）、截止后撤销 | 核心状态：准备 → 递交 → 结果（中标 / 未中标 / 废标）；资格预审、开标、公示等按采购方式可选；截止前撤回、截止后撤销分开 |
| 往来单位 | 角色（客户 / 供应商）、联系人、所属集团 | 按 D17 版本化；合并时广播事件 |
| 协议价目 | 单价条目、生效期 | 配置型版本（D15、D17），报价与合同记所用版本 ID |
| 合同 | 基线版本、条款、付款条件、联合体形态与我方份额、合同—项目关联 | I-7、I-8、I-9 |
| 框架协议 | 限额与占用 | 沿用词表 `framework_agreement` |
| 合同变更 | 范围 / 价格 / 工期（产生新基线） | 「合同信息更正」（名称、附件等）只留痕不动基线；签证、索赔为同 BC 独立聚合（ADR-0016 决定 9） |
| 风险交付授权 | 额度、期限、责任人、转正 / 叫停 | 只登记；度量与预警在 `reporting` |
| 保证金 | 类型（投标 / 履约）、形式（现金 / 保函）、退还、没收、扣减 | 现金保证金触账，经 `operations.facts`（ADR-0016 决定 1） |

## 4. BC（推荐方案）

| BC（暂名，用语交 one-glossary） | 聚合 | 深 / 薄 | 依赖 | 阶段 |
|---|---|---|---|---|
| 往来单位主数据 | 往来单位、集团、协议价目 | 薄（版本化） | 无业务依赖 | 6a 之前；1b 期间经集成层读 A8 |
| 售前 | 线索、商机、投标、报价版本 | 深（投标、报价） | → 往来单位 | 1b 只做报价（商机经集成层引用 A8）；其余待定 |
| 合同（三合一，需新 ADR） | 合同、框架协议、合同变更、签证、索赔、风险交付授权 | 深 | → 售前、→ 往来单位 | 6a |
| `receivables.collection` | 保证金（应收类型，与质保金同列） | 深（触账） | → 合同、→ 售前 | 6b |
| `cost.costing` | 售前投入转入 | 深 | → 售前、→ 合同 | 4 |
| `reporting` | 风险交付度量、承诺量达成、售前投入 | 只读 | → 各 BC | 随阶段 |

## 5. 售前投入转入（用户定：赢单后转入项目）

管理口径：「商机已赢单」且合同生效、项目已建立后，按冲销 + 新事实转入开放期间（ADR-0016 决定 1、2），不改工时行原归集；赢单后长期不签约的设超时规则；一个商机对应多份合同时按合同额分摊。财务口径：按 CAS 14 第二十八条，投标费用通常计入当期损益——两种口径可以并存，**交财务确认**。

## 6. 跨 BC 事件（用词表已有名称，缺的登记提议术语）

售前：线索已确认、`OpportunityAccepted`（赢单）、商机已丢单 / 已放弃、投标已递交（携承诺快照引用）、投标未中标、投标已撤销、报价版本已生效、`ProposalCommitted`。合同：`ContractSigned`（回签）、合同已终止、`ChangeOrderApproved`、框架限额占用被拒。往来单位：往来单位已合并。应收：保证金已缴 / 已退 / 已没收。交付：项目已建立（独立发生，可早于合同）。

## 7. 迁移要点（阶段规格中细化）

商机 9,221、A8 报价 7,210（无版本链，迁为各自独立的已通过版本）、合同 5,247（「合同 = 项目档案」拆为合同与项目两个对象）、历史子项合同 2,072 份未挂框架（按无框架合同迁入）、虚拟客户不迁（历史单据引用改指迁入时确定的往来单位或保留原名文本）。线索、商机是否迁入按 ADR-0021「视情况」交用户定。
