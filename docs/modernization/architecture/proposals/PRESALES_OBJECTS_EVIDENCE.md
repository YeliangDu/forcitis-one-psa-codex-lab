## 0. 先说三个结构性事实

1. **老系统里的线索、商机、客户、集团、项目（含「合同」）都是 A8 的只读镜像**，由 A8 → 老系统的同步作业写入，老系统自己不是这些对象的来源。证据：商机同步 A8 `formmain_0238` → `psa_crm_opportunity`（`docs/ops/oa-opportunity-sync/README.md:3-5`）；`psa_pm_contract` 是 A8 视图，不是表（`[mig]/V20260920190100__rebuild_psa_pm_contract_a8_by_db_name.sql:45-53`）；`psa_crm_opportunity` 9,221 行、`psa_crm_leads` 9,545 行，与 A8 档案行数相同。**只有报价是老系统自己的**，且 2026-09-23 才开始用（`psa_quotation` 最早一条 2026-09-23），之前报价在 A8。
2. **「合同」在老系统里就是项目档案**：`psa_pm_contract` 以 A8 项目档案 `formmain_0051` 为主，左连销售合同档案 `formmain_0374`（取回签日期）与商机档案 `formmain_0238`；`id = 项目档案 ID + 1`，一项目一合同（`[mig]/V20260920190100…sql:45-53`）。老系统的合同领域包只有一个说明文件，没有实体（`[biz]/domain/contract/package-info.java:1-10`）。
3. **没有「投标 / 标书」「风险交付授权」「框架协议 / 任务订单」「合同版本」这几个对象本身**：A8 与老系统里都没有同名表单、表、字段（A8 表单与模板名全量检索、老系统表名与枚举检索）。它们的影子分别是：委托机制与商机阶段（投标）、战略框架合同 / 战略子项合同（框架 / 任务订单）、立项早于回签与「无合同立项原因说明」（风险交付）、合同变更流程单（版本）。详见各节。

## 12. 局限

- **镜像不是来源**：老系统里的线索、商机、客户、集团、项目是 A8 的同步副本，数量与状态以 A8 为准；本次未核对两边字段是否逐行一致，只核对了行数（商机、线索相同，客户老系统多 419、集团多 26）。
- **快照无历史**：状态是当前值，没有阶段迁移时间，算不出各阶段停留时长、阶段间转化率；A8 变更历史表为空。
- **「近 24 个月」用创建时间**：档案类表单的创建时间可能是导入或归档时间，不一定是业务发生时间；按年分布显示 2020 年有一次批量建档（合同、项目、报价 2020 年量偏大）。
- **字段含义取自表单定义**：字段名、枚举来自 `CAP_FORM_DEFINITION` 与 `CTP_ENUM_ITEM`，未读 A8 触发器与流程节点规则；`finishedflag` 取值 1 视为已结束是按数量吻合推断（`ratifyflag` 全 0）。
- **未取子表与条款级关系**：A8 条款子表（`formson_0296`、`0376`）与框架限额相关字段未逐个核实；合同「有效期」字段仅按有无统计。
