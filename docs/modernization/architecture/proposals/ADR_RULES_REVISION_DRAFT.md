### 4. 取代与被部分取代

- 「取代」写在新 ADR，「被部分取代」写在被取代的新格式 ADR；两边必须成对，生成器双向核对。
- 每项一行，**以 `ADR-NNNN` 开头**，后接可选的范围短语；范围只写到「小节 + 条号」，如 `ADR-0047 决定第 5 条第 4 点`、`ADR-0024 影响面「BC」`、`ADR-0041 决定 1（部分）`。
- 不写行号，不写文件路径，范围短语不超过 30 字；逐句细目（被替换的原句、替换后的写法）写进本 ADR 的「决定」或「背景」。
- 整份取代：项中只写 `ADR-NNNN`，被取代方状态改为「已被 ADR-本号 取代」。部分取代：被取代方为新稿时在「被部分取代」加一项 `ADR-本号 范围`；为旧稿时在状态行末尾括注「（范围已被 ADR-本号 取代）」。
- 以上修改与新 ADR 改为「已采纳」在同一提交中完成。

### 5. 小节

二级标题只能取下列名称，按此顺序，不得增设（附加内容并入现有小节：与其他 ADR 的关系写入「背景」，未定事项与接口写入「后果」，评审记录写入「证据」）：

背景 / 决定 / 影响面 / 迁移方案 / 回滚方案 / 需同步修改的守护规则 / 后果 / 证据 / 备选方案（未采用）

| 档位 | 采纳时必有 | 可选 |
|---|---|---|
| 正式 | 全部九节 | — |
| 轻量 | 决定、影响面、证据 | 背景、回滚方案 |

提议期只校验小节名与顺序，不校验是否齐全；改为「已采纳」时校验齐全。

### 6. 档位与勘误

**正式档**：默认档位。

**轻量档**用于可回退的小决定，须同时满足：
1. 回退不涉及已过账事实、已应用迁移（基线关闭后）、已发布的对外接口；
2. 不改变 BC 边界，不引入新的依赖或技术选型；
3. 至多部分取代一份已采纳 ADR 的一条；
4. 源文件不超过 6 KB。

任一条不满足即用正式档。轻量档的「决定」用一句话写：「在〈情境〉下，面对〈问题〉，决定〈方案〉而非〈备选〉，以达成〈目标〉，接受〈代价〉。」后接可判定的条款。轻量档同样占全局编号、经用户批准。

**勘误**不是 ADR、不占编号、不改正文：只用于不改变决定含义的问题（笔误、失效链接、文件或模块改名后的引用、残留标记）。在「勘误与历史偏差」第 2 节登记正确读法，one-coordinator 核对后合并，不需用户批准。拿不准是否改变含义的，按轻量档或正式档走。

### 7. 一份一决定与大小

- 新稿一份只做一个决定（可有多条实施条款，但只有一个可单独采纳或拒绝的选择）；两个可分别采纳或拒绝的选择拆成两份。
- 正式档源文件超过 20 KB（20,480 字节）须拆：提议时生成器告警，改为非提议状态时生成失败。

### 8. 占号与起草

1. **占号**：起草者用 `new_adr.py` 取下一个号，生成空壳并单独开 PR；空壳 PR 合入 main 即占号，不在分支上手查号码。两个 PR 争同号时先合入者得号，后者改号。
2. **空壳最少内容**：完整头部（状态「提议」；类别、BC、阶段可写 `待定`）+「背景」一节两到五句：要决定什么、为什么现在决定、触发出处（intent、派工或评审编号）。
3. **起草即校验**：提议稿与已采纳稿一样落在 `adr/src/`，生成器对提议稿校验头部、字段取值、小节名与顺序、「取代」写法与对象存在。ADR 草稿不再放 `architecture/proposals/`（该目录留给研究、设计方案与评审记录）。
4. **提议不是结论**：其他文档不得把提议稿当作已决定引用。
5. **撤回**：状态改「已撤回」并写理由，文件保留，号不复用。

### 9. 评审

1. 正式档：提议阶段经 `code-modernization:architecture-critic`（opus）对抗性评审；轻量档按评审模板 `quality/review-briefs/03-adr.md` 的轻量子集评审。评审意见与处理结果写入「证据」。
2. **全文检索被改条款**（每份新稿必做）：起草者对本 ADR 修订或涉及的对象、表、列、枚举值、权限码、BC 标识，在 `adr/src/` 全文检索，在「证据」中写「检索记录」：检索词、命令、命中的 ADR 列表，以及每份的结论（相容 / 本 ADR 取代其某条 / 无关）。评审员重放检索并核对：命中而未列入「取代」又判为不相容的，评审不通过。
3. 用户批准后改为「已采纳」，填用户原话与批准证据。

### 10. 提议复审

1. 状态为「提议」且距「日期」超过 7 天的，生成器在 `build_all.py` 输出与 `STATUS.md` 中列为超期提议。
2. one-coordinator 在 `COORDINATOR_LEDGER.md`「ADR 提议复审」一节维护超期提议与搁置清单，每周一在每日简报中列一次，并提交到待决定收件箱（SESSION_PLAYBOOK §11 战队协作第 1、8 条）；起草会话由「起草」字段确定，调度同时通知它补齐材料。
3. 复审结论只有三种：采纳、拒绝、搁置。搁置须写原因与重启条件；调度每周核对重启条件，满足后状态回到「提议」、日期改为当日。
4. 超期不自动作废。
5. 自动核对：intent 中出现对某 ADR 的批准、拒绝或搁置，而该 ADR 状态未相应改变的，生成时告警。

每份 ADR 一个源文件 `src/ADR-NNNN.md`，本 README 的说明段落在 `src/_readme_*.md`；由 `build_adrs.py`（经 `../build_all.py`）生成 `ADR-*.md`、本 README 与 `INDEX.md`，不手改生成产物。生成器校验：状态属于第 2 节；新稿头部字段按第 3 节；类别、BC、阶段取值有效；小节按第 5 节；「取代」与「被部分取代」按第 4 节且双向成立；大小按第 7 节；编号从 0001 起连续无缺号。校验不通过则生成失败，不写任何产物；超期提议、intent 核对只告警。
