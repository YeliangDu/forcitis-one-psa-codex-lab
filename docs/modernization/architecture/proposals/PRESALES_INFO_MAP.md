## 3. 三方不一致处（需用户定，见确认页）

1. 合同与项目：行业把合同（收入单位）与项目（交付单位）分开；老系统两者是同一份档案。（已定：合同与项目分开 i205406；多对多 i210513）
2. 风险交付：老系统没有授权、立项早于回签是常态；新系统做硬控制会立即影响约 90% 的项目。（已定：登记 + 度量 + 预警，i205406；与 Q19 的衔接见 C-53、C-56）
3. 报价：用户说经常多轮，取证平均约 1.3 张、无版本链——多轮是否在线下改，还是同一张反复改。（已定：只有版本链，i205406）
4. 投标：两边系统都没有，行业与法规要求独立对象；比选、竞争性谈判、直接委托是否同一对象。（已定：所有竞争性采购建投标、可多次、可联合体，i205406；直接委托不涉及投标，赢单证据为委托证据，〔售聚〕I-4）
5. 战略协议：老系统按「框架 + 子项」挂靠，用户描述为「只定单价、另签合同」。（已定：两种都有，有限额的为框架协议、只定单价的为协议价目，i205406、i210513）
6. 虚拟客户：60% 客户是虚拟的，说明线索阶段被迫建客户档案；行业做法是线索可以没有客户档案。（已定：线索不强制建客户、虚拟客户不迁，i205406）

## 4. 工作分解的一级 / 次级划分（用户 2026-10-15 同意，intent 见 2026-10-15 one-architecture「有权威理论来源，我同意」）

- 判据：一级 / 次级按依附关系，不按生命长短（BIZBOK v11 §2.5，第 194–195、198 页：次级概念依附其他对象存在，例 Agreement Term 依附 Agreement）。三者分别依附报价（OBJ-21，商机的次级）、协议（OBJ-05，一级；合同是它的类型之一）、项目（OBJ-29，一级），按依附判据即为三个不同的次级概念；报价、合同、项目并非「三个一级对象」（全企业稿 C-38、PRIMARY_OBJECT_TEST）（2026-10-15 opus 评审指出：此前另引 DDD Reference 第 2 页属跨框架误用——限界上下文是领域模型层的概念，不用于业务对象识别，已删去）。
- 一级：服务产品（OBJ-24）与阶段类型（OBJ-25），不依附任何项目（一级对象检验通过）；标准成本费率表（OBJ-26，一级）及其次级计费系数（OBJ-27）同为报价的上游参数（i211139）。
- 次级：报价估算分解（OBJ-22，依附报价，随版本冻结）→ 合同范围条目（OBJ-06，依附协议，只经变更修改；依法招标的不得背离投标承诺）→ WBS 节点（OBJ-30，依附项目；节点类型阶段、子项、工作包，按执行调整、改后更新基线）。
- 串联：每个范围条目自报价起带稳定追溯编号；合同条目记来源报价版本条目，WBS 节点记对应合同条目（可后补，项目可先于合同；挂接即决定收入与成本归属，用户 2026-10-15 Q12，未挂接情形见 C-50），变更记「取代」关系。报价与投标时点须保留快照（合同承诺比对）。
