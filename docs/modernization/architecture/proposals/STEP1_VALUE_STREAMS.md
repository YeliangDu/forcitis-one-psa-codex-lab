### 3.2 推导说明

1. **从干系人与价值推导，不按老系统模块**：每条价值流对应「一组触发干系人 + 一种价值」；触发者与价值各异就分开（BIZBOK 第 157–158 页）。由此新增 VS-03（资本方、既有建筑业主要的是风险结论，不是设计成果）、VS-06（企业监管按法定期限触发）、VS-11（K-1 建知识条目 OBJ-110 后有对象可写门）、VS-12（股东「触：年度回报」，待 Q-C）；把现行「支出到付款」拆为采购（VS-05）与报销（VS-08）——触发者与价值都不同；把现行 VS-03、VS-04 合为 VS-04——同一价值（客户支付价款）；把现行 VS-06 拆为任用员工（VS-07，用人经理与候选人触发，到入职）与获得报酬（VS-13，在职员工触发）——触发者与价值都不同。
2. **VS-03 独立成价值流是推出，不再是待定题**：触发者（资本方、既有建筑业主）与价值（风险结论）都与交付成果不同（BIZBOK 第 157–158 页）。**边界**：品控类服务在施工期做的检查（M-11 施工期类型的 OBJ-49）留在 VS-02.6；资本方或既有建筑业主委托的检查、尽调归 VS-03。阶段用自有阶段（检查策划、现场检查、发现发布、整改跟踪、报告认可），阶段类型目录另设「检查」类（用户答复 Q-A 选 a，intent 082311；`STAGE_TYPES_DRAFT.md` §4 第 1 条已同步）。
3. **交付与收入分开，经对象状态衔接**【推出】：S3 已定阶段只表示工作进程、与商务分界脱开；生产上 90.3% 的项目立项早于回签（C-43），合同可能在交付任一段签。若把合同、收入、开票放进交付阶段，就得让阶段承担商务含义。故 VS-04 单列（BIZBOK 第 157 页：价值流只经共享对象状态相互影响），VS-04.2 以 OBJ-35 的交付侧事实进入，VS-02 各段与结项读取 OBJ-08（共享关系见 3.3 的共享依赖表）。
4. **手册七段即 VS-02 阶段**（M-6）：门按对象状态重写为公共模式——进入：该段 WBS 阶段节点 OBJ-30「未开始 / 进行中」，即已按协议范围建出、未作废，**不依赖启动段的退出**；退出：该段需认可的交付物 OBJ-35 的**交付侧事实**——「已认可」，或「已交付（签收）/ 审查中」且「已声明」（D-8：视为同意的期满判定在收入确认段，交付侧不记「视为同意」），且阶段节点「已完成」；方案、初设、深化另加提资 OBJ-42「已提供」，施工另加我方成果不符合项 OBJ-38「关闭」，启动、结算各有专门条件。启动段进入条件同价值流起始条件（赢单、先行投入批准、直接签约的协议生效），退出为项目「已立项」等。工作子阶段不升格（没有独立的门）。「概念」是目录候选（景观线），标可选。门只预警（S2），阶段并行、倒序、跳段照常。
