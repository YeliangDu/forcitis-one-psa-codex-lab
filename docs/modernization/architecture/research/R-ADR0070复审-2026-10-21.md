# R-ADR0070 首轮独立复审（ARC-1021-COO-05）

- 对象：`pr495:docs/modernization/adr/src/ADR-0070.md`（@446fb3e3，叠在 #493 之上），状态「提议」，起草 one-architecture。
- 依据：用户 #494 评论 6311040189（8 条建成判据与两条提醒）；ADR-0060、0061、0062、0066、0067；`_readme_lifecycle.md`；实施卡 OPS-1021-OPS-02（origin/claude/one-ops-r56 @c5ac20d5）；`att_size_result.md`（P99 97.1 MB、P99.9 465 MB、最大约 2.5 GB、超过 100 MB 的占 0.97%）。
- 方式：只读，未改仓库。

## 结论

**改后可进批准页，现在不能。** 8 条判据、两条提醒都有对应，方向正确。尤其把检测前移到本地暂存，同时满足了「`SCAN` 不用 `INSTREAM`」和「临时区不可外读」，这一判断成立。

问题集中在前移后新带出的工程问题，ADR 没有交代：
- clamd 读文件的权限与「目录只给后端用户」自相矛盾；
- 同步还是异步没有写明；
- 「进程重启时清空残留」在多实例、蓝绿部署和共享目录下会误删别人的文件，被清掉的那笔也会无声无息；
- 判定后「立即删除」与先上传对象存储的先后顺序有冲突；
- nginx 与 multipart 的落盘会形成第二份未检副本；
- 加密压缩包与加密文档实际上等于静默放行；
- 隔离区内容谁能读、留来做什么，没有写明。

取代字段漏了 ADR-0060 决定 2「写入内容」一行。宏判定方法覆盖不全，而且与「不打开文件内容」字面冲突。单文件上限没有擅自定数值（合格），但没有写明这是用户待定事项，也没有写明「≤ 2 GB」这个引擎硬上限。

必改 12 项（高 5、中 5、低 2），建议 9 项。

## 二、检测前移到本地暂存后带出的问题

### 2.1 多实例与部署形态
- 如果扫描**同步**完成（在一次上传请求内），本地暂存只在收到请求的那个实例上存在，不会出现跨实例一致性问题。如果走**异步**，暂存文件要在请求结束后继续存在，故障恢复和重启清理就都要另行设计。ADR 两种都没写。ADR-0060 的指标「检测待处理最久时长」、`GET /files/{id}` 查检测状态，暗示过异步。→ M2
- 「进程重启时清空残留」的问题：
  - 同一台 ECS 上蓝绿或滚动部署时，两个后端进程共用一个目录，新进程启动会删掉旧进程正在扫的文件；
  - 采用「同 VPC 小机 + 共享暂存目录」时，任何一个实例重启都会清掉所有实例的文件；
  - 被清掉的那笔上传不会产生结论，也没有告警，违反 CLAUDE.md 规则 6。
  → M3
- 小机方案要在两台机器上用同一个路径挂载共享目录（NFS 或 NAS），这是新增的基础设施和故障面，影响面、one-ops 段都没提。→ S5

### 2.2 权限
- 决定 2.4 写「目录权限只给后端运行用户」，但 `SCAN <路径>` 要求 clamd 进程（通常以 `clamav` 用户运行）能读这个文件，二者矛盾。要写明一种做法：共用组只读；clamd 以后端用户运行；或者 clamd 只开 unix socket，用 `FILDES` 传文件描述符（这样不用 `INSTREAM`、没有流长度上限、也不需要路径可读，但偏离了用户「`SCAN`」的字面，采用要报用户）。→ M1

### 2.3 磁盘与内存
- 磁盘：暂存需求约为「并发上传数 × 单文件上限」。clamd 解包压缩文件还会在 `TemporaryDirectory` 再落一份，2 GB 的压缩包解开后可能远大于 2 GB。磁盘写满时要按「不可用」拒绝并告警，暂存目录应放独立卷或设配额，免得挤占系统盘和日志盘。
- 内存：clamd 加载全库后常驻约 1–1.5 GB；`freshclam` 触发热加载时，默认会短时占用双倍内存。若改 `ConcurrentDatabaseReload no` 不占双倍，代价是加载期间扫描阻塞，可能每天造成几次「不可用」拒绝。两条路都要在 ADR 或实施卡里写一个取舍。
- 以上并入 M5。

### 2.4 失败恢复
- 判定为「通过」之后，写对象存储失败或读回核对失败怎么办，没写：应拒绝、告警、删本地文件，状态落到终态。
- `stored_files` 的行什么时候插入也没写：是检测前还是判定后？「对象键」在 ADR-0060 里由触发器禁止更新，而本篇的对象键要等判定后才知道（临时区或隔离前缀）。审计要求有「文件 ID」，所以被拒的那笔是否留行、留什么状态，也要定。
- 客户端超时后带同一个 `Idempotency-Key` 重试：如果第一笔还在扫描，幂等记录必须存在数据库里，不能存在本地。
- 以上并入 M2、M4。

### 2.5 与「后端中转、边写边算 SHA-256」的衔接
- 新流程是：上传流 → 本地文件（算哈希）→ `SCAN` → 上传对象存储。要保证三点：
  1. 扫的就是算过哈希的那份字节：写完 `fsync` 并关闭句柄后才发 `SCAN`；
  2. 上传的就是扫过的那份：上传后按 ADR-0060「写后读回核对大小与哈希」整笔核对；
  3. 判定后不能「立即删除」：必须等对象存储写入并读回核对完成后才删。决定 2.4「判定后立即删除（无论结论）」与 2.3 先写对象存储的顺序冲突。
  → M4
- 第二份未检副本：nginx 默认 `proxy_request_buffering on`，会把整个请求体先落到 `client_body_temp`；Spring multipart 超过阈值也会落到 `java.io.tmpdir`。这两处都是本篇管不到的本地落盘，权限和清理都不受控。要么写明「流式转发、不经 multipart 临时文件」，要么把这两处目录纳入同一管控。→ M4
- 时延：从「一跳流式进对象存储」变成「落盘 + 扫描 + 再上传」，2 GB 文件在同步模式下请求时长可能有几分钟，nginx 与网关的超时要随上限一起定（并入 M10 的参数位）。

### 2.6 隔离前缀
- 访问：决定 2.5 让下载角色无权读隔离前缀。如果谁都不能读，保留内容就没有意义；用户判据 4 只要求「隔离、不可关联、留 SHA-256」，没要求留内容。要写明留内容的目的（误报复核或事件取证），谁能读（安全角色经审批、带审计），以及误报能否放行（重新扫描、人工放行，还是只能重新上传）。ADR-0060 交给 one-security 的「重扫」问题本篇也没接。→ M7
- 保存期：「配置项，缺失启动失败」可以。还要补：
  - 默认值或取值范围；
  - 桶开了版本控制（ADR-0060 决定 6 待 one-ops 定）时，生命周期过期只会打删除标记，要另配「非当前版本过期」规则；
  - 误报文件可能含个人信息，保存要有 ADR-0043 意义下的用途说明。
  → S6

## 三、取代范围与宏判定

### 3.1 取代字段
- 头部两项都以 `ADR-NNNN` 开头，范围短语不超过 30 字，合规。按生命周期第 4 节，「被部分取代」字段等用户批准后再在 ADR-0060、0062 上同一提交加，现在不加是对的。
- **漏列**：ADR-0060 决定 2 表的「写入内容」一行（「后端流式写入临时区，边写边算 SHA-256」）也被本篇改了：先写本地暂存，通过后才进临时区。要补一项取代，或者在正文里说明为什么这一行不算被取代。→ M11
- ADR-0060 决定 5 第 4 条（未通过「不进正式区」，原来实际上留在临时区随过期清掉）被改成「写入隔离前缀、按保留期过期」，属于新增行为，也应写进取代范围或逐句细目。→ M11
- ADR-0062 决定 2 第 1 条的核对项（「媒体类型在预览范围内」）事实上加了一条「不含宏」。建议列为取代，或写明是「追加前置条件，原句不变」。→ M11
- 生命周期第 4 节要求把被替换的原句和替换后的写法写进本 ADR 的决定或背景。背景只写了冲突的理由，没有逐句对照。→ M11
- 条号笔误：决定 1.1 的「ADR-0060 决定 2 第 3 条不变」应为**决定 1 第 3 条**（ADR-0060:44；实施卡写的也是「第 1 条第 3 款」）。正文混用「第 5 条第 2 项」和「决定 5 第 1 条」两种写法。→ M12
- 阶段只写了 W0，但决定 4.3、4.4 要随 ADR-0062 的预览在 W2 才生效，建议阶段加 W2（S7）。
- 与 ADR-0067 的冻结：`contains_macros` 和新的检测状态取值属于 `platform.file` 的表结构，必须在 W0 冻结点之前落定，否则以后要走解冻通道。建议在影响面写一句（S8）。与 ADR-0066 的分层没有冲突：适配器在 `platform.integration`，`platform.file → platform.integration` 的边已经存在。

### 3.2 `contains_macros` 判定是否可靠
现写法是：按扩展名判定启用宏的格式；doc、xls、ppt、docx、xlsx、pptx 看 OOXML 是否含 `vbaProject.bin`、OLE2 是否含 VBA 存储；判定失败按「含宏」处理。「失败即按含宏」这条兜底是对的。缺口如下：
1. **Excel 4.0（XLM）宏表**不在 VBA 存储里：OOXML 在 `xl/macrosheets/`，xls 在 BIFF 的宏表里，按现写法会判成不含宏。这是近年常见的投递手法。
2. **xlsb**（二进制工作簿，可以带 VBA）以及 `xlam`、`ppam`、`ppsm`、`sldm` 等加载项和放映格式没有列出。只写「及其模板」不够。
3. **远程模板注入**：docx 的 `settings.xml.rels` 里 `attachedTemplate` 指向外部 `.dotm`，文件本身没有宏，打开时会去拉宏模板。
4. **ODF**（odt、ods）的 Basic 宏，以及 RTF 中嵌入的 OLE 对象，没有涉及。
5. 应当统一**按内容判定、不信扩展名**：把 `docm` 改名成 `docx` 时，扩展名规则失效，内容规则能兜住；反过来，改名后的文件应以内容为准。
6. **字面冲突**：决定 4.2 写「本系统任何环节不打开、不转换、不执行文件内容」，而 4.1 判定含宏必须解析 ZIP 或 OLE2 容器。ADR-0062 的预览服务本身也要做格式转换。应改成「只读解析容器目录、不渲染不执行；解析在检测通过后进行，设解包上限、禁用外部实体」，并注明预览按 ADR-0062 由服务方在服务端渲染。在后端 JVM 里解析不可信的 OOXML 本身就是攻击面（zip 炸弹、XXE）。
7. 参考：ClamAV 有 `AlertOLE2Macros`，但它会把文件报成「FOUND」进隔离，不宜直接拿来当属性判定。可以考虑 Apache POI 或参照 olevba 的检测集合，由 one-security 定检测集合，并附一组正负样本测试。
8. 压缩包里套着含宏文档的情况没有覆盖。建议压缩包下载也给「确认来源」提示，或者把压缩包一律按「无法判定 → 含宏」处理（S9）。

→ M8（检测集合与按内容判定）、M9（字面冲突与解析安全）

## 四、单文件大小上限
- ADR **没有擅自定数值**，写的是「≥ 业务单文件上限」「测得 P99 与 P95 后再定」「未定前不开放上传」「缺失即启动失败」，参数位留了，合格。
- 不足（→ M10）：
  1. 没写明这个上限是**用户待定事项**、候选值是多少（100 MB / 500 MB / 2 GB），只写了「运维测得后再定」，读者容易以为 one-ops 可以自己定；
  2. 没写**引擎硬上限**：ClamAV 单文件超过 2 GB 不能扫，所以业务上限必须 ≤ 2 GB，且 ≤ `MaxFileSize`、≤ `MaxScanSize`，启动时应交叉校验，不满足即失败；
  3. 证据过时：引用的实施卡是 @5643fbc5，P99 已在 @c5ac20d5 测出（97.1 MB，P99.9 465 MB，最大约 2.5 GB），正文仍写「测得」作将来时；
  4. 迁入走同一流程（决定 2.6）时，历史上超过上限的文件（无论上限定多少，最大约 2.5 GB 的那批一定超）会被拒收。要写明按 ADR-0060 迁移方案第 3 条「拒收带原因代码」进核对清单，不能静默跳过；也可以把留在 NAS 的去向交给用户定；
  5. nginx 的 `client_max_body_size` 和请求超时要跟这个上限联动（ADR-0060 已把它列为 one-ops 问题），本篇应引用。
- 建议区分两种超限：上传超过业务上限属于用户输入错误，回 413 并计数，不应每次触发 `ALERT`，否则会刷屏；引擎内部超限（`Heuristics.Limits.Exceeded.*`）才算「不可用 + 告警」。现在 2.3 把两种都归到「不可用」（S3）。

## 五、格式与篇幅
- 头部字段顺序、档位、类别（安全与权限）、BC、阶段都合规；「取代」短语不超过 30 字。正文 101 行，篇幅适中。
- 必备小节齐全：影响面、迁移方案、回滚方案、守护规则、后果、证据、备选方案。
- 「待登记用语」列了三项。另外，「本地检测暂存」和 ADR-0060 的「临时上传区」都叫「临时」，用户原话里的「临时区 / 临时目录」指的是本地扫描目录，容易同名异义。登记时应请 one-glossary 一并裁定，并互列。
- 背景里的行号引用（ADR-0060:114、129）与源文件核对一致。生命周期只禁止在「取代」字段里写行号，正文写行号可以。

## 七、建议项

- **S1** 守护规则加两条：适配器里禁止出现 `INSTREAM`（ArchUnit 或源码扫描，对应实施卡判据 1 的负向验收）；签预签名的接口拒绝非正式键（提醒 1 的机器版）。
- **S2** 出向：阿里云安全组只能按 IP 放行，`database.clamav.net` 走 CDN，IP 不固定，在国内访问也不稳定，库过期就会阻断上传。建议首选**内网镜像**（一台能出网的机器用 cvdupdate 拉库，后端机只从镜像更新）或带域名白名单的出向代理，并把「镜像不可用」也接进告警。
- **S3** 区分两种超限：上传超过业务上限回 413 并计数，不告警；引擎内部超限（`Heuristics.Limits.Exceeded.*`）映射为「不可用 + 告警」，适配器的映射表要写出来（实施卡写的「不可用 / 未通过」与 ADR 写的「不可用」不一致，要统一）。
- **S4** 审计补两项：未通过时记病毒名，不可用时记原因（不可达、超时、超限、库过期、磁盘满）。指标里把 ADR-0060 的「检测待处理最久时长」改为「检测耗时 P95」，与同步模型一致。
- **S5** 小机加共享目录方案要列进影响面：NFS 或 NAS 是新增依赖，路径要两边一致，并考虑共享存储挂掉时的行为。或者明说：同机放不下时先报 one-ops 和用户，再决定。
- **S6** 隔离保留期给出默认值或范围；桶开版本控制时补「非当前版本过期」规则；说明误报文件中个人信息的保存用途（ADR-0043）。
- **S7** 阶段加 W2（决定 4.3、4.4 随预览生效）。
- **S8** 影响面注明 `contains_macros` 和检测状态取值属于 ADR-0067 的冻结对象，须在 W0 冻结点前落定。
- **S9** 压缩包下载也给「确认来源」提示（压缩包里可能有含宏文件，引擎检出又偏弱）；术语登记时请 one-glossary 一并裁定「本地检测暂存」与「临时上传区」两个「临时」，避免同名异义。

## 八、需报用户的点（经调度）
1. 单文件上限的取值（M10，候选 100 MB / 500 MB / 2 GB，硬上限 ≤ 2 GB）。
2. 加密文件是拒收，还是放行但加提示（M6）。
3. 如果 M1 选用 `FILDES`，属于偏离「`SCAN`」字面，要报用户。
4. 隔离文件是否保留内容、误报能否放行（M7）。其中 M7 可以先由 one-security 给意见再报。
