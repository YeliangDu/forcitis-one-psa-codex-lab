## 二、跨份一致性

| # | 检查项 | 结论 | 说明 |
|---|---|---|---|
| 2.1 | 签后件「派生件」模型两稿一致 | 一致 | 签章决定 4 第 3 条与基础稿第 4 条第 3 点逐点对应：派生方式「签署」；签前件另出新版本的从新版本另行派生；重签各产新派生件；两个文件 ID 与哈希分别记录；基础稿 api 有「登记派生件」。图纸签章（第 6 条）的「签章后文件」是否也作派生件，两稿均未写（低，见 N8） |
| 2.2 | ADR-0051 只由基础稿修订，其余写相容 | 一致 | 基础稿头部取代两项；签章决定 2 第 3 条「本稿不另取代」；外部影响面「表由文件服务稿统一改写」；AI 决定 2 第 3 条「与文件服务基础 ADR 对该行的修订相容」；保存期、预览不涉及。基础稿影响面「已建模块不改名」句仍含「10 个平台模块」字样，基础稿说「一句不变」，属事实陈述，可不改 |
| 2.3 | 外部稿引用的文件服务接口名与基础稿一致 | **不一致（轻）** | 外部决定 7：「上传主体」「读取内容（核对哈希）」，基础稿叫「服务端读取」「（主体类型，主体 ID）」。外部稿写了「以定稿名为准」，但应直接改用基础稿用语。另基础稿 api 清单没有平台模块可调的「上传」项，见 N2 |
| 2.4 | 签章稿回调入口时点与外部稿一致 | **不一致** | 签章：先行上线开放时不开，某类印章切换时开，ADR-0054 新文称「回调入口随之在先行期生产运行」，守护第 7 条要求登记外部稿白名单。外部：决定 6 统一规则覆盖回调，但决定 11 第 2 条「通用审批先行上线（TRN-03）期间不开放本入口」，平台部分预计 W2 建。统一规则（主机名、网关、WAF、限流）由谁、何时建没有写，先行期回调开放时可能尚未存在。签章备选方案还引用外部稿「先行期不开放对外入口」，该原句在改后外部稿中已不存在。见 N3 |
| 2.5 | 暂名无撞车（seal 只给印章） | 基本一致 | 全部稿中 `seal` 只指印章；封存用 `file_holds`；`retention_*` 已提示与 `retention_money`、`data_retention_period` 的歧义。「签发」同时指链接、下载链接、预览凭据、交付物，仍只转交 glossary |
| 2.6 | 保存类别名称一致 | 一致 | 签章第 8 条「签署与用印文件」= 保存期表第 3 行「签署与用印文件（用印附件、签前件、签后件）」；签章记录不作类别名。起算口径（合同履行完毕 / 无合同的签署完成日）两稿一致 |
| 2.7 | 依赖方向无环 | 一致 | 逐边与现有 `module-dependencies.txt` 合并：file → integration、audit、identity、scheduling（后两者的现有出边不回指 file）；签章 → audit、integration、idempotency、file、workforce；外部 → audit、file、idempotency；业务 → 平台；预览无新边；AI 稿集成层无出边，场景 BC → audit、integration。均无环。AI 稿审计已改到调用侧，与原复审要求一致 |

## 五、给 one-coordinator 的处理建议

1. 先处理 N1 至 N4（中）：它们都落在文件服务基础稿的接口与时限上，且基础稿已无余量，须先压缩再增补。
2. N3 与外部必改 1 一并交 one-architecture 确认，交用户前取得回复。
3. 批准页须单列的点保持不变：两段式切换、电子印章就绪不作先行前提、自由文本按 `PI` 的后果、检测服务为先行上线硬依赖；另加「先行期回调入口的开放时点」。
4. 以上改完后不需要第三轮完整复审，只复核 N1 至 N4 与部分落实 6 条。
