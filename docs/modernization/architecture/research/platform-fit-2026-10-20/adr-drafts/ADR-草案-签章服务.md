## 背景

触发：用户定名「签章服务（电子签章/CA/图纸签章）」（intent `2026-10-20-201656`）；平台服务 6 问 Q01 选 (d)「省里指定单位制作并备案的电子印章」，落点要求公司用印整体电子化、调整 ADR-0054 先行上线的用印范围并做安全评审（`204731`）；Q03 选 (b)，执业签章在系统外完成，系统登记签章人、日期、文件指纹并核对执业资格（`204733`）；Q04 选 (a)，按类别设默认保存年限、合同约定从长（`204734`）；派 opus 起草（`211104`，ARC-1020-COO-02）。属用户指派，撤回须经用户。

取证（DAT-1020-COO-01，只出计数）：A8 用印申请近 24 个月 4,173 张，归属公司 6 个 × 印章类型 15 种共 35 组，「出图专用章（江苏）」523 次；电子签接口调用 0 次，现状纯线下；老系统无注册执业字段。

已有约束：用印申请（`seal_usage_request`，`organization.administration`，AGG-113）记「印章类别 + 用印法人」，用印登记是该 BC 的命令（INV-118、119、138）；审批不替代所属 BC 的事实处理（ADR-0055 决定 1），BPMN 只编排人工步骤（ADR-0007 决定 3）；外部概念只在 `platform.integration`（ADR-0039）；报价发出前核验实际用印登记（ADR-0057）。文件、内容哈希与签署件的派生关系由同批文件服务基础 ADR 草案（`platform.file`，暂名）定，保存期表由同批文件保存期 ADR 草案定，对外公开入口规则由同批外部访问 ADR 定，本稿引用不重定。

依据：`architecture/research/platform-fit-2026-10-20/` 下 A2 研究稿，以复核 `R2-签章服务复核.md`（下称 R2）为准；审题报告。本稿把「签章服务边界」与「ADR-0054 用印范围修订」写在一份，因后者是 Q01 (d) 的直接后果；其中两段式切换是起草推出的设计，批准页单列确认（决定 9）。BC 与阶段待模块标识登记、T 册写入后填实。

## 决定

### 1. 职责边界

1. 新设平台模块「签章服务」（标识待 one-glossary 登记），职责：印章台账、电子用印的发起与结果回收、签章记录（含图纸签章登记）、电子印章所绑定数字证书的元数据与生命周期。
2. 不做：审批（`platform.approval`）；用印申请的申请、批准、份数与用印登记（`organization.administration`）；文件字节、内容哈希与派生关系（文件服务）；服务商协议与回调（`platform.integration`）；对方回签与外部主体（外部访问 ADR）；保存年限表（文件保存期 ADR）。
3. 依赖方向：用印申请调用签章服务（api），签章服务不依赖 `organization.administration`，也不依赖任何调用方业务 BC；结果经 api 返回或经本模块事件发布，不回调调用方。后续调用方（`delivery.acceptance` 图纸签章登记、`contract.agreement` 签署证据）同样单向。签章服务只依赖 `platform.audit`、`platform.integration`（api、事件）、`platform.idempotency`、文件服务（api）、`organization.workforce`（api、事件，同 `platform.identity`、`platform.approval` 已有方向）。
4. 签章不是审批节点：审批只给批准结论；签章由业务命令在批准后调用。

### 2. 模块落点与命名

1. 落 `platform` 命名空间新模块，不并入 `platform.integration`（印章台账与签章记录是本系统概念，ADR-0039 决定 1 第 1、2 款），不放 `organization.administration`（合同、交付物等也要引用印章，而 B-31 不被业务 BC 依赖）。
2. 中文名「签章服务」；英文名、模块标识、schema、权限码前缀待 one-glossary 登记，登记前代码不落地。暂名约定：印章类对象英文暂名用 `seal`（与 `seal_usage_request` 同族）；文件封存不用 `seal`。「签章记录」只指本模块的记录（决定 7），保存类别用文件保存期稿的「签署与用印文件」（工作名），不另称签章记录。本稿「文件指纹」即文件服务的内容哈希（SHA-256），引用一律为「文件 ID + 内容哈希」。
3. 与 ADR-0051 相容：ADR-0051 决定 2 第 1 条、决定 3 说明句与表 platform 行中「10 个平台模块」的写死，由同批文件服务基础 ADR 统一改为「按已采纳 ADR 与 `contexts.yaml` 登记」，本稿不另取代；本模块按改后的规则登记。

### 3. 印章台账

1. **粒度**：台账条目 = 法人 × 印章类型，自有主键 UUIDv7；初始约 35 条（按取证）。法人用 kernel `LegalEntityId`，不新增依赖。条目带载体（实体 / 电子）与启停状态。
2. **业务唯一约束**：同一法人、同一印章类型在任一时点至多一条启用条目，用版本表的排他约束（法人, 印章类型, 有效区间）实现。
3. **版本化（DATA_DESIGN_CHECKLIST §14.1 D17）**：台账条目被用印登记按 ID 引用，属主数据，按维度型版本化：生效日 / 失效日左闭右开、`EXCLUDE USING gist` 防重叠、只追加、只许关闭不许改写，生效依据为业务声明日（`DECLARED`）；载体、启停、保管部门进版本表；用印登记按用印时刻取当时有效版本，早于最早版本即失败告警；首版本生效日回溯到迁入范围起点，使迁入的历史用印可取到版本。印章类型清单属参考数据，由行政提供（用户 B31-3），按 D15 配置型版本化（生效日、确认人、`decision_ref`）。
4. AGG-113 的「印章类别 + 用印法人」改为引用台账条目 ID。
5. 是否逐枚另定，触发条件二选一：行政确认同一法人同一类型有多枚实体章；或电子印章制作备案（备案即逐枚，作为条目下的逐枚记录追加，不改条目 ID）。
6. 持有人为自然人的执业印章条目随决定 6 建，不在先行期建（R2 §2 第 3 项）。

### 4. 电子印章（省级备案路径）

1. 对外有效的电子印章走《电子印章管理办法》（国办发〔2025〕33 号）：由省级明确的制作管理单位制作并备案（第十一条第（二）项、第十七条，R2 已核）；与实物印章同等效力（第五条，已核）。
2. 服务商（制作管理单位或其合作平台）的协议、凭据、回调只在 `platform.integration`；凭据存 KMS 凭据管家（ADR-0002）。**先行上线开放时不新开任何公开入口**；服务商回调入口在某类印章切换电子用印时才开，鉴权为服务商签名校验。统一公开入口规则（外部访问 ADR 决定 6）由最先需要开放公开入口的实施卡建造——外部访问 W2 首批或某类印章切换电子用印的批次，取早者；主机名与网关由 one-ops 建，数值由 one-security 定；未建成则不开放任何公开入口。不开回调、改主动查询作为该批比较项。
3. 电子用印流程：用印申请批准后，行政经办人在 `organization.administration` 发起「电子用印」，传入申请 ID、台账条目、经批准的签前件；签章服务核对条目有效、经办人有该法人范围的签章授权，经文件服务「读取内容」（只限平台模块）取签前件字节（边读边核对哈希），经集成层签章；回收的签后件经文件服务「写入内容」写入，带「派生自」签前件（派生方式「签署」，基础 ADR 第 4 条），即签前件的**派生件**，不是其新版本，两者 ID 与哈希分别记录；签前件另出新版本的，要签须从新版本另行派生。复核签后件哈希并验章（第二十三条，已核），写签章记录；之后 administration 登记用印并引用签章记录 ID。
4. 幂等键：申请 ID + 签前件 + 台账条目（`platform.idempotency`）。服务商失败、超时、验章不过均拒绝并告警，不登记用印，不自动改用实体章；改用实体章须经办人显式另办。重签或失败重试各产生新的派生件与新签章记录，不覆盖。
5. 系统不保管私钥；签章授权按 ADR-0026（权限码 + 法人范围），是否要求逐次确认或双人见证交 one-security。

### 5. 数字证书（CA）

1. 证书由依法设立的电子认证服务机构签发（电子签名法第十六至十八条【转载】；令第 6 号第三条【已核】）；公司不自建对外 CA。
2. 系统不保管私钥，只登记电子印章所绑定证书的元数据：颁发机构、序列号、主体、用途、有效期、状态、关联印章。电子印章有效期不超过所有者证书截止时间（办法第十六条第（一）项，R2 更正后口径）。
3. USB Key 等载体按 IT 资产登记领用归还（AGG-115），不另建载体台账；执业资格到期提醒用 `registered_practice_certificate`（审题报告撤下 Q12 时的设计自定）。
4. 离职：订阅 `organization.workforce` 本地离职命令发出的人事层事件（不只依赖无角色时不发的 `AccountSeparated`，R2 F17），关闭该人签章授权，若其名下有登记证书则生成吊销申请待办；吊销由 CA 执行，各订阅方各自成事务，不写「同步吊销」。
5. 执业失效：不预留新事件。图纸签章登记时实时查注册执业证书有效期；AGG-66 建成后若发布状态变更事件再订阅。

### 6. 图纸签章（Q03 (b)）

1. 签章在系统外的设计人员终端完成；签章后文件由交付物所在 BC 经「写入内容」上传，不带派生自（系统内无签前件）；系统登记签章人（UserId）、签章日期、该文件 ID 与内容哈希、执业印章条目与注册执业证书记录 ID，登记时校验证书有效期覆盖签章日期，不覆盖或查不到即拒绝。
2. 不验签（Q03 (c) 未选），不代签；调用方为交付物所在 BC，随 W2 交付物实施。

### 7. 签章记录与审计

1. 签章记录是本模块的只追加记录：请求方与申请 ID、台账条目版本或执业印章、经办人或签章人、签前件与签后件的文件 ID 与内容哈希、服务商交易号、验章结果、时刻。不改不删，更正用新记录关联。
2. 签章过程信息另经 `platform.audit` 留痕（办法第二十二条要求记录并保存，已核，无年限）；收入证据（ADR-0047、0056）与签署证据（`signature_evidence`）只引用签章记录 ID。

### 8. 保存期

签前件、签后件关联时给出保存类别「签署与用印文件」（Q04 (a)；默认不少于 10 年，自合同履行完毕或签署完成日起，待法务），到期处置由文件服务按文件保存期 ADR 执行。签章记录是本模块表行，**由本模块自行处置**，不交保存期稿：其到期日取所引签前件、签后件到期日中较晚者（经文件保存期 api「查到期日」），任一文件未到期或起算未发生即不处置；数据访问注册表 `retention.policy` 写此规则（注册表写法待 one-architecture 确认）。签章人只存 UserId，不存姓名与证件号，个人信息去标识经身份侧处理。

### 9. 修订 ADR-0054 决定 1「唯一例外」

原文第 1 句：「范围仅限用印、合同借阅、IT 工单与资产、员工活动经通用审批办理；销售合同归档仍并入合同档案，通用审批不能代替所属 BC 的事实处理（ADR-0055 决定 1）。」

新文：「范围仅限用印、合同借阅、IT 工单与资产、员工活动经通用审批办理，用印含签章服务的印章台账与电子用印。用印分两段：先行上线开放时用实体章办理，用印登记引用印章台账，不新开公开入口；某类印章的省级备案电子印章完成制作备案、服务商接入、one-security 安全评审与该类验收后，该类改为电子用印，签章服务的电子用印及其在 `platform.integration` 的适配与回调入口随之在先行期生产运行；切换前实体章并存，切换后按台账停用。电子印章就绪不是先行上线开放的前提。对外回签、合同签署证据、图纸签章登记不在本例外。销售合同归档仍并入合同档案，通用审批不能代替所属 BC 的事实处理（ADR-0055 决定 1）。」

原文第 3 段末句「已发生的审批结论、附件、历史版本与审计记录须保全」改为「已发生的审批结论、附件、历史版本、签章记录与审计记录须保全」。其余不变。

批准页单列两个确认点（起草推出，非用户原话）：两段式切换；电子印章就绪不作为先行上线前提。

## 影响面

- 平台：新增签章服务模块；`platform.integration` 新增服务商适配，回调于切换时开；文件服务增加「读取内容」「写入内容」使用方。
- `organization.administration`：AGG-113 改引用台账条目与签章记录 ID；新增「电子用印」命令；新增边 → 签章服务（api）。
- `organization.workforce`：本地离职命令须发人事层离职事件。
- ADR-0057：电子用印登记仍是实际用印登记，核验口径不变。
- 词表、AGG-113、`contexts.yaml`、模块依赖、数据访问注册表、数据分级随实施登记。
- 制度：行政与法务定《印章与证书管理制度》（办法第二十一条）。

## 迁移方案

1. 本 ADR 只定决定 1–9；以下为实施卡。
2. 先行上线批（W0）实施卡：印章类型清单、印章台账（含版本表与唯一约束）、AGG-113 引用、与 administration 的 api；不含签章记录、服务商接入与公开入口。
3. 电子印章批（先行期内，按类）实施卡：制作备案（行政与法务办理）→ 集成层适配 → 签章记录与签后件派生登记 → one-security 评审（含回调或主动查询）→ 该类验收 → 切换；证书元数据与离职订阅随此批。
4. 图纸签章登记随 W2 交付物实施卡；执业印章条目同批。
5. 迁入：A8 近 24 个月用印按（归属公司，印章类型）映射到台账条目，取证显示两字段齐全；映射不到的逐条拒收处置（ADR-0054 G-3）；历史记录无签章记录与指纹，标「历史迁入」。A8 无电子签历史，无需迁。

## 回滚方案

- 采纳后改决定须另立 ADR。
- 某类电子用印切换后出问题：关闭该类回调路由，台账条目新开版本改回实体载体，前提是实体章在电子用印稳定前不交回、不销毁（观察期由实施卡定）；已产生的签章记录与签后件不删不改。
- 备案注销是外部不可逆动作，须用户决定，不作技术回滚手段。
- 模块投入生产后只前进修复。

## 需同步修改的守护规则

1. `module-dependencies.txt` 登记新边；`ModuleDependencyTest` 加禁止边：签章服务 ↛ `organization.administration` 及除 `organization.workforce` 外的业务 BC（含传递闭包）；`platform.approval` ↛ 签章服务。负责：签章服务首个实施会话。
2. ADR-0039 守护：服务商名称与协议只在 `platform.integration`（现有外部连接隔离测试与 ACL 用语检查覆盖新包）。
3. 签章服务 schema 不得出现私钥、口令、密钥类列，新增 DDL 断言；gitleaks 照常。
4. 签章记录只追加：表上建拒绝 UPDATE / DELETE 的触发器（G34 同法），数据访问注册表登记 `APPEND_ONLY`，DDL 测试断言。
5. 印章台账：注册表登记为主数据维度型（D17，G-D11）；排他约束有 DDL 测试。
6. `data-classification.txt` 登记新列访问级别与个人信息标记（ADR-0043）。
7. 公开入口：回调端点按外部访问 ADR 决定 6 的白名单守护登记，切换前不得出现在白名单。
8. ADR 生成器：ADR-0054 头部加「被部分取代：ADR-本号 决定 1 唯一例外与保全句（部分）」，与本 ADR 采纳同一提交（README 第 4 节）。

## 后果

- 收益：用印不必实体章到场（A8 用印 P90 约 73 小时）；签章全程留痕；拟发文件可按指纹核验。
- 代价：切换时增加对外连接与回调入口，须单独评审；制作备案与接入有外部周期与费用（未询价）；台账版本化增加实施量。
- 已知限制：对方或当地规则要求实体章时仍用实体章（如沪建建管联〔2016〕596 号第三条第 5 项对外省市保留实体出图章，现行有效性未核），「整体电子化」是默认，不是全部；逐枚台账、证书全量台账、验签均未定；GB/T 38540-2020 等国标全文未核。
- **问题单**（全文见复审报告 §六，随草案入研究目录）：
