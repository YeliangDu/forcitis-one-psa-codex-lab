## 1. 属性去向

| 原建设工程内容 | 去向 |
|---|---|
| 名称、地址、业态、所在城市 | 项目的「工程识别信息」属性组 |
| 外部状态（规划 → 在建 → 已竣工 → 已超设计使用年限 → 改造中 → 已拆除） | 项目的外部状态属性，只记录、不作门、不作本系统状态机 |
| 政府平台编号 | 项目的外部标识（只作外部标识，不作主键，照原规则） |
| 1 → N 建筑系统与部位（OBJ-47） | 改挂项目：OBJ-47 成为项目的从属对象 |

## 2. 「同一工程」的跨项目识别（第②条评估与推荐）

合并后，同一栋建筑上先后的设计、检查等多个项目，以及承接前的商机、招标项目，要靠工程识别属性判断「是不是同一工程」。用途：独立性检查（OBJ-23，承接前核对是否参与过同一工程的设计、施工）、检查历史追溯、客户资产视图。

| 方案 | 做法 | 优点 | 风险 |
|---|---|---|---|
| A 外部标识优先、地址兜底、人工确认（推荐） | ① 有政府平台编号（工程规划许可、施工许可或项目代码）时精确匹配；② 无编号时按「所在城市 + 规范化地址」精确匹配；③ 名称相近只作提示；候选结果由经办人确认后，在项目上记「工程维度识别键」（工程维度的键，跨项目共用，不是业务对象） | 有编号时零误判；无编号时有人把关；不新增对象 | 老项目缺编号、地址写法不一，首批需人工清理 |
| B 名称加地址模糊匹配，自动归组 | 文本相似度超过阈值即视为同一工程 | 全自动 | 同一园区多栋、改名、简称导致误判；独立性检查是合规控制，误判代价高 |
| C 只靠人工挂接 | 建项目或商机时由经办人手选已有工程识别键 | 简单 | 漏挂，独立性检查失效 |

推荐 A。独立性检查改为：承接前以商机或招标项目上记录的工程识别信息，按 A 的规则检索已有项目，命中即列出我方在该工程的历史参与（设计、施工配合、检查），由检查人确认。

## 4. 12 维度候选
