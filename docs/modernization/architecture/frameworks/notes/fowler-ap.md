## 核心思想

- **论断：分析模式须结合问题情境复用，概念结构与软件实现不必同形。** 依据：FAP#分析模式、FAP#概念与实现。含义：对 OBJ-01–125 用模式比较替代方案和查漏，不能由模式图直接生成 BC、聚合或物理表。
- **论断：责任关系须表达两端、类型、有效期和范围，允许哪些关系发生的规则与实际关系分层。** 依据：FAP#责任关系、FAP#知识层与层级约束、FAP#责任范围与岗位。含义：OBJ-01–06、OBJ-54–58 保留身份、任职、协议和授权各自规则，层级与角色约束另行核对；岗位仍只管职位目录，不据模式引入编制。
- **论断：数量的单位与观测的方法、上下文和双时间影响解释，未检查不能当作不存在。** 依据：FAP#数量与金额、FAP#定性观测、FAP#观测方法与双时间、FAP#推导与证据链。含义：OBJ-21、OBJ-26、OBJ-28、OBJ-33、OBJ-38、OBJ-49、OBJ-53 核对单位、方法、适用与录入时间及证据；预测和主观完成百分比不转换为收入证据。
- **论断：账户余额来自变动明细，关联变动组成守恒整体，金额相同的明细仍可代表不同变动。** 依据：FAP#账户与变动明细、FAP#成组守恒与双日期。含义：OBJ-85、OBJ-89、OBJ-98、OBJ-122 分别规定单位、主体、期间、方向和更正方式；Fowler 的单账户 Entry 不直接对应 OBJ-98 的借贷集合，领域 Transaction 也不等于数据库事务。
- **论断：过账规则的更正须让后续影响可抵消，结果还须追溯所用输入和计算，规则与触发策略分别处理。** 依据：FAP#过账规则与可逆性、FAP#触发策略、FAP#计算来源链。含义：OBJ-73、OBJ-80、OBJ-98、OBJ-124 核对输入及规则版本来源链，沿现行单一过账管道、只追加与冲销约束验证原处理和冲销能完整抵消。
- **论断：多路径账户汇总须按明细身份消除重复，按属性筛选的报告视图不必成为业务账户。** 依据：FAP#汇总与备忘账户、FAP#多账户汇总与派生视图。含义：OBJ-85、OBJ-89、OBJ-98、OBJ-122 的汇总不合并同金额的不同变动；分析切面不自动新增账户，需要守恒、转移与审计的变化也不能只剩查询公式。

## 对本系统的启示

### 分析模式提供可检验的结构，不直接指定表与类

序言把模式用于理解业务模型、比较替代方案及发现遗漏；使用模式需要结合问题情境。一个通用模式能横跨医疗、会计或组织关系，不意味着本系统应建立一个万能实体。概念结构与软件实现之间可以有不同映射，不能从模式图直接推导 BC、聚合或物理表。（FAP#分析模式、FAP#概念与实现） 本系统对照：OBJ-01–125 的模式使用边界。

### Party、Accountability 与时间范围

Party 让自然人与组织能够承担共同的联系、行动或责任；Accountability 把责任两端、关系类型和有效期间显式表达。实际责任关系与允许哪些类型发生关系的规则分层处理，后者属于 knowledge level。树状、无环、层级及角色适用规则仍须单独约束，通用关联本身不保证它们。（FAP#主体与组织层级、FAP#责任关系、FAP#知识层与层级约束）

Operating Scopes 补充责任的范围；Post 表达岗位责任先于任职人员而存在的情形，但也增加复杂度。本系统已定岗位只管职位目录，不能据此偷偷引入岗位编制或将合同、任职和项目成员全部并入一个通用责任表。（FAP#责任范围与岗位） 本系统对照：OBJ-01–06、OBJ-54–58。

### Quantity、Measurement 与 Observation

Quantity 把数值与单位以及合法运算放在一起，货币是带币种的数量，不能任意跨单位求和。转换可能随时间变化，天与月也不是固定比例。Measurement 记录某对象在某种现象类型下的数量；Observation 还能表达定性分类、存在与不存在。分类含义须依赖现象与上下文，检查项的空值也不能直接解释为不存在。（FAP#数量与金额、FAP#计量、FAP#定性观测）

Protocol 记录观测采用的方法；同样的数值若方法不同，解释和准确性可能不同。Dual Time Record 区分适用时间与录入时间；被证明错误的观测与曾经成立但后来失效的观测不同。结论还应保留支持它的观测和推导依据。结构可复用，实际观测顺序与处理过程仍因业务不同而不同。（FAP#观测方法与双时间、FAP#假设与预测、FAP#推导与证据链） 本系统对照：OBJ-21、OBJ-26、OBJ-28、OBJ-33、OBJ-38、OBJ-49、OBJ-53。

### Account、Entry 与 Transaction

Account 记录某数量的各次变动，余额由 Entry 的净影响得到；缓存余额不等于可以抛弃变动明细。两笔数值相同的 Entry 仍是两次变动，不能按金额去重。Entry 同时可能具有发生日期与入账日期；Fowler 此处的 Entry 是单个账户上的变动，本系统 OBJ-98 定义的是一笔业务的借贷集合，粒度不能按英文名称直接对应。（FAP#账户与变动明细、FAP#成组守恒与双日期）

Transaction 把相互关联的流出与流入组成守恒整体，允许多条分录，只要求整体平衡，不要求每条两两配对。书中的 Transaction 是领域概念，不是数据库事务。Summary Account 是明细的汇总；若允许多路径汇总，必须处理循环与重叠。按 Entry 身份消除同一分录的重复路径，与把相同金额的不同分录合并，是两件不同的事。（FAP#成组守恒与双日期、FAP#汇总与备忘账户、FAP#多账户汇总与派生视图） 本系统对照：OBJ-85、OBJ-89、OBJ-98、OBJ-122。

### Posting Rule、可逆性及来源链

Posting Rule 将输入变动、计算及输出变动联系起来。错误分录已经影响账单或付款时，不能简单删除；冲销应当使后续计算也能相互抵消。规则本身与触发／批处理策略分离，才能解释执行时机与依赖。来源链还须记录用了什么输入、什么计算生成结果，而不只保留最后金额。（FAP#过账规则与可逆性、FAP#触发策略、FAP#计算来源链）

Memo Account 与 Derived Account 回答不同问题：前者帮助跟踪备忘性质的数量，后者主要提供按属性筛选的报告视图。任意分析切面并不都需要建立账户；反之，需要守恒、转移与审计的变化也不能只剩一条查询公式。（FAP#汇总与备忘账户、FAP#多账户汇总与派生视图） 本系统对照：OBJ-73、OBJ-80、OBJ-98、OBJ-124。

## 我们的取舍

以下全部为**已审定（one-architecture 2026-10-18，页码已抽查（偏差已更正））**；现行定义仍以对象图、术语表及已采纳决定为准。

- 建议借鉴 Account／Entry 的变动历史和 Transaction 的成组守恒，用于核对资金、往来、假期及预算等确有余额转移的场景；每个场景分别规定单位、主体、期间、正负方向、来源和更正方式。不能因为都可记数量，就把它们交给一个通用会计科目体系。
- 建议借鉴计算结果到输入及规则版本的来源链，并核对原处理与冲销结果能完整抵消；沿现行单一过账管道、只追加和冲销约束实现，不把书中的放弃 Transaction 方案视为本系统例外。
- 建议借鉴责任关系的角色、范围及有效期；保留主体身份、任职、项目成员、协议、授权的各自规则。本书不提供自动扩大访问权或合并人员与账号的依据。
- 建议借鉴带单位的计量、方法与证据来源、适用与记录双时间，以及原观测错误／后来失效的区别；检查记录、估算、已认可履约与已过账事实应分别表达，不把预测或主观完成百分比转换为收入证据。
- 不建议采纳可任意扩展的万能 Party／Accountability／Observation／Posting Rule 表，也不以所有实体都通用化作为目标。变化少且定义稳定的领域字段仍须按本系统正式列和强类型契约设计。
- 不建议把 Derived Account 的报告视图当新业务账户、将 Memo Account 的例子用作合法账务依据，或把本书正负号表示替代借贷方向、币种平衡与会计政策。书中账户是跨领域抽象，业务会计细节另有权威来源。

**使用边界：** 本书不决定本系统对象的一级／次级归属，也不提供中国收入准则、税票、薪酬、证据保存期或 FORCITIS 实际组织权责。本卡未生成模型、DDL、代码或新增正式术语，未验证账户／规则执行链。书目缺页、局部阅读和待 one-architecture 审定的边界须随本笔记保留；后续补齐版权页时另核版本，不能从文件名直接覆盖书目。
