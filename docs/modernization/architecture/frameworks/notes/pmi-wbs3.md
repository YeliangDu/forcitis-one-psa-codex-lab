# PMI《工作分解结构实践标准》第三版要点笔记

资料出处：公开资料（不进仓库）《Practice Standard for Work Breakdown Structures》。版次取题名页（PDF 2），发布机构、年份取版权页（PDF 3）。本件共 214 个 PDF 物理页；以下逐项记录印刷页与物理页，不把前置页计入正文页码。本笔记自行概括，短引 0 处，不构成架构决定。

阅读聚焦第 1 章的定位、第 2 章的概念与原则、第 3 章的词典和工作包示例、第 4 章的质量要求、第 5 章的估算、挣值和演进；附录各行业样例未逐个评审。

## 核心思想

- **WBS 是获批范围的层级分解。** 它回答需要产出什么；工作包是可估算和管理的末级工作，活动排程另行表达。（WBS3#WBS、WBS3#工作包、WBS3#活动边界）
- **完整性和互斥性要同时成立。** 子项覆盖父项全部已知工作，同时避免同一工作重复落点；项目管理和中间成果也应纳入范围检查。（WBS3#百分之百规则、WBS3#互斥分解、WBS3#完整成果范围）
- **词典使节点名称可执行、可核对。** 假设、资源、质量要求和验收标准要能定位到具体节点；一棵只有名称的树不足以表达管理依据。（WBS3#工作分解词典、WBS3#工作包说明）
- **分解方法允许混合并随认识演进。** 阶段、产品等分解轴可组合，但不能把样例的层数或编码误认为所有项目必须采用的形状。（WBS3#分解类型、WBS3#分解深度、WBS3#范围渐进明细化）
- **WBS 支撑估算和绩效核对，不独自承载所有管理事实。** 控制点、活动、成本和资源须关联同一工作范围，仍各有自己的记录。（WBS3#管理控制点、WBS3#工作包估算、WBS3#挣值）

## 对本系统的启示

- **范围分解、排程和派工分别核对。** OBJ-30 WBS 的阶段、子项、工作包应可与 OBJ-31 交付计划、OBJ-44 资源需求、OBJ-45 资源分配关联；PRC-18 编计划时检查活动覆盖工作包，不能以树上顺序代替日期和依赖关系。（WBS3#WBS、WBS3#活动边界、WBS3#层级编号）
- **完整范围超出客户交付物清单。** 在 OBJ-29 项目下核对 OBJ-35 对客交付物，还应检查内审、项目管理与收尾工作是否在 WBS 的已知范围内；内部成果仍按 OBJ-107 项目复盘等现有定义处理。VS-02 的交付与结项都要有工作覆盖，不把所有工作一律定为对客交付物。（WBS3#百分之百规则、WBS3#互斥分解、WBS3#完整成果范围）
- **节点应能追溯协议中的范围。** OBJ-05 协议与 OBJ-30 WBS 的挂接可结合词典记录范围说明、排除项、假设、交付质量及验收依据。PRC-48 协议变更生效后，应核对工作分解和 PRC-18、PRC-19 的计划预算是否需要修订。（WBS3#范围基准、WBS3#工作分解词典、WBS3#范围渐进明细化）
- **估算控制点不预设新对象。** OBJ-32 项目预算、OBJ-33 完工估算可按工作包关联范围与状态日，以支持预测和偏差分析；书中的 Control Account、Planning Package 作为独立对象，本系统暂无对应，是否需要新增应另行核对。（WBS3#管理控制点、WBS3#规划包、WBS3#工作包估算、WBS3#挣值）
- **模板需要按项目裁剪。** OBJ-24 服务产品、OBJ-25 阶段类型可提供默认分解，PRC-17 立项时核对实际范围，而非复制房建或自行车样例。书中分解层数不取代本系统已定义的节点类型。（WBS3#分解类型、WBS3#分解深度、WBS3#工作包说明）

## 我们的取舍

- **建议采纳：对 WBS 做范围覆盖、互斥性及词典完整性检查。** 理由：能发现漏项、重复归集与验收依据缺失；百分之百指范围覆盖，不是节点权重相加为一百就算通过。（WBS3#百分之百规则、WBS3#互斥分解、WBS3#工作分解词典）
- **建议采纳：范围、计划、预算、资源和实绩共享可追溯的工作包定位。** 理由：便于解释变更和成本偏差，同时保留各类记录的责任边界。（WBS3#工作包、WBS3#工作包估算、WBS3#挣值）
- **建议不采纳：照抄样例层数、层级编码作为主键，或把全部活动直接变成 WBS 节点。** 理由：样例并非统一结构要求，标识类型由本系统现行决定约束，活动还要有自己的时序与执行语义。（WBS3#分解深度、WBS3#层级编号、WBS3#活动边界）
- **建议不采纳：用管理控制点或挣值直接替代会计履约义务及收入确认。** 理由：书中处理范围和项目绩效，不能覆盖 ADR-0016 的会计边界；若拟改变须待提议。（WBS3#管理控制点、WBS3#挣值）
