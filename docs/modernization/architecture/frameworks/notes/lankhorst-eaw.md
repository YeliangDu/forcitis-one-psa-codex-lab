# Lankhorst 等《Enterprise Architecture at Work》要点笔记

## 核心思想

- **论断：视点规定观察模型的方式，视图呈现具体观察结果，图形相似不保证语义相同。** 依据：LAN#视图与视点、LAN#模型语义与呈现。含义：每个架构视图说明用途、读者、范围和证据来源，分别核对模型语义与视觉呈现，不以图多或图大证明完整性。
- **论断：业务角色、行为、对象及其表示承担不同用途，一个业务对象可以有多种表示。** 依据：LAN#业务结构与表示。含义：信息建模分别检查对象与可感知表示，架构中的过程、功能和服务联系不直接作为执行流程，也不用书中旧版语言替换本项目能力与价值流定义。
- **论断：模型范围与细节应由待解决问题、基线或目标及可获得的信息决定。** 依据：LAN#建模范围。含义：建模前写清问题、边界和信息条件，按用途选择细节；初始简化视图不能作为最终验收省略已知异常、权限及一致性边界的理由。
- **论断：共同理解、模型认可、决定承诺与验证是架构沟通中分别形成的结果。** 依据：LAN#知识转换、LAN#视点选择与确认。含义：分别记录建模正确、干系人认可、决定承诺和实际验证的完成证据，不把模型获认可当作其影响已经落实。
- **论断：性能分析和模拟依赖输入数据、假设及可解释的方法，算出结果不等于现实已验证。** 依据：LAN#性能分析。含义：度量与 BI 对照中将模型分析值与生产实测分开记录，不从书中模拟或示例推断 FORCITIS 的真实运行性能。

## 对本系统的启示

- **业务对象（对照：原笔记未列本系统对象编号）：** 业务角色、行为、业务对象及其表示承担不同用途。一个业务对象可以有多种可感知表示；模型中的概念内容与它画成圆形或矩形等呈现方式也应分开，图像相似不能保证语义相同。（LAN#模型语义与呈现、LAN#业务结构与表示）

- **价值流（对照：原笔记未列本系统价值流编号）：** 本书不涉及本项目采用的 BIZBOK v11 价值流方法。服务及业务流程的例子不能直接当成该方法的价值流阶段。（相关概念：LAN#业务结构与表示）

- **能力（对照：FRAMEWORKS（原笔记未列能力编号））：** 本书不涉及本项目的对象驱动能力图规则。业务功能和角色的旧版语言表示可供比较，不据此替换 BIZBOK 能力定义。（LAN#业务结构与表示）

- **流程（对照：原笔记未列本系统流程编号）：** 过程、功能和对外可见服务观察同一企业的不同方面；架构模型用于表达它们的联系，并非执行流程。架构沟通本身也是知识形成过程，干系人共同理解、认可模型及承诺其影响需要分别完成。（LAN#知识转换、LAN#业务结构与表示、LAN#视点选择与确认）

- **数据建模（对照：FRAMEWORKS（原笔记未列模型编号））：** 模型的内容、语义、视图与视觉呈现不是一层。视点规定如何观察，视图是针对具体模型得到的观察结果；建模前要说清问题、边界、基线或目标，以及是否能取得必要信息。细节选择应服务明确用途。（LAN#视图与视点、LAN#模型语义与呈现、LAN#建模范围）

- **度量与 BI（对照：原笔记未列本系统度量编号）：** 性能分析和模拟依赖输入数据、假设及可解释的方法；模型能算出结果不等于现实已验证。该章不是经营 BI 的指标体系，不能把模型分析值与生产实测混记。（LAN#性能分析）

- **主数据（对照：原笔记未列本系统主数据编号）：** 本书不涉及主数据匹配合并、主记录判定和生效版本实现。跨视图共用模型元素支持一致解释，但共用语义模型不能替代数据写入权和来源治理。（LAN#视图与视点、LAN#模型语义与呈现；后半句为项目应用）

## 我们的取舍

**已审定（one-architecture 2026-10-18，页码已抽查（偏差已更正））。**

- **采纳：每个视图说明用途、读者、范围及证据来源。** 理由：让架构图能被核验，不以图多或图大当作模型完整性。
- **采纳：区分建模正确、干系人认可、决定承诺及实际验证。** 理由：这些是不同层次的完成证据。
- **不采纳：把本书旧版 ArchiMate 模型或全套视点直接导入项目。** 理由：FRAMEWORKS 的采用范围未改变，且语言版本有差异。
- **不采纳：把 p135 初始建模可暂忽略错误/例外的指导用于最终验收。** 理由：沟通中的简化视图可以聚焦，最终规则和实现仍须覆盖已知异常、权限及一致性边界。

**使用边界：** 短引：0 处。没有用书中的模拟或示例推断 FORCITIS 的真实运行性能，也没有新增模型工具、框架或治理流程。
