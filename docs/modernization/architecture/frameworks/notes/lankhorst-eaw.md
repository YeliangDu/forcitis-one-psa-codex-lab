## 2. 与本项目相关的核心思想

### 业务对象

业务角色、行为、业务对象及其表示承担不同用途。一个业务对象可以有多种可感知表示；模型中的概念内容与它画成圆形或矩形等呈现方式也应分开，图像相似不能保证语义相同。（L-02、L-04）

### 价值流

本书不涉及本项目采用的 BIZBOK v11 价值流方法。服务及业务流程的例子不能直接当成该方法的价值流阶段。

### 能力

本书不涉及本项目的对象驱动能力图规则。业务功能和角色的旧版语言表示可供比较，不据此替换 BIZBOK 能力定义。（L-04）

### 流程

过程、功能和对外可见服务观察同一企业的不同方面；架构模型用于表达它们的联系，并非执行流程。架构沟通本身也是知识形成过程，干系人共同理解、认可模型及承诺其影响需要分别完成。（L-03、L-04、L-06）

### 数据建模

模型的内容、语义、视图与视觉呈现不是一层。视点规定如何观察，视图是针对具体模型得到的观察结果；建模前要说清问题、边界、基线或目标，以及是否能取得必要信息。细节选择应服务明确用途。（L-01、L-02、L-05）

### 度量与 BI

性能分析和模拟依赖输入数据、假设及可解释的方法；模型能算出结果不等于现实已验证。该章不是经营 BI 的指标体系，不能把模型分析值与生产实测混记。（L-07）

### 主数据

本书不涉及主数据匹配合并、主记录判定和生效版本实现。跨视图共用模型元素支持一致解释，但共用语义模型不能替代数据写入权和来源治理。（L-01、L-02；后半句为项目应用）

## 4. 对本项目的取舍

**已审定（one-architecture 2026-10-18，页码已抽查（偏差已更正））。**

- **采纳：每个视图说明用途、读者、范围及证据来源。** 理由：让架构图能被核验，不以图多或图大当作模型完整性。
- **采纳：区分建模正确、干系人认可、决定承诺及实际验证。** 理由：这些是不同层次的完成证据。
- **不采纳：把本书旧版 ArchiMate 模型或全套视点直接导入项目。** 理由：FRAMEWORKS 的采用范围未改变，且语言版本有差异。
- **不采纳：把 p135 初始建模可暂忽略错误/例外的指导用于最终验收。** 理由：沟通中的简化视图可以聚焦，最终规则和实现仍须覆盖已知异常、权限及一致性边界。
