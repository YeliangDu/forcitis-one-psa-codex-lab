# 《Star Schema: The Complete Reference》要点笔记

本笔记保存与 FORCITIS one 相关的阅读要点，不构成架构决定。正文为自行概括，短引 0 处。作者、题名取自 PDF 第 4 页题名页，年份取自第 5 页版权页；所读题名页、版权页未标版次，故写「未核」。

本次聚焦第 3 章事实与粒度、第 4–5 章跨过程分析和维度一致性、第 11–12 章事实表类型及第 18 章设计文档，另核读第 1 章维度历史说明，未宣称通读全书。所列正文印刷页与 PDF 页相差 27 页。

## 核心思想

- **论断：跨过程指标必须先分别汇总到共同维度，再合并结果，直接连接两张明细事实表会放大或丢失记录。** 依据：ADAM#事实直接连接、ADAM#跨过程合并。含义：VS-04 中收入确认、发票、回款分配分别保留测量粒度，在共同的项目、法人、期间层级比较，不能以 OBJ-29 项目相同便逐笔连接。
- **论断：比率的业务重要性不使其可加，总计必须用可加组成量重新计算。** 依据：ADAM#不可加比率、ADAM#跨过程指标登记。含义：贡献毛利率用同层级同变体的贡献毛利与净服务收入计算；利用率也须明确分子分母及共同期间，不能把项目或人员的百分比直接相加或简单平均。
- **论断：计划与实际可以有不同粒度，能否比较取决于共同维度的结构和内容是否相容。** 依据：ADAM#一致汇总维度、ADAM#一致性矩阵。含义：OBJ-100 经营计划按组织与期间的目标，应与工时或收入的实际明细在共同层级比较；不为支持日粒度报表而虚构日目标或明细分摊。
- **论断：余额与活动回答不同问题，周期快照不能替代交易明细，也不能沿期间直接求和。** 依据：ADAM#交易事实表、ADAM#周期快照、ADAM#半可加度量。含义：OBJ-85 往来款项同时需要 PRC-60 的核销活动及 PRC-103 对应的期间余额视角，VS-10 的期末应收账款不能通过相加各月余额获得。
- **论断：只有实际发生记录就无法计算未发生或覆盖缺口，必须另有应覆盖范围。** 依据：ADAM#无数值事件、ADAM#条件事实表、ADAM#覆盖与活动比较。含义：内部评审覆盖率既要 PRC-28 已完成评审，也要符合业务条件的应评审项目集合，不能把没有评审事件的项目从分母中消失。
- **论断：可执行的度量设计需要登记来源和变换规则，仅有字段名与星型图不足以复算。** 依据：ADAM#星型定义清单、ADAM#来源变换登记。含义：按 BI_SCOPE.md §3.3 为度量补单位、期间与口径版本，并对 PRC-23、PRC-53、PRC-60 的来源身份、粒度和变换逐项建立可追溯说明。

## 对本系统的启示

- **收入、开票、回款需要保留各自明细关系。** VS-04 中，OBJ-81 收入确认、OBJ-83 增值税发票、OBJ-86 资金收付分别经 PRC-53、PRC-57、PRC-60 产生或处理。按 BI_SCOPE.md §3.2 的来源分别建分析事实，再在共同维度上比较金额；一笔回款多次分配时尤其要防连接放大。（ADAM#交易标识、ADAM#事实直接连接、ADAM#跨过程合并）
- **经营计划与工时明细不能强行同粒度。** OBJ-100 的计划目标值按组织、期间、指标与版本登记，PRC-88 形成基线；PRC-23 提供更细工时。VS-09 的目标达成率只在两边都具备的维度层级计算，目标类型和版本必须唯一选定；不同版本不是可相加的多笔投入。（ADAM#一致汇总维度、ADAM#平均分母与版本）
- **历史归属要说明采用何种时间视角。** OBJ-57 任职、OBJ-55 组织单元与 OBJ-29 项目属性会变化；PRC-136 变更任职后的当前归属不能自动替代旧事件发生时归属。BI_SCOPE.md §3.1 已要求按生效期保留历史，分析维度身份与来源身份应分开说明；具体键类型仍遵守本仓库规范。（ADAM#维度历史、ADAM#一致维度）
- **应收账款需要余额和活动两种观测。** OBJ-85 往来款项的余额与 PRC-60 的核销活动对应不同问题，PRC-103 生成期间余额快照支持 VS-10 的期间比较。不能把期末余额作为每笔核销的事实复制存放，也不能累加各期余额得到年度余额。（ADAM#交易事实表、ADAM#周期快照、ADAM#半可加度量）
- **覆盖率应检查分母来源。** terms.yaml 已有内部评审覆盖率；PRC-28 的完成记录只能给出已评审集合，还需业务定义应评审的 OBJ-29 项目范围及有效期。建立检查项时同时核对范围与活动，未完成与不适用必须可区分。（ADAM#无数值事件、ADAM#条件事实表、ADAM#覆盖与活动比较）
- **过程退回应有度量规则，不能由报表开发临时决定。** PRC-23 工时单审批若出现退回再提交，时效分析须明确取首次提交还是最近提交、是否累积各轮耗时；累积快照只能作为 reporting 分析表示，L0 事实与 L2 冻结规则仍按 BI_SCOPE.md §3 执行。（ADAM#累积快照、ADAM#非线性过程）

### 供度量设计

以下是书中方法对总线矩阵、度量清单和业务库可度量原料的具体检查方向，不表示已完成物理库审计。

- **基础指标与派生指标：** 保留过程相关的可加组成量，并为比率等未直接落列的计算单列定义和依赖；不能因某指标不对应单列就在度量清单中遗漏。（ADAM#可加组成量、ADAM#不可加比率、ADAM#跨过程指标登记）
- **KPI 分级：** 书中已核说明许多 KPI 依赖跨过程比较，未确认统一的 KPI、派生指标、基础指标三级分类；本系统若分三级，应另外登记业务目标与基础测量的依赖，不称为作者原有等级。（ADAM#KPI跨过程基础、ADAM#星型定义清单）
- **指标口径：** 每项度量定义业务含义、来源元素与变换规则，再按 BI_SCOPE.md §3.3 补单位、期间、含税性和口径版本，计算规则不能只散落在查询代码。（ADAM#来源变换登记）
- **比率聚合：** 贡献毛利率用汇总后的贡献毛利除以同层级同变体的净服务收入，小计总计均重算；利用率也从对应的可计费工时和可用工时重算。（ADAM#不可加比率）
- **跨过程派生：** 开票转化率、回款率先对各过程施加适当筛选并汇总至共同粒度，再合并计算，保留只有一侧有活动的结果，缺值含义另按业务口径定义。（ADAM#跨过程合并、ADAM#跨过程指标登记）
- **总线矩阵：** 采用一致性矩阵做法，为每个事实表标出共用维度的可比较层级；月目标与日活动仅在共同月层级比较，未具备的维度不虚勾。（ADAM#一致性矩阵、ADAM#一致汇总维度）
- **粒度：** 先写每行代表的业务记录，检查是否需要业务单据及行身份来区分重复活动，再决定哪些维度可挂接，不能只凭外键组合合并数据。（ADAM#粒度、ADAM#交易标识）
- **交易事实表：** 保留实际活动及其测量上下文，零活动不自动出行；是否预汇总必须明示，并保留可追溯的更细原料。（ADAM#交易事实表）
- **周期快照：** 对余额或状态规定采样频率、对象范围和零值覆盖，并明确期间维度；跨期余额禁止求和，平均值分母不能盲用已存行数。（ADAM#周期快照、ADAM#半可加度量、ADAM#平均分母与版本）
- **累积快照：** 每个过程实例一行，保存里程碑及阶段时长；有退回重做时，先由业务定首次或末次日期与时长累积办法，再实现分析投影。（ADAM#累积快照、ADAM#非线性过程）
- **维度一致性：** 对 OBJ-54、OBJ-29、OBJ-56 等检查共同属性的结构、值和历史处理，副本用同一处理规则维护；同名而内容不同不能支持可靠的跨过程合并。（ADAM#一致维度、ADAM#维度历史）
- **目标版本：** OBJ-100 的计划目标值必须选择目标类型和版本，再与共同期间的实际值比较，不能跨方案或版本相加。（ADAM#平均分母与版本）
- **覆盖原料：** 内部评审覆盖率等同时登记应覆盖集合及有效期、实际活动集合和匹配条件，分母缺失应列数据缺口，不能把缺行默认为不适用。（ADAM#条件事实表、ADAM#覆盖与活动比较）
- **可复算交付：** 每个星型给过程、类型、粒度、事实及计算、维度、装载频率与来源变换清单，作为后续业务库可度量原料逐项取证的依据。（ADAM#星型定义清单、ADAM#来源变换登记）

## 我们的取舍

- **建议采纳：各事实独立聚合、按一致维度完整合并的跨过程分析。** 理由：可降低 VS-04 的一对多关系导致的重复计量与漏项。（ADAM#事实直接连接、ADAM#跨过程合并）
- **建议采纳：把比率、半可加度量与目标版本的限制显式登记。** 理由：BI_SCOPE.md §3.3 的加总规则需要细化到适用维度和计算层级，不能只写 sum 或 average。（ADAM#不可加比率、ADAM#半可加度量、ADAM#平均分母与版本）
- **建议采纳：用星型定义与来源变换清单检查可度量原料。** 理由：能逐列追问来源及规则是否存在，区分设计要求和已有证据。（ADAM#星型定义清单、ADAM#来源变换登记）
- **建议不采纳：把同名字段当成维度一致、把事实表直接连接当成跨过程比较。** 理由：结构相似不保证内容与粒度相容，可能同时放大和漏掉结果。（ADAM#一致维度、ADAM#事实直接连接）
- **建议不采纳：照搬书中整数键、浮点数或分析快照更新方式到本系统业务库。** 理由：示例解释维度模型，不变更本仓库 UUIDv7、金额精度、已过账事实及关账冻结规范。（ADAM#维度历史、ADAM#可加组成量、ADAM#累积快照）
