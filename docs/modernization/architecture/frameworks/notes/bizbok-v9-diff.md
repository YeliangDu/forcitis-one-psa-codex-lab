## 2. 与本项目相关的核心思想（仅版本差异）

### 业务对象

**不是 v11 新增**：v9 已有按存在依赖区分 primary / secondary 的判据，也已有 Finance 等汇聚概念不填类型、状态和关系的例外。v10 的更新记录说明信息概念的上下文和从能力提取概念的文字得到澄清、图及知识库说明移位；不能把这些编辑和澄清误报为 v11 才引入对象分类。（V9D-01、V9D-02、V9D-06）

### 价值流

v11 的版本历史明确记录：更新对象状态转移及共享对象对跨流导航的解释，并把部分制图指导中的对外导向改为外部触发的表述。正文可见例示模板按内外触发分类，并明确入口/退出应引用有效对象状态。**v9 已有内外触发、重入和共享状态的讨论**，所以差异是收紧说明和例子，不是从线性固定流程突然变成动态导航。（V9D-03、V9D-04）

### 能力

v9 的 capability instance 定义列业务单元、价值流或其他情境；v11 §2.2 的定义去掉该并列中的价值流字样，版本历史称强化业务单元中的具体实现视角。v11 还扩展能力定义与分解指导。此处仅记措辞和指导变化，不推断能力从此不能与价值流相映射；v11 正文仍讨论跨价值流使用。（V9D-05、V9D-07）

### 流程

v11 对 §3.4 作整体重写，新增 Process Outcome 作为能力结果与具体流程输入/输出之间的连接，并增加具体映射示例。v9 已把业务架构和流程视为不同观察角度，不能据旧版图把能力、价值流阶段和流程做成固定一一对应；本项目后续核对以现行 v11 说明为准。（V9D-08）

### 数据建模

信息图不等于数据库模型的边界在 v9 已存在。v10 更新移动知识库图并引起编号变化，因此不能把 v9 的图号机械套到 v11；对象到信息概念的语义与实现到表的映射仍须分开。未发现足以改写 v11 笔记这一基本边界的相反规定。（V9D-01、V9D-06）

### 度量与 BI

v9 已有 §3.7 绩效管理，并非 v11 新增。此次只核其存在和框架用途，**未完成该节逐条差异核对，不能断言两版内容相同**；不因阅读旧版而扩大项目采用范围，也不新增 KPI 公式。（V9D-09）

### 主数据

本次已核章节及 v10/v11 相关更新记录没有提供可据以新增匹配合并、主记录优先级或版本表实现的变化依据；这不是全书证明不存在相关文字。主数据实现仍按本项目既有规则，不从版本号变化推导新的写入权。（V9D-06）

## 4. 对本项目的取舍

**已审定（one-architecture 2026-10-18，已抽查）。** [FRAMEWORKS](../../FRAMEWORKS.md) 已锁定 v11，本卡不降低版本。

- **采纳：用现行 v11 的状态、流程结果及映射说明核对架构资料。** 理由：避免旧例和旧图号造成关系误读。
- **采纳：保留确已存在于 v9 的判据来源，版本变化只写可核的改动。** 理由：primary/secondary、汇聚例外和动态导航并非 v11 首创；不能为版本差异编造概念演进。
- **不采纳：退回 v9、扩用参考模型或借版本差异撤销项目裁剪。** 理由：项目先对象后能力、阶段门预警等决定不由本次阅读重开。
- **不采纳：把尚未逐条比较的章节写成无变化。** 理由：绩效管理、主数据及其他章节的未核范围应继续明示。
