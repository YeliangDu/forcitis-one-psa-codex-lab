# AGG-139「奖金调整运行」两张表的设计层复核（one-data，2026-10-23）

依据：`claude/one-arch-finance-closeout` @0b0a23b6，`data-model.finance.yaml` 的 `bonus_adjustment_runs`、`bonus_adjustment_lines`，`BONUS_OVERTIME_COSTING.md` §6.1，PRC-96 第 9、10 步。（@0b0a23b6 本身只重生成全景冻结事实，设计内容在同分支 data-model 与提案里。）

结论：**设计层通过，附 G1–G7**；DDL 草案出来后我对照下列条目逐行核。pi:none、internal 同意——行按法人 × 项目、不到人，不含个人信息；不迁入（结果由 B-16 记账事实承载）同意。

| 编号 | 项 | 要求 |
|---|---|---|
| G1 | 「每法人 × 期间一次有效，冲销后失效」 | 部分唯一索引 `uk_…(legal_entity_id, fiscal_year, period_number) WHERE status IN (…有效状态…)`；状态用 `_kind`/状态枚举加具名 CHECK，**有效状态集合在 DDL 里写死并在列注释列出**；冲销后新建一次的用例入 IT。重复触发（S37）靠此索引兜底，不再另设幂等键（与 AGG-43 的幂等键口径不同，请在注释说明原因） |
| G2 | 项目为空的行 | 「(run, 项目) 唯一，项目为空每运行至多一行」用一个 `UNIQUE NULLS NOT DISTINCT (bonus_adjustment_run_id, project_id)`（基线已有同写法，PG18 支持），不要拆成两条部分索引；`project_id` 列注释写「为空表示拆不到项目，转费用（LEB-05）」 |
| G3 | 调整金额与余额快照 | 条件 S-4b①要求调整后余额归零，故调整额 = −快照。两者都存可以（沿 AGG-41 F4 先例），但须加等式 CHECK `adjustment_amount = -balance_snapshot_amount`，并有"非零"CHECK（余额为零不生成行，S36）；若有例外（如拆分后的差额）请 one-architecture 在提案里写明，否则 CHECK 不放宽。金额与币种成对，币种一列共用，币种随运行的法人本位币，不逐行不同 |
| G4 | 快照不可变 | 行不可变：不留 `version`/修改审计列；运行重做走"冲销 + 新运行"，不改行；用触发器或不授权 UPDATE 守住（沿 F3），不靠应用自觉 |
| G5 | 记账事实引用放哪 | 一次运行只提交一个过账候选（第 10 步）时，引用应放运行根表（沿 AGG-43 的"过账结果引用"），不放逐行；逐行放 `business_fact_id` 会出现一半行有引用的中间态。请 one-arch-finance 说明是逐行提交还是整单提交，整单则上移到根。引用只存 ID、不建外键（跨 BC），为空表示"尚未提交过账候选"，状态与是否有引用成对 CHECK |
| G6 | 待内部结算标记 | 命名 `is_pending_internal_settlement`（布尔，`NOT NULL`，无默认，生成时写）；它是生成时点由员工成本法人与项目承担法人比较得出的**当时值**（ADR-0073 第 1 条），不随之后组织变动重算，列注释写明；若能由两个法人列推出则改为两列存法人 ID、不存布尔（D1 派生值不存），请 one-arch-finance 二选一 |
| G7 | 根表基本列 | 单据编号唯一、落账期间（会计年度、期间序号）的取值范围 CHECK 沿 `labor_cost_allocation_runs` 现有写法；`version` 与审计列照常；业务日期的含义（触发日还是落账期间末）写进列注释 |

说明：①不到人由表结构保证——`bonus_adjustment_lines` 不设员工引用列，无需 CHECK；②读者范围 internal 与 AGG-41 的"奖金计提行"不矛盾；③保留期无个人信息，随财务单据保留期，不单设；④本复核不覆盖 DM-8（AGG-41 分配行是否到人，仍待 FD-09）。
