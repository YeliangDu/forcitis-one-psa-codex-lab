# AGG-41 表级改动复核（ARC-1022-AFI-01：奖金计提与加班计价）

- 结论：**设计层通过，附 F1–F6**；DM-8（分配行是否到人）仍开，在 FD-09 定之前 `labor_cost_allocation_lines` 的 pi 保持待判，不得进表结构 PR。

| # | 改动 | 意见 |
|---|---|---|
| F1 | 分配行加「行类型」与三组可空列族（加班计价、奖金计提、奖金核定引用） | 同意同表（INV-89 守恒要按运行汇总各类行），条件：①行类型用 `_kind` 枚举 + 具名 CHECK；②每组列族与行类型联动 CHECK——行类型为某类当且仅当该族必填列全非空、其余族全空，写成逐类型成对的形式并用 `coalesce(…, false)`；③**奖金计提行、奖金调整行的员工引用列必须为空**（CHECK），保证「按项目、不到人」；④各列族每列注释写「为空表示」。DDL 草案一并送我 |
| F2 | 加班计价（日期类型、是否已安排补休、倍数、计价工时） | 日期类型用 `_kind` 枚举 CHECK；补休标志用 `is_…` 布尔；倍数 `numeric` 带范围 CHECK（大于 0）；计价工时带单位后缀（`_hours`）与非负 CHECK；倍数的取值来源是费率卡版本（F5），不另存规则 |
| F3 | 奖金核定引用与累计计提额（AGG-76，跨 BC） | 引用只存 ID、不建外键；「累计计提额」是核定时点的快照，行不可变，不得被后续计提回写；金额与币种成对，币种随运行 |
| F4 | 新表 `labor_cost_allocation_variances`（pi、sensitive） | 访问级别 SENSITIVE、个人信息 PI 与登记口径一致（SENSITIVE 含「工资」，`data-classification.txt` 文件头）。条件：①`(labor_cost_allocation_run_id, employee_id)` 唯一；②「差异金额 = 计价合计 − 当月实际薪酬」存储列须带等式 CHECK（或不存、读时算——我倾向存，便于对账，CHECK 守住）；③四个金额列共用一个币种列；④员工、部门引用跨 BC 只存 ID；⑤**保留期不得写永久**（含个人薪酬，ADR-0043 R-2），建议随薪酬类记录，具体期限须用户认可（D12）；⑥读者范围在注册表登记为受限（薪资、财务）；⑦`history_migration: none` 同意（结果由权责事实承载、重算） |
| F5 | 运行表加费率卡版本引用（AGG-137，同 BC） | 同 schema，用真外键 `ON DELETE RESTRICT`；因投产前两期按 U-10 重算，每个运行都有所用费率卡版本，建议 `NOT NULL`；引用的版本须已确认且生效区间含业务日期（D7/D15），做成守护触发器或应用校验并有测试；AGG-137 的表须与本改动同批或先于它建 |
| F6 | INV-89「项目分配额 + 差异 = 实际人工成本」 | 跨行守恒无法写成 CHECK；用对账查询 + 集成测试守住，并登记为数据质量规则（D13）；差异计期间损益、不进项目，差异行不得带项目引用 |

另：DM-8 的 pi 判定我这边的口径——只要工时人工行带员工引用，该表即含个人工时成本，按 `SENSITIVE` + `PI`；若 FD-09 定为不到人，才可降为不含个人信息，且须有 CHECK 保证没有员工引用列（或不建该列）。
