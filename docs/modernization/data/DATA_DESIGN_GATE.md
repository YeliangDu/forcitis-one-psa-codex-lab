## 1. 适用范围与流程

### 1.1 什么时候必须过门禁

卡（派工卡、批次卡、规则卡落地卡——指把规则卡写成代码的派工卡）含下列任一项即「涉数据」：

1. 新增或修改 **表、列、约束、索引**（含基线 `db/migration` 的改动）；
2. 新增或修改 **事件载荷**；
3. 新增或修改 **读模型 / 投影 / 报表视图**；
4. 新增或修改 **迁入映射**（含对账口径、来源对照）；
5. 新增或改口径的 **指标**，或改动数据访问注册表、`data-classification.txt` 的条目（SESSION_PLAYBOOK §13 原文只列前 4 项，第 5 项见 §7）。

不涉数据的卡，在卡的「数据设计」一节写「不涉及」并逐项写五项为何都无；one-data 抽查，发现涉数据而写「不涉及」的，按未过门禁处理。

### 1.2 顺序

涉 DDL 的卡，顺序按 SESSION_PLAYBOOK §13「数据模型先行」（表结构单独成 PR、合并后才派写业务代码的代理）：

```
卡 ─▶ one-data 审查 ─▶ 签发 ─▶ 表结构 PR（预期 diff；one-data 复核；合并）─▶ 验收测试 ─▶ 实现
```

不涉 DDL 但涉数据的卡（事件载荷、读模型、迁入映射、指标）：

```
卡 ─▶ one-data 审查 ─▶ 签发 ─▶ 验收测试 ─▶ 实现 ─▶ one-data 复核实现与卡一致
```

> SESSION_PLAYBOOK §13 内两处写法不一致：「数据模型先行」条（表结构 PR 先于业务代码）与「DD 门禁」条的顺序（验收 → 实现 → 表结构 PR）。本清单暂按前者；请用户在 §7 裁定。

1. **卡**：卡作者按附录 A 填「数据设计」一节；材料不全，one-data 退回，不审。
2. **审查**：卡作者把卡路径发 one-data。one-data 按 §3 逐条判，把「数据设计审查」记录（附录 B）交给卡作者（§1.3 说明怎么交付）。逐条给「通过 / 不通过 + 证据」。
3. **签发**：全部通过才签。**未答复、口头答复都不算通过**；one-data 收到后一个工作回合内答复，超过则卡作者报 one-coordinator，不得当作通过。
4. **后续各步前置**：验收测试代理、实现代理开工前核对签发有效（§1.3）；无效不开工。
5. **实现**：只改卡上列出的表、列、约束、索引、事件字段；要多改回到第 1 步。已提交的验收测试，由改动涉及的部分重写，验收代理判定。
6. **补审不通过而卡已合并**：问题登记为修复卡，按阻断 / 高 / 中 / 低排期，不回滚已合并的内容，除非是阻断项。

### 1.3 签发行、交付与有效性

- **写法**：`数据设计：通过（one-data，2026-MM-DD，依据 <卡文件的 git 提交号>）`。
- **交付**（卡在开发会话的分支上，one-data 不改他人分支，CLAUDE.md 第 14 条）：one-data 把审查记录写成片段 `docs/modernization/data/reviews/<卡号>.md`，在自己的分支上提交，把提交号与签发行发给卡作者；卡作者把审查记录片段合入自己分支（或在卡的「数据设计审查」一节原样粘贴），PR 正文引用签发行。
- **有效性判法**：`git diff <签发所依据提交号>..HEAD -- <卡文件>`，「数据设计」一节无改动，且该节引用的信息图 OBJ 行、规则卡、ADR 无改动，即有效；否则失效，只重审变更处并改写日期。
- **有待决项时**：一条条目涉及要用户定的事（保留期、分级、口径），该条目判「不通过（待用户决定）」，登记待决收件箱；用户答复前不签发。允许先把该条目对应的表、列从本卡拆出去，余下部分先签发。**不存在「有条件通过」**。
- **`[建议]`**：标在条目上，不阻塞，写进审查记录由卡作者决定是否改。其余条目不通过即不签发。

### 1.4 表结构 PR 复核（one-data 的第二次介入）

只做五件事：

1. 实际表结构 diff 等于卡上的预期 diff（逐表逐列逐约束对照，多出或少了都退回）；
2. 注册表条目与卡一致，且没有新增 `gaps`；
3. 守护全绿，且没有新增例外清单条目——新增须在卡上有对应的出处（§5）；
4. 逐表打分结论写入 `phase1a/DATA_SCORECARD.md` 的新增行（§14.1 要求逐表打分；打分在设计审查时已做，这里只落表）；
5. 安全与结构由 opus 复审（SESSION_PLAYBOOK §6.1），one-data 不重复。

## 4. 一张卡怎么判

1. 先看 B1：表 → 出处有空格，其余不看，直接退回。
2. 逐表过 O 系列与 C 系列；涉分析事实的过 A 系列；涉迁入或过渡的过 T 与 E3；涉事件、读模型的过 E1、E2。
3. 每条判定写「条目号：通过 / 不通过 + 证据（卡节号、信息图 OBJ、规则卡、迁移文件:行）」。证据缺失即不通过。
4. 同一张卡退回两次仍有同类问题，one-data 报 one-coordinator。
5. 审查记录按附录 B 写，交付按 §1.3。

## 5. 豁免与偏离

- 条目不适用：审查记录写「不适用 + 理由」，one-data 认可后视同通过。
- 要偏离本清单所引的已采纳 ADR 或 §14.1：**不由 one-data 或卡作者决定**，登记待决收件箱（`rules/decide/inbox/README.md`），用户定后在卡与审查记录里引用 intent。
- 例外清单按各自出处走：D17 豁免清单与主键基线「只减不增」（§14.1 D17 细则 2、ADR-0033）；§14「已登记的例外」与 `*-exceptions.txt` 由 one-coordinator 接受并登记（SESSION_PLAYBOOK §14 已登记的例外）。卡要新增例外，写出处与接受人。
