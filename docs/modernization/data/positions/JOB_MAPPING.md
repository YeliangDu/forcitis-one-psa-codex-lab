## 1. 映射方法

1. **粒度**：按人（在职人员的当前主任职）为主；「A8 岗位 → 候选职位」规则表只用来批量给候选，A8 岗位不是目标对象，不建 1:1 对照。
2. **候选生成**：A8 岗位名称剥离职级前缀（T、M、S、A 加数字）得到职能名，职能名对应候选 `job_code`；剥离只用于生成候选，**最终以人工核对为准**（ADR-0029 第 3 项第 1 条对解析老命名的保留意见仍适用）。
3. **每人目标字段**（迁入时写入）：`job_code`、`job_grade`（方案未定前填「待定」并保留原职级前缀原值作来源对照列，只在防腐层使用，D16）、`career_track`（随 J-1）、是否组织单元负责人（随 J-4）、映射依据（岗位名规则 / 人工）、把握（高 / 中 / 低）。
4. **版本化**：目标为版本化主数据（D17）；迁入时每个职位只建首个版本，生效日取新目录启用日；任职的历史区间引用老前缀原值，不回溯改写；员工任职版本的生效依据为人事业务生效日（DECLARED，intent 2026-10-16-134434）。
5. **不在本次映射内**：职称（人员属性）、注册执业证书（OBJ-64）、项目角色（OBJ-34，Q13）。

## 3. 须标出的情形

- 一个 A8 职能名对应多个新职位（例：幕墙类按设计 / 结构 / 检查拆分）：映射类型「拆分」，人工逐人确认；
- 无法归入任何新职位：映射类型「无法映射」，报新职位目录缺口给 one-architecture，不硬塞；
- 前缀不在 T、M、S、A 内或缺失；
- 管理职务（A8 `ORG_LEVEL`）与岗位不一致（随 J-4 的处理方式）；
- 在职人员无岗位：计数，迁入前由人力补登。
