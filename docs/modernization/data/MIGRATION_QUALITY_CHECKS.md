# 迁入质量检查要求（草案 v1，待 ADR-0036 修订与 SESSION_PLAYBOOK §14.2 增项）

- 日期：2026-10-21；起草：one-data；缘起：用户「旧系统数据进来要进行质量检查，确保新数据质量可靠」（经 one-coordinator 转来）。
- 与现行规定的关系：ADR-0036 第 7–8 条与 §14.2 M5、M6、M9 管的是**搬得对不对**（行数、金额、来源 ID 摘要一致，拒收有处置）。它们查不出「老数据本身不合格但搬得一模一样」。本文补**数据本身合不合格**这一层，并把差异清单、负责人、期限、「不通过不入库」写成硬条款。不改变 ADR-0036 的暂存、试提交、提交结构，质量检查嵌在「暂存之后、试提交之前」和「试提交之中」两处。
- 基本原则（D14 数据质量规则、GUIDING_PRINCIPLES 缺失或无效输入失败并告警）：**质量不通过的行不进目标库，也不静默修正**；修正的唯一途径是处置（改源后重抽、业务确认的映射规则、合并/改号/确认不迁），处置有人、有期限、有审计。

## 1. 检查层次与时点

| 层 | 时点 | 做什么 | 谁执行 |
|---|---|---|---|
| Q1 暂存体检 | 暂存完成后，试提交前 | 对暂存表（自有表）跑 SQL 级规则：完整性、取值、范围、重复；不依赖目标 BC 代码 | 集成层迁入适配器的质量检查步骤 |
| Q2 领域校验 | 试提交中 | 目标 BC 迁入入口跑领域规则（引用、状态、跨对象一致），逐行拒收（ADR-0036 第 7 条已有） | 目标 BC 迁入用例 |
| Q3 跨表一致 | 试提交后、提交前 | 对试提交结果（回滚前）跑跨对象一致规则：汇总=明细、父子一致、期间与日期一致 | 编排模块的跨表检查步骤 |
| Q4 对权威源 | 核对（第 8 条）并行 | 与权威源（老系统生产库聚合、财务报表、人事花名册等）比较：行数金额之外还比业务口径（人数、合同额、余额、已开票额） | 核对步骤，权威源取证走 ADR-0037 登记 |
| Q5 抽样复核 | 提交后复核前 | 业务按分层抽样人工核对（表单、附件、关键字段） | 业务负责人，应用内录入结果 |

每个层次的结果都落到同一张**迁入质量差异清单**（第 3 节），不另起多处记录。

## 2. 按数据类的质量规则

规则编号 `MQ-<类>-nn`；每条写明层次、判据、严重度：**阻断**（有一行违反即该对象类型不能提交）、**拒收**（该行拒收并进差异清单，其余可提交，但须有处置）、**告警**（进差异清单，不阻止提交，须有说明）。各阶段迁入规格（M1）必须逐类引用本节，缺类须写理由。

### 2.1 通用（所有类）

| 规则 | 层 | 判据 | 严重度 |
|---|---|---|---|
| MQ-G-01 来源键完整 | Q1 | 来源键非空、同批次内唯一；同一来源键摘要变化走 ADR-0036 第 7 条「已提交不覆盖」 | 拒收 |
| MQ-G-02 必填非空 | Q1 | 目标列 NOT NULL 对应的来源取值不为空串或占位符（如 `-`、`无`、`N/A`、`0000-00-00`） | 拒收 |
| MQ-G-03 取值映射 | Q1 | 来源状态码、类型码全部在映射表内；映射外取值不得落默认值 | 阻断（映射缺口）；单行异常拒收 |
| MQ-G-04 日期合理 | Q1 | 日期在 [2000-01-01, 切换日]；起止日期 起 ≤ 止；业务日期不晚于创建时间超过阈值 | 拒收 |
| MQ-G-05 金额与币种 | Q1 | 金额有币种（M1 规则）、不为负（除冲销行）、小数位不超过目标精度，不静默四舍五入 | 拒收 |
| MQ-G-06 文本清洁 | Q1 | 首尾空白、控制字符、乱码（无法按 UTF-8 往返）、超长；编码类字段（工号、编号）格式符合发号规则 | 拒收 |
| MQ-G-07 范围 | Q1 | 法人在 ADR-0022 的五家之内；对象在本阶段迁入规格的过滤条件之内 | 拒收 |
| MQ-G-08 个人信息分级 | Q1 | 带个人信息的列按 ADR-0043 分级写入；演练数据遵守 ADR-0036 第 10 条（6e 敏感数据不进演练） | 阻断 |

### 2.2 主数据（法人、部门/组织、岗位、员工、客户、供应商、项目、合同主体等）

| 规则 | 层 | 判据 | 严重度 |
|---|---|---|---|
| MQ-M-01 自然键唯一 | Q1 | 工号、统一社会信用代码、项目编号等在来源内唯一；重复一律进冲突清单，**不放宽**目标唯一约束（员工重复工号沿用 W2 设计第 192 行的 `employee_code_conflicts`） | 拒收 |
| MQ-M-02 引用闭合 | Q2 | 上级部门、所属法人、岗位、负责人等引用的对象在本批次或目标库中存在；环（部门上级成环）为错误 | 拒收 |
| MQ-M-03 生命周期一致 | Q2 | 停用/离职对象的结束日期非空且不早于开始日期；在职对象无结束日期；员工任职区间不重叠 | 拒收 |
| MQ-M-04 版本区间 | Q2 | 有版本的主数据：生效区间不重叠、无空洞、起始日不晚于结束日（D6） | 拒收 |
| MQ-M-05 身份证件与联系方式 | Q1 | 证件号校验位、手机号、邮箱格式；不合格不猜测修正，进清单由人事处置 | 告警（不阻断），身份证件校验失败为拒收 |
| MQ-M-06 同一实体多记录 | Q1 | 疑似重复（同名同证件、同名同手机）出疑似清单，人工确认合并或保留 | 告警 |
| MQ-M-07 权威源比对 | Q4 | 在职人数、部门数、法人数与人事花名册/组织架构权威源按法人、部门分组一致 | 阻断 |

### 2.3 账号与权限

| 规则 | 层 | 判据 | 严重度 |
|---|---|---|---|
| MQ-A-01 账号对应人员 | Q2 | 每个账号对应存在的员工；离职员工账号处于停用 | 拒收 |
| MQ-A-02 角色映射 | Q1 | 老角色全部映射到新角色或明确「不迁」；不得按名称相近猜测授权 | 阻断（映射缺口） |
| MQ-A-03 最小授权 | Q3 | 迁入后权限集合不超过老系统同账号权限集合（新增权限为阻断） | 阻断 |

### 2.4 单据与流程（合同、报价、发票、报销、工时单等）

| 规则 | 层 | 判据 | 严重度 |
|---|---|---|---|
| MQ-D-01 状态与时间线 | Q2 | 单据状态与已有的审批/过账记录相容（已通过必有通过记录；已过账必有过账结果）；时间线单调 | 拒收 |
| MQ-D-02 头行一致 | Q3 | 行金额合计 = 头金额（含税/不含税/税额分别核）；行号连续无重 | 拒收（整单） |
| MQ-D-03 编号 | Q2 | 原编号作展示号，唯一；不耗计数器（ADR-0036 第 4 条）；无编号单据进清单 | 拒收 |
| MQ-D-04 引用闭合 | Q2 | 单据引用的合同、项目、客户、员工存在（含已确认不迁的对象 = 引用断裂，必须一并处置） | 拒收 |
| MQ-D-05 在途单据 | Q2 | 未结束流程按 ADR-0036 U-4 处理；在途状态没有对应的当前处理人时进清单 | 拒收 |
| MQ-D-06 附件 | Q1 | 附件元数据完整、文件存在且大小/摘要一致；文件缺失不迁元数据 | 拒收 |

### 2.5 权责事实与财务（过账、期间、余额）

| 规则 | 层 | 判据 | 严重度 |
|---|---|---|---|
| MQ-F-01 借贷/收入三值 | Q3 | 收入确认类含税 = 不含税 + 税额（ADR-0024），逐行成立 | 阻断 |
| MQ-F-02 期间归属 | Q2 | 事实落入的期间存在且为历史期间或开放期间；日期与期间一致 | 拒收 |
| MQ-F-03 冲销配对 | Q3 | 每个冲销行有原行，冲销抵消后金额符合；孤立冲销拒收（ADR-0036 第 7 条） | 拒收 |
| MQ-F-04 汇总 = 权威账 | Q4 | 按（期间 × 法人 × 科目/对象类型）汇总与财务权威报表（经财务提供或生产核对）一致，差异须财务签字（ADR-0036 第 8 条） | 阻断 |
| MQ-F-05 期末余额接续 | Q4 | 历史期间期末余额 = 下一期期初余额，切换日余额与老账一致 | 阻断 |

### 2.6 日历与时间配置

| 规则 | 层 | 判据 | 严重度 |
|---|---|---|---|
| MQ-C-01 日历完整 | Q1 | 年度日历每个例外日期落在所属年份；调休上班日为周末；有来源通知文号（见 WORK-CALENDAR-DDL-2026-10-21 `source_kind = MIGRATION`） | 拒收 |
| MQ-C-02 与权威比对 | Q4 | 年度放假天数与当年官方放假安排核对 | 阻断 |

## 3. 迁入质量差异清单（所有层共用）

在 ADR-0036 的 `migration_rejects` 基础上扩列，或新增 `migration_quality_findings`（建表随迁入核对卡的数据设计签发；本文只定字段与规则）。每行：

| 字段 | 说明 |
|---|---|
| `finding_id` | UUIDv7 |
| `migration_batch_id` | 批次 |
| `rule_code` | 违反的规则，如 `MQ-M-01` |
| `check_layer` | Q1–Q5 |
| `severity` | 阻断 / 拒收 / 告警 |
| 对象列 | 来源对照 ID（`uuid`，指向来源对照）**或**自有对象 ID（`uuid`），二者**恰好一个非空**（具名 CHECK）；不拼文本键（同 SD-1 要求）。对象类别单列 `object_category` |
| `detail_code` / `detail_values` | 违反的是哪个字段、期望与实际值的**非个人信息摘要**（个人信息只存来源对照，不抄值进清单） |
| `disposition` | `PENDING`（默认）、`FIX_SOURCE_RERUN`（改源重抽）、`MAPPING_RULE`（业务确认的映射规则）、`MERGE`、`RENUMBER`、`EXCLUDED`（确认不迁）、`ACCEPTED_WITH_NOTE`（仅告警类可用） |
| `disposition_by`、`disposed_at`、`disposition_note` | 处置人（取自会话）、时间、说明；迁入角色与运维不能代填 |
| `assignee_id` | **负责人**：指派的业务处置人（人事数据→人事负责人；财务事实→财务负责人；其余→业务管理员，沿用 ADR-0036 第 7 条授权口径） |
| `due_date` | **期限**：创建时按批次的切换计划自动设置（默认不晚于该批次「核对签字日」前 N 个工作日，N 由迁入规格定）；逾期自动升级通知给调度会话与该阶段负责人 |
| `created_at`、`resolved_at` | 追加；清单行只追加处置，不删改原始发现（处置另行追加，D8） |

规则：
1. **严重度为阻断的发现，处置必须使它消失**（改源重抽后重跑通过），`ACCEPTED_WITH_NOTE` 与 `EXCLUDED` 不得用于阻断项。
2. **拒收项必须有处置**：`PENDING` 的拒收项数 > 0 时批次不得提交（ADR-0036 第 7 条已有，此处覆盖质量发现）。
3. **告警项**可由负责人确认接受，但须写说明；接受的告警随批次进核对报告。
4. 每条处置写审计（`platform.audit`），清单可在应用内按批次、规则、负责人、期限、状态查询和导出，不是日志文件。
5. 重复工号冲突清单（W2 设计第 192 行 `employee_code_conflicts`）是本清单中主数据 MQ-M-01 的专用形态，可保留专表，但字段须含 `assignee_id` 与 `due_date`，并在本清单中有汇总行（同一视图）。

## 4. 「不通过不入库」的门槛

批次从「核对通过」转「提交中」须同时满足（编排模块在转状态前检查，缺一即拒绝并列出缺项）：

1. 本阶段迁入规格对象清单内的每个对象类型，Q1–Q4 全部已执行（执行记录齐全，缺一类即不能提交，同 G-MG7）；
2. 严重度「阻断」的发现 = 0；
3. 「拒收」类发现全部有非 `PENDING` 的处置；
4. 逾期未处置的发现 = 0（逾期须先由负责人延期并写原因，延期次数计入报告）；
5. 告警项已确认；
6. Q5 抽样结果录入，抽样不合格率不超过迁入规格设的阈值，超阈值则回到 Q1 重查该类；
7. 核对签字（ADR-0036 第 8 条）把本节检查报告作为附件，财务/业务负责人签字对象为「质量报告 + 核对结果」。

提交后复核（第 7 条）再对目标库跑一遍 MQ-G/M/D/F 中的 Q3 类规则，不通过按第 9 条整批冲销。

## 5. 现行规定的缺口清单

| # | 缺口 | 现状 | 补法 |
|---|---|---|---|
| Q-1 | 无「数据本身合不合格」的规则 | ADR-0036 第 7–8 条只有格式/领域校验与行数金额核对；老数据本身脏、搬得一致时全部通过 | 采纳本文第 2 节，ADR-0036 增一条「迁入质量检查」，§14.2 增 M11 |
| Q-2 | 无按数据类的规则库 | M1 要求「核对口径」但没有质量规则模板 | 本文第 2 节作模板，各阶段迁入规格逐类引用 |
| Q-3 | 差异清单无负责人与期限 | `migration_rejects` 只有批次、来源、原因代码、处置取值 | 第 3 节字段；建表走 DD 门禁 |
| Q-4 | 没有「质量问题」的严重度分档 | 拒收一档 | 阻断/拒收/告警三档 |
| Q-5 | 没有与权威源的业务口径比对 | 核对只比行数、金额、ID 摘要 | Q4：人数、余额、合同额、放假天数等，权威源取证登记 ADR-0037 |
| Q-6 | 没有抽样人工复核 | 无 | Q5，应用内录入 |
| Q-7 | 「不通过不入库」只覆盖核对差异 | 提交门槛只有零差异/签字 | 第 4 节七条门槛，G-MG 增守护（提交前检查记录齐全） |
| Q-8 | 日历、账号权限、附件等类无迁入口径 | 只有权责事实有较完整口径 | 第 2.3、2.4、2.6 节 |
| Q-9 | 疑似重复实体无处理 | 只有精确重复工号 | MQ-M-06 疑似清单 |
| Q-10 | 规则集本身无版本管理 | 无 | 规则库放仓库，随迁入规格评审，规则变更记录进该阶段迁入规格版本 |

## 6. 落地路径与负责（建议）

1. one-architecture/one-coordinator：把「迁入质量检查」写入 ADR-0036（修订或补充 ADR），§14.2 增 M11、`NAMING_STANDARD` G-MG 增提交门槛守护；本会话可提供条文草案。
2. one-data：随迁入规格评审逐阶段把本文第 2 节落成具体规则表，并签发差异清单表结构的数据设计。
3. 各阶段迁入负责会话：实现 Q1–Q3 规则（规则放在可配置的规则库，阻断/拒收/告警分档），Q4 权威源取证经 one-ops 登记。
4. 业务负责人（人事、财务、业务管理员）：担任处置负责人，授权口径沿用 ADR-0036 第 7 条。
5. 需要用户定的事：Q5 抽样比例与不合格率阈值、清单期限默认值 N、逾期升级对象。
