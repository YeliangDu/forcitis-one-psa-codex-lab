## 2. 缺口与取数

1. **平均行宽与占用空间**：两库每表的 `rows / data_kb / index_kb`，用 `sys.partitions` 与 `sys.allocation_units`（元数据，不读行值，不 `COUNT(*)`）。
2. **A8 组织、人员、岗位、审批与协同明细**的行数：同一条查询覆盖。
3. **文件本体（NAS）**：业务方提供；数据库侧只有附件元数据（`CTP_FILE`、`CTP_ATTACHMENT`）的行数，在第 1 点里一并得到。

## 3. 量级估算（占位，待第 2 节实测替换）

下表的「假设宽度」是**占位假设，不是测量值**，只用来看量级；换成实测后重算。

|---|---:|---|---|

- **量级结论（待实测验证）**：迁入的数据库行合计 **约 1,700 万行，量级在个位数 GB（假设下约 2–5 GB）**；加索引后翻倍以内。归档与 NAS 文件是另一个量级，不在本页。
- 若实测显示 `psa_cost_*`、`psa_wip_*` 的平均行宽远大于假设，或 `ACT_GE_BYTEARRAY` 等大对象表需迁入，结论要上调，届时重算并告 one-ops。

## 4. 复核要点（给 one-ops）

- 目标库容量按「迁入数据 × 2（索引与约束）× 1.5（演练与暂存并存）」留余量，具体系数以实测后的版本为准。
- 迁入作业分批与耗时，按行数（1,657 万行）与批大小（ADR-0036 的暂存与核对）估；`COL_SUMMARY` 为堆且无 `CREATE_DATE` 索引，按主键分批。
- 11-10 续费前需要的容量结论：本页第 3 节实测版。
