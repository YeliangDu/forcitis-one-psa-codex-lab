# 任务登记片段

依据：`git show origin/main:docs/modernization/SESSION_PLAYBOOK.md` §5「任务命名与登记」，用户原话见 intent `2026-10-17-125047-one-coordinator-后台任务要显示任务名-我们现在派.md`。任务片段属于流程治理记录，不新增领域术语。

每卡 `tasks/<任务号>.md`，键值头沿用该条款的 13 个必填字段：任务号、任务名、主线、bc、种类、会话、执行者与模型、状态、分支、提交、返工轮次、用时、旧编号。可选字段 `来源: 回填` 表示历史回填，仍列入总表，但不参与日报的 Codex 卡数和返工增量；不填表示正常派工。

任务号 `<主线码>-<MMDD>-<会话码>-<两位序号>`，主线码 NAM / CON / ARC / RUL / DAT / IMP / CI / OPS / GOV，会话码 GLO / AFI / ARE / APE / ARC / PAR / NX5 / QUA / RUL / DAT / OPS / MRG / COO，日内序号由派卡会话自增。任务名 `[主线·bc] 动作 + 对象`，主线中文名对应检查器 LANES；bc 取 `../glossary/bcs.yaml` 的 id 或跨域。种类取设计、编码、测试、取证、复审、确认页、文档。

未知写待核；兼容其他会话已写的空值，读取时明确转为待核。`执行者` 是 `执行者与模型` 的兼容别名，只警告，不失败；两种键同时出现按重复字段失败。返工轮次填非负整数；用时填分钟数或 `12m` / `1h30m`，约数兼容 `约40m`、`约 25 分钟`，允许中文括号尾注，按括号前数值分钟统计并保留约数标记。旧编号保留原写法，同名旧卡按来源会话区分；同卡别名放在同一字段，正文说明证据。不把提交、合入或检查通过写成业务验收。

状态枚举为待派、已派、进行中、复审中、返工中、待验收、已完成、已提交、已合并、阻塞、已取消、待核；在途存量的其他状态只警告。任务名的主线中文名或 bc 与字段不一致也只警告。主线码、会话码、月日、必填字段、bc、数值格式非法会失败。

运行 `python3 docs/modernization/build_all.py` 生成 [TASKS.md](TASKS.md)。总表只由片段内容决定，不读取 Git 提交、提交时刻或脏净状态。总表包含按主线、bc、会话、状态的卡数、已知轮次及分钟数、待核卡数和明细；整组未知显示待核，已知为零才显示 0。`TASKS-DATA v1` JSON 仅保留规范化片段字段与内容摘要，不供日报读取。总表与 `_` 开头的说明、结果文件不作片段扫描。`python3 docs/modernization/check_tasks.py --self-test` 离线自测；`--check` 只检查片段，不写总表。`build_all.py --check` 比较重新生成前后内容，允许与片段一致的未提交产物，过期或缺失产物仍失败。precheck 经 build_all 检查片段并按改动运行条件自测。

PR 标题来自 `--pr-title '标题'` 或 CI 的 `GITHUB_EVENT_PATH`；缺任务号只告警，退出码仍为 0，不调用 gh。

日报保留 `codex_cards` / `codex_rework_rounds` 输出键；用 `git show origin/main:docs/modernization/tasks/<任务号>.md` 读取片段，以 `git log --first-parent origin/main` 的首次登记提交时刻计新卡，后续 frontmatter 累计轮次之差计返工增量。轮次下降按更正处理，增量为 0。时间窗口左闭右开；首次登记的历史累计返工、未知基数或执行者待核时对应会话留 null；主线缺片段或历史读取失败时两列为 null 并说明缺口。`来源: 回填` 的卡在卡数、返工两列中整卡排除，含标记添加之前的历史。工作区、其他分支及总表缺失或过期不影响主线统计；登记时刻不是原派工时刻。
