# GOV-1023-MRG-10 自动解冲突与定时同步

排在 GOV-1023-MRG-07 之后、MRG-08 之前。

## 目标

根因：串行合入只保证 main 一次进一个，各分支仍在旧 main 上并行开发数小时，先合者改了同处，后者即冲突；冲突在队列里才暴露，退回作者后无人接（#587 挂 20h）。10-22 后残余冲突在 `frontend/packages/api/openapi.json`、`src/generated/schema.ts`、`validators.ts`（生成物）与会话画像。
做法：①AUTO-RESOLVE 由「仅 build_all.py 产物」扩到 openapi 三件：冲突只在这三件时取 main 版本、重新导出 openapi 并跑 `generate-api.mjs`、推送；②运行器每 2 小时对已批准及待复审的在开 PR 试合 main（merge-tree），无冲突则推同步提交（不触发出队、不算作者改动，MRG-06 的 own_head 同步更新），有冲突即写 GAPS 报作者会话与调度。

## 完成标准

自测覆盖：只生成物冲突自动解、夹带手写文件冲突不解、同步无冲突推送、同步有冲突报 GAPS、同步后不误判 HEAD-CHANGED；破坏验证。

## 依据

同 GOV-1023-QUA-02。

## 不得做

不改分支保护；不替作者解手写文件冲突；不用 --no-verify。
