# GOV-1023-MRG-10 自动解冲突与定时同步

排在 GOV-1023-MRG-07 之后、MRG-08 之前。

## 目标

**10-23 收窄**：OpenAPI 随 QUA-02 出仓后由构建生成，本卡自动解冲突只保留迁移期与仍入库的生成物；定时同步、冲突前报、verify 预跑保留。


根因：串行合入只保证 main 一次进一个，各分支仍在旧 main 上并行开发数小时，先合者改了同处，后者即冲突；冲突在队列里才暴露，退回作者后无人接（#587 挂 20h）。10-22 后残余冲突在 `frontend/packages/api/openapi.json`、`src/generated/schema.ts`、`validators.ts`（生成物）与会话画像。
做法：①AUTO-RESOLVE 由「仅 build_all.py 产物」扩到 openapi 三件：冲突只在这三件时取 main 版本、重新导出 openapi 并跑 `generate-api.mjs`、推送；②运行器每 2 小时对已批准及待复审的在开 PR 试合 main（merge-tree），无冲突则推同步提交（不触发出队、不算作者改动，MRG-06 的 own_head 同步更新），有冲突即写 GAPS 报作者会话与调度；③入队前预跑整轮 CI：已批准或复审已贴结论的 PR，同步后打 `verify` 标签（heavy_gate.py 认 `verify` 等同 `queued` 跑整轮，不进合并），红即写 GAPS 退作者。根因：整轮测试只在 `queued` 后跑，入队前 PR 只有 light 绿（后端 33 秒），10-17 起 HOLD/RERUN-FAILED 29 次都在队首才暴露（10-23 #642 撞新 G42 守护、#599 撞 search_path 守护），每次占 code 道 20–35 分钟；runner 4 台排队中位 0 秒，有余量。入队时若 main 只多了 docs 层提交，沿用预跑结果（同 relevant_change.py 口径）。

## 完成标准

自测覆盖：只生成物冲突自动解、夹带手写文件冲突不解、同步无冲突推送、同步有冲突报 GAPS、同步后不误判 HEAD-CHANGED、verify 标签触发整轮且不入队、预跑红报 GAPS、main 只多 docs 时沿用预跑；破坏验证。

## 依据

同 GOV-1023-QUA-02。

## 不得做

不改分支保护；不替作者解手写文件冲突；不用 --no-verify。
