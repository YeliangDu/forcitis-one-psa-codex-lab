## 目标

防：会话一轮结束把报告或提问只写在本会话、不发给调度，工作流断档（10-23 one-platform-file #587 重批请求、此前 one-quality 同类）；app 限流或排队顶掉消息时报告丢失。

1. **状态声明（Stop 钩子）**：除 one-coordinator 外的会话，每轮最后一条 assistant 消息末行须为 `状态：继续｜待命｜等调度｜等用户｜完成点` 之一（可带一句说明）。缺失挡一次并给出写法；`stop_hook_active` 时放行并告警。
2. **发送检查**：声明为「等调度」或「完成点」时，本轮 transcript 内须有发往 one-coordinator 的发消息工具调用（ccd send_message 或 SendMessage，目标为调度会话 id 或名）；没有则挡，提示先发。限流失败写 outbox 视同已发（PB §11）。
3. **文件信箱**：上述两种声明一律由钩子把末条消息（截至 4 KB）、会话名、会话 id、分支、时刻写入 `~/.modernize/psa/mailbox/<时刻>-<会话>.md`（原子写，先 tmp 再 rename），不论是否已发消息。不写 PR 正文以外的个人信息与密钥（复用 gitleaks 规则或既有脱敏函数）。
4. **调度取信与回执**：`scripts/coord/mailbox.py`：`list --unacked`、`ack <文件>`（移入 `mailbox/acked/`）、`stale --minutes=20`（未回执超时列出）。调度会话用定时检查（CronCreate 每 10 分钟）跑 `list --unacked` 与 `stale`；调度画像与交接清单加「重设取信定时」。
5. 会话画像模板与 PB §11 消息约定各补一句状态声明规则（新规则手册对应 TEAM 条标「守」）。
