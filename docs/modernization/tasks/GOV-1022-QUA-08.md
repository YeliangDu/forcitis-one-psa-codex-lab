# GOV-1022-QUA-08 预检提速

## 目标

推送前检查通过后，同一提交上提 PR 不再重跑 precheck；推送前的后端单元测试只跑改动可能影响的类。

## 完成标准

- `pre_push_gate.py` 在 `precheck.sh --pre-push` 以「ready」收尾后，于 `<git 目录>/forcitis-precheck-pass.json` 记通过标记（提交、origin/main、时间）；工作区不干净不记。
- `precheck_before_pr.py` 见有效标记（提交与 origin/main 相同、工作区干净、不超过 2 小时）就放行并说明；否则照旧跑 `precheck.sh`。
- `light_unit_classes.py --changed` 只留模块外的测试与改动模块自己的测试；backend/ 下有非模块源码的改动（kernel、资源、pom、测试夹具等）退回全跑。`precheck.sh --pre-push` 用它并打印范围。
- 三个脚本的 `--self-test` 覆盖标记的有效、过期、脏树、新提交、基线移动、未跟踪文件，以及选择的各分支。
