# 派工卡 ARC-1022-ARC-04：命令编号持久化

## 1. 依据
- one-arch-people 2026-10-22 提出、one-architecture 裁定：命令编号由 `panorama/scan_commands.py` 的 `command_id(aggregate, name)` 哈希生成，命令改名即换号；编号被 `ssot/10-objects/transitions.yaml`（by_command）、`ssot/11-commands/command-mapping.yaml`、`ssot/12-facts/facts.yaml`（produced_by）引用，改名会断链。改为：编号一经分配固定，改名沿用旧号。

## 2. 范围
- 允许改：`docs/modernization/architecture/panorama/scan_commands.py`、`test_scan_commands.py`；新建 `docs/modernization/architecture/ssot/11-commands/command-ids.yaml`（生成并提交）；重新生成 `scan_commands.py` 的产物及 `build_all.py` 连带生成物。
- 不碰：各组 `closeout/*/commands.yaml`、`RESPONSIBILITY_MATRIX.yaml`（只读）；其他登记文件。

## 3. 规格
1. **编号登记** `ssot/11-commands/command-ids.yaml`：`ids:` 列表，每项 `{id, aggregate, name, former_names: [...], retired: false}`，按 id 排序。首次运行以当前 `ssot/11-commands/commands.yaml` 的 (id, aggregate, name) 为种子，编号一个不变。
2. **取号顺序**（`merge_commands` 内 `add` 取号处）：
   - (aggregate, name) 已在登记中（name 或 former_names 任一相等，且 retired 为 false）→ 用登记的号；
   - 否则，若该命令在任一组 `commands.yaml` 行上声明了 `former_names`（列表，可选新字段），且 (aggregate, 其中某个旧名) 在登记中 → 沿用该号，登记项 name 改为新名、旧名并入 former_names；
   - 否则按现有哈希起新号，与登记中任何 id（含 retired）冲突即报错；登记新增一项。
   - 权责总表 entries 按 (object, command) 同样取号，规则相同。
3. **退役**：登记中有、本次没出现的命令，置 `retired: true`，号不复用；再次出现同名命令时取消 retired、沿用原号。
4. `former_names` 字段校验：存在时须为非空文本列表；同一旧名被两条命令声明、或旧名指向另一聚合的命令，报错。
5. `--check`：登记文件与重算结果不一致即失败（和其他产物同一比对方式）。
6. 测试：种子后编号全不变；改名并声明 former_names 沿用旧号、登记更新；改名未声明则起新号且旧项 retired；退役后再出现沿用原号；哈希冲突、旧名重复声明、旧名跨聚合各报错；重跑字节一致。
