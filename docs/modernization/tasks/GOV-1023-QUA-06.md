# GOV-1023-QUA-06 钩子运行位置与注入瘦身

加急：排在 #653/#654 返工之前（它决定所有守护是否真在各会话生效）。

## 目标

用户 10-23 注入审查、调度实测：
1. `.claude/settings.json` 用 `$CLAUDE_PROJECT_DIR/scripts/hooks/…`，各会话跑自己工作区的旧版本。在用工作区 one-data 落后 main 553 提交、one-ops 381、均无 `start_sheet.py`；8/12 工作区钩子与 main 不一致；开工单 24 小时生成失败 11 次。
2. 推送门被拦时 `precheck_before_pr.verdict()` 回传预检输出末 40 行（每次约 3.8k 字，日约 59 次）。
3. 交接节点提示塞入多张卡的截断正文（每次约 1k 字）。
4. 调度交接阈值例外 50%/60%（intent 2026-10-23-081732）未入 `context_handoff.py`，调度在 30%/40% 被拦且提示「报 one-coordinator」。

做法：①settings.json 各钩子改为解析主检出（`git rev-parse --path-format=absolute --git-common-dir` 的上级）下的 `scripts/hooks/` 运行，主检出不可得时退回本工作区并告警；②verdict 只回失败项行（FAIL 行与其前后各 2 行，上限 15 行）与完整日志路径（日志写 git 目录下）；③交接节点提示只列卡号与标题；④context_handoff.py 按会话名读阈值表（调度 50/60，其余 30/40），调度不再提示「报 one-coordinator」。

## 完成标准

自测：主检出路径解析与退回告警、verdict 截取、节点提示只列卡号、调度阈值；破坏验证；在一个落后 main 的工作区实测钩子取主检出版本。PR 写明代价：钩子改动须合入 main 后才对全员生效。
