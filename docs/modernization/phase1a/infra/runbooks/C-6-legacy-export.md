依据：ADR-0026 第 8 项与 D-9（老角色导出已授权，1a 切换前执行）、`phase1a/TIMESHEET_REPLAY.md`（回放导出需用户授权，Q-4）、D-1a-114（2016–2026 共 4,018 天迁入）。时点：dev 前。性质：读生产数据，**每一类导出执行前须用户单独确认**；只读，不写老库。

查询：`sql/c6_legacy_readonly_export.sql`（STEP 1 列核对、STEP 2 角色、STEP 3 日历；STEP 4 回放按 TIMESHEET_REPLAY.md）。

## 执行前确认点

1. 用户逐项确认本次导出哪几类（角色 / 回放 / 日历），以及导出范围（回放：近期、当前定义版本 v15 的实例样本数量）。
2. 执行通道：与 2026-10-14 核实流程定义时相同的云助手只读通道；连接用只读身份（不使用 B-5 的两个视图账号——它们只能读各自视图；由老系统 DBA 提供临时只读账号或由 DBA 代为执行），用后由 DBA 停用。
3. 数据处理：导出文件含真实人员 ID，只存本机 `~/.modernize/psa/`，不进仓库、不发聊天；服务器临时目录用后删除；角色与日历导出不含姓名、手机号。
4. STEP 1 的列与查询不符时停止，修正查询并在执行记录中写明，不猜列。

## 步骤

1. STEP 1 列核对，结果留档。
2. 角色（STEP 2）：执行 2.1–2.3，各存 JSON；2.4 计数与文件行数一致。交 1a 代码会话做「老角色 → 新角色」对照与差异报告（ADR-0026 第 8 项第 2–5 条），差异由用户逐个决定。
3. 日历（STEP 3）：导出 CSV；3.1 期望 2016–2026 共 11 年、4,018 天、每年 365 / 366 天无重复。转换为每年一份 `{"days":[…]}`（只含 `day_kind` 非空的行），由组织数据管理员会话逐年 `PUT /api/v1/organization/work-calendars/{年}` 导入（或代码会话提供的导入命令），导入后逐年 GET 核对条数。
4. 回放（STEP 4）：按 TIMESHEET_REPLAY.md「导出文件」格式生成 JSON，运行回放命令，产出 `replay-report.md`；`REVIEWED_*` 请用户逐类接受，`DEFECT` 交代码会话修复（出口条件 D-3）。

### 2. 通道与服务器侧

- 与 psa-gl-scope 读 U8C 相同的做法（U8C_GL_PRACTICE「访问方式」）：经云助手在老系统应用服务器 `i-bp1b34hcl0g1cnkdtrb9` 上运行单文件 Java 探针，取老系统数据源，只读连接（`setReadOnly(true)`），拒绝非 SELECT 语句；凭据只在服务器进程内使用，不打印、不回传。
- **服务器上不落盘**：每次调用只取一页（按主键键集分页，每页 ≤ 3,000 行），结果 gzip + base64 后写到标准输出，由云助手结果带回（单次输出上限约 24 KB，超出就缩小页）；探针放在 `mktemp -d` 建的 0700 临时目录，同一次调用结束时 `trap` 删除；云助手命令 `KeepCommand=false`。
- 新 ECS（i-bp122xlpar8w2uylmal2）默认不存放导出文件。只有日历需要在服务器上经运维命令导入时，才放到 `/data/forcitis-one/ops/import/<YYYYMMDD>/`（root 0700，文件 0600），导入核对通过当天删除。

### 3. 本机存放、权限、保留与删除

| 项 | 规定 |
|---|---|
