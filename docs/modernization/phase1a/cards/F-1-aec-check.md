# F-1 数据范围规则对照 AEC 项目制专业服务公司通行做法（2026-10-15，one-1a-par，opus 只读，不联网）

依据：ADR-0026 / 0027 / 0032 / 0034；NEXT_BATCH_PLAN 2.4 F-1 行与第 8 节 F-1 规格裁定；验收分支 claude/one-1a-par-f1-acceptance 的 F1_ACCEPTANCE.md。

## 结论摘要
1. 总体方向符合惯例：仓储层强制范围、越权 404、范围不作请求参数、敏感权限逐人且第二人确认、离职关闭全部授予并逐条审计。
2. 1a 只做部门维度可接受；项目、利润中心、法人维度须按阶段排期（利润中心作为范围维度尚无 ADR）。
3. 冲突：自定义部门「含下级」随组织调整自动扩大，用在双人逐人级角色上时与 0032-Q1 选 (a) 的理由相悖。
4. 空白：自定义部门引用的部门撤销或合并时规则未写，现为静默缩小。
5. 冲突：「范围待复核」送新部门负责人，但处理权限只给组织数据管理员与安全审计员。
6. 安全审计员可「维持授权」（写操作），削弱审计独立性。
7. employee:read 宜明确为「逐人」。
8. 长期休假、外派、外部顾问 / 分包人员未有规则，宜登记后续阶段。

## 拿不准
1. 「本人及直接下属」是否应含整条汇报链。
2. 待调整权限超 5 个工作日：只升级，还是升级后最终期限默认收回（现行 0032-Q2 不自动收回）。
3. 是否需「区域」维度。
4. 长期休假与外派是否暂停访问。
5. 1b 报价是否需要「客户 × 负责人」范围。
6. R3-ID-22 改名随 F-1 实现，勿漏。
