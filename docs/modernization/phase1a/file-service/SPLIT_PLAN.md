## 1. 关键事实

1. 仓库无文件服务；对象存储写入只有归档用的 `ArchiveVault`（`platform.integration`），可借鉴「禁止覆盖、读回核对」，不复用（不同桶、不同语义）。
2. `kernel.DocumentReference` 仍以 `DocumentType` 枚举为字段；ADR-0066 决定 4 要求改为 `DocumentTypeCode` 值对象（注册表改造卡，W0 收口窗口）。文件服务的「关联」以 `DocumentReference` 为键，**须在改造卡之后落表**，否则表列与 CHECK 会按枚举写一次、再改一次。
3. 文件服务属基础层（ADR-0066 决定 2），不得依赖 numbering（公共服务层）：关联时只校验类型码格式，是否已登记由调用方负责（与 audit 同写法，ADR-0066 决定 4 第 5 条）。
4. ADR-0060 的迁入入口写「仅 `platform.migration`」；ADR-0066 决定 8 已改为流程模块「迁入编排」，名待 one-glossary。守护按新模块名写。
5. ADR-0070 尚为提议，它改了写入流程（检测前移到本地暂存、判定后才建行）。写入用例与适配器端口**按 ADR-0070 写**，因为 ADR-0060 原流程（未检文件先进对象存储）违反用户提醒 1；ADR-0070 采纳前，写入用例相关 PR 不入队。
6. 单文件上限已定 100 MB（intent 0746e278），ADR-0070 决定 6 其余三项（加密文件、隔离内容保留、`FILDES`）未定：按 ADR-0070 默认行为实现（加密拒收告警；隔离内容写隔离前缀、无人可读、按隔离保存期过期；保持 `SCAN`），配置化，不预选用户选项。
7. 先行上线（TRN-03）之前，文件服务 api 进入冻结范围（ADR-0067 决定 3）；`contains_macros`、检测状态取值须在冻结点前落定（ADR-0070 影响面）。
