## 1. 关键事实

1. 仓库无文件服务；对象存储写入只有归档用的 `ArchiveVault`（`platform.integration`），可借鉴「禁止覆盖、读回核对」，不复用（不同桶、不同语义）。
2. `kernel.DocumentReference` 仍以 `DocumentType` 枚举为字段；ADR-0066 决定 4 要求改为 `DocumentTypeCode` 值对象（单据类型注册表改造，one-1a-next-5 REG-1）。文件服务的「关联」以 `DocumentReference` 为键，**须在改造卡之后落表**，否则表列与 CHECK 会按枚举写一次、再改一次。
3. 文件服务属基础层（ADR-0066 决定 2），不得依赖 numbering（公共服务层）：关联时只校验类型码格式，是否已登记由调用方负责（与 audit 同写法，ADR-0066 决定 4 第 5 条）。
4. ADR-0060 的迁入入口写「仅 `platform.migration`」；ADR-0066 决定 8 已改为流程模块「迁入编排」，名待 one-glossary。守护按新模块名写。
5. ADR-0070 已采纳，取代 ADR-0060 的写入流程：检测前移到本地暂存、请求内同步、判定后才建行；未检文件不进对象存储。
6. ADR-0070 决定 4、6 用户已定：单文件上限 100 MB、超限即拒（intent 0746e278）；**加密拒收只写审计、不建行**、不新增状态取值；**隔离留内容 90 天**（配置项），仅安全角色经审批可读并审计，到期清内容只留 SHA-256；**误报**由安全角色判定、第二人复核（不得同一人），按 SHA-256 进例外清单，重传时引擎检出且在清单内即按通过并审计「按例外放行」；保持 `SCAN`。指标按原因分类计数（加密拒收、病毒检出、服务不可用、超上限）。
7. 先行上线（TRN-03）之前，文件服务 api 进入冻结范围（ADR-0067 决定 3）；`contains_macros`、检测状态取值、例外清单表与判定复核的状态和权限码须在冻结点前与 one-data 落定（ADR-0070 决定 6 第 3 条、影响面）。
