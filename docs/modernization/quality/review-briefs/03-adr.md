# 评审模板 3：ADR

通用做法、输出格式、七条通用盲区 B1–B7 见 [README.md](README.md)。

## 出题人填（只填这一栏）

- 产出：ADR 源文件路径（`docs/modernization/adr/src/ADR-NNNN.md`）、PR 号 / 提交、基线提交。
- 不填：「已与相关 ADR 核对」之类结论。

## 必读材料（自己读）

1. 产出本身，以及它声明「取代」的 ADR 原文（`adr/src/`）。
2. `adr/src/_readme_lifecycle.md`（生命周期与变更规则：七个状态、档位、头部字段、取代写法、检索记录）和 `adr/build_adrs.py` 文件头注释（格式与校验规则）。
3. SESSION_PLAYBOOK 附 M3（变更治理）：「ADR」不改正文、用新 ADR 取代；「规则调整三类」；「已过账事实」只能冲销重做；「谁可以改什么」；以及 TEAM-91–94（哪些事必须由用户决定）。
4. 用户决定的原话：`docs/modernization/intent/` 里被 ADR 引用的片段。
5. ADR「证据」一节指向的文件、数据、评审记录；与主题相关的其他 ADR（`grep -l` 关键词，自己找）。

## 必查项

| # | 查什么 | 判过 | 判不过 |
|---|---|---|---|
| A1 | **格式**：新稿头部字段（状态、日期、档位、起草、类别、BC、阶段、取代、被部分取代、用户原话、批准证据、理由；字段名是「批准证据」「被部分取代」）、七个状态之一（提议、搁置、已采纳、已拒绝、已撤回、已被 ADR-NNNN 取代、已废弃）、小节名与顺序、所在档位的必有小节 | 对着 `build_adrs.py` 的规则逐条符合，且 `build_all.py --check` 通过 | 缺小节、顺序错、状态词不在七个之内、旧字段名（「证据」「部分取代」）、档位与内容不符 |
| A2 | **决定可判定** | 每条决定有编号，给出数字、枚举、期限、负责人或明确的是 / 否；别人读完能判断某个实现是否合规 | 「尽量」「视情况」「原则上」而无判据 |
| A3 | **状态与用户决定一致**（SESSION_PLAYBOOK TEAM-91–94） | 「已采纳」有对应 intent 片段的用户原话（可点名到文件）；「提议」没有被当作已决定引用 | 「已采纳」无用户原话；他处把提议当结论 |
| A4 | **取代关系双向成立** | 声明取代 ADR-x 时，ADR-x 状态含「已被 ADR-本号 取代」（整份或部分，旧稿为状态行括注）或其「被部分取代」字段（新稿）列有本号；反向也成立；评审员打开 ADR-x 原文核 | 只写了一边（B7 类遗漏） |
| A5 | **与既有 ADR 不冲突** | 评审员 `grep` 相关主题的其他 ADR 与 `docs/modernization/` 规范，列出触及的条款并判相容 | 与另一份已采纳 ADR 条款矛盾而未声明取代 |
| A6 | **「需同步修改的守护规则」真的有后续** | 列出的守护（ArchUnit、清单、CI、precheck）在同一 PR 已改，或登记了带负责人的后续项 | 只写了「需同步」而没人、没处登记 |
| A7 | **影响面、迁移、回滚是真的** | 迁移方案有步骤和验证；回滚方案说明已过账事实怎么处理（§12.3：只能冲销重做，不能改历史） | 回滚写「还原即可」而涉及已过账数据 |
| A8 | **证据支撑决定**；选型类 ADR 有**适配研究** | 证据一节每个主张能在引用的文件里找到；选框架、标准、工具的 ADR 有对照本系统的代价与收益分析（不是泛泛比较） | 证据是转述；选型凭判断 |
| A9 | **备选方案是认真比较过的** | 至少一个备选写明不选的具体理由，且理由引用本系统的事实（模块、数据量、约束）；备选在没有该理由时是可行的 | 备选只有一句话，或不选的理由换到任何系统都成立（稻草人） |
| A11 | **对抗性评审已做且意见有处理**（SESSION_PLAYBOOK 附 M3「规则调整三类」表中「ADR 类」一行） | 证据一节有 `architecture-critic` 评审的意见与处理（采纳 / 不采纳 + 理由） | 没有评审记录，或意见被无声忽略 |
| A10 | **不改已采纳 ADR 正文**（§12.1） | 对已采纳 ADR 的修改是新 ADR 或 README「偏离清单」登记，不是直接改写 | 直接改了已采纳 ADR 的决定条款 |
| A12 | **检索记录可重放**（lifecycle 第 9 节第 2 条） | 「证据」有「检索记录」：检索词、命令、命中的 ADR 列表、每份的结论（相容 / 本 ADR 取代其某条 / 无关）；评审员在 `adr/src/` 重放检索，命中集合与记录一致 | 没有检索记录；重放多出的命中未列入；命中而不相容的 ADR 未列入「取代」 |
| A13 | **粒度与内容边界**（lifecycle 第 7 节、README「ADR 写什么、不写什么」） | 只有一个可单独采纳或拒绝的选择；清单、快照、参数、现状勘查没有写进决定（规范性内容写在 ADR，参考性快照标「参考快照，以 … 为准」） | 两个可分别采纳或拒绝的选择写在一份里；参考性清单当作规范性内容；正式档超过 20 KB 而未拆 |

## 轻量档子集

档位为「轻量」的 ADR 只查 **A1、A3、A4、A5、A12**，另核对：① 影响面、迁移方案、回滚方案、需同步修改的守护规则四节齐全（各一两句即可，但不能空）；② 头部「取代」为空，且没有任何 ADR 的「被部分取代」指向它（轻量档不得取代或部分取代已采纳 ADR）；③ 源文件不超过 6 KB；④ 满足轻量档判据 1、2（回退不涉及已过账事实、已应用迁移、已发布接口；不改 BC 边界、不引入新依赖或技术选型）。任一不满足判为应改用正式档。

## 本类特有的盲区（主动找）

- **B4 的反方向**：ADR 自己引用别的 ADR / 规范时，转述有没有改字面（数字、枚举值、期限）。
- **B7**：新概念或新用语没进 `terms.yaml`；新增的例外或登记项没进对应清单。
- **B3 / B6**：ADR 涉及部署形态时问镜像在目标架构上怎么运行；ADR 改状态机时，事件、审计、读模型、界面状态名是否同步列入「需同步修改」。
- **B2**：ADR 里写死了运行时 / 工具版本，是否与 `CI_RUNNERS.md`、`pom.xml`、`package.json` 一致。
- **B5**：评审员对「现有系统没有 X」「已有 ADR 没提 Y」这类说法自己搜证。
- 「已采纳」的 ADR 的「用户原话」是否被断章取义：对着 intent 片段全文读。
