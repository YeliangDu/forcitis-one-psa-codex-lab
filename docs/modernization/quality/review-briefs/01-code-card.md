# 评审模板 1：代码卡（派工卡落地的代码）

通用做法、输出格式、七条通用盲区 B1–B7 见 [README.md](README.md)。本文只写这一类特有的内容。

## 出题人填（只填这一栏）

- 产出：PR 号 / 分支，提交范围 `<基线提交>..<HEAD>`，卡的 Issue 号。
- 不填：自测结论、重点提示、提问。

## 必读材料（评审员自己读，不读作者摘要）

1. 卡原文（Issue 正文，模板 `.github/ISSUE_TEMPLATE/card.md`；旧卡全文见正文里固定提交的卡链接。依据、卡上文件、验收测试、禁止事项、预期 diff、复审要求，卡上写了的照核）。
2. 卡「依据」一栏列出的规则卡、ADR、intent、`terms.yaml` 词条——**原文**。
3. 完整 diff：`git diff <基线>..<HEAD>`，以及 `--name-only` 的文件清单。
4. 规范原文：`CODING_STANDARD.md`（逐条编号，下表引用到的）、`NAMING_STANDARD.md`、SESSION_PLAYBOOK 附 M1（修复批流程）与 DATA_DESIGN_CHECKLIST §14 / §14.1（涉数据时）。
5. 验收测试目录；PR 描述各栏（`.github/pull_request_template.md`）——其中「改动说明」「本地已跑」是作者结论，**先独立判完 C1–C10 再读**，「改动的断言 / 测试及理由」「precheck.sh 输出」是要核对的事实。

## 必查项

| # | 查什么 | 判过 | 判不过 |
|---|---|---|---|
| C1 | **只改卡上文件**（CS-7.3） | `--name-only` 的每个文件都在卡「范围与卡上文件」一栏内 | 有卡外文件，且 PR 未事先报告 |
| C2 | **没有放宽或删除断言**（CLAUDE.md 第 5 条） | 被删 / 被改的断言在 PR「改动的断言 / 测试及理由」栏逐条有理由，且理由指向具体的规格或契约变化（不是「与实现不符」「测试不稳」）；`scripts/ci/assertion_drift.py` 的告警都有对应说明 | 断言变少、精确断言换成范围断言而未说明 |
| C3 | **验收测试未被实现方改动** | 验收测试目录的提交带 `Acceptance-Test-Author` 或 `Acceptance-Ruling` 行（SESSION_PLAYBOOK 附 M1 第 4 条、TEAM-69） | 实现提交里改了验收测试 |
| C4 | **依据逐条落实**，字面对得上 | 卡「依据」里每一条规则 / ADR 条款，评审员在代码里找到对应实现，取值、枚举、期限与原文一致（B4） | 有条款无实现；实现与原文字面不同 |
| C5 | **新标识符、界面文字、表列名用语**（CLAUDE.md 第 2 条） | 公开 API、类名、表列名、事件名、界面文字都能在 `terms.yaml` 查到（中英文名都查）；查不到的已登记提议术语（B1）。私有方法与局部变量不查 | 方言、同名异义、临时叫法 |
| C6 | **代码规范**：注释只写「为什么」（CS-1.1：删掉这行注释后，读者仍能看懂代码做什么与为什么的，即多余，不过；Javadoc 同判）；只实现当前阶段（CS-1.8）；契约先行，接口变更同步 `openapi.json`（CS-1.10）；通用错误码只在 kernel（CS-2.24）；测试只断言本模块与确定性等待、不用 sleep（CS-5.5 / 5.6）；**事件到达不等于数据已提交**，异步监听器产生的数据要等“读到了”（条件等待），不能只等事件（QUAL-009）；共享 Spring 上下文的 `@MockitoBean` 上不写不带本测试专属参数的精确次数 / `never()` 断言（其他模块的异步监听器也会调用它，见 `quality/SHARED_MOCK_VERIFY.md`），`atLeastOnce()` 加 `getValue()` 取到的是**最后一次**调用，要按动作或 ID 过滤 `getAllValues()` | 逐条在 diff 里找，找不到违反 | 任一条违反 |
| C7 | **缺失或无效输入失败并告警，不静默跳过**（CLAUDE.md 第 6 条） | 新增的 `catch`、`?:`、`orElse`、`continue` 都不吞错误；规则卡明确允许的除外并有引用 | 静默兜底、返回默认值掩盖错误 |
| C8 | **密钥**（CLAUDE.md 第 8 条） | 代码与测试没有密钥字面量，测试密钥运行时生成；日志不打印凭据 | 有字面量或打印 |
| C9 | **缺陷卡 = 一次最小改动 + 一个回归测试**（SESSION_PLAYBOOK 附 M1 第 6 条） | 回归测试名引用复审编号；在基线上该测试应失败——编译不过也算失败（读测试和被测代码判断，能跑且不起容器的就跑） | 没有回归测试，或测试在基线上也通过 |
| C10 | **老系统只作证据**（CLAUDE.md 第 1 条） | 领域模块不出现外部或老系统名称；没有照搬老代码结构 | 出现老系统 / 外部系统名称或照搬 |
| C11 | **precheck 与 PR 各栏** | PR 描述「precheck.sh 输出」贴了完整输出且以 `ready` 收尾；SKIP 有理由；各栏如实（CS-7.1、CS-7.2） | 没贴、`not ready`、栏位空着 |
| C12 | **安全与权限**：新增接口的鉴权与权限码、输入校验、日志不含个人信息或凭据 | 每个新增入口都有权限判断与校验，且有对应测试 | 缺鉴权或校验 |
| C13 | **涉 DDL 的另按** [02-table-structure.md](02-table-structure.md) 再审一遍 | — | — |

## 本类特有的盲区（主动找）

- **B4 最常漏**：卡把 ADR 条款转述成自己的话，转述时改了数字或例外；对着 ADR 原文逐字对。
- **B6**：代码里加了状态或字段，事件载荷、审计动作（`MUST_AUDIT_ACTIONS.yaml`）、读模型、OpenAPI 枚举有没有跟着改。
- **B7**：新增的读取列、例外、测试镜像、权限码有没有登记；新增例外必须有出处。
- **B2 / B3**：卡新增或升级依赖、测试镜像、运行时时，对 `pom.xml`、`package.json`、`test-images.txt`、`CI_RUNNERS.md` 核版本，并问镜像在 aarch64 上怎么运行。
- **B5**：子代理在自查里说「X 已覆盖 / X 没有」，评审员不采信，自己 `grep`。
- 测试里 `@Disabled`、`assumeTrue`、宽松的 `contains` 是否悄悄把断言变成了不检查。
