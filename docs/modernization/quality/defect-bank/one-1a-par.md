### PAR-001　常驻子进程启动验收用固定端口，端口被占时偶发失败

- **日期**：2026-10-16
- **类别**：局部测试
- **现象**：单人运维模式 P1 的启动验收（常驻子进程）在本机多会话并行跑测试时，遇端口已被占用而启动失败，偶发红（PR #440 急修前，出处为该 PR 标题与当日日报的 CI 失败记录）。
- **根因**：测试写死端口，假定本机端口空闲；本机多会话与 CI 跑步机共用端口空间，这个假定不成立。
- **拦下于**：CI 才发现。
- **漏过于**：本地测试（单次运行端口恰好空闲）；重复跑三遍的守护（`scripts/ci/repeat_new_tests.py`，#443）在当时还不存在。
- **新增检查项**：期望启动成功的用例一律用 `--server.port=0`，必须测端口占用的用例换端口重试且只对端口冲突重试（#440）；新增或改动的测试类现由 `scripts/ci/repeat_new_tests.py` 在引入它的 PR 上重复跑三遍。
- **状态**：已落实

### PAR-002　共享 Spring 上下文的模拟对象上写精确次数断言，被其他模块的异步监听器干扰

- **日期**：2026-10-16
- **类别**：局部测试
- **现象**：同步放行用例在整体运行时偶发失败，断言了共享模拟对象的调用次数或唯一一次调用（PR #409 修前）。
- **根因**：共享上下文里别的测试和异步监听器也会调用同一个模拟对象，精确次数或取最后一次调用都不只反映本测试自己的动作（CS-5.6）。
- **拦下于**：CI 才发现。
- **漏过于**：本地测试（单独跑时没有干扰）；`scripts/ci/shared_mock_verify_scan.py` 当时只报告不拦。
- **新增检查项**：断言只看本测试自己的运行（按动作或 ID 过滤 `getAllValues()`，不用精确次数 / `never()`）；写测试前读 `quality/SHARED_MOCK_VERIFY.md`；`scripts/precheck.sh` 的 shared-mock verify scan 条目。
- **状态**：已落实

### PAR-003　纯文档改动开了 PR

- **日期**：2026-10-17
- **类别**：提交卫生
- **现象**：F-1 卡补数据设计开了 PR #451，随后被 one-coordinator 要求关闭；纯文档的签发与合并走分支，不单开 PR。
- **根因**：开 PR 前没有对照调度当前的“纯文档不开 PR”规则，沿用了代码卡的习惯。
- **拦下于**：调度或用户。
- **漏过于**：无（没有机械检查能判断一个 PR 是否纯文档且应走分支）。
- **新增检查项**：开 PR 前先问“本次改动含代码吗”，纯文档只推分支并报 one-coordinator 分支与提交号（待写入画像“工作守则”）。
- **状态**：待落实（负责：one-1a-par，2026-10-24 前把这一条写进画像“工作守则”）

### PAR-004　同一处缺陷修复，只给其中一处改动配回归测试

- **日期**：2026-10-17
- **类别**：局部测试
- **现象**：PR #447 同时改了三处日志（限流消息、登录审计写入失败、访问拒绝审计写入失败），首版只为前两处写了先红后绿测试，第三处（`AccessDeniedAudit`）改回旧写法也不会有测试变红。
- **根因**：回归测试按“先想到的两处”写，没有对着 diff 逐处问“这一处改回去哪个测试会红”。
- **拦下于**：独立评审（`review-briefs/01-code-card.md` C9，PR #447 复审 M1）。
- **漏过于**：作者自审（没有逐处对照 diff）；机械检查（没有守护能判断“改动行有无对应测试”）。
- **新增检查项**：交出缺陷修复前，对 diff 里每一处生产代码改动，回退该处并确认至少一个测试变红；PR 说明里写明每处对应的测试名。
- **状态**：待落实（负责：one-1a-par，2026-10-24 前把这一问写进画像“工作守则”）
