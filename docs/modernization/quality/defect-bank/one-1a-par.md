### PAR-001　常驻子进程启动验收用固定端口，端口被占时偶发失败

- **日期**：2026-10-16
- **类别**：局部测试
- **现象**：单人运维模式 P1 的启动验收（常驻子进程）在本机多会话并行跑测试时，遇端口已被占用而启动失败，偶发红（PR #440 急修前，出处为该 PR 标题与当日日报的 CI 失败记录）。
- **根因**：测试写死端口，假定本机端口空闲；本机多会话与 CI 跑步机共用端口空间，这个假定不成立。
- **拦下于**：CI 才发现。
- **漏过于**：本地测试（单次运行端口恰好空闲）；重复跑三遍的守护（`scripts/ci/repeat_new_tests.py`，#443）在当时还不存在。
- **新增检查项**：期望启动成功的用例一律用 `--server.port=0`，必须测端口占用的用例换端口重试且只对端口冲突重试（#440）；新增或改动的测试类现由 `scripts/ci/repeat_new_tests.py` 在引入它的 PR 上重复跑三遍。
- **状态**：已落实

### PAR-002　共享 Spring 上下文的模拟对象上写精确次数断言，被其他模块的异步监听器干扰

- **日期**：2026-10-16
- **类别**：局部测试
- **现象**：同步放行用例在整体运行时偶发失败，断言了共享模拟对象的调用次数或唯一一次调用（PR #409 修前）。
- **根因**：共享上下文里别的测试和异步监听器也会调用同一个模拟对象，精确次数或取最后一次调用都不只反映本测试自己的动作（CS-5.6）。
- **拦下于**：CI 才发现。
- **漏过于**：本地测试（单独跑时没有干扰）；`scripts/ci/shared_mock_verify_scan.py` 当时只报告不拦。
- **新增检查项**：断言只看本测试自己的运行（按动作或 ID 过滤 `getAllValues()`，不用精确次数 / `never()`）；写测试前读 `quality/SHARED_MOCK_VERIFY.md`；`scripts/precheck.sh` 的 shared-mock verify scan 条目。
- **状态**：已落实

### PAR-004　同一处缺陷修复，只给其中一处改动配回归测试

- **日期**：2026-10-17
- **类别**：局部测试
- **现象**：PR #447 同时改了三处日志（限流消息、登录审计写入失败、访问拒绝审计写入失败），首版只为前两处写了先红后绿测试，第三处（`AccessDeniedAudit`）改回旧写法也不会有测试变红。
- **根因**：回归测试按“先想到的两处”写，没有对着 diff 逐处问“这一处改回去哪个测试会红”。
- **拦下于**：独立评审（`review-briefs/01-code-card.md` C9，PR #447 复审 M1）。
- **漏过于**：作者自审（没有逐处对照 diff）；机械检查（没有守护能判断“改动行有无对应测试”）。
- **新增检查项**：交出缺陷修复前，对 diff 里每一处生产代码改动，回退该处并确认至少一个测试变红；PR 说明里写明每处对应的测试名。
- **状态**：待落实（负责：one-1a-par，2026-10-24 前把这一问写进画像“工作守则”）

### PAR-005　PR 正文等临时文件写在共享的 /tmp，被别的会话同名文件覆盖

- **日期**：2026-10-17
- **类别**：其他
- **现象**：PR #465 开出时正文是另一个会话的“工件治理工具”内容，opus 复审（H1）发现；我写的 `/tmp/prbody4.md` 被别的会话写了同名文件。
- **根因**：本机所有会话共用 `/tmp`，文件名只带序号；本会话有专属 scratchpad 目录却没用。
- **拦下于**：独立评审（`review-briefs/01-code-card.md` C11，PR #465 首轮复审 H1）。
- **漏过于**：作者自审（开 PR 后没有回读 `gh pr view` 的正文）；机械检查（没有守护比对 PR 正文与改动）。
- **新增检查项**：临时文件一律写本会话 scratchpad 目录；开 PR 或改正文后立即 `gh pr view --json body` 回读核对；待写入画像“工作守则”。
- **状态**：待落实（负责：one-1a-par，2026-10-24 前把这一条写进画像“工作守则”）

### PAR-006　含反引号的文字用不带引号的 heredoc 写文件，反引号内容被 shell 当命令吃掉

- **日期**：2026-10-17
- **类别**：其他
- **现象**：PR #465 终审结论写入正文时，`start(...)` 和 `Acceptance-Ruling` 两处被替换成空，我回读 PR 正文才发现。
- **根因**：`<<EOF` 不带引号时 shell 对正文做命令替换；正文里有反引号包起来的标识符。

- **新增检查项**：往文件写含反引号或 `$` 的文字时一律用 `<<'EOF'`，或用 Python 脚本写；写完回读。待写入画像“工作守则”。
- **状态**：待落实（负责：one-1a-par，2026-10-24 前把这一条写进画像“工作守则”）

### PAR-007　测试代理的提交说明里 Acceptance-Test-Author 与 Co-Authored-By 之间隔了空行，守护判“没有 trailer”

- **日期**：2026-10-20
- **类别**：提交卫生
- **现象**：IMP-1020-PAR-02 的测试提交带了 `Acceptance-Test-Author: test-engineer`，但与后面的 `Co-Authored-By` 之间有空行；`acceptance_guard` 报“changes acceptance tests without a valid Acceptance-Test-Author or Acceptance-Ruling trailer”，推送被预检钩子拦下。
- **根因**：git 只把提交说明最后一个段落当 trailer 块；派给测试代理的提示词只写了“要带这一行”，没写“与 Co-Authored-By 同一段、紧挨着”。
- **拦下于**：机械检查（`scripts/ci/acceptance_guard.py`，经 precheck 与推送前钩子）。
- **漏过于**：无。
- **新增检查项**：派测试代理的提示词写明“trailer 行与 Co-Authored-By 之间不留空行”；cherry-pick 测试提交后先跑 `python3 scripts/ci/acceptance_guard.py origin/main HEAD`。
- **状态**：已落实（本条与画像“工作守则”；机械拦截已存在）
