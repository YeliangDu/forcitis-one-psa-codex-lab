# Data design review: organization.workforce slice WC0 (three tables)

Card: #1437 (sign-off; skeleton card WC1, one-dev-org; spec card #1417). Basis: `docs/architecture/proposals/workforce-contract-separation.md` sections 4, 8, 10, 12 at origin/main `9a79818da` (#1401 merged: relationship ids exist), gate `docs/data/data-design-gate.md` appendix A. Signed by one-design (same form as the leave L1a/L1b and payroll PY0 records). The signed content is this record; where it differs from the spec's section 8 sketch, the record governs (list below).

## Scope

Schema `organization_workforce` (exists), three tables: `employment_contracts`, `separation_requests`, `separation_bases`. This record signs **structure, not values**: the `separation_bases` rows (the statute-based list of Q-1 (a) plus the two system-only keys of Q-9) are the WC1 seed and are checked by HR against the legacy form after the forensic read (spec Q-1); the legacy meaning of `field0031` and the legacy contract store are unverified (spec section 2) and do not change a column here (spec section 14). Not signed and not to be built by WC1: legacy import of contracts and requests (WC5), contract amendment rows (Q-8, later slice), any event payload (the two contract events come with WC4 and their catalogue entries with their publisher).

Evidence marks: **verified** = read on origin/main `9a79818da` today (migration `V20261105120000`, registry, classification file, `DdlNamingTest` rules quoted from the files); **unverified** = statute article numbers and the probation tiers (spec section 2, last row; no original text in the repository).

## Columns and constraints

Conventions as the existing workforce tables: UUIDv7 ids generated by the client (a replayed command is idempotent); every enum is `text` with a named `ck_<table>_<column>`; free text has `char_length` and `btrim` CHECKs; every nullable column's comment states 「为空表示」; `created_at`, `updated_at`, `version bigint NOT NULL DEFAULT 0`. The relationship and employee ids use the composite foreign key to `uk_employment_relationships_id_employee` (verified in `V20261105120000`), RESTRICT. Other contexts' and platform ids (`*_file_id`, user ids) are `uuid` without a foreign key (cross-context rule). The contract carries no employer column (ADR-0086 decision 5).

### employment_contracts

| Column | Type | Rule |
|---|---|---|
| `employment_contract_id` | uuid | pk `pk_employment_contracts` |
| `employment_relationship_id`, `employee_id` | uuid NOT NULL | composite `fk_employment_contracts_relationship` to `uk_employment_relationships_id_employee`; `ix_employment_contracts_relationship` `(employment_relationship_id, employee_id)`; `ix_employment_contracts_employee_id` (data-scope reads and the ten-year purge) |
| `contract_kind` | text NOT NULL | `FIXED_TERM`, `OPEN_ENDED`, `TASK_BASED` (Q-5) |
| `term_start_date` | date NOT NULL | the agreed start; the actual start is **not** stored here (C-2: read from `employment_relationship_versions.employment_start_date`, ADR-0046 section 8) |
| `term_end_date` | date null | 为空表示 open-ended or task-based, no fixed end; inclusive; `ck_employment_contracts_term_end` `(contract_kind = 'FIXED_TERM') = (term_end_date IS NOT NULL)` (invariant 3) and `term_end_date >= term_start_date` |
| `signed_on_date` | date null | 为空表示 not signed yet; may be before or after `term_start_date` (invariant 4); required from `SIGNED` on, null before |
| `probation_months_count` | integer NOT NULL DEFAULT 0 | 0 means no probation clause; `ck_employment_contracts_probation_months` `BETWEEN 0 AND 6` (the absolute statutory ceiling, art. 19, **unverified**; the tier table and "first contract only" are command checks, C-8) and `ck_employment_contracts_renewal_no_probation` `renews_contract_id IS NULL OR probation_months_count = 0` |
| `renews_contract_id` | uuid null | 为空表示 first contract; composite `fk_employment_contracts_renews` `(renews_contract_id, employment_relationship_id)` to `uk_employment_contracts_id_relationship` `(employment_contract_id, employment_relationship_id)` (a renewal is on the same relationship); `ck_employment_contracts_renews_not_self`; index `ix_employment_contracts_renews_contract_id` `(renews_contract_id, employment_relationship_id)` where not null; `uk_employment_contracts_one_successor` unique `(renews_contract_id)` where not null and `status <> 'VOID'` (a contract is renewed once; "two consecutive fixed terms" reads the chain) |
| `contract_file_id` | uuid null | 为空表示 no scan stored; `platform.file` id, no FK; set once (null to value) from `APPROVED` on |
| `status` | text NOT NULL | `DRAFT`, `IN_APPROVAL`, `APPROVED`, `SIGNED`, `TERMINATED`, `VOID` (spec 4.1; "effective" is a day reading, not a state) |
| `submitted_by`, `approved_by` | uuid null | 为空表示 not submitted / not approved; the SoD rule needs the two actors on the row: `ck_employment_contracts_approver_not_submitter` `approved_by IS NULL OR approved_by <> submitted_by`; cleared when a rejection returns the row to `DRAFT` (the rejection itself is an audit entry) |
| `terminated_on_date`, `termination_basis_key` | date null, text null | 为空表示 not terminated; both or neither, and exactly when `status = 'TERMINATED'` (`ck_employment_contracts_state_columns`); `terminated_on_date >= term_start_date` and `<= term_end_date` when that is set (so the range below is always valid); `fk_employment_contracts_termination_basis_key` to `separation_bases` RESTRICT, `ix_employment_contracts_termination_basis_key` where not null |

`ck_employment_contracts_state_columns` (the carrier of invariant 4 and the status pairing): `DRAFT` has `submitted_by`, `approved_by`, `signed_on_date` null; `IN_APPROVAL` has `submitted_by` not null and `approved_by` null; `APPROVED` has both not null and `signed_on_date` null; `SIGNED` and `TERMINATED` have `signed_on_date` not null (and both actors not null); `TERMINATED` alone has the two termination columns; `VOID` has `signed_on_date`, `terminated_on_date` null.

Constraints that are not column CHECKs:

- `ex_employment_contracts_in_force_period_overlap` `EXCLUDE USING gist (employment_relationship_id WITH =, daterange(term_start_date, coalesce(terminated_on_date, term_end_date), '[]') WITH &&) WHERE (status IN ('SIGNED','TERMINATED'))` (invariant 1, W-R1; `btree_gist` exists since the workforce baseline, verified; open-ended contracts give an unbounded range). A renewal starting the day after the term ends does not overlap.
- `uk_employment_contracts_relationship_term_start` unique `(employment_relationship_id, term_start_date)` where `status <> 'VOID'` (business key, O3: two live contracts of one relationship never start on the same day).
- `uk_employment_contracts_id_relationship` (target of the renewal key, above).

Trigger `tg_employment_contracts_change` and `tg_employment_contracts_truncate` (refuses TRUNCATE): the full list of legal writes, everything else refused. (1) Insert as `DRAFT`. (2) `DRAFT` to `DRAFT`: term, kind, probation, file columns. (3) `DRAFT` to `IN_APPROVAL` (sets `submitted_by`); `IN_APPROVAL` to `APPROVED` (sets `approved_by`); `IN_APPROVAL` to `DRAFT` (reject: clears both actors). (4) `APPROVED` to `SIGNED` (sets `signed_on_date`). (5) `SIGNED` to `TERMINATED` (sets the two termination columns once). (6) `DRAFT`, `IN_APPROVAL`, `APPROVED` to `VOID` (a withdrawn HIRE or a discarded draft; a `SIGNED` contract is never voided, spec done-when 2). (7) `contract_file_id` null to value in `APPROVED`, `SIGNED`, `TERMINATED`. From `IN_APPROVAL` on, kind, dates and probation are frozen; a change is a reject and edit. `version` and `updated_at` move with every step. DELETE only by the table owner (the purge function, ADR-0068 item 7), as `employment_relationships`; no other delete, no UPDATE outside the list.

| `agreement_file_id` | uuid null | 为空表示 no agreement or notice file; `platform.file` id, no FK |
| `protected_circumstances_checked_on_date`, `union_notified_on_date` | date null | 为空表示 not an employer-initiated basis, or not yet confirmed |
| `union_opinion_note`, `union_notice_result_note`, `note` | text null | 为空表示 not recorded; 1 to 500 characters, `btrim`; no health or pregnancy content (ADR-0079 invariant 10; a note rule, not a CHECK) |
| `personnel_command_id` | uuid null | 为空表示 SEPARATE not entered; composite `fk_separation_requests_personnel_command` `(personnel_command_id, employment_relationship_id)` to `uk_personnel_commands_id_relationship` (new unique on `personnel_commands`, see expected diff; it holds the command on the same relationship); `uk_separation_requests_personnel_command` unique `(personnel_command_id, employment_relationship_id)` where not null |
| `status` | text NOT NULL | `REQUESTED`, `APPROVED`, `SEPARATING`, `COMPLETED`, `WITHDRAWN`, `REJECTED` (spec 4.2) |

`ck_separation_requests_state_columns`: `REQUESTED` has `approved_on_date`, `decided_by`, `personnel_command_id` null; `REJECTED` has `decided_by` not null and `approved_on_date` null; `APPROVED`, `SEPARATING`, `COMPLETED` have `approved_on_date`, `decided_by`, `last_working_date` not null; `SEPARATING` has `personnel_command_id` not null; `personnel_command_id` is null in every other status, except that a `COMPLETED` request may have none only when `request_source_kind = 'SYSTEM'` (a migrated separation has no command, spec Q-9); `WITHDRAWN` may or may not have been approved. Dates: `requested_on_date <= approved_on_date`; `last_working_date >= requested_on_date` unless `request_source_kind <> 'EMPLOYEE_SELF'` (a back-dated separation is HR's or the system's, spec 4.2 dates rule); a `SYSTEM` request is never `REQUESTED` or `REJECTED` and has `approved_on_date = requested_on_date` (Q-9). Employer-initiated bases (a `separation_bases` flag): `APPROVED` and later need the four fields `protected_circumstances_checked_on_date`, `union_notified_on_date`, `union_opinion_note`, `union_notice_result_note` all not null; that reads another table, so its carrier is the trigger below, not a CHECK (B5).

Constraints that are not column CHECKs: `uk_separation_requests_open_per_relationship` unique `(employment_relationship_id)` where `status IN ('REQUESTED','APPROVED','SEPARATING')` (W-R5; a `SYSTEM` request meets it too, Q-9 done-when 12a).

Trigger `tg_separation_requests_change` and `tg_separation_requests_truncate`: the full list of legal writes. (1) Insert as `REQUESTED` (human sources), or as `APPROVED` or `COMPLETED` (`SYSTEM` only). (2) `REQUESTED` to `REQUESTED`: basis, initiator, dates, notes, files, the four dismissal-check columns. (3) `REQUESTED` to `APPROVED` (sets `approved_on_date`, `decided_by`; requires `last_working_date`; when the basis is employer-initiated the trigger reads the basis row and requires the four columns, ADR-0079 invariant 10) or to `REJECTED` (sets `decided_by`); `REQUESTED` or `APPROVED` to `WITHDRAWN`. (4) From `APPROVED` on, basis, initiator, dates, notes and the dismissal-check columns are frozen: a different last working day is a withdrawal and a new request (decision here, cheap to widen later; the spec's "several requests over time" allows it). (5) `APPROVED` to `SEPARATING`: sets `personnel_command_id`; the trigger reads that command `FOR SHARE` and refuses unless its `command_kind = 'SEPARATE'` and its `effective_date = last_working_date + 1` (W-R4, the carrier in the database; the command also checks). `SEPARATING` to `APPROVED`: clears the link when the SEPARATE is withdrawn; a held SEPARATE leaves `SEPARATING`. `SEPARATING` to `COMPLETED` when the SEPARATED version takes effect. (6) `handover_completed_on_date` and `agreement_file_id` (null to value) from `APPROVED` on. Delete only by the table owner (purge), TRUNCATE refused.

## Differences from the section 8 sketch (the record governs)

1. **`uk_employment_contracts_probation_once` is not signed.** Spec 4.1 invariant 2 says "an application check at signing (cross-row), not a unique index", and ADR-0079 invariant 13 says a first contract with probation after REINSTATE (same relationship, settled separation) is accepted with a warning, never blocked; a partial unique index "one probation per relationship" would block exactly that. The database carries only the row-local part (`ck_employment_contracts_renewal_no_probation`, ceiling 6); once-only and the predecessor rule stay commands (W-R2).
2. **Added columns the spec's rules need but did not list:** `submitted_by`, `approved_by` on the contract and `request_source_kind`, `requested_by` on the request (W-R3 and Q-9 need the actors and the source on the row); other state steps' actors and times (rejection, withdrawal, effect) are audit entries, not columns.
3. **`last_working_date` is nullable until approval** (a self-service request may not know it; spec 4.2 says "the day HR fills"); required from `APPROVED` on.
4. **The art. 42 / union check is four fields, not "three".** Spec 4.2, Q-9 and done-when 8a say "the three"; ADR-0079 invariant 10 names the check of the prohibited circumstances, the prior union notice, the union's opinion and the result of the written notice: four columns exist and the trigger requires all four (an opinion note may say "none given within the period"). The spec status line is corrected to point at this record.
5. **Added:** `uk_employment_contracts_one_successor`, `uk_employment_contracts_relationship_term_start` (business key), the term/termination range CHECKs, the exclusion constraint's validity guards, `uk_separation_requests_personnel_command`, the trigger edges above, and `is_system_only` on `separation_bases` (the spec states the system-only keys but no column for them).
6. **Gap found, solved here:** a SEPARATE whose last working day is before a contract's `term_start_date` (contract signed ahead of a start that never happens) cannot become `TERMINATED` (the range would be inverted). The command sets that contract `VOID` ("never took effect") instead; done-when 8 below. The contract with `terminated_on_date` after `term_end_date` cannot occur: a lapsed fixed-term contract stays `SIGNED`, the day reading shows it expired.

None changes a command, an event or a state of the spec; item 1 resolves a contradiction inside the spec.

## Cross-cutting, ADR clauses, value objects (O13 to O16)

- **Legal entity and period (O13, A6):** the contract and the request follow the relationship; the employer is read from the relationship, so neither table has `legal_entity_id` (spec 4.1; ADR-0086 decision 5). No accounting period: they are personnel facts, not postings. A6 stated rather than skipped.
- **Cross-cutting (O14):** audit entries for every command (the spec's state steps not stored as columns, handover corrections); permissions per slice (spec 5); data scope through `employee_id` (the same scope as personnel commands, fail-closed 404); no event payload and no audit `detail` carries a basis, a date of a pending separation or a note (ADR-0043 section 4 item 1; spec done-when 14).
- **ADR clauses (O15):** ADR-0086 decision 5 (no employer column on the contract; composite relationship key: carried); ADR-0068 items 5 and 7 (last working day plus one; purge by table owner: carried); ADR-0046 section 8 (no stored actual start or relationship end: carried); ADR-0079 invariants 5, 9, 10, 11, 13 (carried as above); ADR-0043 R-2 (retention reason, below); ADR-0051 decision 7 item 4 (single-level approval in workforce; no `platform.approval` edge: carried).
- **Value objects (O16):** contract term (start, optional end, kind), probation months, separation dates (`requested`, `approved`, `last working`: three separate facts, golden 034), basis key.
- **Free text (C4):** `union_opinion_note`, `union_notice_result_note`, `note` hold HR-entered text about the dismissal check and the case; no health, pregnancy or medical content (a note rule, ADR-0079 invariant 10); the entry form says so; never in events or audit `detail`.

## Done-when (for the test engineer)

The spec's section 12 items 1 to 15 stand; this record adds the schema-level checks:

1. Two overlapping `SIGNED` contracts of one relationship are refused by the database (`ex_employment_contracts_in_force_period_overlap`); a successor starting the day after the term ends is accepted; `DRAFT` rows never conflict.
2. A fixed-term row without an end date, an open-ended row with one, a row with `term_end_date < term_start_date`, `probation_months_count` 7 or a renewal with probation each fail a named CHECK.
3. A row with `approved_by = submitted_by` fails `ck_employment_contracts_approver_not_submitter`; a human-filed request with `decided_by = requested_by` fails `ck_separation_requests_approver_not_requester`, a `SYSTEM` one does not.
4. A second open request for one relationship fails `uk_separation_requests_open_per_relationship`; after `WITHDRAWN`, `REJECTED` or `COMPLETED` a new one is accepted.
5. Linking a command that is not `SEPARATE`, belongs to another relationship, or whose `effective_date <> last_working_date + 1` is refused by `tg_separation_requests_change`; a withdrawn SEPARATE returns the request to `APPROVED` with the link cleared.
6. Approving a request whose basis is employer-initiated with any of the four dismissal-check columns null is refused by the trigger; an `EMPLOYER_CHANGE` or `MIGRATION` request needs none.
7. An update outside the legal edges (for example changing `last_working_date` on an `APPROVED` request, or `term_start_date` on a `SIGNED` contract, or any UPDATE or DELETE of `separation_bases` by the runtime role) is refused; DELETE by the table owner works (purge); TRUNCATE is refused on all three.
8. A SEPARATE with a last working day before a contract's `term_start_date` sets that contract `VOID`, not `TERMINATED` (a test of the command; the database refuses `terminated_on_date < term_start_date`).
9. `DataArchitectureTest`, `DdlNamingTest`, `ClassificationRegister`: the registry and classification entries above are present; the registry reason for `PERMANENT` names the decision fragment; both contract-content columns and the basis columns read `SENSITIVE | PI`.
