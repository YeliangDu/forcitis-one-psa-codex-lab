# B-31 历史用印迁入：附件、编号、版本保全与缺指纹处置（数据侧要求，草案 v1）

> 冻结（2026-11-04，#1263）：草案 v1，未并入规格；现行口径见 `docs/adr/ADR-0064.md` 与迁入规则。

## 1. 先分清三种「指纹」

| 名称 | 含义 | 历史迁入时 |
|---|---|---|
| 内容哈希（`content_hash`） | 文件服务对写入字节算的 SHA-256 | 迁入入口**必算**，是迁入时刻的指纹，不代表原件盖章时的状态 |
| 源端指纹 | 迁入适配器读老系统文件时、写入前算的 SHA-256 | **必算**并存入迁入清单；写入后读回的 `content_hash` 必须等于它，证明字节一致 |
| 拟发文件指纹 / 盖章凭据指纹（核验用） | 原生流程里用印登记时对「拟发文件」与「实际盖章凭据」的核验依据 | 老系统没有，**不补、不推算**；为空，核验状态记「历史迁入，未核验」 |

## 2. 缺指纹与缺文件的处置口径

| 情形 | 处置 | 谁处置 | 数据落点 |
|---|---|---|---|
| A 文件在、老系统没记过指纹 | 迁入：迁入时算 SHA-256；`fingerprint_basis = COMPUTED_AT_MIGRATION`；不声称与盖章时一致 | 无需处置 | 文件服务 `content_hash`；用印记录 `verification_status = NOT_VERIFIABLE` |
| B 文件缺失、读不出或 0 字节 | **附件拒收**（MQ-D-06）；用印记录本身可迁，但须由行政负责人逐项处置：「保留记录、标无附件」或「确认不迁」；不造占位文件，不伪造指纹 | 行政负责人（迁入业务负责人批准延期） | 拒收清单；记录列 `attachment_state_code = MISSING_AT_SOURCE`（仅 MIGRATION 行可取） |
| C 文件被检测拒绝（加密） | 按 ADR-0070 拒收；行政处置二选一：请持有人解密后补交（走原生上传，不再算迁入）或「确认不迁附件」；原件留在迁入证据归档直到处置关闭 | 行政负责人 | 同上，`ENCRYPTED_AT_MIGRATION` |
| D 文件被检测命中病毒 | 按 ADR-0070 隔离，不入正式区；处置交安全角色，记录同 B 处理 | 安全角色 + 行政负责人 | `QUARANTINED_AT_MIGRATION` |
| E 拟发文件指纹、盖章凭据指纹 | 为空；不得默认填迁入时哈希冒充 | — | 用印记录 `intended_file_hash`、`stamped_evidence_hash` 可空，**仅** `origin_kind = 'MIGRATION'` 的行（具名 CHECK） |

所有处置经应用内带权限的操作录入并写审计，迁入角色与运维不能代填（ADR-0036 第 7 条）。**老系统退役前**，所有 B、C、D 项的处置关闭，拒收附件的原件保留在迁入证据归档（不在业务库），保留期由处置关闭后另定。

## 3. 保全要求（写进迁入规格）

**附件**
1. 字节一致：源端 SHA-256 = 写入后读回的 `content_hash`，大小相等；不一致整批退回暂存（ADR-0036 第 9 条的提交前失败）。
2. 逐文件清单：迁入清单每个附件一行（来源附件 ID → 来源对照、源端指纹、字节数、媒体类型、结果），核对（ADR-0036 第 8 条）加「附件数、总字节数、逐文件指纹」三项，差异为 0 才能提交。
3. 原文件名保全（存 `stored_file_names`），按文件服务规则到期去标识；含宏按 ADR-0070 记录并提示。
4. 同一来源附件再次出现：指纹相同跳过，不同拒收（已提交不覆盖，ADR-0036 第 7 条）。
5. 分级与保存类别：关联时必须给访问级别、个人信息标记、保存类别「签署与用印文件」，起算日 = 历史用印完成日；映射表由行政与 one-security 在迁入规格里定（按用途），**查不到一律拒收，不默认**（ADR-0060）。
6. 迁入不发事件、不发通知、不向外部推送（ADR-0036 第 5 条）。

**编号**
1. 原编号逐字保留，存为单据展示号（`document_number`），同时登记 `legacy_numbers`；不耗编号计数器、不重新取号（ADR-0036 第 4 条）。
2. 同一单据类型内原编号重复：拒收（MQ-D-03），行政处置；不自动加后缀。
3. 老系统单号与新编号的对照可查：来源对照 + `legacy_numbers`；Q7 过渡通道的「同一老系统单号累计份数」以对照为准。

**版本与轮次**
1. 老系统保留的每一轮重提、每一份附件旧版本都迁：轮次进 `round_number`，附件旧版本按 `previous_file_id` 链接；**老系统没保留的不合成**（只有最新版就只有一版，记录列 `history_basis_code = LATEST_ONLY`）。
2. 用印记录引用的台账条目：按（归属公司，印章类型）映射到签章服务台账条目，映射不到逐条拒收（ADR-0064 决定 3 第 5 点）；用印时点取当时有效版本，早于最早版本拒收告警。
3. 迁入行的配置版本引用（制度、核验、提醒）为空，只允许 `origin_kind = 'MIGRATION'`（具名 CHECK）；原生行必填。
4. 状态：老系统历史状态映射到现行状态或「仅历史状态」（`B31_PHYSICAL_MODEL_RULINGS.md` 第 5 节）；每条记录一条迁入初始转换（`from_status` 空、`cause_kind = 'MIGRATION'`）。
5. 迁入后用印登记表只追加（注册表 `APPEND_ONLY`），更正走冲正行（`CORRECTION`），不改原记录。

## 4. 新增质量规则（并入 `MIGRATION_QUALITY_CHECKS.md` 的 MQ-D 类）

3. 磁盘存在性核对放到迁入演练（迁入适配器读取时即发现缺失，按情形 B 拒收），不单独为此重挂 NAS，除非用户要求演练前先摸底。
4. 存储规划：窗口内约 38 GiB 仅来自用印附件，另有全历史与其他表单附件；请 one-ops 在容量规划里计入（`MIGRATION_VOLUME_ESTIMATE.md` 的附件行需用这组实测更新）。

## 8. 第三步取证与定稿（one-ops 只读，已登记）

**事实**：①窗口内 2704 个用印附件里 **108 个超过 100 MB**，最大约 979 MiB，P95 约 76 MiB，中位数约 317 KiB。②`formmain_0643` 的字段显示名已取：**没有「用印单号」字段**，记录自身标识只有表主键 `ID`；`field0077` 是「用印文件上传」（附件字段），`field0048` 报价编号、`field0046` 合同编号、`field0065` 商机编号、`field0066` 项目编号是业务引用，`field0061` 用印日期、`field0041` 印章类型、`field0074` 印章归属公司、`field0043` 份数、`field0075` 用印模式、`field0068` 是否投标配合。

**对第 3 节编号要求的更正**（取代原「原编号逐字保留」一条的前提）：
1. 老系统用印申请档案没有自己的单号。迁入行的身份 = 来源对照（表 `formmain_0643` 的 `ID`）；`document_number` 对迁入行**可空**，仅当 `origin_kind = 'MIGRATION'` 且 `number_basis_code = 'NO_SOURCE_NUMBER'`（具名 CHECK）；界面显示「无原编号（历史迁入）」，不造序号、不取新号。
2. 报价编号、合同编号、商机编号、项目编号作为**业务引用**保存（文本，格式 CHECK，标明来源是历史迁入；将来报价、合同模块上线后按原编号对照解析为 ID），不当作单据编号。
3. Q7 过渡通道里「同一老系统单号累计用印份数」：对新进来的申请，单号由行政手录老系统审批单号（设计 §10 Q7）；对迁入的历史记录，累计基数的键 = 来源对照 ID，**不要求**有老系统单号。
4. 唯一性：因为没有单号，MQ-D-03 对本表只核「来源 ID 唯一」（主键天然唯一）与业务引用的格式，不再核单号唯一。

**对超过 100 MB 附件的处置**（108 个，约占 4% 个数，字节占比待迁入演练清单算出；情形 F）：
1. 文件服务单文件上限 100 MB（ADR-0070）不为迁入放宽。超限附件**拒收**（原因 `FILE_TOO_LARGE`），用印记录照迁，记录列 `attachment_state_code = TOO_LARGE_AT_MIGRATION`。
2. 超限附件的原件**不进业务库**，留在迁入证据归档（只读、带源端 SHA-256 与字节数清单），保存至行政负责人处置关闭，处置选项：压缩或拆分后补交（原生上传，不算迁入）/ 确认不迁附件 / 经 one-security 评审后放宽迁入上限（需另决定）。老系统退役前，这 108 个原件必须已落入证据归档并有清单。
3. 这是需要用户知晓的口径（保全与存储成本取舍），若用户要求「全部迁入」，则须由 one-architecture 与 one-security 先改 ADR-0070 对迁入入口的上限，再回到本节。

**状态**：以上与第 2、3、4 节合并为定稿口径，供 one-1a-admin 写入 B-31 迁入规格（7.10）；磁盘存在性、加密、含宏与超限的真实个数以迁入演练的清单为准，写入质量报告。
