# ADR-0041：架构框架按适配评审收窄，BC 推导改为不变量先行

- **状态**：已采纳（用户 2026-10-15 在适配评审重定页 https://claude.ai/artifact/XsXekbriGB3i8oKeFahe7h 上 30 项中 28 项选「按建议」，等保、个人信息保护法两项选「保持现在」；intent `2026-10-15-195827-one-architecture-适配评审重定页保存-30-项中.md`；原则 intent `2026-10-15-193135`「关于架构的任何选择都要非常谨慎，必须深入研究后才能决策」）（决定 2 整条，决定 1 中维度建模「总线矩阵的行是业务过程」一语、TOGAF「能力地图只留一级作范围漏项核对」一句与框架清单，决定 3 中「按决定 2」的指向，决定 7，影响面「文档」中 togaf/capabilities.yaml 一句已被 ADR-0050 取代）（决定 4 流程登记一句（部分）已被 ADR-0052 取代）
- **日期**：2026-10-15
- **取代**：ADR-0040（整份）

## 背景

- ADR-0040 采纳的知识框架与施工图方法，以及之后加入的 6 项补充框架、13 项工程标准，推荐时只核实了标准存在与现行版本，没有对照本系统做适配研究。
- 两份对抗式适配评审（opus，`docs/architecture/proposals/fit-review-frameworks.md`、`FIT_REVIEW_ENGINEERING.md`）与一次联网核实（`FIT_REVIEW_VERIFY.md`，一手来源）发现：
  - 6 项补充框架与 ArchiMate 在架构 SSOT 中一次都没用到；
  - `togaf/capabilities.yaml` 的 77 个二级能力逐项预标了对应的现有 BC，按它「重推 BC」是循环论证；
  - ADR-0040 决定 3 允许能力地图的推导结果取代 ADR-0016 中有会计规则与生产取证依据的过账主干，优先级倒置；
  - 上下文映射 129 条边中 109 条是照老系统切法的规划边；同一事实多处手写，已出现漂移；
  - Flowable 8 只支持 DMN 1.1–1.3，解析不了锁定的 DMN 1.6；
  - OpenTelemetry 与 GUIDING_PRINCIPLES §11 O-1「不引入 traceId 与分布式追踪库」冲突。

## 决定

1. **知识框架收窄**（`docs/architecture/frameworks.md`）：
   - 保留：DDD（上下文映射只记有代码后果的关系：防腐层、开放主机服务与发布语言、共享内核、遵奉者；子域三分类改为「深建模 / 薄 CRUD」一个标记；事件风暴改为「事件清单推导」）、BPMN 2.0.2（只用可执行流程）、维度建模（粒度、事实表类型、一致性维度、SCD Type 2；总线矩阵的行是业务过程）。
   - 收窄：TOGAF 10 只用基线 / 目标 / 过渡架构与路线图，能力地图只留一级作范围漏项核对，删去「ADM 是骨架」「ABB = BC」；DAMA-DMBOK2R 以 SESSION_PLAYBOOK §14.1 D1–D19 与数据访问注册表为准，去掉 GB/T 36073；C4 只用系统上下文、容器两层。
   - 推迟：DMN，到出现第一张真实决策表时，在 DMN（版本按 Flowable 实际支持锁定）与 D15 版本化配置表之间选，另开 ADR。
   - 去掉：ArchiMate、ISO/IEC/IEEE 42010、Wardley 地图、Team Topologies、商业模式画布；REA 去掉框架身份，只留两个复审问题（每个经济事件的对偶事件在哪里；合同承诺如何成为事实）。
2. **BC 推导改为不变量先行**（`docs/architecture/method.md`）：范围以 OA 模板清单、规则卡、生产取证、业务走查为准 → 从规则卡与会计规则找不变量与一致性需求 → 聚合 → 按统一语言聚成 BC → 用价值流端到端走事件链查断点与孤儿事件 → 数据与分析设计 → 过渡架构与守护。能力地图不驱动 BC 推导。
3. **优先级规则**：已采纳、有证据的不变量 ADR（如 ADR-0016 的单一过账管道、期间闸门、WIP 与开票同一事务边界）约束能力地图与任何推导结果，反之不成立。规划项进入阶段前按决定 2 重新推导；结果与已采纳 ADR 不同时，新开 ADR 并附新证据。
4. **一个事实只手写一处**：上下文映射以 `backend/architecture/module-dependencies.txt` 与已建模块为准，`ddd/context-map.yaml` 删去规划边、到阶段再登记；聚合与表以数据访问注册表为准，删去已有的 `dama/data-objects.yaml`（PR-C 初稿）；流程登记改为由 `.bpmn20.xml` 生成（生成器实现前 `bpmn/processes.yaml` 暂手写）；KPI 与指标只有一个来源，沿用 ADR-0040 决定 4（`togaf/vision.yaml` 只登记 KPI 编号、名称与对应的 M-xx，口径以 OAT 与 METRIC_BASELINE 为准）；GUIDING_PRINCIPLES 各框架章节改为指向 FRAMEWORKS、METHOD 的指针（交 one-coordinator 派工）。
5. **工程层标准**（FRAMEWORKS §9 重排）：合规义务在前（网络安全法与等保、个人信息保护法、数据安全法与网络数据安全管理条例、财会〔2024〕11 号与 12 号、会计档案管理办法、GB/T 24589.1-2024），可选实践在后，每项写落点与负责会话。逐项：OpenAPI 以 springdoc 实际输出为准；AsyncAPI 只作事件目录文件格式；RFC 9457、RFC 9562 保留并加「排序用业务时间列，不用 ID」；CycloneDX 不锁版本、只在发布流程生成；ASVS 取 L2 适用章节一次性对照写进安全不变量；Top 10 并入 ASVS；ISO/IEC 25010 只作非功能需求用语参照；SLSA 不追级别，只写现有发布链对照；DORA 推迟到上生产后；OpenTelemetry 去掉。等保级别上生产前再定、个人信息保护法与 GB/T 35273 同等采纳，均按用户「保持现在」。
6. **推荐须先做适配研究**：今后任何框架、标准、选型推荐，先做对照本系统的适配评审（要求、代价、收益、把握），决策页写明代价，不预选推荐项。
7. **防漂移**：FRAMEWORKS、METHOD 仍列入 one-architecture 画像的上下文文档；改动须引 ADR 或 intent，提交带 `Architecture-Ref:`；标「未核实」的条目不作硬依据。

4. 各阶段开工前按 METHOD 新流程推导本阶段 BC；已建 BC 以代码为准。

## 回滚方案

本 ADR 只改文档、登记与架构生成器，不改业务代码。不采纳时把 ADR-0040 状态改回已采纳、本 ADR 改为已废弃，并按 git 历史恢复 FRAMEWORKS、METHOD、`togaf/`、`ddd/context-map.yaml`、`dama/data-objects.yaml`；生成器的 A1 与边校验可保留；删去的规划边可从 git 历史取回。

## 需同步修改的守护规则

- `architecture/build_architecture.py`（本 PR）：关系 `type` 只允许五种有代码后果的关系或不写，`status` 只允许 built 与 planned（本阶段在建），`via` 必填；实现 A1——`status: built` 的边集合必须等于 `backend/architecture/module-dependencies.txt`（此前只写在文档中、未实现；实现时补登 `platform.web>platform.identity`）；`--self-test` 覆盖拦截与放行两类，经 `build_all.py --check` 运行。
- 取消 ADR-0040 计划中的「追溯完整性 CI 门禁」，改为生成报告（不拦合并）。

## 后果

- 架构理论参照从 13 个框架收窄为 DDD、BPMN、维度建模为主，TOGAF、DAMA、C4 只用少数概念；会话判断的噪声减少。
- BC 推导以会计不变量与生产取证为起点，不再被一天起草的能力地图驱动；第 0、1 步草稿作废，愿景与目标的讨论改为阶段出口度量的讨论。
- 合规义务（等保、个人信息、财会规范、会计档案）在工程标准中排在前面，有落点和负责会话。
- 失去：全企业视角的能力规划工具；若将来扩展为多系统，需重新评估 TOGAF 与能力地图。
