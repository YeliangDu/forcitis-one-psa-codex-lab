## 背景

ADR-0081 决定 3 写明更正前当天不在职（撤销错误的离职）时不生成任职变化条目，因为待调整权限表要求任职变化条目前后部门均非空。用户 2026-11-03 就此答「应该做」：撤销错误离职、让人恢复在职时，对其原有敏感角色重新做权限复核（「原有」的含义见决定 1，用户 2026-11-03 选定）。触发出处：one-lead 2026-11-03 转述该决定并要求裁定形状（#730 评论 6599023412），非用户指派起草。

## 决定

撤销错误离职的 `EmployeeCorrected`（更正前当天不在职、更正后在职）为仍持有敏感角色的当事人生成一条复核条目，放宽一条检查以容纳「触发前部门为空」，并取代 ADR-0081 对本情形「`triggerFieldKinds` 照实填写」的要求，其余照 ADR-0081 不变。

1. **条目**：更正生效时当事人持有至少一个敏感角色（授予按监听器处理该事件当天判定有效，不按更正的人事业务生效日回溯）的，生成一条类型 `SENSITIVE_ROLE_REVIEW`、来源 `ASSIGNMENT_CHANGE`、触发字段 `ORG_UNIT` 的条目，关于这个人、覆盖其当时全部敏感角色；触发命令 ID 取 `EmployeeCorrected.personnelCommandId`，触发前部门为空，触发后部门为当天部门，触发前岗位为空；去重键不变（类型，人，人事命令 ID，触发字段），每人每个更正命令一条，与调岗路径相同；无收件人；不生成范围复核条目（需要前部门才有可缩的范围）。离职已关闭其全部授予、复职只恢复基础 `employee` 授予（ADR-0055 决定 3 第 2、6 项），所以更正到达时通常没有敏感角色，此时不生成条目；条目只复核更正时仍持有的角色，不自动恢复任何授予，重新授予敏感角色照常走授予校验。
2. **事件**：该情形的 `EmployeeCorrected` 的 `triggerFieldKinds` 只发 `[ORG_UNIT]`，不发 `POSITION`，取代 ADR-0081 决定 3 中「`triggerFieldKinds` 照实填写」对本情形的要求（岗位同样从空变有值，但前部门为空的岗位条目会被下面的检查拒绝，且岗位变化在此情形下不单独复核）；`previousOrgUnitId`、`previousPositionId` 为空，`newOrgUnitId`、`newPositionId` 有值；监听器不得因前部门为空而拒收或重试，调岗事件（`EmployeeTransferred`）带空前部门仍拒收并记 ALERT。
3. **表检查**：`ck_permission_adjustments_assignment_change` 放宽，只改触发前后部门这一条：来源为 `ASSIGNMENT_CHANGE` 当且仅当触发后部门（`after_org_unit_id`）非空；触发前部门（`before_org_unit_id`）可空，但仅限类型 `SENSITIVE_ROLE_REVIEW`、来源 `ASSIGNMENT_CHANGE` 且触发字段 `ORG_UNIT`；触发前部门为空时触发前岗位也必须为空；部门变化时前后不同写成对空值安全的 `before_org_unit_id IS DISTINCT FROM after_org_unit_id`。其余分支（触发字段与来源成对、非任职变化行四列为空）不变。不增列、不增枚举值。
4. **仍不覆盖**：更正后当天不在职（更正使人离职）不生成任何条目，监听器不得因此重试。该情形下授予是否关闭、是否发离职事件尚未规定，由人事命令发布方卡（#1089）核实并在需要时另立卡；本 ADR 不规定。ADR-0081 决定 3 的其余部分不变。

## 迁移方案

表无历史数据，条目由监听器新生成，无回填。放宽检查是新迁移里的一次删除并重建约束，不触及行。

## 回滚方案

回到 ADR-0081 决定 3 只需一次迁移重建原检查；已生成的触发前部门为空的条目须先改掉或删除（办结不够，该检查不看状态），否则旧检查建不起来；删除受 10 年保留约束，故回滚只在 F-1 上线前可行，上线前无此类条目。

## 需同步修改的守护规则

- 表结构验收（#729 / #730）：`ck_permission_adjustments_assignment_change` 的新形状——更正前部门为空只收类型 `SENSITIVE_ROLE_REVIEW`、触发字段 `ORG_UNIT`；范围复核或岗位触发时更正前部门为空被拒；更正前部门为空而更正前岗位非空被拒；非任职变化行四列仍须为空。
- 验收（#730，one-test）：撤销错误离职的更正，当事人持有敏感角色时生成一条（每人一条，覆盖其全部敏感角色）且重投不增；无敏感角色则无条目；调岗事件带空前部门被拒；撤销错误离职的更正任何情形都不生成范围复核；更正后不在职不生成且不重试。

## 后果

- 恢复在职且仍持有敏感角色的人多一条复核条目，复核权限本身，不改变授权；离职时被关闭的授予不在复核范围，也不自动恢复。错误离职时仍处于待处理、被「因离职关闭」的条目（含范围复核）同样不恢复。
- 更正前部门为空成为合法取值，监听器与读取方不得再假定任职变化条目的前部门必有值。
- 更正后不在职的情形仍没有条目：被更正为离职的人的敏感角色由离职关闭路径处理，若该路径不覆盖更正产生的离职，需另立卡。
