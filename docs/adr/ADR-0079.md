## 背景

要决定人力资源子域的稳定蓝图：一个人从招聘到离职再入职的全部业务能力（含薪资、社保公积金、个人所得税）、上下文边界、数据归属、核心对象生命周期与上下文间事件。现在决定是因为人事命令线（ADR-0068）已在落地，后续考勤、合同、薪资等若无统一蓝图会各自划界、日后推翻。触发出处：用户 2026-11-02「同意，蓝图包含薪资社保个税（一个人员全生命周期的所有能力）」（intent 2026-11-02-132807-one-lead-同意-蓝图包含薪资社保个税-一个.md），卡 #975。

本稿只定能力与边界层：能力、上下文、数据归属、核心对象生命周期（阶段，不是状态名）、上下文间事件（按含义，不是类名）、关键不变量、范围外。聚合拆分、类名、状态名、表结构按卡另定。本稿不改任何已采纳 ADR：上下文切分沿用 ADR-0051 第 3、4、5 条，人事命令沿用 ADR-0068，数据级别沿用 ADR-0043，自持数据沿用 ADR-0055，工号沿用 ADR-0078。用户草稿「HCM 业务架构」（六上下文、二十一聚合）只作证据：其中与上述 ADR 冲突之处（试用期作人员状态、招聘与绩效独立成上下文、离职按合同→关系→人员三步、两对双向依赖）不采用，理由见「备选方案」。差异表与端到端走查见 `docs/architecture/proposals/hr-blueprint-gaps.md`、`hr-blueprint-walkthrough.md`。

来源标记：【法】法规，括注仓库法规笔记键（`docs/architecture/frameworks/notes/` 下 LAB、LEAV、SOC、IIT、PIPL 各条，笔记为草稿，法条原文以发布文本为准）；【裁】用户裁定 intent；【ADR】已采纳 ADR；【证】老系统生产聚合计数（`docs/legacy/runtime-usage/`，只计数）；【待】本稿确认页待用户答的题（第 8 条）。

### 2. 上下文与数据归属

沿用 ADR-0051 的切分，不新增人事上下文。一个对象只由一个上下文写，别处只经 api 读或订阅事件。

| 上下文 | 独有并负责写 | 不持有 |
|---|---|---|
| `organization.workforce` | 法人、组织单元、岗位与职级、员工与其版本、任职、人事命令、离职暂停、招聘需求与候选人、劳动合同、执业证书、绩效结果 | 账号、工资、考勤 |
| `organization.attendance` | 工作日历、标准工时版本 | 个人考勤 |
| `organization.leave`（ADR-0051 B-27） | 打卡记录、请假、假期额度、加班、月度考勤确认、假期规则版本 | 在职判断（读 workforce） |
| `organization.payroll` | 薪资档案、月度薪资（法人×月）、社保公积金参保与缴费、个税计算与申报、专项附加扣除、薪资规则版本、激励与奖金 | 在职、任职、考勤原值 |
| `organization.administration` | 离职交接等行政事项（订阅离职） | 人事事实 |
| `platform.identity` | 账号、角色、会话、企业微信登录 | 员工档案 |
| 财务上下文（总账过账、付款） | 薪资过账凭证、付款 | 薪资明细 |

依赖方向单向：workforce 与 attendance 互不依赖；leave 读 workforce、attendance；payroll 读 workforce、attendance、leave；workforce、attendance 不依赖 leave、payroll。下游只经事件与 api 取上游事实，不回写上游。不形成环（ModularityTest）。

### 3. 核心对象生命周期（阶段）

1. **员工**：一名自然人对应一个员工，终身不换 ID、不换工号（【ADR】0078）。在职与否由按生效日排列的员工版本判定，不另存镜像（【ADR】0068 第 1 条第 8 项）。阶段：入职生效 → 试用 → 正式 →（停薪留职起止，可多次）→ 离职生效 →（复职）。试用与正式是在职中的阶段，不是另一种就业状态。
2. **岗位**：目录项，可用或停用；不承载编制（【裁】Q-08）。
3. **劳动合同**：订立（可早于或晚于用工日，晚于时一个月内补订）→ 生效 → 续订或变更 → 终止或解除。试用期期限是合同条款，按合同期限受法定上限（【法】LAB#试用期限制）。同一人同一日至多一份生效合同；跨法人调动在同一生效日终止旧合同、订立新合同。
4. **请假**：申请 → 审批 → 执行，可撤回、可销假；额度先占用后扣减，不扣成负数；已封存年度不改，结转记入新年度。
5. **月度薪资（法人×月）**：起草 → 计算 → 审核 → 批准 → 发放 → 过账。批准后不改原值，差错只在后续月度以调整项更正（CS-3.9）。

### 4. 上下文间事件（按含义）

| 事件含义 | 发布方 | 主要订阅方 |
|---|---|---|
| 入职生效、转正、调动、用人法人变更、离职生效、复职、停薪留职开始与结束、更正 | workforce | identity、leave、payroll、administration、审计 |
| 劳动合同生效、变更、终止 | workforce | payroll（社保与薪资档案依据） |
| 绩效结果确认 | workforce | payroll（奖金） |
| 执业证书到期或注册单位变更 | workforce | 印章台账（ADR-0064） |
| 工作日历、标准工时变更 | attendance | leave、cost.timesheet |
| 请假批准与撤销、加班批准、月度考勤锁定 | leave | payroll、cost.timesheet |
| 月度薪资批准、发放、过账请求 | payroll | 财务 |

已建事件（`EmployeeHired` 等）保留名称；停薪留职起止、用人法人变更的事件尚未命名，随其卡定。

### 5. 关键不变量

1. 在职判断只有一处：workforce 的员工版本按业务时区的生效日判定（【ADR】0068）。
2. 主任职不重叠，兼职不限（【裁】`2026-10-28-172404`）。
3. 工号全局唯一、不改、复职沿用（【ADR】0078）。
4. 劳动关系自实际用工日起；未订书面合同的满一个月须提示 HR（【法】LAB#劳动关系建立、LAB#未签书面合同责任）。
5. 同一用人单位与同一劳动者只约定一次试用期（【法】LAB#试用期限制）；再入职是否再约定按【待】Q2。
6. 薪资、社保、个税由支付工资的法人作扣缴义务人，按法人分别核算申报（【法】IIT#扣缴义务人；【裁】Q-09 三种法人口径分别记录）。
7. 批准后的薪资、已锁定的月度考勤、已封存的假期年度不就地改写，只以后续调整更正。
8. 社保公积金的生效与停止以经办回执为准，不以 HR 录入或离职事件代替（【法】SOC#个人社保登记、SOC#公积金增减员）。
9. 身份证号、银行卡号、工资属敏感个人信息或待定：建表前须法务答复 U-11、U-14 并完成个人信息保护影响评估（【ADR】0043 第 5 条；【法】PIPL#保护影响评估）。
10. 招聘需求、劳动合同、离职申请在 workforce 内一级审批，不走 platform.approval；请假、加班、薪资走 platform.approval（【ADR】0051 第 4 条第 5 项）。
11. 离职生效后的各项收尾（工资结清、年假折算、社保公积金减员、交接、账号关闭、执业证书变更）由各上下文订阅离职事件各自完成，不作为离职生效的前置条件（【ADR】0068 单一离职命令）。

### 6. 范围外

编制与定员、培训课程与学习平台（只记执业证书的继续教育学时）、继任计划、纸质档案保管、法定以外的商业福利、费用报销（另有上下文）、工时填报（cost.timesheet）、资源计划（交付）、员工自助门户的界面设计。

### 7. 建造顺序

不在本稿另定：沿用 ADR-0054（W0 人事与账号，W2 请假与加班，W4 薪酬）。每个上下文轮到时再开卡；本稿采纳前不开建造卡。

### 8. 确认页待答题（用户一次作答后写入本条）

## 备选方案（未采用）

1. **用户草稿的六上下文**（招聘、绩效、能力资质独立，考勤与请假合并）：与 ADR-0051 第 3–5 条冲突，且草稿自身登记两对双向依赖（能力↔人员、招聘↔人员），违反模块无环。招聘、绩效、执业证书都以员工为主体且量小（老系统无独立招聘、绩效模板），独立成上下文只增加跨上下文同步。
2. **试用期作为人员状态**（候选→试用→在职→离职）：与 ADR-0068 第 1 条第 3 项冲突；试用期是在职中的阶段并由合同约定期限，作状态会让在职判断有两处。
3. **离职按合同终止→关系终止→人员离职三步**：与 ADR-0068 单一离职命令及离职暂停冲突；改为离职生效后各上下文订阅收尾（不变量 11）。
4. **薪资外购、不自建**（`contexts.yaml` 现记的老观点）：与用户裁定「薪资在新系统计算、公司代扣个税」冲突。
