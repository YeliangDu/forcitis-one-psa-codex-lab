## 背景

要决定人力资源子域的稳定蓝图：一个人从招聘到离职再入职的全部业务能力（含薪资、社保公积金、个人所得税）、上下文边界、数据归属、核心对象生命周期与上下文间事件。人事命令线已落地，其余能力若无统一蓝图会各自划界。触发出处：用户 2026-11-02「同意，蓝图包含薪资社保个税（一个人员全生命周期的所有能力）」（intent 2026-11-02-132807-one-lead-同意-蓝图包含薪资社保个税-一个.md），卡 #975。

只定能力与边界层；聚合、类名、状态名、表结构按卡另定。不取代任何已采纳 ADR（沿用 0043、0051、0055、0068、0073、0078）。用户草稿「HCM 业务架构」与早先人员组页（`decision-pages/archive/PPL_TRACE.md`，未答）只作证据；后者影响边界的题并入第 8 条，其余留各卡。附件：`docs/architecture/proposals/hr-blueprint-gaps.md`（差异表）、`hr-blueprint-walkthrough.md`（走查）、`hr-blueprint-questions.md`（待答题）。

### 2. 上下文与数据归属

沿用 ADR-0051，不新增人事上下文（`organization.leave` 即 ADR-0051 的 B-27）。一个对象只由一个上下文写，别处经 api 读或订阅事件。

| 上下文 | 独有并负责写 |
|---|---|
| workforce | 法人、组织单元、岗位、员工与版本（含用工类型）、任职、人事命令、离职暂停、招聘、劳动合同（含竞业限制约定）、执业证书、技能目录与技能评估、绩效结果、身份证件、户籍住址、员工本人银行账户（【ADR】0036、0021） |
| attendance | 工作日历、标准工时版本 |
| leave | 打卡与补卡、外勤、请假、额度、加班调休、月度考勤锁定、假期规则版本 |
| payroll | 薪资档案（约定工资的权威值）、调薪、月度薪资、社保公积金、个税与专项附加扣除、薪资规则版本、激励奖金 |
| administration | IT 资产归还等行政事项 |
| identity | 账号、角色、会话、企业微信登录 |

- 劳动合同中的工资条款引用薪资档案版本，不另存数值。
- 依赖方向：leave → workforce、attendance、platform.approval；payroll → workforce、attendance、leave、platform.approval、platform.integration、过账（AGG-77，api）、`payables.payment`（提交应付薪酬，法人×月一笔，明细留 payroll，【规】AGG-52；ADR-0016、0026），并订阅其完成事件；「已发放」以付款结果为准，退票或失败的人员记待重发，不改写已批准薪资（intent `142458`，lead 认可此落法）；财务不读 payroll（ADR-0051 第 7 条第 2.7 项）；员工银行账户由 payables 与 payroll 经 workforce api 读。workforce、attendance 不依赖 leave、payroll。不成环。
- workforce 内分为组织结构、用工核心、劳动合同、执业资格与技能、招聘、绩效六区（附件 `hr-blueprint-scope.md` 第四节）；区间只经应用服务或事件，不跨区写表，日后拆分只搬包与表。应聘者不是员工，录用生效前不建员工。
- 交付资源计划经 api 读在职、请假、执业资格与技能，不订阅。个人信息删除与限制请求由 workforce 受理，各上下文对自有数据执行（【法】PIPL#个人信息删除）。
- 已登记未生效的离职：下游经 workforce 只读 api 查询（如资产归还），不新增事件（ADR-0068 第 1 条第 9 项）。

### 3. 核心对象生命周期（阶段）

1. **员工**：一名自然人一个员工，终身不换 ID 与工号。在职由按生效日排列的员工版本判定。阶段：入职生效 → 试用 → 正式 →（停薪留职，可多次）→ 离职生效 →（复职）。试用与正式是在职中的阶段。
2. **岗位**：目录项，可用或停用。
3. **劳动合同**（只适用于用工类型为正式的员工）：订立（早于或晚于用工日；晚于时一个月内补订）→ 生效 → 续订或变更 → 终止或解除。试用期期限是合同条款。同一人与同一用人单位同一日至多一份生效合同（劳动合同法第六十九条允许非全日制多单位）。
4. **请假**：申请 → 审批 → 执行，可撤回、销假；额度先占用后扣减，不扣成负数；已封存年度不改，结转记入新年度。
5. **月度薪资（扣缴法人×月）**：起草 → 计算 → 审核 → 批准 → 发放 → 过账；批准后差错只在后续月度以调整项更正（CS-3.9）。

### 4. 上下文间事件（按含义）

| 事件含义 | 发布方 | 订阅方 |
|---|---|---|
| 入职、转正、调动、离职、复职、停薪留职起止、更正（生效时） | workforce | identity、leave、payroll、审计 |
| 数据范围法人变更（ADR-0073，【规】AGG-117 已草名） | workforce | identity、payroll（口径不一致预警）；成本经 api 读 |
| 劳动合同生效、变更、终止（含用人单位变更） | workforce | payroll（社保依据） |
| 绩效结果确认 | workforce | payroll（奖金） |
| 执业证书到期、注册单位变更 | workforce | 印章台账 |
| 请假批准与撤销、加班批准、月度考勤锁定 | leave | payroll、cost.timesheet |

工作日历与标准工时经 api 读，不订阅（【规】AGG-108）。已建事件保留名称；停薪留职起止事件随其卡命名。

### 5. 关键不变量

1. 在职判断只有一处：workforce 员工版本按业务时区生效日（【ADR】0068）。
2. 主任职不重叠，兼职不限（【裁】`2026-10-28-172404`）。
3. 工号全局唯一、不改、复职沿用（【ADR】0078）。
4. 三种法人口径分别记录，不一致只预警（【裁】Q-09）：个税扣缴与月度薪资按支付工资的法人（【法】IIT#扣缴义务人）；社保公积金按劳动合同的用人单位（【法】SOC#个人社保登记）；数据范围与成本按 ADR-0073 的归属法人。改其中一种不连带改另两种。
5. 正式员工自用工日起建立劳动关系，未订书面合同满一个月提示 HR；实习、退休返聘、劳务派遣不适用劳动合同提示（派遣协议归 `procurement.subcontracting`，ADR-0051 第 5 条）。
6. 社保公积金缴费义务自用工日起，不以登记回执为起点；回执只确认经办状态（【法】SOC#个人社保登记「不登记不免除缴费」）；退休返聘、实习不参保（【裁】P-T4）；劳务派遣人员的工资与社保由派遣单位承担（劳动合同法第五十八条），P-T4「其余都参保」是否含派遣人员待用户确认，确认前本系统不为其参保、发薪。停薪留职期间社保公积金照常缴纳，不停缴（第 8 条 Q5）。
7. 批准后的薪资、已锁定的月度考勤、已封存的假期年度不就地改写；考勤书面记录至少保存两年（第 8 条 Q6）。
8. 个人信息按 ADR-0043 两维（访问级别、个人信息标记）登记。HR 的敏感个人信息：生物识别与定位打卡、外勤定位（行踪轨迹）、病假医疗期体检职业病工伤、孕产、银行账户与工资卡、专项附加扣除中的子女老人配偶（第三人，含不满十四周岁，不得以个人信息保护法第十三条第一款第二项为据，第二十八、三十一条）、身份证号（含民族、户籍）。以同意为据处理的须单独同意（个人信息保护法第二十九条）；建这些列前须完成影响评估并定 U-14（法务答复 intent `2026-11-02-143550`；【法】PIPL#敏感个人信息、PIPL#保护影响评估）；未定前职工名册不含证件号。
9. 招聘、合同、离职申请、绩效在 workforce 内单级审批；需要多级审批的能力须另立 ADR 移出 workforce（【ADR】0051 第 4 条第 5 项、后果 4）。请假、加班、月度薪资走 platform.approval（【规】AGG-70、72、73）。
10. 解除与终止都记录依据；单方解除另须确认已核实第四十二条七项禁止情形、已事先将理由通知工会，并记录工会意见与单位书面通知工会的处理结果（劳动合同法第四十二、四十三条，第 8 条 Q4）；解除记录不存健康与孕产信息。
11. 离职生效后的收尾（工资结清、年假折算、社保公积金减员、账号关闭、执业证书变更）由各上下文订阅离职事件完成，不作离职生效的前置条件；离职交接流程不做（【裁】Q-D `2026-10-16-082311`），只在离职记录上记「工作交接办结日」，payroll 经 workforce api 读取，作为经济补偿的支付时点（第 8 条 Q3）。
12. 各上下文自管保存期限（ADR-0068 第 1 条第 7 项为人事历史十年）；已解除或终止的合同文本至少保存二年（劳动合同法第五十条）；已过账薪资事实不删。
13. 同一用人单位只约定一次试用期（劳动合同法第十九、八十三条，法务答复 `142458`）：停薪留职或长病假后返岗、违法解除经裁决恢复，不设；跨法人调动法务不建议设，lead 默认不设；离职结清后再入职允许设，设定时提示曾在同一法人任职及地方口径风险，不拦截（后两项为 lead 默认，用户可改）。
14. 用人单位合并或分立，原劳动合同继续有效，由承继单位履行（劳动合同法第三十四条），不按跨法人调动处理。
15. 执业注册单位须为当前用人单位，用人单位变更时提示变更注册（lead 默认，注册管理规定待核）。
