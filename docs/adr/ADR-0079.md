## 背景

要决定人力资源子域的稳定蓝图：一个人从招聘到离职再入职的全部业务能力（含薪资、社保公积金、个人所得税）、上下文边界、数据归属、核心对象生命周期与上下文间事件。现在决定是因为人事命令线（ADR-0068）已在落地，后续考勤、合同、薪资等若无统一蓝图会各自划界、日后推翻。触发出处：用户 2026-11-02「同意，蓝图包含薪资社保个税（一个人员全生命周期的所有能力）」（intent 2026-11-02-132807-one-lead-同意-蓝图包含薪资社保个税-一个.md），卡 #975。

### 2. 上下文与数据归属

沿用 ADR-0051，不新增人事上下文（`organization.leave` 即 ADR-0051 的 B-27）。一个对象只由一个上下文写，别处经 api 读或订阅事件。

| 上下文 | 独有并负责写 |
|---|---|
| workforce | 法人、组织单元、岗位、员工与版本（含用工类型）、任职、人事命令、离职暂停、招聘、劳动合同（含竞业限制约定）、执业证书、绩效结果、身份证件、户籍住址、员工本人银行账户（【ADR】0036、0021） |
| attendance | 工作日历、标准工时版本 |
| leave | 打卡与补卡、外勤、请假、额度、加班调休、月度考勤锁定、假期规则版本 |
| payroll | 薪资档案（约定工资的权威值）、调薪、月度薪资、社保公积金、个税与专项附加扣除、薪资规则版本、激励奖金 |
| administration | IT 资产归还等行政事项 |
| identity | 账号、角色、会话、企业微信登录 |

- 劳动合同中的工资条款引用薪资档案版本，不另存数值。
- 依赖方向：leave → workforce、attendance、platform.approval；payroll → workforce、attendance、leave、platform.approval、platform.integration、过账（AGG-77，api）、`payables.payment`（提交应付薪酬：法人×月一笔总额，明细留 payroll，【规】AGG-52），并订阅其完成事件；月度薪资的「已发放」由付款结果置位，银行退票或代发失败由付款作废重发、薪资回到异常处理（财务答复 `142458`；ADR-0016 单一过账管道、ADR-0026 核算与付款分离）；财务与付款不订阅、不读 payroll（ADR-0051 第 7 条第 2.7 项）；员工银行账户由 payables 与 payroll 经 workforce api 读。workforce、attendance 不依赖 leave、payroll。不成环。
- 已登记、未生效的离职：下游经 workforce 只读 api 查询（例如 administration 在登记后生成资产归还），不新增事件，ADR-0068 第 1 条第 9 项不变。

### 3. 核心对象生命周期（阶段）

1. **员工**：一名自然人一个员工，终身不换 ID 与工号。在职由按生效日排列的员工版本判定。阶段：入职生效 → 试用 → 正式 →（停薪留职，可多次）→ 离职生效 →（复职）。试用与正式是在职中的阶段。
2. **岗位**：目录项，可用或停用。
3. **劳动合同**（只适用于用工类型为正式的员工）：订立（早于或晚于用工日；晚于时一个月内补订）→ 生效 → 续订或变更 → 终止或解除。试用期期限是合同条款。同一人与同一用人单位同一日至多一份生效合同（劳动合同法第六十九条允许非全日制多单位）。
4. **请假**：申请 → 审批 → 执行，可撤回、销假；额度先占用后扣减，不扣成负数；已封存年度不改，结转记入新年度。
5. **月度薪资（扣缴法人×月）**：起草 → 计算 → 审核 → 批准 → 发放 → 过账；批准后差错只在后续月度以调整项更正（CS-3.9）。

### 5. 关键不变量

1. 在职判断只有一处：workforce 员工版本按业务时区生效日（【ADR】0068）。
2. 主任职不重叠，兼职不限（【裁】`2026-10-28-172404`）。
3. 工号全局唯一、不改、复职沿用（【ADR】0078）。
4. 三种法人口径分别记录，不一致只预警（【裁】Q-09）：个税扣缴与月度薪资按支付工资的法人（【法】IIT#扣缴义务人）；社保公积金按劳动合同的用人单位（【法】SOC#个人社保登记）；数据范围与成本按 ADR-0073 的归属法人。改其中一种不连带改另两种。
5. 正式员工自用工日起建立劳动关系，未订书面合同满一个月提示 HR；实习、退休返聘、劳务派遣不适用劳动合同提示（派遣协议归 `procurement.subcontracting`，ADR-0051 第 5 条）。
6. 社保公积金缴费义务自用工日起，不以登记回执为起点；回执只确认经办状态（【法】SOC#个人社保登记「不登记不免除缴费」）；退休返聘、实习不参保（【裁】P-T4）；劳务派遣人员的工资与社保由派遣单位承担（劳动合同法第五十八条），P-T4「其余都参保」是否含派遣人员待用户确认，确认前本系统不为其参保、发薪。停薪留职期间社保公积金照常缴纳，不停缴（第 8 条 Q5）。
7. 批准后的薪资、已锁定的月度考勤、已封存的假期年度不就地改写；考勤书面记录至少保存两年（第 8 条 Q6）。
8. 身份证件、银行账户、工资、病假事由属敏感个人信息或待定：建相应列前须法务答复 U-11、用户定 U-14，并完成影响评估（【ADR】0043 第 5 条；【法】PIPL#保护影响评估）；未答前职工名册不含证件号。
9. 招聘、合同、离职申请、绩效在 workforce 内单级审批；需要多级审批的能力须另立 ADR 移出 workforce（【ADR】0051 第 4 条第 5 项、后果 4）。请假、加班、月度薪资走 platform.approval（【规】AGG-70、72、73）。
10. 解除与终止都记录依据；单方解除另须确认已核实第四十二条七项禁止情形、已事先将理由通知工会，并记录工会意见与单位书面通知工会的处理结果（劳动合同法第四十二、四十三条，第 8 条 Q4）；系统不存健康与孕产信息。
11. 离职生效后的收尾（工资结清、年假折算、社保公积金减员、账号关闭、执业证书变更）由各上下文订阅离职事件完成，不作离职生效的前置条件；离职交接流程不做（【裁】Q-D `2026-10-16-082311`），只在离职记录上记「工作交接办结日」，payroll 经 workforce api 读取，作为经济补偿的支付时点（第 8 条 Q3）。
12. 各上下文自管保存期限（ADR-0068 第 1 条第 7 项为人事历史十年）；已过账薪资事实不删。
13. 同一用人单位只约定一次试用期（劳动合同法第十九、八十三条，法务答复 `142458`）：停薪留职或长病假后返岗、违法解除经裁决恢复、跨法人调动，均不设试用期；离职结清后再入职允许设试用期，设定时提示其曾在同一法人任职，不拦截（lead 默认，用户可改）。

### 6. 范围外

沿用 ADR-0054（W0 人事与账号、W2 请假与加班、W4 薪酬）；采纳前不开建造卡。

### 8. 用户答复与附加条件

答复 1A 2A 3A 4A 5A 6B 7A 8A 9A 10A（intent `2026-11-02-141959`；题面见 `docs/architecture/proposals/hr-blueprint-questions.md`）。条件如下，按卡实施：

- Q1 跨法人调动：原法人终止、新法人新签，年限依法合并。调动时记录原法人是否已付经济补偿；已付的，新法人日后解除时不再计原法人年限（劳动合同法实施条例第十条）。
- Q2 外勤进考勤：须审批留痕；外勤记录本身不产生加班。
- Q3 离职结算进薪资：工资在解除或终止时一次付清（工资支付暂行规定第九条）；经济补偿在办结工作交接时支付（劳动合同法第五十条），以「工作交接办结日」为触发。
- Q4 单方解除：见不变量 10 的三项记录。
- Q5 停薪留职期间社保公积金照常缴：单位部分公司缴，个人部分员工交回；B（员工承担单位部分）不合法（用户判定，社会保险法第六十、八十六条，劳动合同法第二十六条第一款第二项）；不停缴（lead 转述）。
- Q6 月度考勤：部门负责人或人力统一锁定，员工锁定前可提异议；考勤书面记录至少保存两年（用户判定：考勤由单位举证；法条依据未核实）。
- Q7 申报：系统计算、导出，人工在经办平台与扣缴端办理后导入回执与专项附加扣除（IIT#全员全额申报）；判定表所引个税法第九条与「60 号公告」未核实。
- Q8 合同：线下签字、系统台账与扫描件；扫描件不替代原件，台账记原件保管处（双方各执一份）。
- Q9 招聘：单级审批，不对接招聘网站；应聘者个人信息须告知并取得同意，定保存期限，期限值日后作参数问用户（【法】PIPL#处理前告知、PIPL#保存期限）。
- Q10 绩效：单级确认；须能记录并关联「不能胜任结果 → 培训或调岗 → 再次不能胜任」（劳动合同法第四十条第二项）。

P13-10、P13-13 等审批与参数题留各卡。
