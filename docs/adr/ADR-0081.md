## 背景

ADR-0068 第 5 条把 F-1 待调整权限表的三列从同步运行改为命令：触发列、到期列 `expiry_separation_hold_id`（待放行离职记录 ID）、关闭列，另许可追加组织命令一侧的 `trigger_org_structure_command_id` 与 `closure_org_structure_command_id`，并让监听器订阅 `EmployeeTransferred`、`EmployeeSeparated`、`EmployeeCorrected` 与组织命令事件。

#729 的数据设计落表时（评论 6597646561、6597992239）核对到三处与现状不符：
1. `platform.identity` 只能经 `OrgDirectory.availabilityOn` 得知某人当天是否被暂停离职（`Availability.separationHeld`，布尔），拿不到待放行离职记录 ID；
2. 组织单元只有新建、改和撤销（ADR-0068 第 4 条，`OrgUnitDissolved` 为终点），没有任何命令使部门恢复，`closure_org_structure_command_id` 与「因部门恢复关闭」没有产生者；
3. `EmployeeCorrected` 的负载只有命令 ID、员工 ID 与受影响区间，不带来源①所需的触发字段与前后部门。

触发出处：one-lead 2026-11-03 对 #729 裁定的要求（评论 6597646561），非用户指派。

## 决定

在 F-1 待调整权限落表、监听器取数时，面对已采纳的 ADR-0068 第 5 条与现有接口、事件不一致的三处，决定按现有事实记录而非新增接口或保留无产生者的取值，以使代码不与已采纳的 ADR 矛盾，接受日后出现恢复部门的命令时再追加。

1. **到期列**：`expiry_separation_hold_id` 取代为 `is_held_at_expiry boolean`，到期前为空，到期时写入当事人当天 `separationHeld` 的值；为真时重新生成等放行后的下一次作业判定（ADR-0044 第 2 项第 3 条不变）。不为这一列新增接口。
2. **组织命令一侧的关闭列**：不设 `closure_org_structure_command_id`，不设状态 `CLOSED_BY_REACTIVATION`、事件 `PermissionAdjustmentClosedByReactivation`、审计原因 `reactivation`。关闭列只有 `closure_personnel_command_id`（`CLOSED_BY_SEPARATION`）。日后出现恢复部门的命令时，随它追加状态值、事件、审计原因与关闭列，是无损变更。
3. **触发**：保留 ADR-0068 第 5 条的 `trigger_personnel_command_id`（来源①）与 `trigger_org_structure_command_id`（来源②，取自 `OrgUnitDissolved` 与 `OrgUnitMerged`），监听器保留 `EmployeeCorrected`。`EmployeeCorrected` 增加与 `EmployeeTransferred` 同名的载荷：`triggerFieldKinds` 必填（更正未触及部门与岗位时为空列表），`previousOrgUnitId`、`newOrgUnitId`、`previousPositionId`、`newPositionId` 在 `triggerFieldKinds` 非空时填写，描述更正前后截至今天的任职；更正前或更正后当天不在职（例如撤销错误的离职，或更正后离职）缺一侧部门，不生成任职变化（`ASSIGNMENT_CHANGE`）条目，敏感角色复核与范围复核都不生成：待调整权限表要求任职变化条目前后部门均非空（`ck_permission_adjustments_assignment_change`）。这两种情形本 ADR 不覆盖，需要时另立卡；缺一侧部门时对应的前后字段为空，`triggerFieldKinds` 仍照实填写；监听器不得因此重试。监听器收到缺 `triggerFieldKinds` 的 `EmployeeCorrected` 时拒收并记 ALERT，不当作空处理；发布方实现卡是 F-1 上线的前置。去重键仍为（类型，人，人事命令 ID，触发字段）。
4. **RULE-387 的末条场景**（「部门重新在用，条目关闭」）在没有恢复部门的命令期间不适用，用户已同意（2026-11-03，见批准证据）；规则正文的修订属代码类，按 CS-7.5 另行进行，本 ADR 不改规则文件。

## 影响面

- `docs/architecture/implementation-cards/f-1.md`：到期列、关闭列、状态集、监听器、不变量 29 随本 ADR（卡文已于 #1086 按 #729 裁定改好，监听器行补 `EmployeeCorrected`）。
- #729 表结构：不变（已按本决定落表，数据设计已通过）。
- `docs/architecture/events/workforce.yaml` 与 `asyncapi.yaml`：`EmployeeCorrected` 增 5 个载荷字段（`triggerFieldKinds` 必填，其余随之填写），`consumers` 增 `platform.identity`；`EmployeeTransferred` 的 `consumers` 增 `platform.identity`；`OrgUnitDissolved`、`OrgUnitMerged`（含载荷 `orgStructureCommandId`）尚未在任何事件目录登记，由组织结构命令的实现卡登记，登记时 `consumers` 含 `platform.identity`。
- ADR-0068：第 5 条与第 1 条第 9 项（`EmployeeCorrected` 负载）被部分取代（本 ADR 改为已采纳的同一提交内，在其头部加「被部分取代」）。
- RULE-387：末条场景，见决定第 4 点；规则文件由另一提交按 CS-7.5 改。

## 迁移方案

无数据迁移：`permission_adjustments` 是新表、无写入方。`EmployeeCorrected` 增加字段（`triggerFieldKinds` 必填，其余随之填写）是加字段变更，现有消费方（`platform.audit`）不读新字段；发布方在人事命令实现卡中填写。

## 回滚方案

回到 ADR-0068 第 5 条原文需要新增一个暴露待放行离职记录 ID 的接口，并加一个迁移把布尔列换成 ID 列；表无历史数据时是一条迁移。新增被取代的取值与列在任何时候都是无损的，不需要回滚。

## 需同步修改的守护规则

- 状态集测试（G-D12）：`PermissionAdjustmentStatus` 枚举与 `ck_permission_adjustments_status` 的取值一致，不含 `CLOSED_BY_REACTIVATION`。
- 人事命令契约测试：`PersonnelCommandContractTest`（约 274、285 行）对 `EmployeeCorrected` 负载的断言随新字段更新。
- 事件目录守护：`EmployeeCorrected` 的载荷字段与发布类一致；`consumers` 与订阅类一致。
- 表结构验收（#729）：`is_held_at_expiry` 与 `ck_permission_adjustments_expiry`、`ck_permission_adjustments_closed` 的形状。

## 后果

- 到期时只记「是否暂停」，不能回答「是哪一条待放行离职」；需要时从人事命令的待放行记录按当事人和日期查，不在待调整权限表里重复存。
- 待裁定 R-2（已维持的来源②条目在部门恢复时是否关闭）随之作废，恢复部门成为业务规则时再定。
- `EmployeeCorrected` 的发布方要多填五个字段，须有对应实现卡（#1089），且是 F-1 上线的前置：在它完成前发布的更正事件不带新字段，事件不可重放，来源①不会从这些更正生成条目，只从调岗命令生成；上线前须确认无此类积压。
- RULE-387 的说明文字里也有「部门重新启用则关闭」一句（`data-scope-rules.md` 第 18 行），与末条场景同属作废，CS-7.5 的规则修订须两处一并处理。

## 备选方案（未采用）

- 保留 `expiry_separation_hold_id`，为 `OrgDirectory` 新增暴露待放行离职记录 ID 的接口：新增一个跨模块接口只为存一条证据，而「是否暂停」已足够判定补生成，未采用。
- 保留 `CLOSED_BY_REACTIVATION` 作为暂无产生者的取值：状态集、事件、审计原因里留一个永远不会出现的值，并让检查约束为它保留分支，未采用；A-4 已对 `GRANT_MODE_UPGRADE` 同样处理。
- 不改事件，由监听器按人事命令 ID 查按日期的任职读取（ADR-0032 第 133 行要求的读取）自行算前后部门：多一次跨模块读取且读到的是当前状态而非命令当时的状态，未采用。
- 登记为勘误：存储的内容由记录 ID 变为布尔，改变了数据含义，不属于勘误（readme-lifecycle 第 6 节）。
