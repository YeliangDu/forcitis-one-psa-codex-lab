# ADR-0042：可观测性不采用 OpenTelemetry

- **状态**：已采纳（用户 2026-10-15 在适配评审重定页 https://claude.ai/artifact/XsXekbriGB3i8oKeFahe7h 上对「OpenTelemetry：去掉；新开 ADR 把 ADR-0002 和 STACK_DECISION 改到与只用 correlationId 一致」选「按建议」，intent `2026-10-15-195827`；GUIDING_PRINCIPLES §11 O-1 为用户 2026-10-15「全部按推荐 (Recommended)」）
- **日期**：2026-10-15
- **取代**：ADR-0002「可观测性」一行中的「OpenTelemetry」

## 背景

- ADR-0002 可观测性一行写「Micrometer + OpenTelemetry → 阿里云 ARMS / SLS（待确认）」，STACK_DECISION 第 49 行照录。
- 之后用户在 GUIDING_PRINCIPLES §11 O-1 定了：关联号 `correlationId` 是唯一的追踪键，不引入 `traceId` 与分布式追踪库；O-4 定了指标走 Micrometer 并暴露 Prometheus 端点。两处口径冲突。
- 适配评审（`architecture/proposals/FIT_REVIEW_ENGINEERING.md` 第 6 项）：单体单主机，跨进程只有几个出站防腐层，关联号出站带头已覆盖；`backend/pom.xml` 只有 `micrometer-registry-prometheus`，没有 OpenTelemetry 依赖。
- ADR-0041（PR #222）把 OpenTelemetry 列为不采用，并要求另开本 ADR 修订 ADR-0002 与 STACK_DECISION。

## 决定

1. 不引入 OpenTelemetry（API、SDK、Java agent、语义约定）与任何分布式追踪库；追踪以 §11 O-1 的 `correlationId`（加事件信封 `causationId`）为准。
2. ADR-0002 可观测性一行改读为：Micrometer 指标经 Prometheus 端点由阿里云 ARMS 抓取，结构化日志（ECS JSON）由 SLS 采集；告警覆盖同步延迟、未完成的事件发布、作业失败、登录失败率（规则见 §11 O-4–O-6）。
3. 不使用会自动注入追踪的探针（如 ARMS Java 探针）；指标只用 Prometheus 抓取方式。
4. 以后若确需跨进程链路追踪（例如拆出独立服务），另开 ADR 重新评估，先做适配评审（ADR-0041 决定 6）。

## 影响面

- 文档：`adr/src/ADR-0002.md` 状态行加注；`STACK_DECISION.md` 第 49 行改为决定 2 的表述。
- 交 one-ops：`phase1a/infra/INFRA_RUNBOOK.md` E-12 删去「方案 B：ARMS Java 探针」，只保留 Prometheus 抓取（`runbooks/C-4-ecs-init.md` E-12 已是该方案）。
- 代码：无（本来就没有 OpenTelemetry 依赖）。
- GUIDING_PRINCIPLES §11、NAMING_STANDARD G-O1–G-O6：不变，本 ADR 与之对齐。

只改文档。若要恢复 OpenTelemetry，另开 ADR 取代本 ADR，并同步修订 §11 O-1。

## 需同步修改的守护规则

- 无新增守护。依赖准入（SUPPLY_CHAIN S1）已能拦下未登记的新依赖；如需显式禁止 `io.opentelemetry` 依赖，可在依赖准入清单中登记为禁用（交 one-ops 评估，不在本 PR）。

## 后果

- 可观测性口径统一为一套：关联号追踪、Micrometer + Prometheus 指标、ECS JSON 日志。
- 失去：跨进程调用链的自动可视化；单体内用关联号检索日志代替。
