## 背景

草案，未占号（ARC-1020-COO-03，intent `2026-10-20-211104-…`），按用户指派处理。头部 BC 另含本稿新增平台模块（暂名，待定名与登记）。

用户 Q02 选 (b)「发一次性链接让对方回签或上传，不建账号」，落点要求另立 ADR 定义外部主体与公开入口并做安全评审（intent `…204732…`）；Q01 选 (d) 电子印章，签章服务另立 ADR（intent `…204731…`）。

现状：外部人员不进系统，签认件由我方登记扫描件或原始邮件（ADR-0047）；身份设计无外部人员一类。ADR-0009 决定 3 的签名票据给外部**系统**用，不是先例（R-opus A-3），且已列待清理（ADR-0055 决定 6）。公开端点只有 5 个登录类。A8 年量：客户产值确认单 1,787、委外交付确认单 130，外部单据合计约 2,845 件，是上限（A2 稿 §2）。

## 决定

### 1. 链接持有人不是账号

1. 新增一类访问主体：**一次性链接持有人**（暂名，下称持有人）。持有人没有账号、会话、`CurrentUser`、`Permission`、`AccessScope`，不进 `platform.identity` 的任何表；能做的事完全由链接限定。
2. 每条**一次性链接**（暂名）签发时绑定以下各项，签发后不可改：
   - 一张单据（所属模块、单据类型、单据 ID）；
   - 一个动作（第 2 条两类之一）；
   - 一个对方联系人：存所属模块的联系人记录 ID，另存签发时冻结的**脱敏显示名**（第 9 条）；
   - 待阅文件：文件服务中的不可变文件引用与哈希，回签必填、上传可空；
   - 签发人 `user_id`、签发时间、失效时间、所在地声明（境内 / 境外）。
3. 同一「单据 × 动作 × 对方联系人」同时只有一条有效链接。重新签发时，在同一事务内撤销旧链接并引用它。下列情况签发即拒绝并告警：联系人未登记、单据不可签发、待阅文件缺失、哈希不符。
4. 用语：词表已有「外部主体标识」（`external_subject`，platform.identity，ACL），本类主体**不得**叫「外部主体」。各名称均为暂名，交 one-glossary 定名。

### 2. 只做两类动作

| 动作 | 持有人能做 | 不能做 |
|---|---|---|
| 回签 | 下载签发时冻结的待阅文件（我方已用印版本），上传签字或盖章后的回签件，勾选声明后提交 | 修改待阅文件；把在线点击当签名 |
| 上传 | 查看我方填写的标题与要求，上传所要文件，提交 | 查看单据其他内容或其他文件 |

1. 点击不是签名：Q01 未选 (b)「系统内约定电子签名」。勾选声明只记录「本人为所示联系人或经其授权」这一陈述。
2. 提交只生成一条**外部回传**，不改单据状态、不触发收入、不形成证据。所属模块人员审核后接收或退回；接收时按该模块规则登记为证据，ADR-0047 共同规则第 1、2 点照旧，签字人由人核对。

### 3. 适用单据（首批，逐类开放）

| 单据 | 动作 | 所属模块 |
|---|---|---|
| 客户价值确认单（A8「客户产值确认单（新）」，ADR-0047 第 1 类） | 回签 | receivables.wip（证据，ADR-0047 / 0049），首个接入卡确认 |
| 审查同意书面意见、发包人书面签收单（第 1、2a、2b 类）、成果确认函 | 回签 | delivery.acceptance |
| 验收单（`acceptance_record`）、阶段末签认单（4a）、检查服务签认单（5） | 回签 | delivery.acceptance |
| 委外交付确认（A8「项目委外交付确认单」）、供方交付成果 | 回签、上传 | procurement.subcontracting（AGG-57 形态待 Q20） |
| 发包人提供资料 | 上传 | delivery.acceptance |

1. 每类单据由所属模块的实施卡接入，经 one-security 评审后，以配置开关开放（SESSION_PLAYBOOK §12.2，默认关）。表外单据不得签发。
2. **不适用**：销售合同与供方协议的签署（INV-124，W3 另定）、劳动合同、检测报告、出图签章，以及涉及收付款信息的单据。

### 4. 令牌与公开端点

1. **令牌**：CSPRNG 生成 256 位，库内只存 SHA-256 摘要（唯一约束）；明文只在签发响应出现一次，遗失须重签；不进日志、审计、事件、错误响应。
2. **部分取代 ADR-0009 决定 2**：链接形如 `https://{对外主机名}/{公开页路径}#{令牌}`。片段属 URL（RFC 3986），故为部分取代。**范围仅限**：一次性链接令牌可出现在片段中；查询串、路径、重定向地址仍不得带令牌，决定 2 其余内容（服务端会话、Cookie、CSRF）不变。条件：公开页读到后立即 `history.replaceState` 清除，之后只经请求头携带。采纳时 ADR-0009 状态行括注。**批准前须 one-architecture 确认。**
3. **不建会话**：公开端点不创建、不续期、不读取会话，不下发 Cookie。不依赖 Cookie，故无 CSRF 面；逐请求校验令牌。
4. **公开端点**：只有下列四个，都用 `@PublicEndpoint(reason)` 并登记白名单，路径为暂名。都用 POST，理由：令牌放在请求头，每次都写审计（有副作用），响应不得缓存（NAMING_STANDARD §2.6 A-1）。
   - `…/one-time-links:open`：只读，返回动作、说明、脱敏显示名、待阅文件清单；
   - `…/one-time-links:download`：只读，服务端流式返回某一个冻结文件；
   - `…/one-time-links:upload`：上传单个文件；
   - `…/one-time-links:submit`：提交并消耗链接。
5. **统一失败**：以下七种原因对外返回同一状态码、同一错误（暂名「链接无效或已失效」），响应时间不随原因变化：不存在、已过期、已撤销、已使用、已锁定、浏览器不符、单据不可签发。具体原因只记审计。

### 5. 有效期、次数、撤销与防转发

1. **有效期**：默认 7 天（配置），上限 14 天（本稿定），可缩短；到期失效，不续期。
2. **只读与写入分开**：`open`、`download` 是只读请求，不绑定浏览器、不消耗链接、不计入锁定，只受限流约束。`upload`、`submit` 是写入请求，才计次：上传不超过 10 个文件，提交时消耗链接。消耗按 I-9 原子占用，并发提交恰好一次成功。
3. **撤销**：签发人或有该单据权限者可撤销并写原因。单据作废、终止、被替代或已线下回签时，所属模块同一事务内经 api 撤销全部有效链接；审核时再核单据状态。
4. **防转发**（只能缓解）：**首次上传时**公开页生成随机值存于本浏览器，服务端存其摘要并绑定；之后其他浏览器的写入请求按统一失败处理，累计 3 次锁定。邮件网关、链接预览只触发只读请求，不会抢先绑定。残余风险见后果。

### 6. 公开入口统一规则

适用于**全部非登录公开入口**：本稿四端点及签章服务稿的服务商回调（该稿引用本条，X-5）。

1. 对外入口用单独主机名，网关只路由白名单公开端点与公开页静态资源，其余拒绝；内部入口不对其开放。
2. 应用层按来源 IP、按令牌限流，全局无效令牌超阈值告警；网关与 WAF 作纵深防御；计数故障即拒绝；数值由 one-security 定；失败尝试按「IP × 时间窗」聚合写安全事件。
3. 公开页是独立前端入口，只引公开端点的生成客户端，无第三方脚本；响应头 `Cache-Control: no-store`、`Referrer-Policy: no-referrer`、`X-Robots-Tag: noindex`、严格 CSP、`frame-ancestors 'none'`。
4. 鉴权按入口各自定：本稿四端点按令牌（I-14）；服务商回调按服务商签名验签（签章服务稿），不适用 I-14，但同受本条第 1、2 点约束。
5. **谁建、何时建**：统一公开入口规则（本 ADR 决定 6）由最先需要开放公开入口的实施卡建造——本模块 W2 首批或某类印章切换电子用印的批次，取早者；主机名与网关由 one-ops 建，数值由 one-security 定；未建成则不开放任何公开入口。后到者只登记白名单。

### 7. 上传、关联与审核打开（经文件服务）

用语以 ADR-0060（下称基础稿）为准。

1. **签发时冻结**：所属模块签发时给出访问级别、个人信息标记、保存类别，存入链接；缺一即拒绝签发。
2. **上传**：经基础稿「写入内容」，上传主体为（「一次性链接」，链接 ID），文件留在临时区并检测；该来源临时区时效不短于链接上限加 2 天（基础稿第 5 条），故有效期不受其限。检测不通过即隔离，按上传失败提示。
3. **类型与大小**：按单据类型配置，须在文件服务白名单内；首批建议 PDF、OFD、JPG、PNG，单个 ≤20 MB；不收 CAD、BIM、压缩包。
4. **持有人下载**：经基础稿「读取内容」（仅平台模块，核对哈希）流式返回，持有人拿不到预签名地址。
5. **提交即关联**：提交时本模块以冻结值把已检测通过的文件**关联**到所属单据（关联主体为该链接），再发「外部回传已提交」；未提交的随临时区过期。
6. **审核**：所属模块订阅该事件生成待审项；审核人经所属模块的下载命令打开，按该模块权限与数据范围授权。接收即登记证据；退回不删除，文件仍按类别保存。

### 8. 身份核验强度与发送

1. 本期只用「持有链接 + 浏览器绑定」，不加验证码：系统无对外发送通道（ADR-0019 短信不迁移，I-4），新建属对外调用；且提交只生成待审回传。
2. 签发人用自己的渠道发送，系统不外发，只记「已发送」时间与方式（枚举，不记收件地址）。
3. 以后加验证码或系统外发须另立决定（外发通道先问用户，满足 I-4 条件，经 one-security 评审）；本期不预留（CS-1.8）。

### 9. 审计与个人信息

1. **审计**（`platform.audit`，detail 不写直接标识）：签发、标记已发送、打开、下载（文件 ID、哈希）、上传（文件 ID、哈希、大小、类型、检测结果）、提交、消耗、撤销、到期、锁定，以及所属模块接收或退回回传。来源 IP 只进 `source_address` 列。审计写入失败，该操作就失败。
2. **事件**：「外部回传已提交」只带链接 ID、单据引用、文件 ID，由所属模块订阅后生成待审核项。依赖方向为「业务 → 平台」，本模块不依赖业务模块。
3. **脱敏显示名**：签发时由所属模块经本模块的签发 api 传入（例如「张**（某公司）」），冻结在链接记录里。打开链接时不回查业务模块，所以依赖方向不变。
4. **分级**（ADR-0043，先例见括注）：

   | 列 | 访问级别 + 个人信息标记 | 先例 |
   |---|---|---|
   | 令牌摘要 | `SENSITIVE` + `NONE` | 同 `sso_ticket_uses.ticket_hash` |
   | 浏览器绑定摘要 | `SENSITIVE` + `PI` | 同 `browser_identifiers.identifier_hash` |
   | 脱敏显示名 | `INTERNAL` + `PI` | 本稿提议，交 one-data 与 one-security 确认 |
   | 联系人记录 ID | 代理键，按 ADR-0043 第 4 条第 2 点 | — |

   链接、回传记录与文件同取决定 7 第 1 点冻结的保存类别，不得永久；年限未定以带到期日的 gap 登记（R-2）。持有人不填姓名、证件、手机；公开页告知文字由法务定。
5. **境外对方**：法务答复出境问题（附录 L-2）之前，所在地声明为境外的，一律拒绝签发，提示改用线下方式。

### 10. 与电子印章平台签署链接的分工（Q01 选 d）

1. 签章服务（另立 ADR）管我方电子用印、验章与平台接入，平台概念只在 `platform.integration`（ADR-0039）；本模块只管持有人回签与上传入口。
2. 我方文件先经签章服务用印，再冻结为待阅文件；持有人可自行验章。
3. 对方能在电子印章平台在线签署（平台自发链接）时，该单据该动作走平台通道，实名与结果回收归签章服务，结果经事件交所属模块。**同一单据 × 动作只走一个通道**；本模块不签发、不嵌入、不代理平台签署页。
4. 否则走本模块：对方线下签字盖章后上传；对方电子签章是否验证留给签章服务 ADR。

### 11. 留给实施卡与建造时点

1. **留给实施卡**：模块名、表列名（UUIDv7）、端点路径与 OpenAPI 契约（CS-1.10）、限流数值、各单据类型有效期默认值与文件类型、告知文字、签发入口与权限码、审核界面、数据访问注册表（不得新增 `AccessScope.system` 调用方）。
2. **建造时点**：W0 不预留（CS-1.8）。平台部分与首个接入单据同批建，预计 W2（`delivery.acceptance`）。本模块四端点在通用审批先行上线（TRN-03）期间不开放；统一规则基础设施可能先由签章回调建成（决定 6 第 5 点）。

## 影响面

- **新平台模块**：链接与外部回传两类记录、四个公开端点、一个事件。只依赖 `platform.audit` 与文件服务，与现有边合并后无环（复审 X-8）；HTTP 写入的幂等经 web 层按 Idempotency-Key 应答缓存，不依赖 `platform.idempotency`（X1 补确认订正）。ADR-0051 平台模块表与本稿相容：表由文件服务稿统一改写为「按已采纳 ADR 与 `contexts.yaml` 登记」，合入次序由 one-coordinator 定（X-1）。
- **platform.identity**：不改。`SecurityConfiguration` 只按 `PublicEndpointRegistry` 放行（G33 不变），不复用 `ticket_issuers`、`sso_ticket_uses`，ADR-0055 决定 6 不受影响。
- **业务模块**：各自增加签发入口（传入脱敏显示名）、撤销义务、回传审核。
- **文件服务**：模块依赖，基础稿采纳前不能实施。**签章服务**：文档关系（分工见决定 10），无模块依赖边。
- **运维与等保**：对外主机名、网关白名单、WAF、告警；纳入等保定级。

## 迁移方案

老系统与 A8 都没有这项能力，无数据迁入、无在途单据。

1. 文件服务、签章服务 ADR 采纳；one-security 给出威胁模型与数值；法务答复附录 L-1 至 L-3。
2. 实施卡先交契约与守护测试，再交模块；开关默认关。
3. 逐类评审，非生产合成数据完成负向测试与限流演练后开放；随统一投产开放。

## 回滚方案

1. **总开关**：关闭本模块端点的网关路由（签章回调不受影响），全部单据类型开关置关，批量撤销有效链接，原因写「回滚」，逐条审计。
2. 回传、证据、文件、审计全部保留不回改；待审回传仍可审核。业务回到线下与邮件回传，ADR-0047 不受影响。
3. 单类出问题只关该类开关并撤销该类链接；重新开放须重新评审。ADR-0009 决定 2 的例外随之无可用令牌。

## 需同步修改的守护规则

1. `public-endpoints.txt`：增四行（理由引本 ADR）；文件头改为「登录类端点须核实身份才能建会话；一次性链接端点不建会话、不授权」。CODEOWNERS 评审。
2. `SECURITY_INVARIANTS.md`：I-3 补一句说明一次性链接端点的性质；I-9 纳入链接消耗；新增 I-14（一次性链接），测试清单见附录 §3（含预取不绑定、统一失败、不建会话、令牌卫生）。
3. `ApplicationIntegrationTest` 匿名访问用例：白名单快照随第 1 条更新，不放宽断言。
4. ArchUnit / Modulith：本模块不依赖业务模块；公开 handler 只在本模块的 web 包；不引用 `CurrentUser`、`AccessScope.system`。
5. 前端：公开入口只 import 公开端点的生成客户端（F5 / CS-4.2 照常）。
6. `ProductionConfigSanityTest`：有效期不超过 14 天，限流不得关闭。
7. 数据访问注册表（按第 9 条第 4 点分级）、DDL 命名基线、事件目录与 `asyncapi.yaml`、权限清单、OpenAPI：随实施卡登记。

## 后果

**收益**：对方免注册回传；回传绑定单据、联系人、签发人并带来源、时间、哈希；登记量与回签周期下降。

**代价与残余风险**：新增一个免登录的对外写入口，等保与运维面随之扩大。持有链接即可提交：首次上传前被转发、终端被控时防不住；提交前任何持链接者都可下载待阅文件（是否加水印见附录 S-5）。回传的证明力仍以回签件本身和人工核对为准，不会因为经过链接就成为可靠电子签名。ADR-0009 决定 2 多一处受限例外，**批准前须 one-architecture 确认取代范围**，未确认不交用户。
