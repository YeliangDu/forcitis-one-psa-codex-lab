## 背景

合同原件借阅在先行范围内（ADR-0054 决定 1 例外段与 ADR-0055 决定 1 写「合同借阅经通用审批办理」，借阅记录随之先行是本篇的推断），目标归属是 `contract.agreement` 的 AGG-13 协议，受 INV-125 约束：协议已归档，同一份原件同时只能有一笔未归还借出，借出须引用已通过的借阅审批实例。合同模块在 W3 建成。用户 B31R 答复（intent `2026-10-21-083929`，原文 `docs/decisions/decision-pages/answers/b31-r.json`）：

- **Q8**：先记在行政事务里，合同模块建成后整批移过去；要求按目标形状建，字段与约束照合同档案，INV-125「同一份原件同时只能有一笔未归还」第一版就建（部分唯一索引）；第三批只搬所有权与界面，不洗数据；过渡期用老系统合同编号并保留对照，便于迁到合同 ID。
- **Q9**：合同经办部门负责人批；借到公司外的，再加该公司负责人。「外借」定义为离开办公场所或交给外部人员，必须写用途、地点、携带人。
- **Q10**：借出时填归还日，最长 30 天，可续借一次；续借需原批准人同意；逾期提醒借用人和其部门负责人，7 天后升级到行政负责人；确需 30 天以上的由公司负责人批准，不得改归还日应付。

ADR-0058 决定 4 要求转换记录由领域入口产出，决定 2 要求转换记录只追加、不删除。整张表连同历史从一个模块移交另一个模块，现有 ADR 没有写法。one-data 给出了移交步骤（`docs/modernization/data/B31_PHYSICAL_MODEL_RULINGS.md` §11，`claude/one-data-handoff-1` @7447c040）；ADR-0039 有整表换 schema 的先例。

## 决定

在合同模块 W3 才建、而用户要求先行期就能借阅的情况下，决定先行期由行政事务持有、W3 以整表换 schema 并复制历史的方式移交，而不是先行期提前建合同模块或 W3 重新迁入，以便不洗数据、历史连续，代价是 W3 要开一次维护窗口，并对 ADR-0058 决定 4 开一处例外。

1. **先行期表与约束**：W3 之前，借阅由 `organization.administration` 持有，表与状态历史在它的 schema 里，两张表按 AGG-13 的目标形状建：
   - **合同原件**：法人（合同签约主体）、老系统合同编号、原件类型、存放位置、归档状态。W3 时它就是 AGG-13 的原件归档记录，另加合同 ID 列回填，老编号列保留。
   - **借阅记录**：引用合同原件；借用人、借出日、应还日、实际归还日；审批实例 ID 必填。借出时必填应还日，自借出日起最长 30 天，超过 30 天须经第 2 条的公司负责人审批；应还日一经借出不得修改。
   - **外借**：「外借」指离开办公场所或交给外部人员（Q9 备注）；外借时必填用途、地点、携带人。
   - **续借记录**：续借另起一条，引用原借阅记录，带新的应还日与续借审批实例；每笔借阅最多续借一次；原记录的应还日不变。
   - **INV-125**：借出前，合同原件须为「已归档」；同一份原件同时只能有一笔未归还借出，以合同原件 ID 为键建部分唯一索引；借出须引用已通过的借阅审批实例。
2. **审批**：借出与续借经通用审批，单据类型码一经登记不变，W3 后照用。审批人：
   - 借出由合同经办部门负责人批；外借另加**公司负责人**。本篇所称「公司负责人」（本条与借期超 30 天一条），指合同中我方作为签约主体的那一方法人的负责人，不指对方当事人（用户 A7677-03）；
   - 续借由原批准人批；
   - 借期超过 30 天的，由公司负责人批。
   - **缺位**：公司负责人缺位时，由预先指定的备用审批人批（GL4-01），不临时另找人。
   - **逾期提醒**：过应还日未归还，提醒借用人和其部门负责人；逾期满 7 天升级到行政负责人。到期时点按 `closeout/CONVENTIONS.md`「定时触发」的幂等键写法。
3. **W3 移交**：在一次维护窗口内完成，以 one-data §11 为准，与本条不同处以本条为准：
   1. 冻结：关闭借阅写入入口，定时作业先停。不要求窗口前办完或撤回在途借阅（用户 A7677-01）：窗口前把在途借阅（含审批中的）导出留档，含借阅记录 ID、审批实例 ID、申请日与当前环节；行随表移交。
   2. 同一个事务里依次做四件事：两张表 `ALTER TABLE … SET SCHEMA contract_agreement`（行不动）；把原 schema `state_transitions` 中这两种主体类型码的行原样复制到目标 schema（`id`、时间、序号、`cause` 都不改）；改数据访问注册表；两张表加来源标记列 `origin` 与原主键列 `source_id`，移交时已有的行回填 `origin = ADMIN_PRE_MIGRATION`、`source_id` = 原行 id（用户 A7677-01；行不换主键时两值相同，仍单列，使「哪些行是搬来的」可直接查询，不靠时间倒推），此后合同模块新建的行不取该值；在提交前完成第 7 条的核对。任何一步失败或核对不通过，整个事务中止，什么都不写，不删任何行。
   3. 触发器函数在目标 schema 重建，并把触发器指向它。
   4. 审批的单据类型码不变，只把回调绑定切到合同模块。
   5. 旧的逾期作业停用；新模块自声明作业，按表内的提醒标记做到幂等。
   6. 补登：搬完后按第 1 步的留档逐条核对在途借阅；审批未能在合同模块续办的，在合同模块按原申请日补登，日期取原日期，不以移交日代替。
4. **ADR-0058 决定 4 的例外**：第 3 条第 2 步复制的转换行，不经领域入口产出，是本篇对决定 4 的唯一例外，只限这次移交、只限这两种主体。原 schema 的原行按决定 2 保留，不删除。
5. **分析去重**：数据访问注册表在原 schema 的 `state_transitions` 登记 `transferred_aggregate_types`，列出这两种主体的类型码与移交日；分析投影不读原 schema 中这些类型码的行，只读目标 schema。
6. **权限与路径**：W3 新增合同模块的权限码，是对 `platform.identity` api 中 `Permission` 枚举的新增；identity 属基础层（ADR-0067 决定 5 第 1 条），枚举新增不在决定 4 的兼容新增之列，届时按决定 4、5 由 one-architecture 判定通道；行政事务属首次生产，旧路径按 ADR-0035 登记弃用，弃用期以该 ADR 为准；新旧权限码对同一批角色授权一致、且旧码无调用持续一个弃用期后，才删旧码。
7. **核对**：在第 3 条第 2 步的事务内、提交前核对两张表的行数与逐行摘要、`origin` 与 `source_id` 全部回填、复制的转换行数与摘要、INV-125 索引存在；不一致即中止事务，表与转换行都不动，入口不切换。权限副本在入口切换前另行核对，不一致不切换入口、不删旧码。第 3 条第 6 步补登完成后，留档的在途借阅逐条有去向（已续办或已补登），才算移交完成。

## 影响面

- `organization.administration`：建两张表、借阅审批（流程键、单据类型码）、逾期作业；权限码与名称待 one-glossary 定。
- `contract.agreement`（W3）：建成时带移交迁移与核对；基线须预先包含这两种主体的类型码与状态取值。
- `architecture/ddd/contexts.yaml`：`contract.agreement` 由本 PR 同步以 planned 登记（ADR-0051 决定 3 已列，SSOT 重写尚未进行）。
- 数据访问注册表：两张表登记为 B-31 所有，注明「W3 移交 contract.agreement」与到期日（`optional` 加 `due` 写法）；移交时加 `transferred_aggregate_types`。
- ADR-0074 决定 3：借阅审批落在本篇，ADR-0074 补一句指向本篇。

## 迁移方案

1. 本篇采纳后，借阅随 B-31 的独立施工卡建（ADR-0074 已采纳为前提）。
2. W3 由 `contract.agreement` 的负责会话开移交卡，按决定 3–7 与 one-data §11 落迁移与集成测试。
3. 采纳时在 ADR-0058 头部「被部分取代」字段追加本篇。

## 回滚方案

先行期内撤回本篇：借阅改由合同模块提前建，按决定 3 的同一写法把已有记录移过去。W3 窗口内失败：核对在事务内完成，失败即中止，表与转换行都不动，不需要反向操作。

## 需同步修改的守护规则

- 数据访问注册表守护：两张表的 `optional`、`due`，以及 `transferred_aggregate_types` 字段（one-data 负责）。
- 模块边界与依赖：移交 PR 同步改 `module-dependencies.txt` 与模块边界测试（`contract.agreement` 负责会话）。
- 集成测试（B-31 负责会话先行期建，`contract.agreement` W3 补）：外借必填三项、归还日不可改、续借上限、INV-125 拒绝并发借出与未归档借出；移交后写入仍成立、复制的转换行可读、分析投影不重复计数、回滚可恢复；移交后已有行 `origin`、`source_id` 全部回填，留档的在途借阅逐条有去向；公司负责人缺位时转备用审批人。

## 后果

- 好处：先行期满足用户的借阅要求，不提前建合同模块；W3 只搬所有权与界面，行与历史都不洗，符合 Q8。
- 代价：W3 要开一次维护窗口；对 ADR-0058 决定 4 开一处限定的例外；原 schema 留有一份只读历史，分析侧按注册表清单排除。

## 备选方案（未采用）

1. **先行期就建合同模块的借阅部分**：合同模块的其他聚合要到 W3 才建，只为借阅提前建模块，违背 CS-1.8，也与用户 Q8「先记在行政事务」相反。
2. **W3 由合同模块按迁入重新接收**：只写初始转换，历史断成两份；还要建合同 → 行政事务的读取边，与 ADR-0064 决定 2 第 1 条（第 42 行）「行政事务不被业务模块依赖」相悖。
3. **两模块共享一张表**：违反 ADR-0058 决定 3 与数据访问注册表的所有权规则，过渡期的写入守护说不清。
