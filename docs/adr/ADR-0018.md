# ADR-0018：统一语言：强制登记、自动起草、对齐准则与行业标准

- **状态**：已采纳（用户 2026-10-14：「采纳 ADR-0018」；起因：「改造过程中 DDD 的统一语言会自动登记吗？这里的语言要符合中文英文行业、规范标准的习惯」）（决定 1–3 与后果中的词条结构诸句已被 ADR-0053 取代）（后果第 3 条（部分）已被 ADR-0055 取代）
- **日期**：2026-10-14

## 背景

- 现状：词源是老仓库的 `03-通用语言.md`，GLOSSARY.md 由脚本生成并补上模块路径和老名对照；命名守护只禁止拼音、老名和含糊词，**不检查新代码里的领域词是否已登记**，也不检查用语是否符合准则和行业标准。
- 审计中发现的例子：「合同资产」的代码名是 `WipAccount`，而准则用语是合同资产（IFRS 15：contract asset），WIP 是管理口径的未开票价值，两者不是一回事；还有 `PlLedger`、`CarryBatch`、`CostWip` 这类自造写法。

## 决定

1. **单一来源**：新仓库 `forcitis-one-psa` 的 `docs/glossary/terms.yaml` 是统一语言的唯一来源（初版由老词表加标准审计生成）。每条术语包括：中文、英文代码名、snake_case、类别（实体 / 值对象 / 事件 / 命令 / 状态 / 指标）、所属模块、中文定义、标准依据、可信度、别名（含老名，标注废弃）、禁用写法、状态（已批准 / 提议中）。GLOSSARY.md、数据字典、OpenAPI 的术语说明、前端界面文案键都由它生成，老仓库的 `03-通用语言.md` 冻结为历史版本。
2. **用语标准的优先级**：
   1. 法规与会计准则：中文用《企业会计准则》原文（如第 14 号收入：履约义务、交易价格、合同资产、合同负债、合同履约成本、履约进度）；英文用 IFRS 15 与 IFRS XBRL 分类标准的用语；
   2. 工程与项目管理标准：中文用国标（GB/T 50326、GB/T 50358、GB 50500 中的变更、签证、索赔、质量保证金、竣工结算）；英文用 PMI PMBOK / AACE（WBS、WorkPackage、EstimateAtCompletion、EarnedValue）与 FIDIC（Variation、Claim、RetentionMoney）；
   3. 专业服务行业的通行写法（Timesheet、TimeEntry、Utilization、RateCard、WIP），用于前两类没有覆盖的概念；
   4. 公司内部用语只作别名，不作代码名；禁止拼音和自造缩写。
   - **方言**（用户 2026-10-14 裁定：「所有跟正式用语不符合的，都归为我们公司内部的方言，新系统一律采用正式用语，不把方言带入新系统，不确定哪些是正式用语，哪些是方言可以登记用语表，我来确认」）：
     - 凡与正式用语不符的叫法（业务口头、旧系统、A8 等外部系统里的叫法）都是方言，登记为别名类型 `dialect` 并列入禁用写法，只用于检索和沟通，不进入代码、界面文案、接口文档、列注释；
     - 判定不了的标为 `undetermined`，汇总在 `glossary/TERM_CONFIRMATION.md`，由业务 Admin 确认；确认前不得在新代码中使用；
     - 没有外部标准对应的公司自有概念（如经营口径、无合同风险敞口），以词表定义为正式用语，同样经确认；
     - 已裁定：「产值确认单」「产值」是「收入确认单」的方言。
     - 2026-10-14 业务 Admin 在用语确认页上确认了全部 197 项（A 组 4 项为方言；B 组 G-8 至 G-29 共 59 项同意改为标准用语，原叫法归为方言；C 组 134 项公司自有概念确认为正式用语），`terms.yaml` 293 条全部已批准，方言别名 33 个全部列入禁用写法。确认记录：`docs/glossary/decisions-2026-10-14.json`。
     - 2026-10-14 第二轮（psa-terms-review）：模块提议术语 58 条（架构守护模板 33 条、Phase 1a 平台契约 25 条）全部按建议确认，55 条转为正式、3 条并入已有正式用语（`Budget`→`ProjectBudget`、`ProgressRecognition`→`RevenueRecognition`、`AuditTrail`→`AuditLog`）；改名 `DeclaredHours`→`SubmittedHours`、`WebScan`→`QrCodeLogin`、`DirectLeader`→`Supervisor`（直属上级）、`Task`→`ApprovalTask`、`Capacity`→`NumberingCapacity`、`Subject`→`AuditSubject`；新 BC 命名：考勤与休假 `organization.attendance`、应付与付款 `payables.payment`。OA 盘点登记的 20 个 A8 叫法全部归为方言（项目委外按单据分别对应分包成本 / 外包成本；应收坏账申请是坏账准备计提，6b 起草词条后改挂）。仍被代码使用的 4 个旧写法暂登记在 `backend/glossary/proposed/pending-renames.yaml`，由 1a 会话改名后删除并写入禁用。确认记录：`docs/glossary/decisions-round2-2026-10-14.json`。
3. **强制登记**：构建时的守护测试扫描领域、接口、事件、Web 层的类型名、字段、枚举、方法，以及迁移脚本中的表名和列名，拆成单词后必须能在词表或通用词白名单中找到；出现禁用写法即失败；列注释的中文必须与词表中文一致（G37–G39，前端界面文案与 OpenAPI 模式名随后接入）。
4. **自动起草，人工批准**：守护失败时自动生成可直接粘贴的词条草稿（`target/glossary-draft.yaml`）。agent 或开发在同一个 PR 中补全中文、定义和标准依据，状态为「提议中」；会计类术语由财务确认，业务术语由业务 Admin 确认，确认后改为「已批准」。「提议中」的术语可以先用，但每次构建都会列出提醒。
5. 现有改词建议 G-1 至 G-7 之后，标准审计提出的改名为 G-8 至 G-29（共 22 条），见 `docs/glossary/standards-audit.md`，与 G-1 至 G-7 一起评审；其中 G-8 至 G-13、G-16、G-17、G-20、G-21、G-27 涉及会计口径，须财务确认。要点：合同资产 `WipAccount` → `ContractAsset`，管理口径的未开票 WIP → `UnbilledWip`；成本侧 `CostWip` → `ContractFulfilmentCost`（合同履约成本）；补「合同负债 `ContractLiability`」；`ProgressRecognized` → `RevenueRecognition`；「完工百分比 `Poc`」→「履约进度 `MeasureOfProgress`」；质保金 → 「质量保证金 `RetentionMoney`」并补「缺陷责任期」。

## 后果

- 统一语言不会再静默漂移：新词不登记，构建就不通过；登记的同时就要说明标准依据。
- 词表评审成为每个阶段的入口条件之一：本阶段涉及的术语全部为「已批准」，或「提议中」的已经列明并有评审日期。
- 改名会影响老表映射和反向同步，改名表要同步更新 NAMING_STANDARD.md §6 的老名对照。

## 证据

GLOSSARY.md；`docs/glossary/terms.yaml`（293 条：已批准 233、提议中 60；通用词白名单 158 个；生成器 `glossary/build_terms.py`）、`docs/glossary/standards-audit.md`（G-8 至 G-29）。缺口：OAT 正本 `08-财务原语.md` 及其映射 CSV 不在本机，未能与已有原语映射比对，拿到后补一轮；architecture-guardrails/backend 的 `GlossaryTest`：`mvn verify` 56 项全绿（新增 4 项）；注入 `SiteVisaRecord`（未登记词）、`ManHourEntry`（禁用写法）、列注释「预计工时」与词表「计划工时」不一致、未登记新表 `site_visas`，四种全部被拦下，失败信息附可粘贴的词条草稿（negative-test.log）。盲区：前端与 OpenAPI 未接入；方法参数、常量、私有成员只受禁用写法检查；不识别 RENAME；`common_words` 白名单须人工评审，防止塞入领域词绕过

## 备选方案（未采用）

只靠人工维护词表（会漂移，agent 不会主动登记）；全自动登记、不经人工批准（会把自造词合法化）
