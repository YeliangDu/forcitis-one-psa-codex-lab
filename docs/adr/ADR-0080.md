## 决定

### 1. 适用范围

附件中 L3 及以上的行；登记源仍是 `data-classification.txt`，建 L3 列的卡同时补附件行。按 Q1：费率、报价成本与毛利、开标前投标价、往来单位银行账户、合伙人出资、利润分配为 L3；业务合同与分包金额、预算、报销为 L2，按数据范围；intent `143550` 的「合同金额」指劳动合同金额，即工资，为 L3。

### 2. 明细与合计分开授权

1. **明细**：ADR-0026 第 7 项第 2 条的 `-sensitive:read`，只授附件「明细可见」列的具名角色，逐人双人，不经岗位或同步授予（CC-P10，`cross-cutting-matrix.md:124`）。新增系统角色「薪酬管理专员」。
2. **合计**：含 L3 数值的资源另设合计读权限（暂名 `<资源>-total:read`），只返回分组的和、计数、均值；与第 4.3 条导出权限都按 ADR-0032 第 2 项声明为双人逐人。双人角色只取 ALL、自定义部门、SELF（`SensitivePermissions.java:25`），部门负责人的合计须逐个列部门。
3. **k = 5**（Q2）：分组不同人数少于 5 的合计，对无明细权限者掩码（`null` + `Masked`），适用于报表、项目与部门人工成本合计、分析层与审批单据头。
4. **审批**（Q2 (b)）：单据头合计对参与人可见，个人行掩码（ADR-0026 第 3 项第 2 条）；少于 5 人的薪酬审批，处理人（当前与已办理）可见金额并记 `access.via-approval`，知会对象不可见。此为对「审批只看合计」的有意例外，用户已选。
5. **薪酬事实分层**：payroll 向过账提交的按人薪酬事实与 AGG-41 按人 × 项目分配行是 L3 明细，只供 cost.costing 系统任务与明细持有人；项目真实人工成本以项目合计可见并受 k（intent `222541`）。按 Q7 (a) 用标准成本法入总账：项目、部门按职级标准费率入账，实际与标准的差异只按法人 × 科目入账。**实施条件**：W4 薪酬过账卡开建前取得财务对该核算口径的确认；财务不同意则另立 ADR。财务另收应付薪酬法人 × 月一笔（ADR-0079 `:83`）。
6. **合成**：两种权限各按自身数据范围（ADR-0026 第 1 项第 2 条），先取范围再合计，范围算不出即拒绝（I-10）；管理模式与 `super_admin` 都没有（I-11）。

### 3. 本人查看（补充 ADR-0026 第 7 项第 2 条，原句继续有效）

- 员工对以本人为主体的行（工资条、薪资档案、社保公积金、个税、专项附加扣除、本人银行账户、证件号、私人联系方式）明文可见，不需该列读权限；固定规则，不能授予或收回，不属 ADR-0026 第 6 项第 2 条的敏感读。依据：个人信息保护法第四十五条（未核实本次原文）。
- 这些表登记为 `SCOPED`，`owner_id` 声明为主体员工（ADR-0026 第 1 项第 5 条），本人规则以 SELF 范围读取（I-10）；掩码组件比对主体后放行。不适用于公司数据；不记审计。

### 4. 审计、日志、错误、导出、分析层

1. **明文只在一处给出**：掩码组件放行明文时写审计（暂名 `platform.identity.access.sensitive-read`）：操作人、权限码、资源类型、对象 ID 或（列表）不含 L3 值的条件与行数、涉及人数；L3 值不进审计任何列。读合计不记。
2. **错误出口（补充 ADR-0026 第 7 项第 3 条，原句继续有效）**：异常消息、校验错误、错误应答不回显 L3 值；驱动异常只记类名与约束名（同 `JdbcTimesheetRepository.java:134`）。
3. **导出**：L3 明细导出需明细权限加独立导出权限（暂名 `<资源>-sensitive:export`），每次记审计；其余按 CC-P08 / G-X5（`cross-cutting-matrix.md:122、295`）。
4. **分析层**：个人行不进 `reporting`（ADR-0043 第 5 项第 4 条、第 7 项）；只进满足 k 的合计。

### 5. 生产访问

1. **数据库白名单**：RDS 的账号（建、删、重置口令、改权限）、数据（DMS、DAS）、日志（查看、下载）、备份（下载、恢复、克隆）、参数的全部动作与高权限账号只归用户；运维只留具名只读监控动作。现运维经云接口建账号（`dev-db.md:66`、`readonly-probe.md:22`）；生产 RAM 现状未核实。
2. **数据库日志**：生产设 `log_error_verbosity = terse`，约束违例 DETAIL 不进日志（`prod-db.md:17` 的设置只管参数）；RDS 是否允许客户设置该参数未核实，C-2 购买时确认。
3. **应用账号**：口令放 KMS 凭据，只有 ECS 的 RAM 角色能读（`prod-db.md:26`、`kms.md:25`）。按 Q5 (a)，生产主机 root（云助手、Workbench）只归用户，运维只执行登记的固定命令（状态、回滚）；按命令授权的 RAM 写法未核实。
4. **只读排障角色与视图**：含 L3 的 schema 没有默认授权（现 `one-db-roles-schemas.sql:92` 对全部表默认授 SELECT）；只读角色对含 L3 的表只按列清单授非 L3 列；视图、物化视图、`SECURITY DEFINER` 函数同受此规则，读到 L3 列的只授明细持有人所用的应用路径。
5. **老系统**（Q6 (a)）：只读账号对存工资、银行卡、证件号的表拒读；这些表的迁入取证用用户持有的专用账号，只出计数与聚合（ADR-0037 背景 `:13`）。
6. **演练与 dev**：非 6e 的 L3 列不再按 ADR-0036 决定 10 第 1 点在 dev 用真实数据，与 6e 同按 ADR-0054 `:88` 只在专用演练环境使用，该环境按本条与生产同等管理；普通 dev 只用合成数据。ADR-0030 不受影响。
7. **迁移**：以属主身份在生产执行；迁移不得含 `GRANT`、`ALTER DEFAULT PRIVILEGES`，建读到 L3 列的视图或 `SECURITY DEFINER` 函数须登记（守护第 5 条）。
8. **对象存储**：业务文件桶（ADR-0060 `:105`，含 B10 病假证明等）、长导出暂存位置（ADR-0025 `:63`，含 L3 导出与代发文件）与归档桶（`resources.md:21`）中存 L3 的前缀，对象读取、预签名、桶策略、ACL、复制只归应用 RAM 角色与用户，运维只留指标。各桶现行 RAM 与桶策略未核实（ADR-0060 `:162` 已要求复核）。

### 6. 静态加密

1. **生产 RDS 开云盘加密**，默认服务密钥，购买时勾选；快照与备份随之加密（未核实）。是 RDS 自带功能，不另装软件、不增供应商，不属第三方应用。只防磁盘与快照被盗，第 5 条仍是主控。不选 TDE。按用户 #494 生产为独立实例（`order-proposal-2026-10-21.md:3`），与 `prod-db.md:3` 所引 ADR-0025 第 2 条（沿用现有实例）不一致，购买清单以独立实例为准。
2. **证件号、银行账号字段加密**（Q4 (b)）：AES-256-GCM，带密钥版本；密钥存 KMS（C-8 凭据，只授 ECS 角色），用户保管离线备份；证件号另存 HMAC 盲索引供查重。密钥丢失即数据不可恢复，离线备份是唯一兜底。
3. **薪酬金额不加密**：算薪、合计、对账都在 SQL 中运算；工资为 PI 非 SPI（第 7.2 条）；能连库者已限为用户与应用。

### 7. 已答事项收口

1. **工号**（F1）：L2 + PI；登录名维持 SENSITIVE；工号仍按 ADR-0043 第 4 项不进日志。
2. **U-14 与工资**（F2）：U-14 为 (c) 分项放行，每项先做影响评估并告知：生物识别打卡须单独同意并提供替代方式；病假只存证明与期间；外勤定位须有规章且限工作时间；不满十四周岁的第三人专项附加扣除须员工以监护人身份确认，不收大病医疗；无规章不收民族、户籍。证件号完成评估与告知后可进职工名册（ADR-0079 不变量 8「未定前不含」随之失效）。工资、日薪为 L3 + PI。ADR-0060 的 SPI 文件同按本条。
3. **派遣**（F4）：不为派遣人员参保、发薪。
4. **薪资保存期**（F6，Q8 (a)）：已过账薪资事实保存 30 年后去标识（依据会计凭证保管期，会计档案管理办法原文未核实）；注册表登记该期限并引本决定（ADR-0043 R-2）；与 ADR-0068 的人事历史十年清除各自执行。
5. **职责分离**（F8，Q3 (a)）：薪酬管理专员与出纳不得为同一人（新 `GrantConflict`）；出纳凭单独的代发明细导出权限执行代发并留审计；有银企直连后改由系统推送，出纳只审批合计。

## 迁移方案

现无 L3 业务数据。只读角色现有授权按第 5.4 条改为列清单；生产实例未购买，加密与参数购买时设；老系统账号加拒读；桶策略随卡收紧。

## 回滚方案

各卡独立回退：去掉合计权限回到 ADR-0026 第 7 项原状；授权、RAM、桶策略按原脚本恢复；云盘加密不回退；字段加密回退须先解密回写，密钥丢失不可回退。第 7 条收口的用户答复不随回滚恢复。

## 需同步修改的守护规则

扩展：
1. `SensitiveFieldExposureTest`（ADR-0026 守护第 10 条）：出参与导出行中来源列为 L3 的字段须经掩码组件。
2. `ClassificationRegister`：`SENSITIVE_NAME`（`:32`）、`SPI_NAME`（`:34`）补 `id_number`、`card_number`；`SENSITIVE_NAME` 与 `PAY_NAME`（`:36`）补 `contribution_base`、`bonus`，`SENSITIVE_NAME` 补 `cost_rate`。
3. 含 `@SourceColumn` L3 字段的 record 须覆写 `toString`。
4. G-X5：导出行含 L3 字段的端点须声明 `-sensitive:export`。
5. 迁移脚本：含 `GRANT`、`ALTER DEFAULT PRIVILEGES` 即红；建视图、物化视图或 `SECURITY DEFINER` 函数而其定义引用 `data-classification.txt` 中 SENSITIVE / RESTRICTED 列的，未登记即红（匹配语句不匹配注释）。
6. 运维校验（C-9，不进 CI）：只读角色对任何 SENSITIVE / RESTRICTED 列 `has_column_privilege` 为假，且经 `information_schema.view_column_usage` 与 `pg_depend` 查得的可读视图、函数不依赖这些列；`log_error_verbosity = terse`。

不做：按列解析全部 SQL；运行时扫日志；静态检查 k；CI 解析授权脚本。

## 后果

- 好处：谁见明细、谁见合计逐资源可查；数据库、库日志与存 L3 的对象只有用户与应用能读；明文只在一处给出并留痕；四份 ADR 的过期「未定」收口。
- 代价：每个 L3 资源多一到两个权限码；部门负责人的合计逐部门维护；运维排障看不到业务敏感表与对象；老系统 L3 取证须用户执行；回滚等主机操作须用户执行或用固定命令；小组合计被掩码。
- 残余风险：不同分组之差可推算个人值；两名管理员可互相确认把薪酬管理专员授给其一（I-12 只禁自授）；应用被攻破时应用能读的都能被读。
- 未定：Q7 的财务确认（第 2.5 条）。各资源明细与合计的具体角色由建造卡逐阶段问用户（CC-P10）；附件 B12 若要让成本会计看按人分配行，属偏离「只有薪酬管理专员可见」，须另问。
