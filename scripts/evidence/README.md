# 取证单入口

本目录放取证单入口 `evidence.py` 与取证单 `sheet_<名>.py`（二乙 #6 O22a；定稿 2.6、1.12）。

## 规则（调度 10-27 定）

1. 新增或改动取证单一律走首轮复审加 opus 终审；PR 里写明这张取证单「整支只读」的依据：连什么、用哪个只读账号、只读不写的理由。
2. 登记行由作者运行 `evidence.py --entry` 生成，再手贴进 `scripts/gates/prod_targets.json` 的 `trusted_entries.entries`。`evidence_selftest.py` 比对两者，防止漂移。不让脚本改门的表。这一条另有两个白名单字段 `allowed_imports`、`allowed_builtins`，在表里手写，不由 `--entry` 生成。

## 威胁模型（调度 10-27 定）

- 前提：取证树 `scripts/evidence/` 整棵与 origin/main 逐字节一致，而且每张取证单都过了首轮和终审。所以取证单本身的逻辑按「已审、可信」处理。
- 边界：只要取证单「有能力执行或加载取证树外的东西」，不论用什么写法，都在威胁模型内，因为树外内容受分支控制。只有「取证单本身的逻辑作恶」才在模型外。
- 门要防的只是：分支里取证树以外的东西（别的目录、sys.path 能指到的地方、大小写变体、链接）被取证单执行或导入。
- 复审口径：某种绕法如果要以「已审的取证单本身逻辑作恶」为前提，就不判必改，只记建议；能让树外内容被执行或加载的，仍判必改。

## 门怎么判（主防线加白名单）

- 整树比对：本目录整棵树的每个条目（不论文件名、扩展名、大小写，目录也算）都要与 origin/main 列出的集合完全相同，每个文件逐字节一致；不许有符号链接；读不了就判不可信。
- 白名单是威胁模型的执行手段。门从 origin/main 上 evidence 那一条登记读两个字段：
  - `allowed_imports`：取证单只能导入这里列的模块（全名，不认子模块），或同目录的其他取证单。相对导入不许。
  - `allowed_builtins`：取证单用到的内置名都要在这里。
- 以 `__` 开头的名字或属性，以及以 `_` 开头的属性，一律不许。只有 `if __name__ == "__main__"` 这一种写法例外。
- 取帧、代码、回溯的属性（gi_、cr_、ag_、tb_、f_、co_ 开头）不许。
- 白名单模块里凡是能通到模块对象的属性名，也不许，例如 `datetime.sys`、`json.decoder`。门在运行时导入白名单模块，逐层算出这些属性名。
- 加模块或内置名就是改门的表；表在 final_paths 里，要过终审。
- 取证单需要白名单外的能力（含第三方 SDK，如阿里云）时，随 #7、#18 再定。

## 入口用法

- 运行方式固定为 `/usr/bin/python3 -I -S`，参数是 `--session=<会话>` 和取证单名。登记写法见 `prod_targets.json` 的 evidence 一条，其他写法门按不可信处理。
- 入口只运行本目录列表里名字逐字等于 `sheet_<名>.py` 的文件（区分大小写）。
- 取证单写一个 `collect(session, output)`：会话名和输出文件路径由入口传进来，取证单不自己读环境。它返回若干行文本，由入口写进输出文件。
- 取证单运行前，入口先切到 `/`，不受当前目录里 `.pdbrc` 一类文件影响。运行时不写 `__pycache__`：本目录出现树外条目，门就不再信任这个入口，清掉才恢复。
- 输出写到 `~/.modernize/psa/ops/evidence/`，目录 0700、文件 0600，文件名带 `expires-YYYYMMDD`，文件头第一行写「过期：」。到期由 janitor 处理。过期天数取 `policy.json` 的 `retention_days.evidence`。
- 标准输出只打印输出文件路径。取证单出错时只报异常类型。
- 无口令：取证单运行时，标准输入接到 /dev/null，getpass 直接失败。凭据只来自专用只读账号的本机配置。

## 已知未覆盖

门只认两件事：整树一致，加上取证单的白名单写法。取证单运行时做什么，门看不到，由生产只读账号兜底（底线 4）。
