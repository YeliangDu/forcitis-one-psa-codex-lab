# 取证单入口

本目录放取证单入口 `evidence.py` 与取证单 `sheet_<名>.py`（二乙 #6 O22a；定稿 2.6、1.12）。

## 规则（调度 10-27 定）

1. 新增或改动取证单一律走首轮复审加 opus 终审；PR 里写明这张取证单「整支只读」的依据：连什么、用哪个只读账号、只读不写的理由。
2. 登记行由作者运行 `evidence.py --entry` 生成，再手贴进 `scripts/gates/prod_targets.json` 的 `trusted_entries.entries`。`evidence_selftest.py` 比对两者，防止漂移。不让脚本改门的表。

## 威胁模型（调度 10-27 定）

- 前提：取证树 `scripts/evidence/` 整棵与 origin/main 逐字节一致，而且每张取证单都过了首轮和终审。所以取证单本身的内容按「已审、可信」处理。
- 门要防的只是：分支里取证树以外的东西（别的目录、sys.path 能指到的地方、大小写变体、链接）被取证单执行或导入。
- 整树比对是主防线：本目录整棵树的每个条目（不论文件名、扩展名、大小写，目录也算）都要与 origin/main 列出的集合完全相同，每个文件逐字节一致；不许有符号链接；读不了就判不可信。
- 取证单写法限制是辅助：门对每张取证单（文件名不分大小写以 sheet_ 开头）做静态检查。
  - 导入用白名单：只许标准库模块和本目录模块。
  - 相对导入、sys.path、importlib、__import__、exec、eval、compile、runpy、open、os.system、os.exec*、os.spawn*、ctypes、星号导入一律不许，属于加固。
  - 解析不了也判不可信。
- 复审口径：某种绕法如果要以「已审的取证单本身写了恶意代码」为前提，就不在威胁模型内，不判必改，只记建议；能让树外代码被执行的，仍判必改。

## 入口用法

- 运行方式固定为 `/usr/bin/python3 -I -S`，参数是 `--session=<会话>` 和取证单名。登记写法见 `prod_targets.json` 的 evidence 一条，其他写法门按不可信处理。
- 入口只运行本目录列表里名字逐字等于 `sheet_<名>.py` 的文件（区分大小写），运行它的 `collect(session)`，每行一条文本。运行时不写 `__pycache__`：本目录出现树外条目，门就不再信任这个入口；清掉才恢复。
- 输出写到 `~/.modernize/psa/ops/evidence/`，目录 0700、文件 0600，文件名带 `expires-YYYYMMDD`，文件头第一行写「过期：」。到期由 janitor 处理。过期天数取 `policy.json` 的 `retention_days.evidence`。
- 标准输出只打印输出文件路径。取证单出错时只报异常类型。
- 无口令：取证单运行时，标准输入接到 /dev/null，getpass 直接失败。凭据只来自专用只读账号的本机配置。
- 取证单在 `-I -S` 下运行，只能用固定解释器的标准库；本目录不在 sys.path 上。需要第三方 SDK（如阿里云）的取证单不在本次范围，随 #7、#18 再定。

## 已知未覆盖

门只认两件事：整树一致，加上取证单的静态写法限制。取证单运行时做什么，门看不到，由生产只读账号兜底（底线 4）。这包括取证单或它起的子进程自己打开 /dev/tty 要口令。
