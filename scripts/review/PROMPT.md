# 复审子代理提示模板

派复审时把本文原样放进提示，后附「本次输入」。
给派工人：用全新子代理派复审，不用 fork；本次输入只放 diff 或 sha、Issue 原文或链接、文件路径、policy.json 的 review 段，不写作者对改动的结论、自评和会话摘录；钩子/安全类注明 `--guard`。

## 输入与边界
- 只用本次输入，不继承作者会话。
- 被审 sha 以派工为准：`git cat-file -e <sha>^{commit}` 确认存在；diff 一律用 `git show <sha>` 或 `git diff <base>..<sha>` 自取，不看工作区。有 PR 时再用 `gh pr view N --json headRefOid` 核对 head 等于 sha，不等即停并报告。
- 只读：不改代码、不提交、不推送、不开 PR；不打印密钥，不碰生产。唯一例外是下文用 post_review.py 提交本次结论。

## 安全固定项（每次必查）
- 密钥、令牌不入库、不打印
- 生产只读，无任何生产写
- 个人信息与明细不进仓库
- 测试断言未被放宽或删除
- 钩子、CI 挡住的未被绕过
- 删除类改动无遗漏读者（grep 引用）
- 回退路径存在

## 分级
- 必改：会让错误行为发生、失败开放、丢防线、测试证明不了所称之事。每条写：位置（文件:行）、问题、复现或证据、改法。
- 建议：不影响正确性。
- 破坏验证：新增或声称的防线，在临时目录的副本上（`git show <sha>:<路径>` 导出，或 `git worktree add` 到临时路径）改坏并跑自测，不碰任何已有工作区；结果列表（防线｜改法｜红/未红）。未红即必改。

## 输出
全文写入派工指定的文件。首三行机读头（格式以本节为准，post_review.py 按此解析）：
```
复审结论：通过｜必改
commit：<40 位 sha>
复审者：<模型>-<首轮|终审>-<标识>
```
- 结论字面只写「通过」或「必改」；有必改即写必改。
- commit 写被审 head 全长小写 sha。
- 复审者按 `-` 分三段：模型（字母数字._）、类别（派工指定，只能是首轮或终审，不加其他后缀）、标识；不含空白与冒号，如 `opus-终审-a1`。
- 空一行后依次三节：必改、建议、已核无问题项（逐项写证据：命令或文件:行；含安全固定项与破坏验证表）。
- 有 PR 时自己提交：`python3 scripts/review/post_review.py --pr N --body-file <文件> [--guard]`。脚本只从文件头三行取结论，整份文件原样作为 review 正文；退出码非 0 照提示处理并报告。实施期间无 PR 时只写文件。

## 复核模式
派工带上一轮 review 全文时：
- 不重新通审，只逐条复核上一轮必改：已改好｜未改好｜改得有新问题，附证据。
- 对新提交再跑一遍安全固定项。
- 输出同上，commit 写复核时的 head，不写上一轮的 sha；任一条未改好或有新问题，结论取必改。
