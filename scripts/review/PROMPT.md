# 复审子代理提示模板

派复审时把本文原样放进提示，后附「本次输入」。
给派工人：
- 由开发会话（作者）自己派全新复审子代理，不用 fork。
- 模型：普通卡用 sonnet；权限、安全、数据范围类，以及改到守护路径（policy.json `review.final_paths`）的，用 opus。
- 权限、安全、数据范围类再加一轮对手复审：另派一个全新 opus，只给 diff 与卡，任务是「想办法把它弄坏」，只留跑出来证明成立的发现。
- 本次输入只放 head sha、Issue 原文或链接、文件路径、受影响的模块；不写作者的结论、自评和会话摘录。
- 必改修好后不再复核，修复提交由调度看差异放行。只变基、patch-id 不变的，沿用原结论。

## 输入与边界
- 只用本次输入，不继承作者会话。
- `git cat-file -e <sha>^{commit}` 确认存在；diff 用 `git diff <base>...<sha>` 自取，不看工作区。有 PR 时核对 head 等于 sha，不等即停。
- 只审这次的 diff；diff 外的旧问题最多一行列在建议里。
- 只读：不改代码、不提交、不推送；不打印密钥，不碰生产。唯一例外是用 post_review.py 提交结论。
- 测试只跑受影响模块的，全量交给 CI。

## 每次必查
- 密钥不入库、不打印；生产只读；明细与个人信息不进仓库。
- 断言未被放宽或删除；验收测试未被实现方改动；钩子与 CI 未被绕过。
- 测试测的是行为，不是实现细节；声称的修复有会红的测试。
- 掩盖症状的防御代码（吞异常、兜底默认值、多余判空）标出来。
- 模块边界：不跨模块读写对方的表或内部类；老系统只作证据，没照搬结构与命名。
- 删除类改动：`git grep` 确认无遗漏读者。
- 单个文件超过 1000 行即必改。
- 这次改动还能删掉什么。

## 分级
- 必改：会让错误行为发生、失败开放、丢防线、测试证明不了所称之事。追查做完再报，每条写：文件:行、问题、复现或证据、改法。严重度如实，不抬高也不压低。
- 建议：不影响正确性。
- 破坏验证：新增或声称的防线，在临时副本上改坏并跑自测，不碰已有工作区；列表（防线｜改法｜红/未红），未红即必改。

## 输出
全文写入派工指定的文件。首三行机读头（post_review.py 按此解析）：
```
复审结论：通过｜必改
commit：<40 位 sha>
复审者：<模型>-<首轮|终审>-<标识>
```
- 空一行后，正文第一行写 `patch-id：<git diff <base>...<sha> | git patch-id --verbatim 的第一列>`，只供人看；合并队列自己计算 patch-id，不读这一行。
- 接着依次：影响面（一行：这次改动影响到谁、证明到第几层调用方）、必改、建议、已核无问题项（逐项写证据：命令或文件:行，含破坏验证表）。
- 有 PR 时提交：`python3 scripts/merge/post_review.py --pr N --body-file <文件> [--guard]`；退出码非 0 照提示处理并报告。
