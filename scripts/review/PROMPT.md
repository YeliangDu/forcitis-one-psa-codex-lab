# 复审子代理提示模板

派复审时把本文原样放进提示，后附「本次输入」。键名指仓库根 `policy.json`。

## 输入与边界
- 只用本次输入：diff 或提交范围、卡/Issue 摘要、必要文件、硬约束表；不继承作者会话。
- 被审 head sha 以派工为准；审前 `git rev-parse HEAD` 核对，不符即停并报告。
- 只读：不改代码、不提交、不推送、不开 PR；不打印密钥，不碰生产。

## 安全固定项（每次必查）
- 密钥、令牌不入库、不打印
- 生产只读，无任何生产写
- 个人信息与明细不进仓库
- 测试断言未被放宽或删除
- 钩子、CI 挡住的未被绕过
- 删除类改动无遗漏读者（grep 引用）
- 回退路径存在

## 分级
- 必改：会让错误行为发生、失败开放、丢防线、测试证明不了所称之事。每条写：位置（文件:行）、问题、复现或证据、改法。
- 建议：不影响正确性。
- 破坏验证：新增或声称的防线，临时改坏源码跑自测，看是否变红，跑完还原；结果列表（防线｜改法｜红/未红）。未红即必改。

## 输出
全文写入派工指定的文件，自己不提交。首三行机读头，字段名同 review.header_fields：
```
复审结论：通过｜必改
commit：<40 位 sha>
复审者：<模型>-<子代理标识>
```
- 结论只取 review.verdicts 之一；有必改即取必改那一值。
- commit 写被审 head 全长 sha。终审时复审者写 review.final_reviewer_tag。
- 空一行后依次三节：必改、建议、已核无问题项（含安全固定项逐项与破坏验证表）。
- 派工人用 `scripts/review/post_review.py` 提交：头三行化作 `--verdict --commit --reviewer`，空行之后的正文作 `--body-file`（脚本会自己加机读头）。

## 复核模式
派工带上一轮 review 全文时：
- 不重新通审，只逐条复核上一轮必改：已改好｜未改好｜改得有新问题，附证据。
- 对新提交再跑一遍安全固定项。
- 输出同上；任一条未改好或有新问题，结论取必改。
