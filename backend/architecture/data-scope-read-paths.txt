# Every GET handler of every HandlerMapping of the running application of the servlet context (controllers, actuator, static resources) (#730, security-invariants I-10), and the data scope its rows answer under.
# Endpoints on the separate management port (prod: 8081) live in a child context and are out of this register (#730 comment 6604403956), on the condition that this port exposes only
# health and prometheus; exposing anything more is an infrastructure change under the runbook.
# DataScopeReadPathsGuardTest keeps this file well formed; DataScopeReadPathsIT keeps it equal to the GET mappings of the running context
# (an unlisted handler or a line that matches no handler fails the build).
# Format: GET <path as mapped> | <mode> | <reason>
#   SCOPED           rows are bound to an org unit or a person and are filtered by the caller's data scope (acceptance A1-A4 prove it)
#   SELF             only the caller's own data (acceptance A5 proves a second account's data is never returned)
#   NOT_SCOPE_BOUND  case i: rows have no org-unit or person binding (configuration, reference data); case ii: rows that do carry a person or unit but are
#                    GLOBAL by an adopted decision, so the holder's role scope is not applied to them (a grant of the permission is a whole-company read). The permission
#                    that guards the line is either (first form) held by a system role, or (second form) a two-person sensitive permission that other roles obtain only
#                    through two-person confirmation (ADR-0026 item 6.2, ADR-0027 item 3). The reason names the ADR row that registers the data GLOBAL and which form applies.
#                    The reason is required; if a case-ii permission can be held by an ordinary role without two-person confirmation, the line is SCOPED.
# The reason is kept on every line so that a reviewer of the mode does not have to open the handler. Modes ruled by one-design, #730 comments 6603659958, 6604041421 and 6604403956.
