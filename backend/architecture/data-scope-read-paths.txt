# Every HTTP read handler the running application maps (#730, security-invariants I-10), and the data scope its rows answer under.
# DataScopeReadPathsGuardTest keeps this file well formed; DataScopeReadPathsIT keeps it equal to the GET mappings of the running context
# (an unlisted handler or a line that matches no handler fails the build).
# Format: GET <path as mapped> | <mode> | <reason>
#   SCOPED           rows are bound to an org unit or a person and are filtered by the caller's data scope (acceptance A1-A4 prove it)
#   SELF             only the caller's own data (acceptance A5 proves a second account's data is never returned)
#   NOT_SCOPE_BOUND  case i: rows have no org-unit or person binding (configuration, reference data); case ii: rows that do carry a person or unit but are
#                    GLOBAL by an adopted decision, reserved for a system role and not filtered by scope: the reason names the decision and the role.
#                    The reason is required; a reviewer who adds or checks a case-ii line confirms the permission is held only by system roles, else the line is SCOPED.
# The reason is kept on every line so that a reviewer of the mode does not have to open the handler. Modes ruled by one-design, #730 comment 6603659958.

GET /api/v1/organization/employee-profile-change-requests | SCOPED | pending profile changes, one employee each (name, gender, requester)
GET /api/v1/organization/legal-entities | NOT_SCOPE_BOUND | legal-entity master data (code, name, status): company level, no unit or person
GET /api/v1/organization/legal-entities/{legalEntityId} | NOT_SCOPE_BOUND | one legal entity: company level, no unit or person
GET /api/v1/organization/org-unit-legal-entities/{orgUnitId} | SCOPED | legal-entity periods of one org unit
GET /api/v1/organization/org-units | SCOPED | org units; the read path that already refuses an unresolvable scope (OrgUnitScopeIntegrationTest)
GET /api/v1/organization/org-units/{orgUnitId} | SCOPED | one org unit; out of scope answers 404
GET /api/v1/organization/work-calendars | NOT_SCOPE_BOUND | the years a company work calendar is maintained for: no unit or person
GET /api/v1/organization/work-calendars/{calendarYear} | NOT_SCOPE_BOUND | one year of the company work calendar (days, holidays): no unit or person
GET /api/v1/platform/approval-task-overviews | NOT_SCOPE_BOUND | case ii: open tasks of everyone, read only by holders of the process administrator system role (checked in ListAllTasks by role code; ADR-0032 section 1, ADR-0034 item 7, D-1a-61); an operations view, unit scope would make it useless
GET /api/v1/platform/approval-task-records | SELF | tasks the caller has handled
GET /api/v1/platform/approval-tasks | SELF | the caller's inbox
GET /api/v1/platform/approval-tasks/{taskId} | SELF | one task of the caller's inbox
GET /api/v1/platform/audit-entries | NOT_SCOPE_BOUND | case ii: audit_entries is GLOBAL by decision (ADR-0026 table "审计", ADR-0027 section 3 item 1): permission audit-entry:read goes to the security auditor system role (D-11); unit scope would show a head their staff's login addresses
GET /api/v1/platform/audit-entries:export | NOT_SCOPE_BOUND | case ii: the list above without paging, same GLOBAL decision (ADR-0026 table "审计", ADR-0027 section 3 item 1); permission audit-entry:export, security auditor system role (D-11)
GET /api/v1/platform/authorization-requests | NOT_SCOPE_BOUND | case ii: pending grant requests for the confirmers, who hold account-role:update; account_roles is GLOBAL by decision (ADR-0026 table, "user_accounts, roles, account_roles 为 GLOBAL")
GET /api/v1/platform/files/{fileId} | SELF | status of an upload the caller made and has not yet linked
GET /api/v1/platform/legacy-numbers | NOT_SCOPE_BOUND | original number to document id, legal entity and batch; no person or unit attribute in the answer
GET /api/v1/platform/legacy-numbers:resolve | NOT_SCOPE_BOUND | one original number to document id, legal entity and batch; no person or unit attribute in the answer
GET /api/v1/platform/numbering-rules | NOT_SCOPE_BOUND | numbering rules per document type: configuration
GET /api/v1/platform/numbering-rules/{documentType} | NOT_SCOPE_BOUND | one numbering rule: configuration
GET /api/v1/platform/own-login-records | SELF | the caller's own login records

GET /api/v1/platform/roles/{roleId} | NOT_SCOPE_BOUND | case i: one role definition: configuration; roles is GLOBAL (ADR-0026 table)
