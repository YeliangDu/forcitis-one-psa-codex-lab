# 列登记：访问级别与个人信息标记两个维度（ADR-0043；NAMING_STANDARD §2.5，GUIDING_PRINCIPLES §6 数据安全）。
# 格式（四段，守护 ClassificationRegister 解析，段数、取值、理由不得含 | 都会报出具体行）：
#   <schema.table.column> | PUBLIC|INTERNAL|SENSITIVE|RESTRICTED | NONE|PI|SPI | <理由>
# 访问级别（用户按业务决定）：PUBLIC L1 公开 | INTERNAL L2 内部 | SENSITIVE L3 敏感（个人联系方式、生日、工资与日薪、证件、银行卡、安全材料：脱敏展示、按范围授权）| RESTRICTED L4 机密（口令、密钥、会话：不出库、不进日志与分析层）。
# 个人信息标记（按法律判定，拿不准按 SPI）：NONE 非个人信息 | PI 个人信息 | SPI 敏感个人信息（个人信息保护法第二十八条；SPI 的访问级别不得低于 SENSITIVE）。
# 理由：PI、SPI 行以「用途：」开头写明该列的功能；SPI 行另写影响评估报告路径（docs/privacy/…md，须存在）；NONE 行以「豁免：」开头表示名字像个人信息但不是（如代理键）。
# DdlNamingTest 检查：名字像凭据、薪酬、银行、证件的列须登记 SENSITIVE 及以上；名字像敏感个人信息的列（银行、证件、民族、户籍、生物识别、行踪、健康、病假、工伤、生育、专项附加扣除）须标 SPI；薪酬列须标 PI 或 SPI；登记的列必须存在。
# DataArchitectureTest D5 检查：名字像个人信息的列（姓名、登录名、企业微信、收件人、账号名、工号、邮箱、性别、手机、生日、地址等）须标 PI 或 SPI，或有「豁免：」行。未登记的列默认 INTERNAL + NONE。
